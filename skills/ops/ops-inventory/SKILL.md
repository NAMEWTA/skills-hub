# 核验运行对象与项目关系

交付有身份、来源和时间的运行视图。让用户能从服务器查项目，也能从项目查组成服务、共享依赖和真实位置；不知道的对象保持未知。

## 先定位工作范围

读取本次运维工作根的 `.agents/ops/AGENTS.md` 和已明确的清单入口，不假定宿主递归加载。工作根可独立于源码仓库。沿用项目现有资产清单、配置和运维文档，按真实路径引用，不要求安装其他领域。

登记、改名或按 `01` 这样的主别名定位主机时，先读[主机别名](references/host-alias.md)。从 `.agents/ops/registry/01.md` 取得稳定身份和连接引用，文件名就是别名；不要把 `01` 直接当成 SSH 入口。

传给 `ops-execute` 本次目标、授权范围和已有 run，由其建立或接续调用记录。首次登记没有远端目标时先建立空目标本地 run，再补已核验对象；不因尚无清单而先无记录扫描。缺少执行/记录方法时完成材料分析和计划，明确缺口。

## 建立足够回答问题的关系

按 [发现与核验](references/discovery.md) 读取权威来源、收集授权内运行事实、比较声明与观测。先解决用户涉及的对象，不默认扫描全部账号、网段或服务器。

按 [运行关系模型](references/runtime-model.md) 区分项目环境、逻辑服务、项目使用关系、稳定运行实例、资源和有向依赖。相同名称、同机或一条网络连接不足以认定项目归属；项目也不等于依赖图中的一个连通块。

- 项目使用关系可以指向共享数据库或缓存，写明逻辑数据库、schema、租户或 namespace 等实际消费范围；未知时不猜。
- 实例 ID 不使用 PID、容器 ID 或 Pod UID。短期标识和动态节点位置放入带时间的观测。
- 一个共享服务只登记一次，通过关系被多个项目引用；别名变化和资源替换分别处理，不覆盖历史身份。
- 重要关系区分声明、观测、推断与未知，记录来源和核验时间。互相矛盾的来源分别保留，不用旧文档盖掉现场。

## 形成查询与交接

按 [双向查询与影响分析](references/queries.md) 回答服务器、项目和共享服务视角。影响分析列出直接目标、可能受影响者和覆盖缺口，不能扩大写权限或自动生成启动、停止、恢复顺序。

小范围发现可直接把必要关系和来源保存在同一 run；需要持续查询关系时在 `.agents/ops/registry/` 保存 [运行关系模板](assets/registry.md) 的实际内容，引用已存在的单主机登记。已有权威资料不迁移、不重复建立竞争清单。项目专属解释放 `.agents/ops/projects/<project-id>/` 或已指定的位置。

把身份、运行定位、证据、时间、歧义与影响交给需要它们的技能，继续同一任务。健康结论由 `ops-inspect` 负责，恢复先决条件由 `ops-recover` 负责，历史查询由 `ops-history` 负责。

## 完成条件

报告已核验对象、项目使用关系、跨机位置、共享影响、声明与观测差异，以及未知、过期和未覆盖范围。登记成功不代表服务健康、取得操作授权或已经完成部署。

按 [两个项目与共享服务示例](references/example-topology.md) 检查多对多表达；该文件全部是假设夹具，不能写成用户资产。全部方法见 [资料索引](references/method-index.md)。
