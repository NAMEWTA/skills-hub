### 轨迹取证

**你负责从产物诊断。**

区别于观测活进程的**运行时取证**。这里捕获已存在，产物是固定数据集，读取，不重跑。工具保持通用：cpuprofile 和 `.json.gz` 用 DevTools 或轨迹解析器，spindump 用文本编辑器，heapsnapshot 用堆工具。

1. 识别格式，用正确工具加载。大产物交子智能体解析，主线程保留缩减发现，遵循 **principle-guard-the-context-window**。按“子智能体”一节选择推理级别与快速或标准速度。
2. 把原始产物转成可查询形态。将轨迹或堆快照导入 sqlite，每样本、帧或节点一行。先达到可查询形态再阅读。
3. 收敛到原因。查找耗时最多的帧，沿调用树找到热路径。泄漏则沿泄漏对象到 GC 根的保留链，spindump 则找卡在 CPU 或阻塞的线程及等待原因。
4. 归因源码。借产物自身符号，把热帧映射到文件、符号、行。没有源码映射的帧还不算诊断。解析符号，或明确说产物没有携带它们。
5. 有成对捕获时，比较前后产物确认；没有则把发现标为产物支持的最强假设，不是已确认原因。
6. 交还有引用诊断，未要求就不修。原因已知后路由缺陷或性能问题。吞吐检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 产物与格式、缩减发现、源码位置、产物路径、是否由成对捕获确认。
