一个松散想法来了，大到单个智能体会话装不下，且笼罩在迷雾中：从这里到**终点**的路还不可见。探路是找出那条路，而不是冲向终点。本技能在仓库事项跟踪器上绘制**共享地图**，再逐一推进**决策任务**；它们是解决后形成决定的问题，而不是准备执行的构建切片，直到路线清楚。

每项工作的终点不同，命名终点是绘图的第一步，它塑造每个任务。终点可能是一份可交接并迭代的规格、开始规划前必须锁定的决定，或原地完成的数据结构迁移等变更。地图不限领域：工程工作、课程内容，凡符合这种形态的工作都可使用。

## 规划，不执行

探路默认是**规划**：每项任务解决一个决定；当道路清楚、执行者动手前已无决定待定时，地图完成。想直接做工作的冲动通常意味着已抵达地图边缘，该交接了。某项工作可以在**笔记**中覆盖此默认，把执行纳入地图本身；没有这种覆盖时，产出决定，而非交付物。

## 按名称引用

每张地图和每项任务都是事项，所以都有**名称**，即标题。在人会阅读的一切内容中，包括叙述、地图的“目前决定”，都用名称引用，绝不用裸 ID、编号或 slug 代替。满屏 `#42、#43、#44` 不可读，名称一眼就能理解。ID 和 URL 不会消失；用名称包住链接，让它们位于名称**内部**，不代替名称。

## 地图

地图是本仓库事项跟踪器中的单个事项，标签为 `wayfinder:map`，也是规范成果。其任务是地图的子事项。

地图是**索引**，不是存储。它列出已经作出的决定，并指向持有细节的任务；一个决定恰好存在于一个地方，即它的任务，因此地图不重述，只概括并链接。

**地图、子任务、阻塞关系和前沿查询实际放在哪里，取决于跟踪器。** 事项跟踪器应已提供；没有则告诉用户运行 `/setup-matt-pocock-skills`。查看跟踪器文档的“探路操作”，了解**本仓库**如何表达。如果尚未提供跟踪器，默认用本地 Markdown。

### 地图正文

低分辨率呈现整张地图，每个会话加载一次。**不**列开放任务：它们是开放的子事项，通过查询查找。

### 任务

每项任务都是地图的**子事项**，跟踪器事项 ID 是其身份。正文写问题，大小适合一个 100K token 的智能体会话：

```markdown
## 问题

<本任务要解决的决定或调查>
```

每项任务带 `wayfinder:<type>` 标签，类型是 `research`、`prototype`、`grilling`、`task` 之一，见[任务类型](#任务类型)。地图和任务只带 `wayfinder:` 标签，不带 `ready-for-agent` 等分诊标签：它们是决定，不是实现工作。

会话**先认领**任务，再做任何工作：把任务指派给推动地图的开发者，让并发会话跳过它。负责人**就是**认领标记；开放而未指派的任务就是未认领。

阻塞使用跟踪器的**原生**依赖关系。这很重要，因为跟踪器 UI 会**可视化**显示前沿，人无需打开地图就能看出哪些可领取。只有不支持原生阻塞的跟踪器才退回正文约定。当所有阻塞任务都关闭时，一项任务就**解除阻塞**；**前沿**是开放、未阻塞、未认领的子任务，即已知区域的边缘。

答案不放在正文里，而在解决时记录，见[推进地图](#推进地图)。解决任务时创建的资产从事项链接，不整段粘贴。

## 任务类型

每项任务要么是 **HITL**，即人在循环中，与能代表自己发言的人共同完成；要么是 **AFK**，由智能体独立推动。HITL 任务只能通过真实互动解决，智能体绝不能替人扮演另一方；追问智能体自行回答自己的问题就违反了这一点。

- **研究（AFK）**：阅读文档、第三方 API 或知识库等本地资源，找出某项决定所等待的事实。由子智能体调用 Skill 工具加载 `research` 来解决。需要当前工作目录之外的知识时使用。
- **原型（HITL）**：调用 Skill 工具加载 `prototype`，制作便宜、粗糙、具体的成果供人反馈，提升讨论保真度，例如提纲、粗稿、桩或 UI／逻辑代码。把原型链接为资产。关键问题是“应该长什么样”或“应该怎样行为”时使用。
- **追问（HITL）**：对话，默认类型。始终分别调用 Skill 工具加载 `grilling` 和 `domain-modeling`。
- **操作（HITL 或 AFK）**：在能作出**决定**之前必须先发生的手工工作；没有东西要决定、原型化或研究，但不做就无法继续讨论。例如注册服务以便评估 API、配置访问权限、搬运数据以便看清形状。这是唯一**执行**而不作决定的类型，它凭解除决定阻塞获得位置，不是为了交付终点。智能体能独立做就自己做，属于 AFK；否则给人准确清单，属于 HITL。工作完成即解决；答案记录做了什么，以及后续任务依赖的事实，例如凭证位置、新 URL、行数。

## 战争迷雾

地图**有意**不完整：看不见的地方不要绘制。当前任务之外是**战争迷雾**：能隐约看出未来将出现的决定和调查，但因为依赖尚未解决的问题，还无法锁定。解决任务会拨开它前方的迷雾，把刚刚能够明确表达的内容升级为新任务，逐步推进，直到通往终点的路线清楚、没有任务剩下。

地图的**尚未明确**保存这种模糊视野：怀疑将遇到的问题、以后要重访的领域。它是**朝向**终点的未发现前沿；这里的全部内容都在范围内，只是不够准确，暂时不能制成任务。按视野允许的程度宽松或完整地写，它也给协作者指明工作的方向。

**是迷雾还是任务？** 检验在于现在是否能准确表述问题，**不是**现在是否能回答。

- **写成任务**：问题已经准确，即使被阻塞、暂时无法行动。
- **列为尚未明确**：暂时无法那么准确地表述。不要预先把迷雾切成任务大小；它比任务粗，一片迷雾在前沿抵达时可能升级成多个任务，也可能一个都没有。

**尚未明确**不包括已经决定的内容，即“目前决定”；也不包括已有活跃任务或范围之外内容，见下一节。

## 范围之外

迷雾只沿着**朝向**终点的方向积聚。终点确定范围，超出终点的工作就是**范围之外**：它不是迷雾，也不属于**尚未明确**。把主动排除在**本项**工作之外的内容放到地图独立的**范围之外**节。它由范围决定，而不是由清晰程度决定。

范围之外工作永不升级，因为前沿在终点处停止。只有重画终点后它才会返回，而且应作为新工作，不是恢复旧工作。

划定范围是范围管理，不是路线中的一个步骤。当已有任务被发现位于终点之外，例如绘图时误纳入，或某个答案暴露了这一点，**关闭它**：已关闭任务明确不在前沿。然后在**范围之外**留一行要点和排除理由，并链接已关闭任务。它不进入**目前决定**；那里记录实际走过的路线，而范围边界不是路线上的一步。

## 调用

两种模式。不论哪种，除研究任务外，**每个会话绝不解决超过一项任务**。

### 绘制地图

用户带着松散想法调用。

1. **命名终点。** 分别调用 Skill 工具加载 `grilling` 和 `domain-modeling`，明确地图正在寻找通路的是什么：规格、决定还是变更。终点确定范围，所以先确定。
2. **绘制前沿。** 再追问，这次**广度优先**：展开整个空间，不深挖单个线索，找出未决决定和现在可走的第一步。**如果没有发现迷雾**，即路线已经清楚、全程小到一个会话能完成，就不需要地图。停下，询问用户想如何继续。
3. **创建地图**，标签 `wayfinder:map`：填写终点与笔记，目前决定为空，把迷雾勾勒在**尚未明确**中。
4. **创建现在能明确描述的任务**，作为地图子事项，再在**第二遍**连接阻塞依赖，因为事项必须先有 ID 才能相互引用。交叉引用也在这一遍用真实 ID 写入；占位符 `#<n>` 会自动链接到无关事项。接线把任务分为前沿和被阻塞者；不能明确的内容仍在迷雾中，即**尚未明确**节。
5. **启动研究子智能体。** 为每个刚创建的 `research` 任务启动全新上下文子智能体，调用 Skill 工具加载 `research` 并行解决；把发现记录在一次性 `research/<name>` 分支上，在任务中留上下文指针。推送分支，但不开 PR，因为它永不合并。
6. 停止：绘图就是一次会话的工作，不手动解决任何任务。

### 推进地图

用户提供地图 URL 或编号调用。任务是**可选的**：不指定时由你选择下一个决定，而不是让用户选。

1. 加载**地图**，即低分辨率视图，不读全部任务正文。
2. 选择任务。用户指定了就使用它，否则按顺序取第一个前沿任务。**认领它**：做任何工作之前先指派给自己。
3. 按 `wayfinder:<type>` 标签命名的类型解决，见[任务类型](#任务类型)。读取标签，不能只读正文，因为正文不会声明类型。**按需放大**：需要时获取相关或已关闭任务的完整正文；`## 笔记` 点名了哪些技能，就用 Skill 工具加载哪些。如果不确定，就分别加载 `grilling` 和 `domain-modeling`。
4. 记录解决结果：把答案作为**解决评论**发布，**关闭**事项，再向地图“目前决定”**追加上下文指针**。
5. 添加新发现任务，先创建再接线；把答案使之能够准确表述的迷雾升级为任务，并从**尚未明确**清除对应内容，让它只存在于新任务。如果答案揭示当前或其他任务位于终点之外，就**划到范围之外**，而不是当作路线上解决的任务。如果决定使地图其他部分失效，更新或删除这些任务。

用户可能并行推进未被阻塞的任务，所以应预期其他会话正在同时编辑跟踪器。
