# 页面风格

## 概要

让 DSH 页面易于浏览、不易误读的页面级风格偏好：简短概要、受控技术英语、主要部分之间的 `-----` 分隔线、让章节标题保持可见的 `<details>` 折叠区，以及有纪律的强调。模板是 `session-persistence-jsonl` 的 README 双语对。

## 简短概要

每份人工编写页面以简短 `Summary` 开头：一个段落、三到五句话，陈述读者能做或观察什么、为何关心、运行模型及最重要的限制。目录与各节承载细节；位置与章节顺序见 [structure-hierarchy.md](structure-hierarchy.md)。英文包 README 的 Summary 还由 `verify-package-readme-summaries` 限制为按 `wc -w` 方式计数最多 100 词。

## 受控技术英语

对 agent、译者或非母语读者需要解析的英文文字，进行受 [ASD-STE100](https://www.asd-ste100.org/) 启发的审查。这是清晰度纪律，不是经过认证的 ASD-STE100 合规。仓库不复制或验证该标准的受控词典。

- 指明主体与动作。主体重要时优先主动语态。
- 每个概念使用一个稳定术语。不为求变化轮换近义词。
- 优先直接动词。存在准确动词时，替换名词化和含糊短语动词。
- 每句只放一个指令。三个以上步骤或条件用列表。
- 拆开分号与长从句链。每段只谈一个主题。
- 删除无依据的品质形容词与堆叠的保留措辞。保留来源中的每个事实及不确定程度。

指令 20 词、描述 25 词仅作审查提示，不是机械门禁。拆句会掩盖条件或关系时，保留长句。绝不为满足长度目标而删除或强化 `must`、`may`、`never`、时机、例外、数字或其他约定用语。[文字规范](../../dsh-prose-standard/SKILL.md)负责完整命题规则。

## 章节分隔线

页面主要部分之间使用独占一行的 `-----` 水平线，前后各有空行。紧跟段落的线会被解析为 Setext 标题；包 README 最后两节 H2 内的线会破坏 Model Experience 门禁。模板分隔：前置内容 → 使用章节 → 折叠开发者章节 → Further Exploration → Model Experience。

## 可折叠内容章节

面向开发者的细节及最后的 Dev Note，折叠在 GitHub 原生 `<details>`／`<summary>` 区块内。章节标题（H2 或 H3）及其 `<a id>` 锚点保持可见，只折叠标题下方内容。区块内 `<summary>` 后放空行，每个 Markdown 行保持第 0 列（缩进会变成代码块），空行后以 `</details>` 关闭。折叠区内标题、列表、表格和链接照常解析并保留锚点。`session-persistence-jsonl` 的 README 双语对展示实现章节与 Dev Note 两种折叠。

包 README 中，`## Model Experience` 与 `## Known Limitations and Deferred Work` 保持为最后两个 H2 标题。限制锚点紧放在其 H2 后，避免成为前一 Model Experience 正文的一部分。最后的 Dev Note 放在限制章节下，作为带锚点的 H3。明确豁免限制章节的包，可以使用 H2 Dev Note。

## 强调纪律

只为改变行为的分句或关键比较保留加粗。基准表格中，将列标题及每行最佳值加粗，参照参考示例。
