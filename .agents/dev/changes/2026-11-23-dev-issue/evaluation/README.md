# dev-issue 的离线使用场景

本目录记录新增技能的独立使用检查。MemoDesk 是本次专门构造的离线项目，全部账号、Issue、评论和 example.invalid 链接都是场景材料，不能当成真实用户需求或对外发布目标。项目源码只用于让撰写者核对事实和运行已有最小检查。

## 执行方式

各执行者从独立会话读取 dev-issue 包及提供的原始材料，不继承本次实现过程或主代理的判断。请求限定只读项目、只交付草稿、禁止网络与远程写入。恢复场景使用已提供的读取结果，检查结果不是实际网络故障注入。

| 场景 | 原始请求与材料 | 交付 |
| --- | --- | --- |
| 新功能 | MemoDesk 增加可切换并持久化的笔记置顶；置顶分组内沿用更新时间降序，搜索及归档规则保留 | [功能草稿](outputs/feature-draft.md) |
| 性能 | 用户报告十万条笔记搜索卡顿，目标 80ms；没有设备、负载或测量资料 | [性能草稿](outputs/performance-draft.md) |
| 更新 | 结合 #42 初始与最新正文、作者评论、已完成项和附件，完善导出需求正文 | [更新草稿](outputs/update-draft.md) |
| 评论 | 根据 #55 的异常日志和当前代码，给原作者追加分析与建议 | [评论草稿](outputs/comment-draft.md) |
| 恢复 | 创建请求超时，提供搜索和近期 Issue 结果，核对实际可确认状态与后续动作 | [恢复结果](outputs/recovery.md) |
| 路由 | 八条自然请求覆盖完整 Issue、分诊、本地票据、直接修复、更新、评论、材料整理与草稿 | [入口选择](outputs/routing.md) |

## 材料范围

- [fixture/](fixture/) 包含 AGENTS、README、Node.js 项目文件、两项现有测试和 Bug 模板。
- [snapshots/](fixture/snapshots/) 是原始讨论与恢复结果。
- 输出保留执行者原文，用于核对它能否从技能和任务材料独立完成工作；主代理的结论集中在上一层 verification.md。
- 本次没有向模拟仓库发送请求，没有新增运行时脚本，也不把场景代码装入技能包。npm 白名单本来就排除 .agents/。
