# 按文件名登记和查找主机

主别名在实际运维工作根内唯一。`.agents/ops/registry/<别名>.md` 的文件名就是别名。不建第二份映射表，正文也不必重复保存别名。

## 登记

1. 取用户明确给出的别名，不按主机名或 IP 自动起名。接受小写 ASCII 字母、数字和连字符，首字符为字母或数字。把别名当字符串，保留 `01` 的前导零。拒绝路径成分、Windows 保留设备名和大小写冲突；不自动转换输入。`runtime.md` 等已有非主机登记文件不是可覆盖的别名目标。
2. 按[运行关系模型](runtime-model.md#稳定身份)核实主机身份。新登记使用[单主机模板](../assets/host-registration.md)。已有权威资产或已知的稳定资产编号沿用原值。已有单主机登记可保留原结构，使用真实身份、当前定位和来源，不复制成另一张主机卡。没有主别名时沿用原有清单或 run，不预分配编号。
3. 只在本工作根的 registry 中写入目标文件。不跟随指向工作根之外的链接或目录联接。若文件名已被其他对象、关系总表或不明内容占用，保留原文件并报告冲突，不猜测或覆盖。同一资源已登记在别处时，按下文直接迁移现行文件。

## 使用

1. 对「检查 `01`」这样的主别名请求，先读当前根的 `.agents/ops/registry/01.md`。从登记正文取 `resource_id`（或既有稳定资产编号）、实际主机名、当前连接引用、适用环境、身份依据及核验时间。不要把文件名当成 SSH 参数或稳定 ID。
2. 文件不存在、正文并非单主机、身份/连接定位不全或与其他证据冲突时，返回缺口和可核实的候选。不猜默认生产目标，不改走同名 SSH 入口，不跨根搜索，不开始现场动作。用户明确给出主机名、资源 ID 或另一个权威清单时，可按原有发现方法核验该线索。
3. 把稳定 ID、真实连接引用、适用范围和证据交回调用者，沿用同一任务和授权。别名仅解决定位。实际连接仍须核对入口和身份，run 保留当时的稳定 ID 和定位。

## 替换现行登记

| 经核实的变化 | 对现行登记的操作 | 对历史的操作 |
| --- | --- | --- |
| 同一台主机改主机名或换 IP，仍叫 `01` | 直接替换 `01.md` 内的相关定位及核验时间 | 旧快照不变 |
| 用户把同一台主机的别名改成 `edge-01` | 确认目标路径空闲，将 `01.md` 直接改名为 `edge-01.md`，同步所有现行链接，只留新路径 | 不回写旧 run，不为旧文件名留转发或副本 |
| 换成另一台主机，明确由它承接 `01` | 核实新身份，按新 `resource_id` 替换 `01.md`，记录新旧身份的承接来源和时间 | 仍按当时的 ID 区分两台主机 |
| 只是复用 IP，未确认身份或未指定别名承接 | 保留原登记，先核验，不让当前别名自动指向另一台机器 | 不合并两台主机 |

改名之前找出现行链接和目标路径冲突，由一位写入者更新。改名后重新按新路径读取，确认旧文件不存在、现行链接可打开。链接修复失败时恢复原文件名及本次已改的链接，再说明未完成项。历史证据中的旧路径可用于说明当时定位，不用现行登记替代。

例：「把这台机器登记为 `01`」写 `registry/01.md`；「检查 `01`」读该文件的连接引用。即使实际主机名改了，只要别名仍是 `01`，下一次会话仍从该路径定位。
