**实施契约与边界**

- 两种导出统一调用 `encode(rows)`，不能在入口各写一套转义。
- 固定表头为 `sku,quantity,note`。字段含逗号、双引号或换行时加双引号；字段内部双引号写成两个双引号。
- 延续现有调用者可省略 `note` 的用法，导出为空字段；不增加 SKU、数量或库存业务校验。
- 保留 `exportCsv(rows)` 与 `download(rows)` 的同步调用形式。HTTP 返回值保留 `status`、`body`，计划增加 `headers`，其中 `Content-Type` 为 `text/csv`。不引入 HTTP 服务框架或权限体系。
- 预览只解析、统计或报错，不修改输入，不调用任何库存写入流程，不增加真正导入、去重或合并策略。
- 计划采用 LF 输出；预览接受 LF 与 CRLF。行数指表头以外的 CSV 记录数，字段内换行不增加记录数；错误行号按原文物理行计算，从 1 开始。多行字段相关错误至少指出出错记录的起始行。
- 本项目没有独立构建、类型检查或 lint 命令；开发检查使用 `node --test`。不新增工具链。

**唯一需要补齐的产品约定**

规格没有定义 CLI 从哪里取得行数据，也没有现成命令入口可沿用。此项会影响调用者用法，不能当作已经确认的事实。

建议采用：`node cli.mjs <input.json>`，输入文件内容为现有 `rows` 数组，CSV 写入 stdout，诊断写入 stderr。另一选项是从 stdin 读取同样的 JSON 数组。

该决定只阻塞下面 A 中的命令参数、读取逻辑及对应进程测试；共享 CSV、HTTP、预览均可先做。无论采用哪种输入方式，都不增加覆盖输入文件的输出选项。后文命令示例按建议方案描述，实施前须确定这一约定。

**A：CLI 导出**

构建内容：

- 保留 `exportCsv(rows)`，命令入口与模块导入分离，导入模块不能触发读文件或进程退出。

**P：导入预览**

计划新增 `preview.mjs`、`test/preview.test.mjs`；在现有 `csv.mjs` 中增加解析能力，复用 `schema.mjs` 的列定义。不替换编码器或引入无关重构。

拟新增接口：`previewCsv(text)`，成功返回 `{rowCount}`，格式错误返回 `{error: {line, message}}`。解析函数供它调用，不向调用者暴露可写库存操作。

构建内容：

- 按 CSV 引号状态解析记录，不能用逐行 `split` 处理带换行的字段。
- 校验固定表头与每条记录的三列结构，允许空 note。
- 识别引号未闭合、非法引号位置、列数错误等格式问题，并关联原文行号。
- 表头后没有记录时返回 0；允许文件末尾换行，不凭空计入一条记录。空文件或缺少规定表头返回错误。

验收及证据：

- `node --test test/preview.test.mjs` 使用手写 CSV 样本独立验证，避免编码器和解析器的相同错误互相掩盖。
- 正确统计普通记录、空 note、带逗号／双引号／多行 note、LF／CRLF、仅表头及末尾换行。
- 错误样本断言 `line` 的具体值及诊断原因，包含多行字段之后发生的错误。
- 对冻结输入及现有导出入口运行前后进行比较，证明预览没有修改调用者数据；检查实现中没有库存写入调用。
