# 组合验证方法

## 确定真正要验证的组合

从用户目标和 `home-map` 已核实的关系取得生产者、消费者、契约 owner 与受影响条件。若目标只是单项目测试，让当地项目方法完成；若需要证明 A 的输出被 B 正确消费，就不能以 A、B 各自测试通过替代。

先复用已有跨项目任务、规格和验收位置；需要新增摘要时使用[组合验收模板](../assets/integration.md)补在有关 coordination 中。它描述本次组合结果，不建立会话、发布或原始日志第二真源。

## 明确执行者和先决条件

1. 用户可指定其中一个项目 Agent 或已有集成测试项目负责真实联调。没有执行者且现有授权不能合理确定时，只问这一具体缺口；不为图形完整另建中心仓库。
2. 规定共同功能/契约、真实关键操作、输入、预期输出与失败判据；保留已有规格和用户认可范围。不要只写“跑完所有测试”。
3. 说明生产者交付物、消费者接入条件、环境/账号/服务前提、测试数据及权限范围。角色名称不绑定厂商，执行工具由项目当地有效规则决定。
4. 由 `home-route` 定位准确 checkout；通过 `home-workflow` 的普通项目任务交执行者，要求按当地 AGENTS、永久知识和所需 SKILL 处理，并把原始证据留本项目。
5. 同一资源池的容量只引用其现有 owner。临时服务和测试进程的启动、停止、恢复归执行项目已有方法，不由 Home 建新调度器。

## 取得足够的组合证据

以下是项目/联调报告需要回答的信息，不是强制项目接收 schema；已有报告可以直接引用。

| 信息 | 为什么需要 |
| --- | --- |
| 准确 repo ID、实际 checkout、HEAD、dirty | 确认实现与验证针对同一工作状态 |
| 实际被测文件/构建产物身份 | dirty 或构建结果可能不由 HEAD 单独表示 |
| 包声明、锁文件、解析来源、构建/发布物版本 | 排除消费者仍读旧包、旧缓存或另一 checkout |
| 相关运行配置与实际环境 | 同一代码在不同环境可能使用不同服务 |
| 服务身份、连接目标与就绪证据 | 进程存在或旧服务可达不证明目标实例就绪 |
| 实际命令/操作、关键输入输出、退出与观察结果 | 让结论能被复查，而不只有“通过”自报 |
| 项目内原始报告、日志、测试与截图位置 | Home 保存引用，原件由执行者负责 |
| mock、跳过条件、外部缺项和未覆盖路径 | 限定通过范围，避免模拟冒充真实运行 |
| commit/PR 与测试时间 | 连接项目交付和这次证据；后续更改需再判断 |

需要读取代码、日志或环境证据时，仍交实际项目/联调执行者核对。Home 可对比报告、引用、版本和结论，不直接重新扫描项目并维护镜像。

## 执行与判断

按实际依赖顺序准备产物和环境。允许用户已授权的独立准备工作并行，但不能在关键输入未就绪时把跳过测试写成通过。

执行者先确认消费者实际使用目标产物，再完成至少覆盖共同功能/契约的关键操作；其他项目方法和必要测试由当地选择。若使用 mock、手工替代、只做静态检查或未接真实外部系统，单独标明，不扩大成完整端到端通过。

| 状态 | 报告条件 |
| --- | --- |
| 通过 | 所定义组合与关键条件有真实证据，明确绑定版本/工作状态和范围 |
| 失败 | 已实际执行并观察到不满足条件；给最小可复查证据与相关 owner |
| 部分完成 | 一些独立条件已验证，其他条件未满足；分别列出 |
| 受阻 | 必要输入/环境/权限缺失，无法执行有关验证 |
| 未执行/未知 | 没有足够运行证据，不以推断补通过 |

dirty 工作区可验证，但应报告“本地工作状态通过”，附实际变更/产物证据与限制。HEAD 是参考，不代表整个测试对象已经提交或可从一个 SHA 完全复现。

## 失败、复验和交付

失败先交直接负责人，保留实际组合、失败输入、关键输出和原证据位置。区分契约不一致、消费旧产物、环境/服务问题与实现缺陷，再由当地 owner 选择修复方法；Home 不越级重启子 Agent 或修改各项目发布设置。

变化影响被验证的契约、产物、环境或服务身份时，要求执行者复验相应范围，并明确新证据覆盖旧结论的哪一部分。早期 review 或旧包测试不能覆盖后来修改；不相关的 HEAD 变化也不自动抹掉全部证据。

交付组合结论、依据、未覆盖项、下一 owner 和项目报告引用。有价值的联合事件交 `home-history`；长期协调经验交 `home-knowledge`，当前关系变更交 `home-map`。原始测试材料与项目内知识不迁移到 Home。

多仓提交/发布没有自动原子性。需要发布、回滚或分阶段兼容策略时，交当地负责方法按已授权要求处理；不因联调通过自动对外发布，也不由 Home 再造统一发布引擎。
