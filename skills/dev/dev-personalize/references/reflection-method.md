# 反思

从当前对话中挖掘长期有效的经验，再把它们路由到技能修改。

用户说“反思”或“复盘这个会话”时调用。对话琐碎、无关，或现有技能已经覆盖且父智能体正确遵循时跳过。一次性事件不是经验。

## 1. 定位当前对话记录

扇出前，在当前工作区明确提供的会话记录位置中找到这段对话的记录。不要跨其他工作区做通配搜索，那会越过工作区边界，读取其他项目的私人对话。

```bash
ls -t <agent-transcripts>/*.jsonl <agent-transcripts>/*/*.jsonl <agent-transcripts>/*/subagents/*.jsonl 2>/dev/null | head -10
```

这涵盖旧版平铺（`<id>.jsonl`）、当前嵌套（`<id>/<id>.jsonl`）和子智能体（`<parent>/subagents/<child>.jsonl`）布局。对每个候选，读取第一条 JSONL。选择 `message.content[0].text` 包含本次对话最初用户提示的文件。没有匹配时，改为传入紧凑的会话摘要。

## 2. 并行派出三位审查者

可并行时使用三个独立审查视角。审查者只读取当前授权范围的会话及其引用证据，不因为工具具有写权限而写入。无并行能力时依次完成三个视角。

使用当前可用的模型，默认继承父模型；有独立模型时可增加判断差异，不要求特定模型或配置文件。

| 视角 | 关注内容 | 提示模板 |
|---|---|---|
| 判断 | 决策、证据与范围 | [完整提示](judgment-review.md) |
| 工具 | 调用、权限与成本 | [完整提示](tooling-review.md) |
| 发散 | 替代解释与遗漏 | [完整提示](divergent-review.md) |

原样传入各模板，在标记处替换为对话记录路径或摘要。审查者在 子智能体工具 响应正文中返回发现。

## 3. 综合

使用独立综合上下文，抽查引用证据并综合三份报告。若没有子智能体工具，由当前智能体综合并明确这一限制。依据[完整综合提示](reflection-synthesis.md)形成“接受 / 拒绝 / 待办”列表。

## 4. 结构化强制检查

任何可由 lint 规则、脚本、元数据标志或运行时检查更可靠执行的“接受”项，都移至“待办”。参见[结构化经验](structural-learning.md)。

## 5. 应用

展示完整“接受 / 拒绝 / 待办”结果。用户已明确要求修改本项目技能时，直接执行其范围内的编辑；仅要求反思或建议时先交付可审查改动方案。跨项目、全局或组织级技能改动若未授权，说明具体影响后请求缺失授权。

“待办”先记入 `.agents/wtadev/changes/<日期-主题>/` 的任务记录，已有事项按真实位置引用。只有已有授权覆盖外部工单写入时才写跟踪器；不得自动发送消息或创建外部事项。

编辑用户指定的源仓库，不编辑插件缓存或擅自安装个人技能。目标技能使用标准 `<domain>-<name>/SKILL.md` 与本包相对资源。提交、推送、PR 按用户已授权交付方式执行。

按每项已授权修改的规模选择路由：

- 现有技能的小改动（一行条目、一句收紧措辞、纠正过时事实）：父智能体直接做。
- 现有技能的实质修改（新增章节、新模式表、超过约 10 行）：按本地技能编写指南，先明确规格、修改文档，再验证格式、引用和真实场景。
- `tune description: <skill path>`（技能存在但应触发时未触发）：按本地技能编写指南核对触发条件、描述与使用场景。
- `new skill via 技能编写: <kebab-name>`：按本地技能编写指南创建，不要发明复杂状态协议。

环境提供 SKILL.md 验证器时，在宣布完成前对所有触及的技能运行。

## 6. 向用户总结

简短列表，无开场白：

- 已应用编辑：`<skill path>`。每项一行说明变化。
- 已创建新技能：`<skill path>`。每项一行，应该很少。
- 已写入开发体验跟踪器的待办：`<issue title>`（`<tags>`）。每项一行。
- 已排除：每条拒绝发现一行，附综合者理由。


具体编辑按[技能编写方法](authoring-a-skill.md)与[本地结构规则](skill-authoring.md)执行。
