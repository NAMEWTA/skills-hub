# 知识、记忆与归档

## 项目记忆保存什么

这套机制使用可版本管理的 Markdown 和代码引用。它不要求向量数据库、专用记忆服务、JSON 状态文件或复杂 schema。检索索引应能从这些资料重新构建，不成为新的事实来源。

有价值的记忆是下一次接手时不容易仅从代码恢复、却会影响决定的内容：业务术语、用户真实意图、约束的来源、架构取舍、反例、错误经验和模块入口。函数实现、完整文件清单、一次性聊天过程通常不值得重复保存。

## 资料分区

项目记忆按领域维护，以下开发路径相对目标项目根目录。系统记录位于 `.agents/system/<host>/`，运行运维事实位于 `.agents/ops/`。技能安装目录 `.agents/skills/` 保存方法，不保存项目知识；根 `AGENTS.md` 提供当前事实的读取入口。完整目录及托管导航规则见[持久化规范](persistence-roots.md)。

| 类型 | 位置 | 更新方式 |
| --- | --- | --- |
| 当前任务 | `.agents/dev/changes/<日期-主题>/` | 随任务更新实际进展，完成后归档 |
| 需求来源 | Change 内 `source/` | 保存完整 Issue、可取得的讨论与必要方案附件，同源更新保留版本 |
| 简短入口 | `AGENTS.md`、`.agents/dev/notes/index.md` | 指向有关主题和条件，不复制全部知识 |
| 术语 | `.agents/dev/notes/glossary.md` | 核实同义词、边界、关系及代码映射 |
| 背景 | `.agents/dev/notes/context/` | 记录非显而易见的约束与由来，事实变化时更新 |
| 决策 | `.agents/dev/notes/decisions/` | 保留为什么、替代方案和后果；真正反转时建后继 |
| 错误经验 | `.agents/dev/notes/errors/` | 保留复发识别、根因证据、修复与恢复条件 |
| 学习导读 | `.agents/dev/notes/learning/` | 指出完整用例、入口、边界和二次开发位置 |
| 部署现状 | `.agents/dev/deploy/<环境>/runbook.md` | 核对当前实际环境后更新 |
| 历史发布 | `.agents/dev/deploy/<环境>/releases/` | 保存当时事实，不能当当前环境说明 |
| 任务历史 | `.agents/dev/archive/changes/<result>/<type>_<YYYY-MM-DD>-<slug>/` | result 为 implemented 或 rejected；归档时分类重命名，沿用创建日期，旧历史不自动迁移 |
| 退役知识 | `.agents/dev/archive/notes/` | 保留原分类，明确历史用途并修复引用 |
| 项目配置 | `.agents/dev/project/` | 保存项目专用的非秘密配置、自动化功能图和分流规则 |
| 开发环境与资源 | `.agents/dev/context/environment.md` | 按执行主机保存采样、峰值预算和预留，条件变化时重新核验 |
| 按需团队配置 | `.agents/dev/context/team/<team_name>.md` | 用户明确要求时创建或更新，由用户在任务中显式引用 |
| 系统维护 | `.agents/system/<主机标识>/` | 记录对应主机的实际操作与验证，秘密只留安全引用 |

开发领域的导航由安装器管理，业务目录和记录在真实内容出现时建立。目录 `AGENTS.md` 说明职责，不代替主题笔记，也不保证宿主自动加载。已有 `docs/adr`、`docs/architecture` 或运维手册时，在 `.agents/dev/notes/` 的有关主题或入口记录其真实路径，引用有效内容；不复制一套重复正文。用户明确指定其他资料位置时遵循该要求，并在导航中记录。

旧目录和重复资料按[迁移规范](persistence-roots.md#从早期-agentswtadev-迁移)逐项处理冲突、保留有效内容并修复导航；安装技能不会自动搬动业务记录。

## Home 入口与合作约定

Home 的 AGENTS 格式、渐进式披露、读取条件与语义维护由 [home-knowledge](../../skills/home/home-knowledge/SKILL.md) 负责。根短入口由 setup 在完整初始化中合并。安装器首次补缺时创建 Home 入口，之后沿用用户文件。知识正文和用户约定保留在各自真源，入口保存实际资料指针。

profile 保存 Home 职责和用户背景，preferences 保存语言、时区及执行默认。只有用户明确要求保存、且既有位置尚未承担的合作原则或表达风格，才按需建立 SOUL。已有等价文档原地引用，不新增同义 USER/MEMORY 文件。文件缺省合法，启用后由入口说明何时读取，不假定宿主自动加载。

AGENTS 与 SOUL 用普通文件编辑，先读取基线，写前重新核对并最小合并，写后回读。知识/历史 CLI 的锁和 `--expect` 只保护其白名单内的文件。更正或忘记时处理实际 owner 与派生入口，说明覆盖范围。详见[入口与合作约定](../../skills/home/home-knowledge/references/agent-entry.md)。

## 证据优先级不等于“代码永远正确”

当前源码、配置和运行结果证明**系统现在是什么**。用户明确决定和有效规格说明**系统应当变成什么**。发现不一致时分辨是实现缺陷、文档过期还是目标已变化，不能用旧实现否定新需求。

运行事实带上环境、版本和时间；一个本地函数存在不证明生产已部署。长期文档中的引用尽量使用相对路径、关键符号、调用入口和适用范围。必要时保留核对提交来复现当时判断。行号可辅助定位，但不是稳定语义标识。

“最近核对”只在实际检查后更新。未读到代码或拿不到环境时标注待核验，不把日期刷新当成知识变新。

## 轻量术语关系

术语表是给人和 Agent 共用的导航，不要求本体语言或图数据库。例如在一个假设项目中：

| 项 | 示例说明 |
| --- | --- |
| 规范名 | 用户账号 |
| 用户叫法 | 用户账户、账号；仅在个人身份语境下等价 |
| 代码映射 | `UserAccount` 类型、账号创建服务和身份存储入口 |
| 不等价概念 | `Credential` 是登录凭据；`Organization` 是组织；不能合并 |
| 关系 | 账号拥有凭据；账号通过成员关系加入组织 |
| 证据与核对 | 实际项目路径、符号、有效需求及核对版本 |

这些代码名字只是示例，实际使用必须换成已读到的真实符号。先确认语义，再统一词汇；发现同一个词在不同领域含义不同，就记录作用域，不强行选一个全局含义。

## 每次归档做什么

1. 核对需求实际交付结果、最新代码与部署记录。区分已实现、已验证、已上线和未完成，不能把关闭文件夹当作完成。
2. 从本次工作挑出会影响以后决定的知识，找到已有的主题所有者。已有知识就更新，不再创建同义副本。
3. 逐项处理事实过期、真实决定反转、完整替代和部分替代。修复过期路径；决定反转建立带关系的新记录；部分替代保留仍生效的约束。
4. 完整合并前保留旧记录中独有的动机、替代方案、代价、负面保证、未覆盖风险与重新引入条件。不能只说“Git 有历史”就删掉仍重要的理由。
5. 移动或删除后检查所有入链、常用入口、术语映射和导读；更新当前文档指向现行主题，历史引用注明历史用途。
6. 把已结束的 Change 按[change 收尾](../../skills/dev/dev-archive/references/change-closure.md)归档：已交付进入 implemented，明确不实施进入 rejected，归档时增加五类主类型前缀并保留原创建日期；尚待决定、暂缓、阻塞或必要交付未完成仍留 changes。保留 `source/`、规格、设计与方案讨论、计划、确认原型、task、同名验收和总报告。执行过程原件留 `temp/`；误放其中的来源或正式资料先按[持久化规范](persistence-roots.md)核对迁入。修复移动、改名和目录深度变化造成的引用；旧历史不自动迁移。把最新代码导航、决策与经验留在现役知识里，否决理由也可有长期价值，但不冒充已实现事实。简要报告路径映射、保留、合并、更新、归档或删除了什么及原因。

归档依据是**未来决策价值**。内容旧、文件长、数量多都不是单独的删除理由。小 UI 调整和机械日志通常可删除或留在工作历史；短短一段安全边界也可能必须长期保留。

## 为什么不像复杂状态系统

目录表达职责，Markdown 表达事实和理由，Git 表达版本变化。记录按真实需求建立，不通过状态字段或机械模板替代对代码、交付和历史的判断。

现行事实跟着代码变化，重要决定保留取舍，完整与部分替代分开判断。知识按需要自然增长，不要求双语三件套或机械门禁。`index.md` 只是少量常用入口，不是所有文件都要登记的全局索引。

## 学习与记忆形成循环

`dev-learn` 选择一个真实用例，贯通入口、处理、数据/状态、返回结果、失败和恢复。导读解释业务意图、边界和修改入口，详细实现直接引用源码。无法从代码证明的设计动机明确标为推断，不替历史作者编理由。

后续需求使用这些导航快速定位；实现改变边界或文件时同步更新；交付后 `dev-archive` 整理新经验并清理冲突。这样积累的是更准确的项目理解，而不是越来越长的上下文。

## 凭据

部署资料保存账号用途、配置键与秘密的真实保管位置。密码、token、私钥或含认证信息的连接串不进入普通项目知识。安全存储使用项目已有密钥系统或受限未跟踪配置，不能凭空写一个 URI 就声称已保管。

## 本地操作资料

归档与知识维护的完整步骤在 [dev-archive](../../skills/dev/dev-archive/SKILL.md) 及其包内参考中；理解模块的方法在 [dev-learn](../../skills/dev/dev-learn/SKILL.md)。每个技能安装后都保留自己的完整资源，使用时不用回到本仓库或访问外部文档。资料对照与适配规则见[资源组织](resources.md)。长期面向使用者的架构、接口和操作契约放在 `docs/`；本次调查、验证流水与工作进度留在 change，避免把每次执行记录追加到长期说明。

## 会话证据的归属

开发会话由宿主保存。`dev-session-history` 指引读取限定项目的原件，`dev-recall` 校正历史中的工作状态，`dev-reflect` 找出工作方法的改进点。能用工程机制防止复发的交 `dev-guardrails`；稳定项目事实仍由 `dev-archive` 写入实际知识位置。保留结论和必要事件指针，原始聊天留在原处。
