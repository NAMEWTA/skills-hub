# 复现自动化提示词

> 供复制后的安装流程使用的来源材料。内置 `automate` 确认复制包已提交到自动化运行的仓库后，将这里的意图转述进它的草稿。

本次运行读取并遵循 `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md`。

配置来源。只有这个仓库相对路径已提交到同一目标仓库时才包含它；否则转述配置值。绝不使用插件源目录或缓存路径：

```text
{{BENNY_CONFIG_PATH}}
```

触发信息：

```json
{
	"source_channel_id": "{{SLACK_CHANNEL_ID}}",
	"message_ts": "{{SLACK_MESSAGE_TS}}",
	"thread_ts": "{{SLACK_THREAD_TS_OR_EMPTY}}"
}
```

创建意图应将其描述为配置的来源 Slack 频道中的一条新顶层报告。它应包含已配置的仓库、默认分支、问题跟踪器、控制适配器、功能图及草稿拉取请求能力。

把来源频道和根讨论串时间戳视为不可变。任一值缺失或与配置不匹配时，停止，不发帖。

在这个准确的讨论串中，等待配置的分诊身份发出配置的分诊标记。只有 `[benny:bug]` 或 `[benny:performance]` 才继续。

尝试复现前必须具有配置的控制适配技能。通过真实 UI 两次复现能够区分该问题的准确症状。验证已有拉取请求或提交，不在其上编写改动。只有确认复现且通过操作文件的修复门槛后，才尝试有边界的修复。

协调者是唯一的 Slack 发帖者。每份子任务提示都必须禁止 `SendSlackMessage`、`PostToSlack`、`chat.postMessage` 及其他所有 Slack 写入。子任务只返回发现。

绝不在来源频道发布根消息。
