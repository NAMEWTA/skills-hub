# 设计解决流程

在 Claude Code 中，每个会话在遵循此技能前，先阅读一次 [Claude Code 适配器](../../docs/harness/claude-code.md)。它将 pstack 技能中的 Cursor 名称映射到 Claude Code。

任务不匹配任何手册时，设计一份。写代码之前的交付物是工作流本身：一串按任务调整严谨程度、采用科学方法、留下决策轨迹的阶段，让人离开后也能审计。

## 开始

建立待办清单，第一项是阅读 **poteto-mode** 技能的“原则”章节。然后把以下阶段加入待办。

## 阶段 A：界定

先建立依据，再投入。能说明以下内容前，不开始执行：

- 用可证伪判据表达完成定义，遵循 **prove-it-works** 原则技能。
- 量化范围：大致单元数、工作量，以及建立依据时发现的阻塞。
- 严谨程度，倾向高标准。单向门与高影响范围需要更多严谨性，可逆低风险步骤需要更少。严谨是门禁与产物，不是“更努力”。

开始长时间执行前呈现界定与取舍。可逆工作继续，遵循 **never-block-on-the-human** 原则技能；但数小时运行值得一个检查点。

## 阶段 B：设计工作流

分解成原子、可独立落地的单元，先处理风险最高的未知。基础设施与验证先于功能，遵循 **foundational-thinking** 原则技能。

- 工作开始前构建验证驱动，从变更前状态捕获基线，让检查呈现“旧值与新值”。
- 对难以逆转的设计决定运行 **architect** 技能，它会运行 **arena**。形态已经明确的机械工作跳过。已定设计再跑一次 arena 属于过度设计，遵循 **laziness-protocol** 原则技能。
- 决定什么可以扇出。只沿接缝并行，每个执行者有独立工作树或分支，遵循 **separate-before-serializing-shared-state**。不要过度扇出。按 **poteto-mode** 的“子智能体”章节为每个子智能体选择推理级别及快速或标准速度。
- 写下设计出的阶段清单。这份清单就是人审查的对象。

然后执行设计。在待办阶段 C 与 D 之间插入具体步骤，每步都按阶段 C 的循环纪律执行，阶段 D 的日志穿插其中，每步落地写一行，不把全部记录拖到最后。

## 阶段 C：运行循环

每个单元都是一次实验。陈述假设、做最小改动、在真实产物上对照判据测量；推进了就保留，没有就回滚。应用 **sequence-verifiable-units**，下一单元开始前验证当前单元，不在末尾批量检查。

- 检查产物验证，绝不依赖自述。太容易通过时，先怀疑观察方法，再怀疑系统。
- 委派工作配独立评判。执行者迎合门禁时，重置并加强契约。门禁自身错误时，单独修门禁，不绕开它。
- 结论为 VERIFIED、NOT VERIFIED 或 INCONCLUSIVE。无结论不是通过，不隐藏负面结果。

## 阶段 D：保留审计轨迹

通过 **show-me-your-work** 技能记录执行。figure-it-out 的工作通常足够复杂，值得提交轨迹，让审查者能在 PR 中读取。轨迹加差异，使人回来后可以信任工作。

## 阶段 E：验证并交接

在真实产品上，依据阶段 A 判据检查整体，不只检查驱动。把重复纠正编码为门禁、lint 规则、检查或脚本，遵循 **encode-lessons-in-structure**。

**回复：** 设计的执行手册、严谨程度及原因、轨迹路径、哪些已按判据验证，以及哪些仍开放。
