# Home 任务协调

完成用户的当前目标，保留已有决定、授权、实际目录与证据。Home 保存项目基本背景、定位、项目管理和跨项目知识；项目内部知识、SKILL、源码和运行材料由项目当地 Agent 获取与维护。

主入口已在当前上下文读取且 Home 根和版本相同时可复用；新会话、压缩后缺失、入口更新或换根时重读。入口读不到先核对根、路径和安装状态，再调用可用的 `home-doctor`；未装该技能仍可做最小只读检查，继续不依赖缺项的工作。

## 按意图选择方法

| 当前缺口 | 调用准确名称 |
| --- | --- |
| 建立 Home、登记项目、保存默认或协作配置 | home-setup |
| 确认 repo ID、实际 checkout、身份或资料入口 | home-route |
| 查当前背景、长期决定，整理入口、知识或合作风格 | home-knowledge |
| 查过去事件、会话摘要、当时理由或接续线索 | home-history |
| 管理派发消息、回复、占用和状态，查询任务或重建视图 | home-tasks |
| 确认项目关系、契约 owner 和影响集合 | home-map |
| 验证多个项目共同工作的版本组合 | home-integrate |
| 诊断登记、路径、导航和必要入口 | home-doctor |

用户明确点名方法可直接使用，不强制先过本入口。没有相关技能时说明具体缺项，继续不依赖它的工作；不声称未安装的方法已执行，也不从其他仓库借装。

## 执行

1. 确定实际 Home 根，先读 `./.agents/home/AGENTS.md`，再按本次目标、范围、完成条件和已有任务打开对应资料。读取失败时交 `home-doctor` 核对 Home 根及安装状态。需要 Home 项目背景或长期决定时，用 `home-knowledge` 按 repo ID 或主题查询。已有背景足够回答时直接作答。
2. 复合任务只补真实缺口，按上表调用；始终沿用同一目标和证据。缺少登记或配置时让 `home-setup` 处理有关分支，不重新做全套初始化。
3. 向登记项目派发工作或查询项目内部资料时，读取[项目任务与多级自治](references/delegation.md)。用 `home-route` 核对 checkout，从 Home 偏好选定派遣方式和 team，按目标 repo ID 核对 CLI、模型和推理参数。
4. 按[协调与接续](references/coordination.md)使用 `home-tasks` 管理主题、派发、回执和项目占用。核对发送前的占用与依赖后，调用选定入口。尚未能派发的工作先记录为待派。需要新派发而缺 `home-tasks` 时说明缺项。恢复既有会话时查原方法。
5. 收到交付后核对任务范围、绑定版本、实际读取的项目上下文和验证边界；必要时交原负责人修订。项目自报完成不代替 owner 验收。跨项目组合结论交 `home-integrate`。
6. 按任务价值和用户约定调用 `home-history` 保存实际事件、`home-knowledge` 提炼仍有效结论。允许没有值得记录的内容；history 不改当前派遣状态，知识推断不改执行默认。

## 交接与完成

使用[项目任务简报](assets/project-brief.md)补足任务内容，交给用户选定方法已有的 task/message，同时保留 Home 自己的项目管理记录。Home→A 归 Home 验收，A→子 Agent 的派遣和验收归 A。

交付结果、证据位置、未完成条件和下一责任人。中断、受阻和取消如实记录；只完成部分时保留已交付成果并继续独立已授权工作。没有实际执行条件的能力标未知，不能把终端存在、idle、退出码或“done”当成交付验收。
