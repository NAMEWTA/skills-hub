# 01 由用户或项目指令指定协作规则

规格：本次请求不在实施、审查等技能里反复强调协作配置，更不由技能替用户指定规则文件或规则组。背景和历史选择见[计划](../plan.md#协作规则为什么到处出现)。

交付：用户点名某套协作规则或项目指令明确选用时，执行者只沿用该选择；未选用时照常实施、审查或交付。存在候选文件或保存的组，不等于通用技能获准为任务自动选组。当前任务的选择随任务交接，不外溢到新任务。

直接依赖：无。

边界：本票维护 `skills-hub` 的协作引用及相关文档，不改消费者的 `AGENTS.md`、角色表、预算或宿主配置。保留项目本身的规范、实际并行的写入边界、审查的规格与规范两轴，以及已经明确要求的独立复核。已要求独立复核但工具无法提供时报告缺口，不以自查冒充。

## 实施要点

1. 删除 [dev-build](../../../../../skills/dev/dev-build/SKILL.md)、[dev-review](../../../../../skills/dev/dev-review/SKILL.md)、[dev-workflow](../../../../../skills/dev/dev-workflow/SKILL.md)、[dev-parallel](../../../../../skills/dev/dev-parallel/SKILL.md)、[dev-program 批次方法](../../../../../skills/dev/dev-program/references/batch.md)、[dev-deploy](../../../../../skills/dev/dev-deploy/SKILL.md)中重复的固定路径和自动选组说明。删除整句优于逐处改写成另一套选择规则；只在有实际影响处保留分工、复核或发布检查动作。复扫帮助、实施参考与交接，不把“可并行”“能独立审查”写成仅因工具存在就必须派发。
2. [dev-setup 的配置方法](../../../../../skills/dev/dev-setup/references/configure-models.md)仍负责按请求保存、修改和介绍规则组。保留真实模型、预算和模板方法。让项目作者自行在有效项目指令中选择长期规则，不让执行技能探测角色文件并自行启用。`dev-handoff` 只携带影响本次接续的有效选择及未完成复核。
3. 对齐 [dev-help 设置方法](../../../../../skills/dev/dev-help/references/guide-setup.md)、相关宿主适配和[开发流程](../../../../../docs/development/workflow.md)。保留已发布版本的历史说明，不让旧说明充当当前规则。没有必要新增解析器、规则注册表或配置文件。

## 验收

- [ ] 隔离项目有一个角色文件及未选用的命名组，只要求按规格实现或审查。执行者不主动读取候选文件、不自动启用规则组或独立复核，也不因没指定而停下来提问。
- [ ] 本次任务明确指定另一文件中的规则，或项目指令明确指定规则。执行者使用实际指定来源，只在满足触发条件时应用其复核或分工要求。当前任务显式覆盖后，接续保留该选择，新任务不继承本次覆盖。
- [ ] 项目明确要求独立复核但当前宿主无法提供时，报告缺口和受影响版本，普通两轴审查及适用验证仍继续。没有要求独立审查时，保有两轴审查，不自动把它升级成多人门禁。

完成证据：在隔离项目使用实际安装的技能，用上述任务比较读取路径、审查结论和接续产物。将实际结果记录在本票或本 change 的共用验证记录；结构检查由计划的整合步骤执行。
