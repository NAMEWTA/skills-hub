# 先分离，再串行化共享状态

并发执行者可能写同一文件、分支、键或对象时，先判断它们是否需要同一个共享对象，还是只是在发布独立事实。默认让每个执行者拥有自己的文件、键、分支或状态目录，只在读取状态时合并。两个 worker 各自写同一个 `state.json` 中的一个字段，仍属于共享修改。

只有单个共享写入目标确实是不变量时，才用结构性机制串行化访问，例如锁文件、单一写入者、顺序阶段或 compare-and-swap。指令不是并发控制，“需要一把锁”应先被视为值得检查的设计异味。
