# 技能维护与上游同步约束

维护目标是让用户和 Agent 能按任务找到完整方法、完成实际工作，并留下可核对的结果。保留成熟方法的步骤、判断、例子、反例和工具语义；篇幅与技能数量都不是单独的质量目标。

## 项目定位

`skills/<domain>/` 保存按长期协作体系整合的技能；`upstream-skills/zh-<原名>/` 保存保持独立的上游中文运行包。前者统一命名、持久化和运行约定，后者保留必要结构、metadata、原工具和外部调用。两类共享安装接口，具体分工见[项目架构](../reference/architecture.md)。

来源、版权和改造说明统一见[第三方声明](../../THIRD_PARTY_NOTICES.md)。当前来源身份从[材料父清单](../../materials/manifest.tsv)读取，逐文件采用关系从其 `manifest_path` 指向的子清单读取；这些材料只用于维护对照。

## 允许怎样适配

| 调整对象 | 本项目做法 | 保留内容 |
| --- | --- | --- |
| 入口与名称 | 用任务、产物和前提写触发条件，收拢重复入口 | 专门方法的独特适用条件和完成标准 |
| 流程融合 | 按已登记主线组织协作，为不同用途保留明确分支 | 需求、切片、架构、实施、验证、交付及复盘的方法本体 |
| 工具与宿主 | 使用实际可用能力，明确缺少的工具或权限 | 身份、环境、失败补偿和证据条件 |
| 文档结构 | 入口指向包内完整方法，模板与工具按职责存放 | 步骤、表格、数值、例子、反例及边界 |
| 持久化 | 采用对应领域目录，已有资料引用真实位置 | 历史身份、有效内容与可恢复的链接 |

用户指定的上游是对照基准。默认先完整复制和翻译，再做满足当前需求、明确规范、真实冲突或工具差异所需的适配。模板栏目和顺序具有方法含义时保留，不能为了个人表达偏好换成摘要或另一套流程。

必要改动在子清单 `adaptation` 中说明原文要点、理由与影响；第三方层面的统一说明归根声明，单次对照和验证证据归所属 change。发现矛盾要修改具体步骤，不能只在顶部加一句覆盖声明而保留相反指令。

## 谁负责最终结果

跨阶段任务由 `dev-workflow` 协调，阶段已明确时直接使用对应技能。被调用的方法解决当前问题后返回原负责人，沿用同一规格、计划和证据，不重复开启任务记录。完整职责见[开发方法归属](../development/method-ownership.md)，常见组合见[开发流程](../development/workflow.md)。

入口描述、路由、帮助示例和 UI 元数据必须与方法职责一起更新。实现遇到故障可以调用 debug，明确选择测试先行时调用 tdd，需要解释机制时调用 learn；相邻技能的存在不意味着每次必须执行全套流程。

新布局、交互或用户明确要求的可视化对齐，按[确认原型](../development/prototype.md)取得具体版本与范围的体验依据。已有有效确认直接沿用；只限制依赖未决体验的部分，其他已授权工作继续。原型模拟成功不能替代后端、权限、持久化或外部副作用验证。

ops 的方法职责和项目交付边界见[ops 方法归属](../operations/method-ownership.md)。跨领域按真实任务引用已有资料，不让一个领域维护另一领域的竞争事实或隐含发布入口。

## 可移植运行与分发

仓库维护脚本、测试及自有 `skills/` 的执行工具和可运行示例使用 Node.js 22.14+ 的 `.mjs` 或 `.js`。Git 固定名称的 `pre-commit`、`pre-push` 是 JavaScript 薄入口。迁移算法时保留输入、输出、退出码、错误行为和完整例子，使用既有夹具与真实调用核对。

独立 `upstream-skills/` 优先保留原运行工具，列明实际前提。Java/TLC、浏览器或其他任务工具仍需单独具备，Node 基线不替代它们。materials 保留原扩展名和执行位，不参与技能发现、安装或自动加载来源指令、依赖、CI/hook。维护回放显式复制固定 corpus 到临时目录，由本项目状态图工具加载其中的 `view.mjs` 投影配置并回放捕获输出；不执行任意来源脚本，也不运行新 TLC。

npm 只分发实际安装所需内容，发布前检查真实 tarball 的资源和安装结果。版本、源码提交、标签和上传文件须对应，见[发布指南](release.md)。

## 入口与渐进式披露

`SKILL.md` 保留准确的元数据、完成目标、关键条件和资源读取入口。主分支尽量直达完整方法；只有部分任务需要的参数表、示例和反例放在包内参考，入口说明何时读取。

`references/` 保存方法，`assets/` 保存要填写或复用的产物，`scripts/` 保存必要确定性工具。长参考使用清楚标题和适量导航，避免多层索引藏起执行步骤，也不把全部文件列表塞进入口。

自有入口的预算见[质量规则](skill-quality.md)。超限先移动可独立读取的细节并补读取条件，再修剪重复表达；保留验收、例外和完整知识，不能靠合并长行或删方法达标。

## 完整资料与副本

同一完整方法只由一个技能维护。帮助提供选择指南，工作流负责协调，专门技能持有方法、模板和工具。包内资源用相对链接，跨技能按准确名称调用；不递归复制兄弟包，也不另建公共方法库。

交接携带目标、当前阶段、产物版本、证据、已有授权和返回条件。宿主缺少技能调用 API 时，可以读取实际安装入口应用方法；不能虚构子代理执行。缺少必需包时说明安装缺口，并继续不依赖它的工作。

新增、移动、合并或删除运行资源后，更新唯一归属、调用入口和材料映射。变体按来源路径、blob 和正文语义比较，不能仅靠文件名或字节相同推断用途一致。已有业务记录不随技能资源迁移而搬动。

自有运行内容采用本项目中文语境，来源说明与法律文本由[统一第三方声明](../../THIRD_PARTY_NOTICES.md)及其所指原文管理。独立包的上游原生法律文本保持完整，材料选定树自带的 LICENSE/NOTICE 也原样保留。

## 同步上游的最小过程

1. 明确要同步的来源单元，读取父清单的仓库、`ref` 与 `source_root`。每次显式同步解析最新提交，再固定同一个 SHA 完成整棵选定树读取；`ref=HEAD` 每次解析远端默认分支。
2. 预览新增、修改、删除、模式变化和同 blob 移动，保存覆盖前的运行映射。内容变化的移动、拆分或合并只列为候选，逐项确认，不能机械继承。
3. 在临时准备树生成完整原件、适用中文对照和子清单。原件按 Git 对象保留字节、模式与集合；逐份核对变化译文。中文原文不另复制，法律和机器对照保留原字节，不把缺译改标为无需翻译。
4. 按[同步接口](../../materials/README.md#显式同步预览准备应用)完成 `REPORT.md` 的 Outstanding work，再显式 apply。应用前核对准备 SHA、身份、当前基线和完整对照；来源远端又有变化时报告差异，不悄悄更换本次 SHA。
5. 分别对照旧来源、新来源和当前唯一运行正文。保留已有本地适配；确认无需改变也写清理由。完成适配和验证后才更新 `runtime_reviewed_blob`，新材料不等于运行包已升级。
6. 同步修改受影响的描述、路由、帮助、模板、方法归属和 UI 元数据。来源退出范围不自动删除本地技能或适用许可。
7. 运行结构、安装与受影响行为检查，阅读原文检查全文忠实性。工具和自然请求条件变化时补实际使用验证，记录结果及限制。
8. 按任务已明确的授权完成提交、推送或发布。清理临时准备树，长期保留当前来源与映射，历史由 Git 和所属 change 的证据承担。

普通检查和 CI 不刷新材料，也不扩大用户选定的来源根。完整操作说明与字段定义归[材料说明](../../materials/README.md)，本页维护贡献时必须遵守的边界。
