# 布局思路：八种命名页面

构建新仪表盘前，从下面选择**两种**布局，按名称各用一句话说明为何适合该屏幕的问题，让用户选择。不要对所有需求默认使用相同的“指标条—图表—列表”页面。所选方案的宽度、网格和手机适配见 [layout.md](layout.md)，实际案例见 [inspiration.md](inspiration.md)。

每种布局都说明问题、线框图（桌面，12 列）、适用和不适用场景。

<a id="1-classic-strip"></a>

## 1. 经典指标条（Classic strip）

“情况如何，是什么在推动变化？”这是分析页面的默认布局：KPI 条、由选中指标卡驱动的一张图，然后是成对排列的排序列表。

```text
[ 日期范围 · 筛选 · 更新时间 ]
[ KPI ][ KPI ][ KPI ][ KPI ][ KPI ]   ← 选中卡片着色，并驱动下方图表
[ 主图表 ··························· ]
[ 排序列表 ][ 排序列表 ]
[ 排序列表 ][ 排序列表 ]
```

适合流量、产品使用，以及“先看一个指标随时间的变化，再看来源”的问题。Plausible、Vemetric、Fathom、OpenPanel 中可见。不适合监测（问题会藏在列表中），或没有单个主指标的场景。

<a id="2-control-center"></a>

## 2. 控制中心（Control center）

“我的哪些指标发生了变化？”指标卡组成网格，每张都有小图和“原为 $X”的基准，侧列显示变化分解与实时动态。

```text
[ MRR + 图表 ][ 净收入 + 图表 ] [ 分解：哪些发生变化 ]
[ 费用 + 图表 ][ 其他 + 图表  ] [ 实时动态           ]
```

适合收入和财务场景中 4–6 个指标同样重要的情况。Baremetrics 中可见。一个指标最重要时不适合；应让它占据主视觉。

<a id="3-status-board"></a>

## 3. 状态看板（Status board）

“现在是否有故障，从何时开始？”总体状态横幅、未结束事件及其时间线，之后每个服务一行逐日条带。

```text
[ ● 所有系统正常 · 09:45 UTC ]
[ 未结束事件：标题 · 更新，最新在前 ]
[ 服务 A  ▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮  99.96% ]
[ 服务 B  ▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮  100%   ]
```

适合可用性、后台作业、集成，以及任何“是否正常运行”的问题。OpenStatus、Claude Status 中可见。仅给异常日期着色。

<a id="4-monitor-grid"></a>

## 4. 监测网格（Monitor grid）

“今天谁需要关注？”热力图（对象 × 日期）成为主视图，异常单元格直接带有操作。

```text
[ KPI ][ KPI ][ KPI ][ KPI ]
[ 热力图：行 = 班级/客户，列 = 日期 ][ 需关注：3 ]
[ 子弹图：每行的预算或目标           ]
```

适合每天检查许多相似对象（班级、客户、门店、服务器）；学校案例和 README 的广告测试使用此布局。只有一个对象时不适合，应使用经典指标条。

<a id="5-leaderboard"></a>

## 5. 排行榜（Leaderboard）

“谁领先，谁在变化？”排序行包含标志、名称、数值、涨跌和迷你趋势图，通常分两列，上面放一张趋势图。

```text
[ 随时间的用量（堆叠，≤6 个系列 + 其他） ]
[ 1 ◉ 模型 A  66.8T ↑9% ][ 6 ◉ 模型 F  6.6T ↓10% ]
[ 2 ◉ 模型 B  23.5T ↑…  ][ 7 ◉ 模型 G  4.5T ↑33% ]
```

适合 AI 模型、产品、客户、股票、销售人员。OpenRouter、Stocks 中可见。只关心阈值而不关心排名时不适合。

<a id="6-map-hero"></a>

## 6. 地图主视图（Map hero）

“事情发生在哪里？”分级设色地图占满首屏，使用一种顺序色阶；事件用另一种形状和色相的标记，位置筛选放顶部。

```text
[ 位置：全球 ▾ ]
[ 地图 ························· 图例 ]
[ 浏览标签：按国家 · 按城市 ]
```

仅当问题关心地点时适用（流量、故障、配送、外勤团队）。Cloudflare Radar 中可见。否则带旗帜的国家排序列表读起来更快。

<a id="7-wall"></a>

## 7. 大屏（Wall）

“从房间另一头也能看清。”四到八个巨大数字，每个数字下方铺一条浅淡趋势线；正常用一种颜色，唯一异常数字用另一种。没有控件，自动刷新，时间放角落。

```text
[   549   ][  3483  ][   433   ][   86   ]   ← 只有异常项为红色
[ 趋势图 ··········][ 趋势图 ·········· ]
```

适合办公室电视、值班屏幕。Grafana 中可见。保持少文字，不放说明段落或仪表盘式量表。

<a id="8-list-and-detail"></a>

## 8. 列表与详情（List and detail）

“先看全部，再深入一项。”左侧是密集列表（每行：名称、迷你趋势图、数值、涨跌胶囊），右侧是选中项目的详情。

```text
[ 搜索 ][                                   ]
[ 行 ~~~ 49 595 +1.4k ][ 详情：名称、数值 ]
[ 行 ~~~  7 237  +326 ][ 图表            ]
[ 行 ~~~    349  +6.5 ][ 相关项目        ]
```

适合投资组合、收件箱、队列、项目，以及原生 Mac 和 iPad 应用。Stocks、Activity Monitor 中可见。手机上由列表占据整屏，详情以推入方式打开。

<a id="choosing-two"></a>

## 选择两种方案

| 屏幕要回答的问题 | 首选 | 次选 |
| --- | --- | --- |
| 情况如何，是什么在推动变化？ | 经典指标条 | 控制中心 |
| 我的哪些指标发生了变化？ | 控制中心 | 经典指标条 |
| 是否有故障？ | 状态看板 | 大屏 |
| 今天谁需要关注？ | 监测网格 | 列表与详情 |
| 谁领先或正在变化？ | 排行榜 | 列表与详情 |
| 事情发生在哪里？ | 地图主视图 | 带国家列表的经典指标条 |
| 整个房间在关注什么？ | 大屏 | 状态看板 |
