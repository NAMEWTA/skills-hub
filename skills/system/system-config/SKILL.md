# 配置调整

从用户要改变的行为出发，先找实际生效的配置来源。避免套一份“最强配置”，也不要把当前工具环境当成用户的真实设备。

## 修改流程

1. 明确实际主机、程序/系统版本、目标行为和用户级/项目级/系统级范围。沿用已有授权，只澄清会扩大范围或改变后果的问题。
2. 读当前生效来源与优先级：命令参数、环境、用户配置、项目配置、管理策略、生成配置。区分文件存在、值被保存、程序实际加载。
3. 查本机帮助/配置契约与对应版本的官方文档。未知键或旧版本不支持的行为不要猜写；先完成可核验部分。
4. 准备字段级脱敏 diff、必要备份、验证和恢复方法。已经授权且可安全实施的具体修改直接执行，不重复添加确认步骤。
5. 用当前格式的正确解析/编辑方式保留注释与未知键，避免正则替换整个配置。写前重读本轮涉及内容，防止覆盖用户并发编辑。
6. 读回并验证真实宿主行为。需要重新加载、新会话或用户重启时明确说明，未经要求不关闭用户进程或重启设备。

[变更与恢复参考](references/changes.md) 处理优先级、备份、秘密值和并发写入；时区/语言/区域任务再读 [平台偏好](references/locale.md)。可按需使用 [配置记录模板](assets/configuration.md)。

## 保持范围

- 初始化不存在的配置是正常情况，记录原先不存在，不把缺文件当损坏。
- 不因优化模型/推理而固定最高 effort、最大窗口或最大并发；根据实际可用模型、任务与收益选择。
- 不以关闭 TLS、放宽权限/沙箱、禁用安全控制或删除历史来解决未知故障。
- 账号密码、token 和私有 provider URL 不写入公共笔记；凭据存到宿主支持的位置，记录引用。
- 只改时区就不顺带改语言、键盘、账号国家、NTP 或网络；不从 IP 地理位置推断偏好。

## 完成与持久化

报告原值→新值的脱敏摘要、作用域、实际读回、行为验证、恢复位置与待生效项。保存成功但尚未被程序加载时不能写“已生效”。

值得保留的运维约定写到用户现有目录或 `.agents/system/<host>/`：少量意图、配置来源、版本和验证方法。不要复制整份配置，不建设 JSON 状态机。纯查询无须新建记录。

## 完整本地材料

按目标平台、故障层或配置类型，从[材料导航](references/index.md)读取完整操作说明与模板。全部必要资料在本技能内，单独安装后可用；按需要读取，不每次加载全部材料。
