## 选择方法和范围

当前 Home 主 Agent 来自用户启动的环境。按本次适用明确要求、明确选用的命名配置、用户设置的 Home 默认依次选择；未指定模型或推理字段就不传覆盖。整项 CLI 或派遣方法仍没有依据时，指出具体缺项，不擅自尝试发现到的第一个工具。

Home 的默认只约束 Home 发起的直接任务。A/B 进入自己的项目后，读取当地规则、永久知识、文档和所需 SKILL，按用户适用于当地的要求决定如何进一步派遣。用户明确指定全链规则时原样传递其作用范围和来源，并让每层核对能力；不要把 Home 的普通默认伪装成全链规则。

派遣方法由用户选择，例如当前仓库已安装的 `system-herdr-core`；这个例子不构成依赖、工具候选清单或默认。按准确名称读取实际安装入口与其要求的帮助。用户未选择的 CLI 缺失不算故障，选定方法缺失则说明所在仓库与缺项，不借用别仓的安装或静默换方法。

## 准备项目任务

先用 `home-route` 确认 repo ID、身份和实际 checkout。Home 自己的协调根不是代码 cwd；项目基本背景可以从 Home 提供，项目内部细节要让当地 Agent 调查。

使用[项目任务简报](../assets/project-brief.md)，按实际规模保留这些内容：

- 目标、范围、只读/修改性质与完成条件；已有授权继续适用。
- 准确 repo ID、Git 身份、实际 checkout 与必要版本。
- 明确要求先读取当地 `AGENTS.md`、有关 `.agents/` 永久知识、文档和所需 SKILL。统一入口是任务约定，不保证所有 CLI 会自动发现。
- 当前适用的用户要求、选用配置、项目级跨仓背景和来源；不复制父会话全部历史。
- 已知同仓/同工作树活动、文件冲突与依赖，避免重复修改。
- 需要返回的结果、实际目录、资料来源/产物、验证、commit/PR、未知与未完成条件。
- 本层方法已经指定的 task/report 或消息回执位置，及写入范围；不要求项目安装 Home 接收器或统一 schema。

任务可只是“在项目 A 查询永久知识并解释当前决定”。收到项目结论后 Home 可以保存适合长期保留的管理概况与原件引用，不能把源码、项目知识全文或全部技能复制回 Home。

## 一条派遣边的记录归属

**派发者在自己的协调仓库，用自己选定方法的记录方式维护自己的直接任务。** 执行 cwd 可以是另一个项目；进入 A 后再次派遣才产生归 A 的新边。

以各层均主动选择同一技能为例：

| 边 | 派发者/记录 owner | 实际工作位置 |
| --- | --- | --- |
| Home → A | Home 的派遣记录 | A 的实际 checkout |
| Home → B | Home 的派遣记录 | B 的实际 checkout |
| A → feature/review | A 的本地派遣记录 | A 指定的 checkout/worktree |
| B → fix | B 的本地派遣记录 | B 指定的 checkout/worktree |

A 读取 Home 授权共享的上层任务并写指定回执，是向上交付；A 内部任务不追加到 Home 的 manifest。每层派发者验收自己的执行者，再向上级返回项目级结果与必要引用。不同仓库或连接的短名称可以重复，完整身份按原方法处理。

派遣图只提供导航和责任说明，不授予 Home 越级控制后代会话、修改后代 manifest 或全树 kill 的权限。项目依赖图另由 `home-map` 管理，不与派遣图混为一张全局可编辑 DAG。

## 使用已安装派遣技能

若用户选用 `system-herdr-core`，按该技能实际版本先读取 `hc --skill` 与所需帮助，沿用它的完整终端地址、连接上下文、共享文件、模板和冲突处理。Home 只传入真实 cwd、目标和输入，引用其产物；不维护第二份启动、就绪、投递、接管、恢复、回收命令表。

当前方法的本层记录示意为 `.agents/system/herdr-core/YYYY-MM-DD-topic_name/`，其中 topic、manifest 与 task/report 归该方法维护。Home、A、B 的根分别位于自己的协调仓库；诊断和运行原件也留该层既有临时位置。实际格式以当地安装版本为准，home 不重定义它。

方法要求双方可达的共享路径时，核实真实可达；不可达就报告该前提。短任务可以采用该技能已经提供的消息协作模式；不要为绕过条件创建同步器、接收器或隐藏服务。用户要求交互/接管就用满足要求的实际模式，不能静默换一次性输出。

其他派遣方法按自己的协议工作，不强迫套用 Core 目录、状态或字段。Home 不创建 `.agents/home/tasks/`、launchers 参数账本、统一 session 数据库、PTY 包或中央临时运行缓存。

## 直接交付的验收

分别判断会话是否建立、任务是否送达、上下文是否读取、结果是否满足完成条件。这些证据由实际派遣方法已有记录提供，home 不建立统一状态机。

1. 核对报告来自正确直接负责人、仓库、实际 checkout 与绑定产物。
2. 检查当地 Agent 实际读取了哪些规则和知识入口；路由看到文件存在不能代替读取证据。
3. 比较目标、产物、验证范围、commit/PR 或 dirty 工作状态。review 必须绑定被审版本，持续修改后的新版本不能沿用旧审查通过。
4. 缺少运行验证、外部服务或真实能力时标未知/未覆盖；不能将 send 成功、终端 idle、退出 0 或 worker 自报 done 当作验收。
5. 需要项目内复查时交原负责人；Home 只汇总必要结果。A 的 feature/review 由 A 验收，Home 验收 A 的项目级交付。

## 接续、异常与回收

| 情形 | 行为 |
| --- | --- |
| Home 会话结束后继续 | 先读有关历史/协调入口，再用原派遣方法核查直接任务 |
| A 恢复内部工作 | A 使用当地原主题和记录；Home 向 A 取项目级进度 |
| 投递超时/结果不明 | 先查原实例和原产物，不直接重派同一修改任务 |
| 终端仍在但 Agent 已退出 | 交原方法区分状态，不盲投到普通 shell |
| 更换 CLI、执行者或 checkout | 按原方法建立新身份与前序引用，不冒称跨 CLI 原生 resume |
| 短任务名相同 | 按协调根、连接和完整地址核对，不找“最近一次” |
| 项目受阻 | 保留已完成部分与未满足依赖，继续独立已授权工作 |
| 停止或回收 | 交当前 owner 处理明确归属资源，不凭祖先关系控制全树 |

记录隔离不自动隔离进程生命周期。退出 Home 不证明后代完成、退出或继续存活；脱离父级运行、接续和回收都按实际方法及用户要求处理。必要父子引用保留在普通任务说明中，不增加强制 parentTaskId 或全局清单。
