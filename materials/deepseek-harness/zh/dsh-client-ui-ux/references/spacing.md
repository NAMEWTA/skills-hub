# UI 间距与分组

在 [UI 开发循环](../SKILL.md#required-review-loop)中应用。距离应解释哪些文字、输入和操作属于一组。

### 先识别分组，再选择间隙

按同一对象、动作或重复单元分组，不按 DOM 同级、背景或 React 组件分组。定位前先陈述关系。独立检查每个嵌套层级；外部间隔更大，不要求内部间隔也更大。

例如，标题与描述共同引入一节；三个对话操作组成一个操作组；成员卡片组成与任务分开的区块。模型表单中，复选框与标签组成一个选项，选项组成字段，字段组成模型，模型组成列表。检查每种关系，而不是处处套同一个间隙。

没有显式分隔线时，可比较的相邻组之间，必须比组内有明显更大的间隔。相等只是防止关系颠倒的下限。重复组合共享间隙、内边距及对齐；标签长度不能成为不相关间距变化的理由。

换行、元数据、子组或独立操作增加复杂性时，充分增加外包间隔，以保留分组。紧凑图标／标签对与多行卡片区块需要不同间距层级。不要按卡片面积推导间隙，也不要把每个 margin 都乘倍数。分隔线与不同表面可以强化分隔，但标题必须更靠近自身内容，而不是前一组。

按正常尺寸判断实际留白，包括内边距、行高、字形空白及边框。仅有 CSS margin 比例不能证明分组；解释性标签需要一个无歧义的归属者。例如声明 16px／8px margin，计入行高及容器内边距后，标题仍可能更靠近前方内容；应比较渲染后的间隙，而非把这组数值当规则。

匹配两个可见间隙时，指出两对端点，计入每个容器的内边距、边框和文本行框。相等的可见间隙可能需要不相等的 margin。控件绘制边缘与文字字形边缘是不同端点；审查过程中保持选择一致。

复用页面间距与[样式设计变量](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/docs/web-styling.md)，保留[对齐](alignment.md)轴，不确定的判断查阅[案例](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/docs/ui-design-review-cases.md#grouping)。本技能不定义数字比例尺。
