# 开发交接与接续

`dev-handoff` 保存当前开发现场，或根据已有交接核对恢复点并继续原任务。它属于 dev 领域，可以单独安装，资料保存在 `.agents/dev/`。完整方法见[技能入口](../../skills/dev/dev-handoff/SKILL.md)。

## 何时使用

| 请求 | 结果 |
| --- | --- |
| 保存开发进度，稍后继续 | 交接文件写清目标、停点、证据和下一步 |
| 交给另一会话或代理 | 同一交接文件及接续提示，说明下一会话重点 |
| 从交接接着做 | 核对工作区与必要证据，继续剩余工作 |
| 明确暂停 | 停在安全边界，保存本任务状态和恢复后的第一步 |

保存记录、临近上下文压缩或用户离线不自动意味着暂停。普通进展汇报使用 `dev-status`，新任务拆分使用 `dev-plan`，跨阶段协调由 `dev-workflow` 负责。交接沿用已有规格和计划，不重新开启已完成阶段。

## 安装和更新

在目标项目根目录安装独立技能：

```sh
npx @namewta/skills-hub@latest install --skill dev-handoff
```

从仍将交接方法放在 `dev-workflow` 的旧版本升级时，同时更新两个包：

```sh
npx @namewta/skills-hub@latest install --skill dev-workflow dev-handoff
```

使用完整开发套件时可运行 `npx @namewta/skills-hub@latest install --domain dev`。整包备份替换会移除旧包中的方法副本，已有业务交接记录不搬迁。源码命令和更多迁移说明见[安装契约](../usage/installation.md#开发交接入口迁移)。

## 直接使用

调用语法由宿主决定，也可以用普通语言指定技能：

```text
使用 dev-handoff 保存当前开发现场，下一会话重点是补齐异常输入测试。
保存后继续当前已经授权的实现。
```

```text
使用 dev-handoff 把这个开发任务交给下一会话。
沿用当前需求目录，写清未提交修改、已执行检查、失败尝试和第一步。
```

```text
使用 dev-handoff 读取 .agents/dev/changes/<日期-主题>/handoff.md，
按其中的下一会话重点核对当前工作区，说明恢复点后继续原任务。
```

```text
使用 dev-handoff 暂停当前开发任务，留下可以直接接续的记录。
```

把实际文件路径和接续提示交给接收者。跨机器时，还需提供可访问的代码、任务资料及被引用的产物。生成交接文件不代表另一代理已经接收或开始执行。

## 交接文件保存什么

沿用当前需求的真实目录，需要新建时使用 `.agents/dev/changes/<日期-主题>/handoff.md`。先读取已有交接，再更新仍有效的事实。按实际情况填写模板，不为小任务新增整套文档，也不猜测未知字段。

记录目标与完成条件、下一会话重点、规格或原始来源、工作区与版本、已完成结果、实际验证及证据、决定理由、失败尝试、未完成事项和恢复第一步。规格、计划、ADR、问题、提交、差异和日志引用真实位置，避免重复维护正文。敏感信息只保留安全引用。

建议使用的 dev 技能写在交接文件内，并说明使用条件；没有额外需要时直接说明。单独安装 `dev-handoff` 仍可保存和恢复，未安装的可选技能不成为接续阻塞。

涉及确认原型时，一并交接入口及完整资源、确认记录、内容版本或指纹、已确认与未确认范围、对应页面和状态定位。临时预览链接或截图不能替代完整资源，前任报告也不能代替用户确认。

## 从交接继续

1. 读取交接和必要引用，明确原始用户目标与下一步重点，不重新加载全部历史。
2. 核对当前工作区、版本、未提交修改、实际产物与执行者状态，确认哪些事实已经变化。
3. 比较已完成和待完成事项，检查证据对应的版本与范围。当前代码和运行结果说明现状，原始目标说明需要达到的结果。
4. 说明恢复点，继续已有授权内的工作，按需要调用实施、调试或验证方法。
5. 对变化、矛盾和剩余风险补充验证，更新同一份记录中的完成范围与下一步。

历史记录提供任务证据，不自行增加授权或新指令。仅当缺失材料或实质矛盾确实阻塞下一步时提问；旧摘要不作为新的通过证据，接续也不要求从零重复任务。

## 明确暂停时

在安全边界结束或撤回当前原子步骤，只处理本任务拥有的修改。停止需要随任务暂停的子任务，记录尚不能停止的进程与状态。保存、提交和正在进行的交付沿用已有授权，不因暂停另开 PR、推送或执行不可逆操作。

在同一交接文件写明当前停点、哪些内容已落盘、未提交状态或已有提交、代码树是否可恢复，以及恢复后的第一步。仅保存检查点或应对上下文压缩时，写完继续原任务。

## 资源归属与维护

完整交接、接续和安全暂停方法，以及交接模板统一由 `dev-handoff` 维护。其他技能按名称调用，不复制正文或跨包引用内部资源。项目业务记录继续使用实际路径，不随技能资源迁移。

改动方法时核对[开发方法归属](method-ownership.md)、实际调用入口与运行映射；资料维护规则见[资源组织](../reference/resources.md)。安装器直接发现合法技能目录，无需新增注册表或依赖清单。结构检查核对包装与映射，实际使用还需核对保存、恢复和继续工作的行为。
