# 跨项目联合验收

交付针对真实组合的通过、失败、部分完成或受阻结论，以及项目内原始证据引用。Home 定义和核对组合条件；实际联调由用户指定或任务中明确选定的项目 Agent/已有集成测试项目执行。

## 执行

先读取下述 Home 主入口，再读[组合验证方法](references/integration.md)，采用[组合验收模板](assets/integration.md)补齐已有权威任务。同一上下文已读同一根、同一版本可复用；新会话、压缩后缺失、入口更新或换根时重读。入口读不到先核对根、路径和安装状态，可用时调用 `home-doctor`；无需先成功读取才能做最小只读诊断。不强制新建中心测试仓库。

1. 从实际 Home 根读取 `./.agents/home/AGENTS.md`，明确用户可观察的共同目标、参与 repo ID、影响关系和完成条件。关系不清交 `home-map`，实际位置交 `home-route`，项目内部调查交当地 Agent。
2. 指定一个实际联调执行者、交付顺序、所需输入和最终证据位置。执行者按自己项目规则工作，必要协作通过各项目直接负责人；Home 不直接接管所有服务。
3. 核对每个项目的实际 checkout、HEAD、dirty 和被验证产物，记录包来源/锁文件/依赖解析、环境、服务身份及就绪证据。信息来自项目报告，Home 不扫描原件建立镜像。
4. 将组合目标和已有资料交 `home-workflow`，按用户选择的当地派遣方法调用实际执行者；无须要求项目使用 dev 或固定 CLI。
5. 比较执行结果与验收目标，检查实际使用新产物、关键输入输出、绑定版本及范围。mock、缺环境、外部服务未接入和未覆盖路径分别说明。
6. 失败按最小证据交有关直接 owner 修订；影响组合的变化发生后复验有关范围。最终 Home 只保存组合摘要与引用，原始日志、测试与项目报告留实际执行项目。

## 完成条件

项目分别报告完成不替代联合验收；dirty 通过只能称相应本地工作状态通过，不能凭一个 SHA 宣称完全复现。无法验证的条件标未知或受阻。项目发布、回滚与内部交付继续归当地方法，多仓提交和发布不被描述为原子事务。
