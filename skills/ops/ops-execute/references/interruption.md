# 中断、重试与写入交接

## 先区分发生在哪一段

| 观测 | 当前结论 | 下一步 |
| --- | --- | --- |
| 本地准备失败，尚未发出远端请求 | 现场操作未开始 | 修复准备或记录问题；不要编造后端任务 |
| 平台明确拒绝提交 | 根据拒绝证据记录未接受 | 核对范围、能力或权限，不无限重试 |
| 远端已接受，随后断线或超时 | 执行/现场结果未知 | 查询原 job/session 和实际对象 |
| 命令失败，可能执行过部分步骤 | 执行失败，现场待核实 | 按目标确认已发生的副作用 |
| 一个目标成功，另一个失败，第三个未开始 | 部分完成 | 保留差异，只处理尚需处理部分 |
| 父会话或控制进程退出 | 控制会话结束 | 不能据此断言远端任务已停 |

## 查询原操作，再决定是否重试

1. 从原 run 取得后端任务 ID、真实目标、提交时间、入口版本、参数引用和最后证据。
2. 查询已有后端任务状态；工具没有任务 ID 时，根据服务调用标识、日志、时间窗口和现场变化核实。当前进程不见了不自动证明先前请求未执行。
3. 核对实际命令/job 定义是否仍是上次版本。重新运行通常使用当前入口，不能把名字相同当成动作不变。
4. 区分未提交、仍运行、已完成、失败且部分生效、结果未知。未知保留为未知；不要为了清空任务列表选择成功或失败。
5. 按业务 owner 判断尚需动作是否可安全重复。只有真实后端提供幂等键、事务或取消保障时才使用该能力，不宣称本包补上了这些保证。
6. 需要新尝试时写新的 attempt/步骤，关联旧尝试和核实证据；只执行仍需处理且仍被授权的部分。

暂停请求不等于强杀远端。先报告进行中的动作、可安全中断点及真实取消能力；已完成可逆部分按现有方法处理，不能对数据恢复等不可安全中断操作贸然终止。

## 记录失败时怎样继续

执行前本地与后端都无法可靠记录，停止现场变更，保留可做的分析和缺口。不要先操作再承诺补记。

执行中本地摘要失败、但后端完整保留原 execution 时，继续使用该权威事实来源，记录本地待补状态。摘要保存失败不会触发命令重放。

如果所有可靠记录都失效，停止尚未开始的新变更，并继续核实已经运行的任务。保留已知任务引用和当前缺口，使用恢复后的记录追加事实；不把后补时间伪装成实际执行时间。

本地助手在原子提交后同步目录仍可能报错，因此错误返回也不能单独证明文件未保存。先 show / 读取原路径核实：已有步骤不可覆盖；同名步骤的存在也不代表远端恰好执行一次。没有可靠证据时保留记录状态未知。

## 接续原 run

同一协调者继续同一任务，沿用 writer 和原 run，读取最新步骤再推进。新会话成为写入者时：

1. 核实运维工作根和 run 的身份、父/子任务关系及当前 writer。
2. 核实原协调者已停止向此 run 写入或已明确交出责任；列明仍运行的后端 job 和未知目标。
3. 读取最新 run.md 内容摘要，填写[写入交接记录](../assets/writer-handoff.md)，说明依据、已确认责任及原授权范围。
4. 使用本地记录助手 handoff 原子转交责任；如果摘要或 writer 已变化，重新读取，不强制覆盖。
5. 新会话从实际未完成步骤继续。变更 writer 不会自动取消、重试或恢复任何远端任务。

父会话加载了技能不等于新的项目 CLI 已加载。独立 CLI 要核实自己的 cwd、实际技能发现位置、所需 ops owner、记录根与子 run；缺少方法或记录能力时只分析，不复制临时执行器。

## 遗留的本地写锁

`.agents/ops/runs/.<run-id>.write-lock/` 只覆盖一次本地文件写入。正常退出会释放，崩溃可能留下。工具不会按年龄、超时或 PID 不存在自动抢锁。

先检查 holder.md 的主机、进程、创建时间和标识，核实该本地写入已结束并确认没有其他写入者。保存这次核实的证据后，才可以显式清理已确认遗留的这一把本地锁，再读取 run 完整性。无法确认时保留锁并报告缺口。不要批量删除锁、临时目录或其他 runs。

释放本地记账锁不等于释放远端资源冲突保护；远端是否停止仍按上面的查询规则核实。此工具以可信、受权限控制的本地目录为前提，不是对抗拥有同目录写权限的恶意进程的安全隔离层。
