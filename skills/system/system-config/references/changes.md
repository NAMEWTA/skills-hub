# 配置的来源、改动与恢复

## 找到真正控制行为的地方

从运行实例与官方配置说明定位路径；多个旧目录、便携安装、工作树和配置管理器并存时，不取首个文件。区分配置的作者来源与程序生成结果，优先修改作者来源。

常见优先级包括命令行参数、环境变量、项目配置、用户配置与托管策略，具体顺序由产品决定。不要通用地假定“项目级总能覆盖用户级”。无法覆盖的管理策略不是需要绕开的故障。

在真实版本上核验配置键、值类型和作用域。网页介绍某字段只证明它属于文档描述的版本，不保证用户安装版支持。不要为了通过检查而把未知能力写成已核验。

AI CLI、MCP 和 hooks 的“检查”可能启动工具、联网或执行用户脚本；只读阶段先看相关行为，不批量运行全部服务。单个语法校验通过不等于远端 API、账号配额或模型协议已经验证。

## 用一份小规格描述改动

写清目标行为、当前证据、要改的精确字段/文件、保留项与成功条件。选择最小差异，避免把一次初始化变成整机重配。

对于模型/推理/上下文，先保留现有可用供应商与模型；只有任务需要才调整。上下文容量、请求 body 限制、压缩阈值和账号用量是不同问题。先消除重复指令或错误配置，不机械提高所有上限。

纯字段修改无需大型计划。涉及多文件、活动写入程序或跨作用域时，补充具体执行顺序与失败恢复即可；不用固定 JSON schema 或大量状态枚举。

## 安全保存

备份仅覆盖本轮会改变的文件/字段，保存原字节、权限、原先不存在状态与必要指纹。POSIX 放入当前用户私有且权限受限的目录；Windows 检查私有目录 ACL。包含凭据的备份不能进入 Git、公开附件或共享日志。

原配置是符号链接、由管理器生成或有并发 writer 时，先理解所有权，使用支持的入口。不要先破坏链接再写入，也不要为了方便杀进程。需要停止写入时使用正常关闭方式与已授权范围。

写前比较所读内容是否仍是当前值。支持原子替换时使用同一文件系统的临时文件与 rename，并保留必要权限；多文件更新不宣称天然原子。未知字段和用户注释尽量保留，不通过重序列化清空整个文件。

环境变量优先限于任务进程/项目所需范围。不要为一个 CLI 代理或工具版本修改全局 shell profile、系统 PATH 或 HOME。临时改变后恢复“原来不存在”与原值两种状态。

## 验证与恢复

验证分三层：

| 层 | 证据 |
|---|---|
| 存储 | 内容/格式正确，差异只在预期范围，文件权限合适 |
| 加载 | 真实程序读到了该来源与值，未被更高优先级覆盖 |
| 行为 | 原问题对应的实际操作产生预期结果 |

不为验证非网络配置而额外登录账号或查询私有 API。使用真实任务相关的最少检查即可。

失败后只恢复本轮写入。若用户随后修改了同一字段/文件，不能整文件覆盖；保留备份和冲突说明，采用可审阅的合并。新建文件恢复为“原先不存在”时也先核对它仍仅含本轮内容。

记录暂存、已加载、行为验证以及待重新打开/待登录/待重启的区别。没有执行的检查标为未验证。
