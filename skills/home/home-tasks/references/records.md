# 主题、派发与回执记录

## 资料位置与权限

```text
.agents/home/coordination/
  all.status.tsv
  YYYY-MM-DD-topic/
    topic.md
    task_01.md
    report_01.md
    task_02.md
    report_02.md
    status.tsv
```

一个业务任务对应一个主题，跨项目也沿用一个主题。项目相同但业务目标独立时分别建立主题。对旧协调页保留原入口，新主题引用已有 Issue、规格或协调页。纯查询不创建主题。日期使用 Home 当地日期，短名用小写字母、数字、连字符；重名先区分接续或新任务，新主题选择未占用短名。

`topic.md` 的正文记录背景、目标、直接负责人、验收标准和接续条件，工具管理其状态区。每条派发的 Markdown 正文由 Home 提供，写出具体要求、已接受的决定、范围、repo ID、实际 checkout、角色、派遣方式及 team、预期产物与验收。读者在旧会话或原件不可访问时仍可理解工作。跨项目消息分别写各目标，实际发送时只给目标项目与它有关的内容。每个 `task` 双位起递增，多个项目共用一个编号。原样补发尚未收到的目标复用该编号；补充要求、用户答疑或重做追加新 task，引用前序 task 与有关 report。

每次收到实际回复由 Home 追加一份独立编号的 `report`。`progress`、`question`、`blocker` 或 `result` 统一带来源 repo ID 和对应 task。正文保存回复原意、时间、已经完成的工作、实际核查及观察结果、限制、未决事项与下一步。原方法的回执和项目产物可供追溯。项目有共享文件或以消息回复时都可用同一记录方式。项目 Agent 无须读取或改写 Home 状态文件。用户答复之后的下一条派发是 task。任务与回执发布后保留原件，补充通过新编号完成。

## 工具调用

所有命令要求 `node <本技能目录>/scripts/tasks.mjs <命令> --home <Home>`；`--help` 列出完整选项，返回 JSON。输入 Markdown 用 `--input` 指定。Home 在真实派遣前后调用工具，工具不连接派遣服务。

| 命令 | 行为与关键参数 |
| --- | --- |
| `init` | `--topic --title --input` 建立主题，初始未派发 |
| `task` | `--topic --repos --input` 追加消息，`--repos` 是逗号分隔的 repo ID，可选 `--previous task_01.md --reply-to report_01.md` |
| `report` | `--topic --task --repo --kind --input` 归档相应项目的实际回复，状态仍由 Home 判断 |
| `show`、`list`、`project` | 分别用 `--topic`、无额外参数或 `--repo` 查询主题详情、全局或项目；`show` 返回每个目标的 `revision` |
| `reserve` | `--topic --task --repo --evidence`，持久化占用和本次尝试，再交派遣方法发送 |
| `state` | `--topic --task --repo --state --expect --evidence`，`--expect` 使用最近读到的目标 `revision`，证据填真实来源或简短可核查说明 |
| `release` | `--topic --repo --evidence`，确认没有已派发且仍未结束的工作，释放占用。尚未派发的轮次保留待发 |
| `close` | `--topic --state done` 或 `cancelled`，加 `--evidence`，先处理各目标状态和占用再为主题结案 |
| `rebuild` | 读取源记录并更新两层 TSV，保留旧手写协调页和未受管理的视图 |

## 状态与派遣次序

| 状态 | 依据 |
| --- | --- |
| `pending` | 未派发，或已证实上次发送没有发生。等待项目空闲、所需上游或派遣前置可记录原因 |
| `reserved` | 写入实际投递前的占用，尚无送达证据；汇总展示为进行中 |
| `running` | 有送达、执行、交回待验收等进展证据 |
| `blocked` | 已派任务正在等明确回复、依赖或其他解除条件 |
| `unknown` | 已尝试但不能确定现状或是否送达，继续占用并核查原方法 |
| `done` / `cancelled` | Home 验收本轮结论或确认取消；项目最终交付还须单独释放，再结案主题 |

- 用准确 repo ID 检查 Home 的直接工作，已占用项目的另一个主题可以先记录 `pending`。项目或用户明确报告的外部占用也是派遣依据，记在待派目标的证据里。仅凭 Home 无记录只能确认 Home 没有占用，不能推断项目内部完全空闲。
- 同主题追加优先接续原直接负责人。`reserved` 或 `unknown` 的投递先查原结果；不能确认证据时保持占用。任务同时涉及多个项目时独立判断每个目标，空闲项目可先做无依赖部分。检查跨项目契约、产物与实际环境由 `home-integrate` 负责。
- task/report 编号是业务消息身份，原生 session 由实际派遣方法管理。一个合适会话可顺序接收多个 task；新编号、保存摘要或更改默认配置都不证明需要新会话。上下文压缩、恢复和取消按原宿主真实能力处理，不建立第二套 session 状态表。
- Home 明确判断哪轮达成目标。提问回执可在答疑处理后结束该轮，后续实际交付仍须验收。只有原方法证实未送达且无动作时才将异常投递恢复为 `pending`。确认所有已派轮次已验收或停止，或证明尝试未送达后，才能调用 `release`。
- `status.tsv` 每条 task 一行，含所有目标项目的状态和已归档回执。同一主题 `all.status.tsv` 一行，含项目列表、各项目汇总状态和主题视图路径。完成所有消息仍可能需要 Home 验收与联调，主题以 `close` 的结论为准。既有手写协调文件不会加入新表。若查询状态超出最后一次实查时间，不把记录当作当前会话在线证明。

## 写入中断与接续

工具按 Home 使用排他写锁，写入原件前核对读取版本，新文件独占发布，状态与 TSV 分别原子替换。发布编号文件后即为源记录，TSV 写入失败返回 `views: needs-rebuild`，读回原件并重建，不重复追加或重新发送。写锁只在本地文件操作期间持有，不能跨远程执行建立分布式锁。遗留锁先核实原写者和原件，不能按时长推断可清理。读取到受管理原件损坏时停下核对，不用旧 TSV 释放项目或重新派发。
