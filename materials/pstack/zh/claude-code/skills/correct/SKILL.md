# 纠正

操作人反复纠正智能体在这个仓库中的同类错误。改变仓库，让下一个智能体无法再犯。

假设每位贡献者都是智能体，只看到自己打开的文件，会复制最近的示例，并走能编译的最短路径。设计仓库，使从单个文件看似正确的改动，对整个仓库也正确。

## 找出错误类别

先读最近提交、回滚、审查评论、智能体指令文件，以及解释绕路的注释。将错误分型。某类发生两次后，才算一类重复错误。

## 在有效的最高层修复每一类

1. **用架构消除。** 每份状态只有一个所有者，每项任务只有一条受支持路径。隐藏内部，使错误导入失败。把手工同步列表替换为单一事实来源。删除旧途径与智能体可能照抄的死代码。
2. **用类型约束，让错误状态无法写出。** 错误代码仍能编译时，增加 lint 或 CI 检查，错误信息指出应使用的文件、类型或函数。模式已经普遍存在时，只在变更新增实例时失败。
3. **测试行为。** 测试所检查行为损坏却仍通过，或者只有内部变化却失败时，修正或删除该测试。
4. **最后才写文档或智能体规则，且只写需要判断的选择。** 智能体跳过它们时，没有东西会失败。

## 修复并证明

现在修复最常见的类别，每类一个提交。证明每项新检查会在真实历史错误上失败。在本地与 CI 运行同一命令。例外放在违规行，带原因、到期日期和一位人的批准。

## 维护规则表

最后，在智能体指令文件里保留一张表，将每条规则与约束它的机制对应。操作人纠正你时，修复错误并加入规则。规则已经存在却没有机制执行时，就是重复，应在同一变更中于最高有效层修复。错误已不可能发生时，删掉规则。

**回复：** 每类错误及其证据、选择的层级，以及更高层为何无效。
