# 项目后续处理

- 原 run / 诊断步骤：
- 项目、环境、服务、实例与稳定资源：
- 当前实际版本/制品/配置观测及来源时间：
- 症状、首次异常、最近完成窗口：
- 已确认事实、候选原因与反证：
- 已实际执行的操作及其结果：
- 共享消费者、影响范围和未知覆盖：
- 当前服务状态与仍在运行/结果未知的任务：

## 需要项目处理的事项

写需要应用修复、发布、制品回滚、配置/拓扑变更或 migration 的具体原因及证据。列已有项目入口或责任方；未知则说明缺口，不要求它增加接收器或改格式。

## 后续运维复验条件

写处理确已发生应提供的普通证据、应重新检查的原失败路径和消费者，以及观察窗口依据。

这份交接留在 ops 的原 run，引用项目现有资料。没有项目执行证据就明确“尚未执行”，不创建竞争的发布历史。
