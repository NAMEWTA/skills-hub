# Herdr 验收附件与安装验证

## 实施范围

两个 Herdr 技能默认在同号 Markdown 报告记录验收。需要保留的临时附件镜像工具、主题和执行者目录，写入 `.agents/system/ignore/<工具>/<主题>/<执行者目录>/<task 文件基名>/`。旧报告沿用原链接。

安装任一 system 技能时，交互和显式命令共用安装事务，在目标项目根 `.gitignore` 补齐 `/.agents/system/ignore/`。用安装前的原字节恢复写入失败的文件。附件保持按需创建。

## 本机验证

- Windows PowerShell、Node.js v24.21.0。安装与交互专项测试 28 项通过，覆盖已有规则的字节与换行、重复安装、零写入预览和取消、目标冲突及部分写入回滚。
- 隔离 Git 项目的 `git check-ignore` 确认两个工具的日志、JSON 和截图均被忽略，清单、任务与报告仍可追踪。
- 用安装后的两套模板在隔离目录演练普通报告和需附件的连续任务。含空格的主题、百分号编码的 pane 目录、不同任务编号的相对链接均解析到各自文件。
- `npm run check` 和 `npm run check:package` 通过。实际 npm 包包含 52 个技能、1031 个分发文件，预览、安装与重复安装中的忽略规则检查通过。
- `npm run check:full` 的隔离回归为 360 通过、11 跳过、1 失败。Windows 在 `tests/materials-sync.test.mjs:160` 创建测试用文件符号链接时返回 `EPERM`，失败发生在材料同步断言之前。单独运行有限状态示例的原实现、故障注入和恢复三阶段检查通过。

文件协作走查覆盖模板和文件路径。实际 agent 任务及远程挂载留待对应环境验证。
