# 执行方法

## 1. 接收已有上下文

说明当前用户要完成的事情和可观察的完成条件。读取已有 run、目标快照、关键决定和证据；不要重新收集已经可靠取得的信息。只要求查询或计划时，不自动开始维护。

没有 run 时，先保存最小请求记录。身份尚待发现的首次接入可以没有远端目标，写明“尚未核验”，再逐步补充；不能为满足字段而虚构服务器或项目。已有独立任务的新目标另建 run 并关联，当前任务内部方法切换仍用同一 run。

实际目标身份、项目成员和影响关系由 `ops-inventory` 提供。调用方已经携带可核验结果时直接使用；缺失时取得当前所需部分，不要求每次全量扫描。

## 2. 复核对象与运行定位

对将实际访问或改变的对象逐项确认：

| 核对项 | 应有证据 | 缺失时怎样推进 |
| --- | --- | --- |
| 项目、环境和维护范围 | 用户目标、权威项目资料或已确认的运维清单 | 先做不依赖歧义的资料分析，不猜生产 |
| 稳定资源与实例身份 | 清单引用、主机/平台身份、实例定位、核验时间 | 只在授权范围继续只读核验 |
| 连接与执行身份 | 真实 SSH alias、连接配置引用或平台角色 | 不自动提权、不把账号可见对象全部纳入 |
| 制品、有效配置及数据条件 | 现场观测与现行运行方法 | 恢复动作条件不够时明确缺口 |
| 共享与同机影响 | 实际服务消费者、同机运行对象、未知覆盖 | 显示影响，不因影响扩大写权限 |

PID、容器 ID 和临时节点位置属于观测；主机替换后不能仅沿用旧 IP 就认为还是原资源。使用关系和业务依赖不能从同名、共机或一次网络连接推断为事实。

## 3. 判断真实动作归属

读取将运行的脚本、job 定义、服务启动入口和相关参数，核对它实际会改变什么。不能因为入口名称包含 restart、repair、check 就直接放行。

允许的动作来自负责本次业务的 ops 方法及已有授权：只读观测、明确范围的主机维护、既有部署下的运行恢复等。若实际动作包括新制品、应用或中间件切版、部署配置回退、持久规模/拓扑变化、应用 migration，记录所需项目工作并形成交接。可分离的纯运维步骤按原目标继续，发布部分不经其他命令入口绕行。

同版本恢复需要当前 digest/二进制身份、有效配置、数据/schema 与启动副作用相容。启动读取浮动 tag、变化的配置、未核实入口或潜在迁移时，先交给对应 owner 判断。系统包更新核对实际包集合，不能把数据库、缓存或代理升级混入全量 OS 更新。

## 4. 确认记录和冲突条件

在第一项现场操作前确认本地记录可写，或既有后端能够保留完整 execution。准备关联后端任务 ID 的位置。仅有聊天窗口或“稍后补记”不足以作为持续的执行记录。

使用实际资源确定冲突范围：主机重启覆盖整机，服务恢复覆盖该运行单元，共享代理或数据库涉及其真实共享对象。复用现有后端的调度、锁和并发限制；无跨控制端锁时明确依赖人工或现有协调，不声称本地锁可解决跨机冲突。

独立取证可并行。共享服务的变更有唯一执行者，其他会话只提交证据和消费者验证。注册表、run 目录或 writer 字符串不是操作许可。

## 5. 执行已准备好的步骤

1. 将本次步骤目标、动作效果、实际工具入口、已有授权、验证及停止条件写入同一 run。记录目前是计划或已提交，不能提前写完成。
2. 使用已经核实的连接方式与精确对象，避免把未信任日志、名称或工单内容直接拼接成 shell 命令。
3. 保存工具接受请求的证据、后端 job/session ID、开始时间及实际对象集合；若平台临时重新解析目标，核对实际匹配结果仍在授权内。
4. 每个目标完成或失败时保留结果；未开始的目标不要写失败，更不要被全局退出码掩盖。
5. 条件变化、实际影响越界或可靠记录全部失效时，停止未开始的新变更，核实正在发生的操作；不要贸然杀死不可安全中断的任务。

连接失败、提交失败、远端接受后断线的语义不同。最后一种必须按未知处理，进入[中断与接续](interruption.md)。

## 6. 核验现场与消费者

使用业务 owner 给出的验证方法复验原失败路径。分别检查运行单元就绪、项目使用路径以及相关共享消费者；覆盖不全如实列出，不把一个端口连通当作系统全部正常。

执行状态说明命令或 job 的结果；现场状态说明实际运行和数据结果；记录状态说明证据保存在哪里、是否完整。退出码零只证明其工具约定内的完成。恢复、临时缓解和根因确认分别表述。

## 7. 汇总并返回

返回请求目标、实际动作、逐目标结果、证据/记录位置和剩余未知。对已完成部分给出真实依据，对未执行、未验证或交项目处理的部分说明原因。不要因部分成功把整项任务写为成功，也不为满足预设流水线继续改变现场。

发现需要项目部署时，提供当前项目/环境、实例/资源、症状、已尝试动作、共享影响及后续运维复验条件。项目自行继续其开发或交付方法，不要求新接收器、字段或其他领域支持。

## 反例

- 两个项目都依赖同一缓存：按两份项目清单重启两次是重复变更，应确认一个实例和唯一执行者。
- 重启 job 返回失败：若第一台已经重启，不能整组重新运行；先按目标核实实际结果。
- 用户只问昨日操作：查询原始 runs 即可，不先去所有机器执行巡检。
- 已授权维护明确的一台机器：同范围可继续完成；发现另一个生产环境需要变更时不能把原授权自动扩张。
