# 开发技能的方法归属与协作重构

## 原因与目标

重构前 `skills/dev` 有 1166 个文件，239 组字节完全相同的文件、多出 674 份完全相同副本；此外还有仅修改链接、标题或本地适配的同源变体。不能只删同名文件，也不能以摘要代替完整方法。

当前约定是**技能可以协作依赖，完整方法只在其负责技能维护**。`dev-workflow` 是编排入口，不是另一个方法全集。调用按任务发生，不要求每个技能单独包办全部阶段。

## 方法归属

| 归属 | 保留内容 | 其他技能如何使用 |
| --- | --- | --- |
| `dev-help` | 十章指南、能力地图、提示词与场景配方 | 查使用方式，不内嵌执行包 |
| `dev-workflow` | 任务路由、工程执行、恢复、暂停、自主队列、跨日协调、决策证据 | 负责同一任务的推进与结果集成 |
| `dev-intake` / `dev-grill` / `dev-spec` / `dev-plan` | 来源整理、访谈、行为规格、垂直切片与多阶段计划 | 消除对应不确定性，沿用已完成阶段 |
| `dev-architecture` | 架构设计、模块深度、依赖与候选方案 | 接受当前契约，返回接口与理由 |
| `dev-build` | 实施、任务图、功能交付、行为保持重构、原型、可操作界面 | 故障调用 debug，测试先行调用 tdd |
| `dev-debug` | 缺陷手册、科学诊断、人工复现循环 | 返回根因、修复和原场景证据 |
| `dev-tdd` | 六步缺陷回归、逐切片测试先行、测试设计与替身 | 默认以 pstack 缺陷回归为主；明确选择新功能 TDD 时采用 Matt 的逐切片补充，不串行重复两套流程 |
| `dev-benchmark` | 测量清单、性能修复、指标迭代、运行/轨迹取证 | 复用同一负载与基线 |
| `dev-guardrails` | 24 条原则、类型与 TypeScript、注释审查、结构化防错 | 按触发条件读取，不给每个包复制原则集 |
| `dev-review` | 两轴审查、对抗审查、影响范围、盲测与审查意见分诊 | 返回证据支持的发现 |
| `dev-verify` | 真实入口验证、项目验证方法创建/维护、功能图、视觉等价 | 不再携带形式化检查器或状态图工具副本 |
| `dev-formal-verify` / `dev-statechart` | 属性检查与模型维护 / TLA+ 结果图与重放工具 | 各自保留脚本、模型、模板与执行前提 |
| `dev-deploy` | 指定环境发布、PR 准备/跟进/落地、观察器、工作树审计 | 在授权交付阶段执行，不因绿灯自动扩大授权 |
| `dev-learn` / `dev-why` | 机制讲解、教学与背景恢复 / 历史证据调查 | 当前机制与当时理由分开，不再复制全部来源手册 |
| `dev-archive` / `dev-writing` | 项目知识、ADR、词汇表、复盘 / 技术与 Agent 文档写作 | 方法各存一处，记录引用真实项目位置 |
| `dev-issue-setup` / `dev-issue-triage` / `dev-issue-fix` | 来源配置与共同协议 / 分诊 / 可信交接后的真实 UI 复现修复 | 三个阶段互相调用，配置包不再自带两套执行包 |
| 其他专门入口 | UI 设计、并行、环境配置、偏好提炼、状态报告、请求深化 | 保留自身方法，依赖专门技能完成相邻工作 |

23 条执行路线的具体归属与返回条件见 [工作流协作路由](../skills/dev/dev-workflow/references/method-handoffs.md)。完整原件、中文底稿、图片和机器夹具未删除；本次基于仓库已固定的上游版本，不声称同步了上游最新版本。

## 追踪与变体处理

[资源迁移表](dev-resource-moves.tsv)记录每个移除位置和当前归属。[资料清单](../materials/manifest.tsv)将同一上游方法的运行映射收拢到一个负责技能；一个来源分拆为同一技能内的正文与模板仍合法。映射变更不修改原件或译文摘要。

变体按来源身份和正文差异核对，不仅按文件名去重。保留专门包已完成的授权、宿主、持久化与证据适配；剔除递归复制增加的导航尾注。ADR 的强制编号/状态枚举、原型隔离、后台能力、只读调查与历史报告边界仍需在唯一正文处维护。指南是用法说明，不冒充方法全文。

## 安装与执行

安装器按用户选择安装技能，不维护额外依赖清单。需要完整开发套件时可选择 dev 领域；执行时按具体任务读取相关技能的方法，资源仍各存一处。

调用者传递目标、阶段、已有产物、代码版本、证据、授权与返回条件。被调用者完成后返回原任务；同一未解决问题不能无新增证据地往返调用。缺少宿主的技能调用 API 时直接读取已安装入口应用方法，不虚构子代理执行。

## 防止再次膨胀

- 资料校验拒绝同一个开发来源映射到多个技能。
- 包装校验拒绝长篇完全重复资源，也识别只改变 Markdown 链接目的地和空白的复制。
- 对开发领域各类方法归属、迁移目标与帮助不嵌套执行包保留回归断言。
- 结构门禁不证明翻译忠实，也不能发现所有近义改写；后续同步仍需对照原件与唯一运行正文审查。
