# 资源组织与完整性

来源原件、中文对照与运行包各有用途。前两者用于维护时核对，只有运行包参与技能发现与安装。完整材料、映射和实际执行资源需要同时清楚，不能用一份摘要代替方法，也不能把来源树当作运行入口。

## 四类文件各有职责

| 位置 | 内容 | 读取方式 |
| --- | --- | --- |
| `skills/<domain>/<domain>-xxx/` | 按领域整合的中文方法、模板、示例和脚本 | 按任务读取本包资源，跨技能按名称调用 |
| `upstream-skills/zh-<原名>/` | 独立上游中文运行包及原工具、资源 | 保留包内的按需读取和工具调用方式 |
| `materials/<project>/` | 完整选定来源树、适用中文对照和逐文件清单 | 维护核对及明确的固定夹具回放，不安装 |
| `licenses/` | 法律原文及必要通知 | 按[第三方声明](../../THIRD_PARTY_NOTICES.md)随源码和 npm 分发 |

自有包的 Markdown 资源必须从入口沿本地链接可达。独立上游包可沿原有 CLI、guide ID 或自身索引选择资源，不强制改成一份静态目录；已有包内链接仍须真实有效。入口预算和两类包的检查范围见[质量规则](../maintenance/skill-quality.md)。

## 来源双树与两级清单

一个来源单元对应某个 Git 提交内的完整选定目录。父清单 `materials/manifest.tsv` 保存 `project`、`repository`、`ref`、`revision`、`source_root`、`manifest_path`。具体来源和当前版本只在这里维护，文档不再重复固定 SHA 或文件数量。

子清单按来源相对路径记录文件类别和语言、Git mode/blob、原件及对照 SHA-256、运行路径和最后核对依据。字段定义、读取 API 与准确来源根见[材料说明](../../materials/README.md)。

| 内容层 | 保留要求 |
| --- | --- |
| `upstream/<path>` | 选定根全部 Git 文件的原目录、名称、字节和执行位，包括隐藏文件、CRLF、BOM、空文件和 LFS 指针 |
| `zh/<path>` | 同路径适用中文对照；原本完整中文的文件不另复制，清单的 zh 字段为空 |
| 程序、配置和模板 | 保留逻辑、技术标识、协议、业务字符串和可执行语义，按类别翻译适用说明 |
| 机器夹具、资产与法律原文 | 按清单保留原字节，明确不是中文译文 |

来源读取使用 Git 对象，避免 checkout 过滤器或 export 属性改写字节。符号链接、gitlink、不安全路径、跨平台冲突及缺少对象必须明确失败，不能跟随链接或静默漏文件。所选根外的引用不自动扩大收录范围。

非中文和混合文档需要完整翻译自然语言，保留列表、判断、表格、数值、代码、例子与反例。语言和类别逐文件判断，不能因出现一个汉字或文件扩展名就断定无需翻译。为保持工具语义而原样保留的程序或示例须在清单写明，不冒称全文中文化。

中文底稿保留来源名称与语境，不加入本地宿主扩展或裁剪。译文指向没有 zh 副本的中文原件时，改指实际 upstream；范围外链接必要时使用固定 SHA 地址并保留来源语境。来源原件自己的问题不通过改写原件修复。

材料内的 AGENTS.md、SKILL.md、CI 和 hook 不作为当前指令加载，不参与技能发现、安装或来源依赖初始化。维护回放显式复制固定 statechart corpus 到临时目录，调用本项目工具并加载夹具的 `view.mjs` 投影配置；这是明确的测试入口，不是任意来源脚本执行能力，也不运行新 TLC。npm 白名单排除整个 materials，具体回放范围见[验证指南](../maintenance/validation.md#行为与工具检查)。

## 自有技能的运行适配

| 对象 | 运行版约定 |
| --- | --- |
| 语言和内容 | 中文方法完整保留，必要技术标识维持真实拼写 |
| 资源引用 | 自身资源使用包内相对路径，跨技能按名称调用 |
| 方法归属 | 一份完整正文归一个负责技能，不向帮助或编排入口递归复制 |
| 工程方法 | 按任务组合规格、测试、真实运行、原型和形式化分析 |
| 宿主能力 | 使用实际工具，不把未提供的模型、CLI 或子代理接口写成必然存在 |
| 自有脚本 | Node.js 22.14+ 的 `.mjs` / `.js`，保留协议和错误行为 |
| 项目资料 | 按对应领域保存必要事实和证据，复用已有记录与授权 |
| 来源与法律 | 统一由[第三方声明](../../THIRD_PARTY_NOTICES.md)导航，原生法律文本按要求保留 |

运行版经过适配，不能声称其行为与原件完全相同。中文底稿帮助核对信息保留，运行资源落实本项目契约；必要差异进入子清单 `adaptation`。

## 独立上游包的对应与安装

独立运行包保持上游技能粒度，目录与 `name` 使用 `zh-<原技能名>`，保留完整参考、原工具、必要 metadata 和原生法律文本。默认适配限于中文说明、身份、自身引用和真实需要的宿主差异，不强制重组为 dev/ops 流程或重写工具语言。

两个运行根都由安装器动态发现并平铺到 `.agents/skills/<技能名>/`。`upstream-skills` 是选择分组，不建立业务持久化域。详细安装和依赖见[上游独立技能](../usage/upstream-skills.md)。

固定快照的中文静态资料与外部 CLI 的最新响应分别说明。外部工具仍可能返回英文或新版本内容；本地译文不能绕过原有检索、版本与策略检查。具体工具边界以运行入口为准。

## 资料如何进入自有技能

先确定方法负责哪个问题，再选择归属技能。开发方法的当前职责见[开发方法归属](../development/method-ownership.md)，运维方法见[ops 方法归属](../operations/method-ownership.md)。相邻方法通过目标、产物、版本、证据和返回条件协作，不复制资源来消除依赖。

同源变体需要按条件和语义比较；相同文字不一定表示相同用途。合并时保留仍有效的授权、宿主、持久化和失败边界，修复所有调用者。已有业务资料引用真实位置，不借方法迁移改写历史事实。

状态图工具中的解析、投影、反例和报告算法属于运行资源，捕获夹具留在来源材料作维护对照。真实 TLC 求解仍需要 Java/TLC，SVG 渲染仍需要相应渲染器。PR 观察器中的服务地址属于实际查询协议，不能因此假定 GitHub 认证已经具备。

报告来源的适配契约也不等于连接器实现。读取、追踪器、代码仓库、UI 控制和触发能力分别核对，见[报告来源与持续任务](../development/issue-sources.md)。

## 维护与验证

显式同步选择来源、解析最新 ref 并固定 SHA；普通校验与 CI 不联网刷新。预览、准备、补译和应用的命令见[材料同步接口](../../materials/README.md#显式同步预览准备应用)。同一快照重跑应保持幂等，失败保留正式树。

`runtime_paths` 表示当前采用关系，`runtime_reviewed_blob` 表示实际核对过的来源 blob。更新原件后，逐份阅读对应译文和运行适配；确认无需改变也说明理由。完成真实对照及验证后才更新核对依据，删除来源也不自动删除本地方法或许可。

结构、摘要和集合检查能检出遗漏与不一致，不能证明全文忠实或运行方法有效。使用[验证指南](../maintenance/validation.md)选择结构、安装、行为和实际工具检查；单次结果归所属 change，长期规则保留在本页和[开发约束](../maintenance/development-constraints.md)。
