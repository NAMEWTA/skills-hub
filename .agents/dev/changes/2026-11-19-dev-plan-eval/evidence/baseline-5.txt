# 01 提交草稿并持久记录投递结果

**构建什么。** 用户从写信浮层提交已保存的草稿，能看到 SMTP 接受、明确未提交或结果未知。工作台和已开放的 CLI/MCP 提交同一草稿版本时，取得同一业务操作。重启后可按操作查询结果。发件箱列表与核对由任务 02 接入。

**规格来源。** Mail #8 的 M-05 至 M-07，以及「网络事实、发送与持久数据」中的发信、只读与离线、恢复和统一能力条款。[行为规格](../../../../../mail.md#durability)

**被谁阻塞。** 两个切片中无前置任务。真实入口联调需要当前 Vault 的可写草稿和受管附件、可发送账号及 SMTP 认证、Mail 的共享 schema 与 handler。使用既有产物，实施前核实可用性。CLI/MCP 实际入口验收依赖 #6 的目录、能力选择与传输。

**当前进展。** 规划完成。源码入口、基线命令、设计和原型确认版本待实施时核实。先定位草稿保存、SMTP、Vault 写入守卫和写信提交入口，再检查上述前置产物。

### 交接契约与责任

本任务独占提交与显式重试的 handler、投递操作的持久数据及其迁移、SMTP 结果归类。先持久记录操作及本次投递意图，再进入可能被 SMTP 接受的阶段。若进程中断后无法证明未提交，恢复为结果未知。修改正文或收件人产生新草稿版本，旧版本的操作和尝试记录仍可查询。常规重试只能显式发起，且只投递能够证明未提交的收件人。

向任务 02 提供可按 Vault、账号和业务操作定位的持久记录和读取契约，包含草稿及版本关联、稳定 Message-ID、各次尝试、逐收件人结果和可重试范围。保留账号代约束，隔离其他 Vault 和失效账号的响应。Message-ID 仅用于关联。工作台和已开放的外部入口复用同一提交、查询及重试语义。

写信浮层涉及提交反馈、失败修复和结果未知提示。实施时核对原型与确认记录中的对应场景、状态及源码位置，登记版本或指纹。资料缺失时可推进已明确的提交与持久化行为，依赖该体验决定的界面部分待有效依据齐备后验收。[原型](../../../../../prototype/index.html) · [确认记录](../../../../../prototype-review.md) · [在途发送设计](../../../../../design.md)

### 验收

- [ ] 在可写 Vault 从写信浮层提交带受管附件的草稿，同时从已开放的 CLI/MCP 提交同一版本。各入口返回同一业务操作，受控 SMTP 只观察到一次初始投递。重启后查到同一操作及尝试。修改正文或收件人并显式提交时，产生新版本和新操作。
- [ ] 用受控 SMTP 分别验证完整接受、明确未提交和部分接受。只有明确接受的收件人显示已接受。用户显式重试时，服务端只收到已证明未提交的收件人，查询结果保留前后各次尝试。
- [ ] 在 SMTP 可能已接受但响应丢失时，以及明确响应尚未持久化时，分别注入断线或进程终止。重新查询显示结果未知，常规重试排除这些收件人。关闭、超时、重启和重连均不会产生额外 SMTP 投递。任务 02 负责从发件箱进入核对的联验。
- [ ] 在只读 Vault、接收专用账号、Mail 认证不可用或离线时尝试提交，返回对应原因，SMTP 无投递。可写 Vault 离线保存的草稿仍可打开。停用插件后外部能力不可调用，关闭外部工具后工作台仍可使用。切 Vault、关闭或按设计删除在途账号时，迟到响应不会写入另一 Vault 或新账号代。

### 完成证据

在当前检出的隔离 Vault 中，经实际工作台、CLI/MCP 和投递查询入口执行上述场景。保留脱敏的 SMTP 会话次数、逐收件人结果、重启前后查询及界面截图。受控 SMTP 故障场景由实施者新增或复用现有夹具，真实 SMTP 接受另按原实施计划采证。记录运行入口、版本、输入和实际结果于本任务，证据放入变更目录 `evidence/01/`。原计划或环境无法核对的项目记录为待验证。[原实施与采证计划](../../../../../plan.md)

# 02 从发件箱核对投递并恢复处理

**构建什么。** 用户重开发件箱后恢复原选择，可以续编草稿、查看每次投递及逐收件人结果、进入结果未知的核对入口，并删除本地发件记录。服务器 Drafts/Sent 与本机记录分别展示。CLI/MCP 已开放的对应操作与工作台共用 schema 和 handler。

**规格来源。** Mail #8 的 M-02、M-06、M-07，以及「网络事实、发送与持久数据」中的发信、只读与离线、恢复和统一能力条款。[工作台行为](../../../../../mail.md#workspace) · [持久数据契约](../../../../../mail.md#durability)

**被谁阻塞。** [任务 01](01-submit-delivery.md) 须交付已验证的持久投递记录、读取契约和受限重试入口。核对需要任务 01 记录的账号、草稿版本、Message-ID、尝试及逐收件人事实，以恢复详情并判断可重试范围。服务器 Drafts/Sent 展示联调需要已有账号来源与同步读取能力。新格式恢复联验需要 S6b 产出的真实恢复入口，其可用性单独记录，发件箱核心验收可先用符合任务 01 契约的恢复记录夹具执行。

**当前进展。** 规划完成。提交记录与读取契约待任务 01 交付。实施前核实发件箱、草稿续编、服务器目录、本地删除及恢复的现有入口。

### 交接契约与责任

本任务负责发件箱列表、选择恢复、详情、续编和本地删除，以及核对入口与已有同步来源的接入。消费任务 01 的投递事实，使用其 handler 执行用户明确发起的常规重试。核对按原 Vault 和原账号查看可用的本地尝试与服务器 Sent 来源，显示已找到的关联及其来源。相同 Message-ID、查无副本、同步失败或查询范围不完整，均不足以把未知结果改成已接受或可重试。本轮以已有服务器目录读取能力处理核对，远端 Sent APPEND 超出本项范围。

涉及发件箱选择、续编、本机与服务器来源、结果详情、未知核对和本地删除的界面，实施时从原型和确认记录定位对应页面、状态及源码，登记版本或指纹。桌面及 Web 按相同状态、主题和视口核对，缺失或变更的体验依据只影响对应界面行为。[原型](../../../../../prototype/index.html) · [确认记录](../../../../../prototype-review.md)

### 验收

- [ ] 在两个账号中准备本地草稿、带 Bcc 的本地投递记录和服务器 Drafts/Sent 副本。选择一条本地记录后重开发件箱，恢复该选择并可查询每次尝试与逐收件人结果。服务器与本机来源分别可辨，Bcc 仅见于相应私有发件记录，仅密送的邮件可从发件箱找到。
- [ ] 从发件箱续编草稿，确认原账号及可用受管附件仍可使用。修改正文或收件人并保存后，旧投递仍关联原版本，保存和续编均无 SMTP 请求。恢复记录缺少附件字节时，显示待重绑。
- [ ] 打开结果未知的投递并核对，分别验证同账号 Sent 中有相同 Message-ID、没有匹配、服务器不可达，以及另一账号存在同 ID。界面显示原账号可获得的事实和查询限制，未知收件人仍显示结果未知且不可常规重试。对混合结果执行显式重试时，只有已证明未提交的收件人进入 SMTP，详情保留此前尝试。
- [ ] 删除一条本地发件记录，再检查服务器副本及其他本地账号记录，均仍可查询。删除与核对不会产生 SMTP 投递。在只读 Vault 仍可查看缓存及已有结果，本地删除、续编保存和重试均由统一入口拒绝。
- [ ] 将含有已接受、部分接受和结果未知操作的 Huhu 新格式包恢复到目标 Vault，打开详情并重启后再次查询。原有投递事实和尝试可读，从恢复开始到查询结束的 SMTP 投递次数为零。清缓存、重建 FTS 后仍能查询持久操作记录。真实恢复联验由本任务负责，随 S6b 入口就绪执行。

### 完成证据

在隔离 Vault 中经桌面、Web 和已开放的 CLI/MCP 操作，用受控 SMTP 和来源夹具核对尝试详情、部分重试、结果未知和删除的副作用。用任务 01 的实际投递产物串起「响应丢失、重启、发件箱核对」场景，保留脱敏 SMTP 计数及结果截图。真实邮箱的服务器 Drafts/Sent 行为及 S6b 恢复分别保留运行记录。将版本、输入、入口、实际结果及待验证范围记在本任务，证据放入变更目录 `evidence/02/`。[原实施与采证计划](../../../../../plan.md)
