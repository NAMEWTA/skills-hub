# 开发能力地图

名称是可选的技能交接，不表示当前宿主已经安装或暴露了这些能力。单独安装本技能时，仍可使用[完整指南](guide-index.md)和[完整执行方法](workflow/entry.md)回答使用问题、推进可做的工作；专用工具要求以实际环境为准。

| 技能 | 职责与可组合模式 |
| --- | --- |
| `dev-help` | 选择方法、解释调用方式、组织提示词、排查流程偏离 |
| `dev-setup` | 发现真实宿主能力、配置角色模型和推理预算、明确作用域 |
| `dev-workflow` | 从目标选择流程，持续推进到约定交付；包括接续、暂停、长期协调、PR 队列与技能评测 |
| `dev-intake` | 接收不同来源要求，先复述目标与根本问题，区分事实、范围和待决定事项 |
| `dev-grill` | 沿关键产品决定逐轮澄清，只问会改变方案的问题 |
| `dev-spec` | 明确行为、边界、成功条件与必要约束 |
| `dev-plan` | 拆分垂直切片、识别真实依赖、建立可验证的多阶段计划 |
| `dev-sharpen` | 四问深化提示词；没有现成流程时设计一次可审查执行路径 |
| `dev-architecture` | 从调用者用法确定类型、接口、模块与状态所有权，比较不同方案 |
| `dev-parallel` | 切片覆盖、竞速与多候选比较，隔离写入并综合验证 |
| `dev-ui-design` | 产品界面与完整落地页设计，复用实际视觉体系和交互约束 |
| `dev-figma-design` | 在实际设计工具中建立或使用设计变量、组件、变体及响应布局 |
| `dev-build` | 按已确定目标实施，处理新功能、重构、原型、视觉对齐与交付细节 |
| `dev-tdd` | 公共接口上的逐切片红绿循环；缺陷存在低成本本地测试时用回归驱动修复 |
| `dev-debug` | 真实复现、根因定位、修复、回归和运行取证 |
| `dev-guardrails` | 24 条工程原则、类型与接口约束、重复问题治理、可选注释策略 |
| `dev-review` | 规格与工程规范两轴检查、对抗审查、影响范围和有证据的发现 |
| `dev-verify` | 真实入口与副作用验证，创建和维护项目专用验证方法与功能图 |
| `dev-formal-verify` | 选择属性与工具，建立代码映射，检查反例，维护模型与实现一致性 |
| `dev-statechart` | 从模型输出生成中文状态图、规则标记与最短反例，解释边界 |
| `dev-benchmark` | 核验性能数字，控制负载与比较条件，持续实验与取证 |
| `dev-deploy` | 在指定环境交付真实制品，核对服务与业务结果，记录发布和恢复方式 |
| `dev-learn` | 机制导读、教学、通俗复述与相关上下文恢复，帮助接手与二次开发 |
| `dev-why` | 从代码、历史及实际可访问证据追溯设计理由，区分事实、推断与未知 |
| `dev-archive` | 反思交付，更新术语、背景、ADR 与错误经验，处理冲突和过时引用 |
| `dev-writing` | 完整技术写作标准、文档模式、清晰表达、PR 与提交说明 |
| `dev-status` | 回顾本次进展与待决事项，可选字幕视频及基于真实能力的状态界面 |
| `dev-personalize` | 从用户授权的真实工作历史中提炼个人工程方法，并验证技能变化 |
| `dev-issue-setup` | 为项目配置问题分诊、复现修复及可选自动化，核实渠道、路由与权限 |
| `dev-issue-triage` | 分类、去重、路由问题报告，保留原始证据与处理关系 |
| `dev-issue-fix` | 检查已有修复、真实复现、定位修复、再次验证和有授权的交付 |

运行声明要与证据相称。没安装专用技能不证明项目缺少同类能力；先检查既有脚本、验证代码、连接器与知识。形式化、测试、实际操作和静态约束互补，任何单项都不能替用户证明需求本身正确。

完整原则正文见[原则指南](principles/guide-principles.md)，注释处理见[注释审查](principles/comment-review.md)。
