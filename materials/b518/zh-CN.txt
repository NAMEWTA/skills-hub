# 安装 Benny

Benny 作为尚未启用的自动化包随 pstack 提供。插件清单只暴露 pstack 的普通技能根目录；本文件和两个操作文件都不是斜杠技能。

用户通过让 Cursor 读取包内的 `FOR_AGENTS.md` 进入安装流程。引导流程把整个包复制到目标仓库，然后直接读取 `.cursor/automations/benny/skills/setup-benny/SKILL.md` 中的这个文件。

Benny 需要外部配置和两个实际运行的 Cursor 自动化。

用户未明确要求时，不创建或更新自动化。绝不把秘密值写入插件文件、提示词或已提交配置。

## 1. 复制包并启用共享 pstack 技能

询问 Benny 配置和调用内置 `/automate` 技能之前，先完成这一步。

询问哪个仓库将运行自动化。来源包是包含 `FOR_AGENTS.md` 的目录。目标是 `<target-repository>/.cursor/automations/benny/`。

将整个来源包合并到目标：

1. 目标不存在时创建。
2. 把每个来源文件复制到相同相对路径。
3. 保留仅存在于目标的文件。安装或刷新期间绝不删除无关文件。
4. 将用户拥有的配置、功能图和路由图保存在目标之外。绝不覆盖它们。
5. 已有的来源管理文件不同时，检查差异并合并，不丢弃本地编辑。归属不明确时，替换前停止并询问。
6. 验证目标包含 `FOR_AGENTS.md`、这个安装文件、两个操作文件、它们的参考资料以及模板。

如果已经从目标位置读取这个文件，就把复制视为完成，但继续前仍进行相同验证。

把 pstack 加入目标仓库的 `.cursor/settings.json`。文件或 `.cursor` 目录不存在时创建。

将以下条目合并到现有 JSON 或 JSONC：

```json
{
	"plugins": {
		"pstack": { "enabled": true }
	}
}
```

保留所有无关顶层设置和其他插件条目。`plugins.pstack` 已存在时，只修改其 `enabled` 值。文件采用 JSONC 时，保留注释和合法 JSONC 语法。编辑后验证文件。

重新加载目标项目，或启动一个以该项目为根的新智能体。验证以下共享 pstack 技能从项目作用域解析：

- `how`
- `why`
- `tdd`
- `unslop`
- `principle-separate-before-serializing-shared-state`
- `principle-minimize-reader-load`
- `principle-guard-the-context-window`
- `principle-sequence-verifiable-units`
- `principle-fix-root-causes`
- `principle-prove-it-works`

不要把当前会话或用户作用域插件加载的技能算作通过。检查必须证明目标仓库中的新智能体通过项目设置获得 pstack。

项目作用域插件安装不可用，或任一共享依赖无法解析时，停止并解释失败。

Benny 文件直接从 `.cursor/automations/benny/` 读取。不要把该目录加入插件清单，也不要期待其中 `SKILL.md` 文件出现在斜杠技能列表。

告诉用户，启用任一自动化前，必须提交 `.cursor/settings.json`、`.cursor/automations/benny/` 以及所有被引用且不含秘密的配置。除非用户要求，不要替他们提交。

这项检查通过后，实际运行的自动化提示词才可以使用稳定的仓库相对路径读取已提交操作文件。不得嵌入插件缓存路径，也不得复制文件内容。

## 2. 适配配置

打开以下已复制示例：

- `../../templates/configuration.example.yaml`
- `../reproduce-and-fix-issues/references/feature-map.example.md`

在 `.cursor/automations/benny/` 之外创建用户拥有的副本。它们是配置文件，不是包文件。示例位置：

- 项目配置，例如 `.cursor/benny/configuration.yaml`
- 项目功能图，例如 `.cursor/benny/feature-map.md`
- 项目路由图，例如 `.cursor/benny/routing.md`
- 用户配置，例如 `~/.config/benny/configuration.yaml`
- 用户功能图，例如 `~/.config/benny/feature-map.md`

自动化可能复现的每个面向用户功能，都填写一个功能图章节。保持用户视角，不把实现细节或当前代码路径固定进图中。

不要编辑复制来的示例。刷新包可以在审阅冲突后更新来源管理文件，但绝不触碰用户拥有的副本。

新自动化检出需要读取时，优先使用目标仓库中已提交且不含秘密的文件；否则将所需值转述进实际提示词。只有内置 `/automate` 技能确认文件已提交到自动化运行的同一仓库后，才引用该仓库文件。

已提交包文件和配置文件使用稳定的仓库相对路径。实际运行的自动化绝不引用插件源目录或插件缓存路径。

## 3. 填写必需选择

询问或确认：

- 来源 Slack 频道 ID
- 可选运维或状态频道 ID
- 仓库 URL 与默认分支
- 分诊身份或 Slack 用户 ID
- 问题跟踪器类型、团队、项目、标签及收件状态
- 跟踪器适配技能或 MCP 动作
- 可选路由图路径
- 必需控制技能名称
- 必需的用户视角功能图路径
- 状态表情字符串
- 拉取请求 URL 格式
- 轮询与工作量预算
- 分诊、复现、代码工作与媒体审阅的模型标识

只使用用户 Cursor 模型选择器或支持模型列表实际展示的标识。不猜测标识，也不沿用私有默认值。

来源频道、分诊身份、仓库、跟踪器适配器、控制技能与功能图必须明确。任一必需值仍有歧义时，安装失败。

保存前，用 pstack 的 `unslop` 技能处理最终自动化名称、描述与提示词转接层。

## 4. 检查集成能力

分诊自动化需要：

- 配置的来源 Slack 频道及讨论串读取权限
- 该频道中的讨论串回复权限
- 报告含媒体时所需的附件元数据与文件下载权限
- 通过配置的问题跟踪器适配器搜索、读取、创建及更新的权限

复现自动化需要：

- 来源讨论串读取权限
- 来源频道中的讨论串回复权限
- 配置的运维频道中可选的发布与编辑权限
- 仓库读取与历史访问
- 能创建草稿拉取请求的动作
- 配置的控制适配技能

读写优先使用配置的 Cursor Slack 动作。可选 `BENNY_SLACK_BOT_TOKEN` 可弥补一个狭窄缺口，例如编辑一条运维状态消息或下载附件。令牌值保存在密钥管理器或环境中，不放 YAML。

不要使用未记录的集成端点。

## 5. 准备路由图

用户希望转交或提醒负责人时：

1. 将 `../triage-issue-reports/references/routing.example.md` 复制到 `.cursor/automations/benny/` 之外。
2. 将每个占位值替换为公开或组织内部的值。
3. 默认关闭负责人提醒。
4. 只有配置的功能负责人或已确认的可能回归作者才允许被提醒。

没有配置路由图时，分诊可以分类报告，但不能猜测目的地或负责人。

## 6. 验证控制适配器

读取 `../reproduce-and-fix-issues/references/control-adapter.md` 及用户填好的功能图。

确认指定技能能够：

- 启动目标应用
- 通过真实 UI 导航到每个映射功能
- 通过声明的适配器动作操作映射状态
- 检查状态而不强制制造结果
- 捕获截图
- 开始和停止录制
- 清理自己创建的进程与临时数据

缺少任一能力时，保持复现自动化禁用。它必须停止，而不是声称进行了实际上没有完成的复现。

## 7. 准备实际自动化

询问这是首次创建，还是配置已有自动化。

两种路径都读取复制包中的 `../../FOR_AGENTS.md`，作为主要用户意图来源。通过它理解两种触发器、工具、指令、结果和共同规则。

### 首次创建

一次创建一个自动化。

对每个自动化：

1. 阅读对应的已复制提示词模板，作为次要内部来源材料。
2. 将 `FOR_AGENTS.md`、填好的 Benny 配置及模板意图转换为完整自然语言请求。
3. 让实际提示词读取并遵循 `.cursor/automations/benny/` 下准确的已提交操作文件。
4. 使用稳定的仓库相对路径，而非插件源目录或缓存路径。不要把操作文件内容复制进实际提示词。
5. 读取并遵循内置 `automate` 技能。
6. 让 `automate` 发现 Slack 频道、仓库和已连接集成。
7. 让 `automate` 确认复制包及所有引用的配置文件已提交到自动化运行的同一仓库。
8. 让 `automate` 展示草稿表、取得批准、询问是否就绪，并打开 Automations 编辑器。
9. 完成当前自动化的编辑器交接后，再开始下一个。

向 `automate` 提供以下完整分诊意图，值从配置中填写：

- 名称 `benny-triage`。
- 每次运行读取并遵循 `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md`。
- 配置的来源 Slack 频道中每条新的顶层报告都触发。
- 读取触发讨论串，只在该讨论串内回复。
- 使用配置的问题跟踪器集成。
- 分类、检查证据、追踪原因、去重，只为明确新缺陷创建工单。
- 在仅限讨论串的单次结论末尾，附配置的 `[benny:bug]`、`[benny:performance]` 或 `[benny:other]` 标记，以及可选跟踪器 URL。
- 绝不发布来源频道根消息。

完成分诊编辑器交接后，向 `automate` 提供以下完整复现与修复意图：

- 名称 `benny-reproduce`。
- 每次运行读取并遵循 `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md`。
- 由配置的来源 Slack 频道中相同的新顶层报告触发。
- 使用配置的仓库与默认分支。
- 读取来源讨论串，只在该讨论串内回复。
- 包含拉取请求创建和已配置跟踪器、控制适配器、功能图的要求。除非 `automate` 确认同一仓库中存在符合要求的已提交文件，否则转述映射的用户路径和状态。
- 行动前等待可信分诊标记。
- 通过映射的真实 UI 两次复现准确症状，并捕获证据。
- 验证已有修复，不在其上编写改动。
- 仅在确认复现后尝试可选的有边界修复；证据与检查通过时打开草稿拉取请求。
- 绝不发布来源频道根消息。

不要重复 `automate` 对 Slack、仓库、集成、完整性、认证、草稿审阅、批准、就绪与编辑器交接所做的工作。

### 已有自动化

内置 `automate` 技能只能创建。不要用它搜索、检查或更新已有自动化。

完成配置、路由、控制适配器和功能图验证，然后向用户提供下面的简明编辑器清单。

对于已有分诊自动化，更新：

- 名称和描述
- 直接读取 `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md` 的指令
- 新顶层 Slack 报告触发器及来源频道
- Slack 讨论串读取与回复能力
- 问题跟踪器集成
- 转述后的分诊指令、仅限讨论串规则和 Benny 结论标记

对于已有复现自动化，更新：

- 名称和描述
- 直接读取 `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md` 的指令
- 匹配的 Slack 触发器与来源频道
- 仓库和默认分支
- Slack 讨论串读取与回复能力
- 拉取请求动作
- 跟踪器、控制适配器及功能图要求
- 转述后的标记等待、证据、验证及有边界修复指令

请用户直接在各自 Automations 编辑器更新已有自动化。不要创建替代项或重复项。

### 创建边界

绝不调用直接的自动化后端服务或后端自动化工具。绝不使用携带草稿字段的浏览器 URL。绝不构造或打开 Cursor 协议深链接。新自动化唯一的完成路径，是内置 `automate` 技能经过审阅后的 Automations 编辑器交接。

编辑器保存之后，讨论串安全测试通过前，不启用任一自动化。

## 8. 测试讨论串安全

使用测试频道或一份无害测试报告。

测试前，确认目标仓库的 `.cursor/settings.json`、`.cursor/automations/benny/` 和每个被引用且不含秘密的配置文件，都已提交到自动化检出使用的分支。确认两个实际提示词指向它们准确的已提交操作文件。任一检查失败就停止，并告诉用户自动化还不能启用。

验证：

1. 分诊保存根 `thread_ts`，并恰好发送一条作为回复的结论。
2. 结论包含一个配置的标记。
3. 复现只接受配置的分诊身份发出的标记。
4. 复现保持相同、不可变的来源坐标。
5. 没有出现来源频道根消息。
6. 被委派的执行者不能使用任何 Slack 写入动作。
7. 坐标缺失、父消息已删除或预检失败时，不发帖，也不创建跟踪器问题。

全部七项检查通过后，才启用正常流量。
