# 开发技能的方法归属

每份完整方法由一个技能负责。`dev-workflow` 协调任务，`dev-help` 帮助选择，专门技能持有执行方法、模板和工具；按任务调用，不要求每个包独自承担全部阶段。

## 原因与目标

单一归属让方法修改只发生在一处，调用者通过明确的输入、产物和返回条件协作。它保留完整知识，也避免帮助、工作流和各阶段各持一份稍有差别的副本。共享方法仍归某个实际技能，不另建公共方法库或依赖注册表。

## 方法归属

| 负责技能 | 完整职责 | 协作方式 |
| --- | --- | --- |
| `dev-help` | 能力地图、使用指南、提示词与场景配方 | 提供选择与用法，不内嵌执行包 |
| `dev-setup` | 宿主、角色模型、预算、工具和验证配置 | 记录真实环境；目录导航归安装器 |
| `dev-workflow` | 任务路由、工程执行、自主队列、跨日协调和决策证据 | 推进同一任务，集成阶段结果 |
| `dev-handoff` | 开发上下文交接、会话接续、安全暂停 | 保存或核对恢复点后返回原阶段；仅保存不暂停 |
| `dev-intake`、`dev-grill`、`dev-spec`、`dev-plan` | 来源整理、产品澄清、行为规格、垂直切片与多阶段计划 | 分别消除对应不确定性，沿用已经完成的决定 |
| `dev-architecture` | 架构、模块深度、依赖与候选方案 | 接受行为契约，返回接口、取舍及理由 |
| `dev-ui-design` | 设计系统、语义 token、组件与交互规则 | 沿用项目设计约束，不要求 Figma |
| `dev-prototype` | 确认原型、设计证据、版本指纹及探索原型 | 用可操作 HTML 固定体验依据，确认绑定具体版本与范围 |
| `dev-build` | 功能实施、任务图、行为保持重构和界面交付 | 读取规格与适用原型，调用诊断、TDD 或探索方法 |
| `dev-debug` | 缺陷回归、科学诊断与人工复现 | 返回根因、修复和原失败场景证据 |
| `dev-tdd` | 缺陷红绿回归、逐切片测试先行和替身设计 | 按当前任务选择适用方法，不重复两套同目的流程 |
| `dev-benchmark` | 测量、性能修复、单指标迭代和轨迹取证 | 固定负载、版本与基线比较 |
| `dev-guardrails` | 工程原则、类型、注释审查和结构化防错 | 按实际风险选约束，不给其他包复制原则集 |
| `dev-review` | 契约与工程审查、对抗审查、盲测和意见分诊 | 返回有证据的缺陷与残余风险 |
| `dev-verify` | 真实入口验证、项目验证方法、功能图和视觉对照 | 检查实际对象，必要时调用专门验证工具 |
| `dev-formal-verify`、`dev-statechart` | 属性与模型维护；TLA+/TLC 结果图和回放 | 各自保留模型、脚本、模板及工具前提 |
| `dev-deploy` | 指定环境发布、PR 准备/跟进/落地、观察器和工作树审计 | 按授权交付范围执行，核对真实版本和入口 |
| `dev-learn`、`dev-why` | 当前机制讲解；历史理由调查 | 区分现在如何工作与当时为何决定 |
| `dev-archive`、`dev-writing` | 知识维护与 change 收尾；技术和 Agent 文档 | 分别维护归档方法和写作规则 |
| `dev-issue-setup`、`dev-issue-triage`、`dev-issue-fix` | 来源配置与共同协议；分诊；可信交接后的 UI 复现修复 | 阶段间调用，配置包不复制执行包 |
| `dev-parallel`、`dev-personalize`、`dev-status`、`dev-sharpen` | 并行协作、稳定偏好、进展报告、请求深化 | 在当前负责人任务内提供所需结果 |

具体条件和返回结果见[工作流协作路由](../skills/dev/dev-workflow/references/method-handoffs.md)。这里描述职责，不替代完整方法或当前目录发现；可运行 `node install.mjs list --domain dev` 查看实际入口。

## 追踪与变体处理

[资料父清单](../materials/manifest.tsv)导航到逐文件子清单。`runtime_paths` 指向实际采用方法，`runtime_reviewed_blob` 记录最后核对的来源对象。来源、完整对照与运行适配分开维护，当前材料不等于运行版已经更新。

去重前按来源路径、blob、正文和适用条件比较。保留专门方法的授权、宿主、持久化、证据和失败条件；同一来源在同一技能内拆成方法与模板可以有多个映射。来源删除、移出范围、拆分或合并时，先保留旧映射的影响分析，不自动删除运行方法。

历史资源迁移表作为[回归夹具](../tests/fixtures/dev-resource-moves.tsv)保留。它记录过去移除位置及保留资源，用于回归检查；当前归属以运行文件和材料映射为准，新增改动在自己的 change 记录路径变化。

## 安装与执行

安装器按显式选择复制完整包，不自动解析兄弟依赖。完整开发套件可按 dev 领域安装，部分安装在缺少必要方法时说明具体缺口。已有 handoff、prototype 或旧 UI 包的升级步骤见[安装迁移](installation.md#开发交接入口迁移)。

调用者传递目标、阶段、已有产物、代码版本、证据、授权、返回条件，以及适用原型的资源版本和确认范围。被调用者完成后返回原任务；同一未决问题不能在没有新证据时反复转交。没有宿主调用 API 时直接读取实际安装入口，不声称启动了不存在的子代理。

项目中的规格、原型和交接文件保留真实位置，技能资源归属改变不搬动业务记录。

## 防止再次膨胀

材料检查拒绝同一开发来源映射到多个负责技能。包装检查识别长篇完全重复资源，以及仅改 Markdown 目标或空白的复制；回归检查核对方法唯一归属、历史迁移目标和帮助不内嵌执行包。

这些检查不能证明译文忠实或识别所有近义改写。修改后还需对照完整原件和唯一运行正文，核对调用者与返回条件。来源与改造说明统一见[第三方声明](../THIRD_PARTY_NOTICES.md)。
