### 会话接续

**你负责恢复点。读前任轨迹，不重做。**

1. 定位前任轨迹。可能是当前工作区 `agent-transcripts/` 下本地记录（系统提示指出路径；不要跨 `~/.cursor/projects/*/` 搜索，那会越过工作区边界读取其他项目私人聊天）、云智能体地址、已推送分支。先读元数据概览和最后消息，再向前扫描决策点。长记录交子智能体解析，主线程保留压缩时间线，遵循 **principle-guard-the-context-window**。按“子智能体”一节选择推理级别与快速或标准速度。
2. 重建操作状态。分支与工作树、已落地内容（`git log`、对基础分支的 `git diff`）、开放待办、已有决策。前任轨迹是权威输入，抵抗重新推导的偏见。
3. 比较完成与待办。对照计划和交付，指出恢复点，不重跑前任复现、不重做已完成工作。“让我从头验证”意味着把权威轨迹当作不可信。
4. 把剩余工作路由到匹配手册，选择结论：继续执行、交付完成的建议、认可或推翻前结论、复盘失败执行。接续手册在此结束，其余由被路由手册负责。
5. 在真实产物上按原始目标验证继承主张，遵循 **principle-prove-it-works**。前任自报通过不是证据。

**回复：** 前任停在哪里，继承和重做了什么（理想情况没有重做），恢复点和结果。
