# 修复根因

调试时修复故障，不只修复故障显现的位置。症状是错误状态变得可见的地方。根因是系统最早做了不该做的事，或没有处理本应处理的状态的位置。

**原因：** 修症状会隐藏证据，故障仍可在其他地方显现。每次这样的修复都会增加理解难度，因为代码如今包含一个没人明确命名的缺陷绕路。

**模式：**
- 先复现。
- 每一步都问“为什么”，直到答案指向代码中的错误决定，而非更早错误的后果。
- 卡住时增加观测。读取真实错误与真实状态，不猜测。
- 问触发症状的状态是否合法。系统可能处于该状态时，无法处理它的代码就是根因，在那里处理状态就是修复。状态本不应存在时，在崩溃位置添加检查是在隐藏缺陷，应寻找是谁产生了状态。防护、重试、吞掉错误、截断数值、丢弃状态，都是常见的掩盖方式。
- 只有重启后才失败时，先怀疑持久化状态，包括配置文件、缓存、锁文件、序列化状态。
- 检查模式，不只检查单个实例。找出具有相同故障的每个位置，并全部修复。
- 一个绕路需要整段注释解释其合理性时，代码就是错的。修代码，不修注释。
- 决定性事实需要深挖才能找到时，提出一种廉价、始终开启的信号，使以后第一眼就能发现它。
