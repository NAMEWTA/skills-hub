# 加速 DeepSeek Harness

把宽泛“更快”请求转为可复现用户路径测量及小型有证据修复。这是指导，不是配额或脚本：广泛调查、跟随实测成本，拒绝无法改善用户真实负载的诱人变化。

## 确定范围及当前权威

阅读 [AGENTS.md](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/AGENTS.md)、[架构](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/docs/architecture.md)、[测试政策](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/docs/testing.md)、[防御模式](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/docs/defensive-patterns/README.md)，及受影响包指令和 Agent Notes。进程、时钟、浏览器测试及异步清理使用 [CI 测试可靠性](../dsh-ci-test-reliability/SKILL.md)。

约定用户可见终点、负载范围、资源约束、可接受轻微行为差异及停止规则。后端与浏览器端到端测量分开：历史迭代器或 Client 折叠快，不证明传输、绘制、滚动或输入响应快。测本地开销时排除模型／网络延迟，并说明排除，不称为完整产品延迟。

检查准确当前基准，不只运行中的检出。研究最终合并差异、负责源码、测试及已解决评审线程；PR 正文可能描述已放弃实现。区分已合并、关闭未合并、被替代、估计及新测证据。[已归档性能流程决定及证据](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/.agents/notes/archived/process/2026-09-06-evidence-driven-performance-skill.md)提供历史线索，不授权重新引入其实现。

## 调查用户路径，再排序候选

广度有益时委派独立领域，要求测量及生产调用点，不要猜测。有用领域包括：

- 配置档冷启动、首次历史读取、当前代重开及可写恢复。
- 多 turn、工具密集历史，大型单条消息／结果，子 Session 列表及反复会话导航。
- 初始历史传输及折叠、浏览器首次可用绘制、加载旧页、滚动、展开工具及激活非活动视图。
- 实时流及重连，包括长活动尝试、交错工具工作、结算、取消及拆除。

变化独立成本驱动量：字节、持久事件、紧凑记录、原始增量、turn、工具、子项及可见 DOM 节点是不同数量。不检查压力对应用户操作，就不把大量微小相同消息称为“真实”。包括典型与尾部负载，但避免无决策价值的组合矩阵。

按观察到的用户延迟、CPU／分配、保留内存、出现频率及置信度排序。每项指出生产消费者、重复工作、预期复杂度、最小可证伪干预及必须稳定的行为。仅可疑循环、未用缓存或大文件，不是瓶颈证据。

## 先建真实合成基准

遵循 [benchmarks/AGENTS.md](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/benchmarks/AGENTS.md)及[性能门禁决定](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/.agents/notes/implemented/testing/2026-09-04-session-open-performance-gate.md)。扩展已有必需通道，不创建竞争校准或报告设施。包本地诊断留负责者旁；跨包必需案例放 `benchmarks/` 中被测用户路径下。

用户授权本地语料检查时，只抽取聚合负载特征。绝不把提示、输出、路径、身份、ID、凭据、录像或可识别片段复制到夹具、日志、截图、PR 或产物。由已审常量生成固定输入；基准不依赖用户主目录、环境仓库、网络服务或私有数据。

实现前记录测量卡：

| 字段 | 必需决定 |
|---|---|
| 用户操作 | 准确动作及外部可观察完成条件 |
| 负载 | 固定维度、分布、构造种子／常量，为何覆盖普通与尾部使用 |
| 入口路径 | 生产调用／组合及构建产物；模拟外部边界 |
| 时钟 | 包含的准备、冷／热状态、计时起止及排除成本 |
| 内存 | 终点可达对象、基线、GC 政策、保留与瞬态上限 |
| 判定 | 原始样本、所选聚合、已校准绝对／比例／内存上限及负控制 |
| 行为 | 负责功能测试／快照及允许轻微差异 |

CPU worker 在普通 Node 下测构建 JavaScript；源码加载器开销及模块解析不是交付路径。浏览器案例经已有测试框架，使用构建产品资产及支持的 `dsh` 配置档。不为测量新增生产导出，不将算法复制成“基准实现”。

冷／进程内存样本使用新子进程及私有临时根。热样本明确保留目标缓存；夹具准备不偷偷预热冷场景。两侧保持相同输入、验证、完成条件及可达输出。解析后丢弃的基线，不能与验证并保留历史相比。

报告全部样本及决定结果的聚合。Node 通道用已有共享时间校准及已审波动余量；不按 CPU 速度缩放字节、计数或无量纲比。手工浏览器诊断不设阈值。必需浏览器性能案例需要显式通道决定，并在真实 CI 浏览器／runner 重复测量后才采用时限；仅 Node 机器倍率不算浏览器校准。预算是源码常量，不是环境覆盖。被测工作与自己拥有的其他 CPU 密集任务串行；参考及候选在可比条件测量。不放宽预算或挑幸运运行隐藏回归。

端到端延迟独立于组件阶段测量。目标对象保持可达时追踪保留内存；瞬态压力通过受限堆完成或适当峰值测量另查。执行更快但无界保留，不自动算赢。

浏览器响应性用真实输入并观察结果 UI 更新。帧／输入测量包括最后卡顿，区分调度计时器与实际输入，限制合成生产者，避免追赶突发创造另一负载。说明是否覆盖首次绘制、滚动、分页、实时更新及已激活但隐藏视图。仅 Node 折叠、假 DOM 或自定义心跳事件不能证明浏览器响应性。

## 证明回归，再删除工作

改生产代码前运行未优化负载。保存命令、修订、运行时／平台、夹具维度、原始测量及判定。缩减失败场景但仍覆盖真实瓶颈，打补丁前排序可证伪假设。用剖析、分配样本、工作计数或阶段时序区分。

值得测试的常见模式，不是自动处方：

- 下游读取保持紧凑表示；消费者只需结算内容或聚合时，避免逐增量对象。
- 识别真实责任归属及信任转换后，才删除重复解析、复制、冻结及验证。同进程有类型借用不授权弱化持久或传输解析。
- 流式转换产物并限制中间状态，不保留每代。用户操作要求时，包含发布、验证及可写就绪义务。
- 只读准备与写入／发布分开，但不把被等待工作移到正确性要求的终点之后。
- 延后非活动视图及折叠细节工作；也测首次激活及保留状态。延后不是删除，视口高亮不是完整虚拟化。
- 稳定身份、缩窄订阅，避免单节点变化使整个历史失效；保留更新顺序及立即事件行为。
- 用合适数据结构替代重复移位、扫描或重建。测完整消费者路径，不只孤立容器操作。
- 仅有明确失效、有限保留、独立等待者取消及释放归属时，才按修订键复用或 singleflight。不为反复基准好看而缓存展开表示。

每次只改一个因果因素。重跑聚焦场景及其端到端父场景。要求负控制：收紧的断言在原实现或受控重引目标成本时失败。宽到回归也通过的阈值不保护；低于已证噪声底的预算也不可靠。

## 保留行为及资源责任

性能测量补充功能证据，不替代。按适用情况运行或增加输出、顺序、分页、流索引、错误、取消、并发及释放的最窄负责测试。保留模型可见／日志等价、已发布代不可变、原子发布、必需验证及可写就绪。不悄悄截历史、跳工具结果或改生命周期语义来达数字。

说明有意轻微可见差异，用负责的无密钥快照验证。产品可见 GUI 变化含必需浏览器证据／GIF。功能预期独立于基准内部；基准断言需足够证据到达真实终点，不要第二套语义测试。

端到端收益消失、典型负载实质回归、复杂度超过小收益，或取消／保留／持久性无法解释测试时，拒绝优化。简记被拒假设，不扩大范围为它辩护。

## 交付有界、可审查结果

长期理由、替代、校准、排除及残余风险按 [Agent Note 规则](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/.agents/notes/README.md)。查相关笔记替代关系，不把性能工作变成全语料文字清理。可复用程序留本技能，场景事实归基准或包负责者。

任务要求堆叠 PR 时，编辑前选择层，使用 GitHub 官方堆叠及独立工作树。每层可合并：基准设施保护已测基线；优化层带修复、功能覆盖及更紧预算。独立瓶颈可用独立堆叠。先在负责层修发现，再向上传播。

应用[推送前检查](../dsh-pre-push-checks/SKILL.md)，只报已执行证据，检查 CI，不假设本地时序证明 runner 稳定。标就绪后按代码及可执行证据评估评审发现；回复理由或修复，解决已处理线程。不因来自机器人就否定报告。

每项总结：负载 → 前后绝对值及比例 → 终点与内存语义 → 行为证据 → 负控制 → 准确检查 → 排除。区分作者报告的历史数字、新本地测量及 CI 证据。按约定场景／修复范围停止；保留简短有序后续列表，不追无关机会。
