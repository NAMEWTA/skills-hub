# 用历史错误与合法场景验证防错方法

逐段对照 pstack 固定版本 `correct` 和本地 `dev-guardrails/references/recurring-corrections.md`。本地入口明示三类触发信号，完整方法区分独立事故与重复报告，按架构、类型、机械检查、行为验证、判断性说明选择。新机制须让真实历史错误或同机制复现失败、合法输入通过，本地和 CI 使用同一命令或核对等价条件。例外与抑制就近记录复核条件，有时效才给期限。结构覆盖后复核可退役的重复指令。[固定来源](https://github.com/cursor/plugins/blob/b7b93c36be9bcc36a74db438e0fd385d660bc559/harness/pstack/claude-code/skills/correct/SKILL.md)

结构和引用检查通过。真实 Codex CLI 0.172.0 在只读隔离项目收到「同类错误已被用户纠正两次，但现有规则被忽略」的分析请求，读取 `dev-guardrails/SKILL.md` 和包含两条独立合成事故的 `notes.md`。输出将根因定位为共享的原始数组入口与被复制的近处示例，建议让 Importer 成为唯一验证者，同时保留合法已验证调用。给出了恢复 A1 错误后拒绝合法字段、恢复 B2 错误后接受空表头的负对照，以及合法字段、合法外部调用、仿造句柄和修改原输入的测试要求。本次验收验证方法选择和证明方案；样例分析未实施产品代码或运行拟议机制。

另外用 Node.js 24.21.0 对最小合成机制运行负对照。恢复 A1 的重复字段检查，合法字段用例失败；恢复 B2 的空表头验证绕过，空表头拒绝用例失败。修正后的路径通过合法字段、空表头拒绝与仿造句柄拒绝三项断言。该演示未进入产品，也未验证真实 CSV 实现或 CI 接线。

在隔离 Node 实验中实现上述最小机制：唯一 prepare 入口逐字段核验、复制并冻结原始列，以 WeakMap 验证交给消费方的句柄。合法双字段和外部已验证句柄通过，原数组随后修改未影响输出；空字段、空数组、原始数组绕过与仿造句柄均被拒绝。此实验验证合成案例的区分能力。
