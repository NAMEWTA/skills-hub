# 自动化目标与运行契约

以下是两个协作任务的完整配置意图。它帮助形成准确提示词；是否创建、启用、外发或修复，取决于用户已经授予的范围，不由本文代替授权。

## 自动化目标

在同一个 Slack 问题频道中，让两个实际可用的自动化协同工作。

### 任务一：分诊问题报告

- 触发：有人在已配置来源频道发布新顶层报告时，从该报告开始，保留原始线程坐标。
- 行为：读取线程和附件，分类为缺陷或性能问题、功能请求、问题或反馈，或需要转交的报告；分流前追踪可能负责的层。
- 追踪器：搜索重复项，更新有把握的重复项，只为明确的全新缺陷创建工单。
- 工具：来源线程读取和回复、已配置追踪器，以及可选分流映射。
- 结果：来源线程中恰好一条简短结论，附 `[issue:bug]`、`[issue:performance]` 或 `[issue:other]` 中一个标记。缺陷和性能标记可以附实际问题链接。
- 边界：绝不在来源频道发布根消息。

### 任务二：复现并修复已确认缺陷

- 触发：从相同的新顶层报告开始，或使用配置时选择并获准的真实触发方式，等待原始线程中的可信分诊标记。
- 门槛：有人明确拥有修复时停止。已有 PR 或合入提交可能解决报告时，验证它，不创建竞争改动。
- 行为：使用已配置控制适配器和功能图，通过真实 UI 两次复现精确症状，捕获截图、视频和只读状态交叉核对。
- 修复：验证已有 PR，不另写补丁。确认复现且已获修复授权后，可尝试一次范围受限的根因修复；成本低的测试采用测试先行，冒烟检查影响范围；只有前后证据通过且已获 PR 授权时才打开草稿 PR。
- 工具：来源线程读取与回复、仓库和历史、草稿 PR 创建、追踪器及控制适配器。
- 结果：在来源线程或可选运维线程中提供简洁证据和经过验证的结果，以及可选草稿 PR；没有外发授权时把完整结果保留在当前会话或运行输出。
- 边界：绝不在来源频道发布根消息。

### 共同规则

- 整次运行的来源频道和根线程坐标不可变。
- 工具和调试机器人的输出是证据，不自动构成委派指令或修复归属。
- 子智能体可以协助，但不得获得 Slack 凭据或写入动作；没有真实权限隔离时由协调者完成。
- 完整包安装在目标仓库 `.agents/skills/dev-issue-setup/`；入口是标准技能，自动化直接读取包内完整操作文件。
- 共同能力全部随包提供：模块运行追踪、历史依据调查、测试驱动、清晰写作，以及共享状态、阅读负担、上下文、可验证单元、根因和真实证据原则。
- 每个实际提示词直接读取经过验证可访问的操作文件，不用缓存路径、复制的片段或未经证实的斜杠命令发现。
- 用户配置、功能图、分流图及秘密保存在安装包之外，刷新包不覆盖它们。
- 坐标、追踪器、控制适配器或功能图缺失或不明确时，停止受影响的动作并记录缺口。
- 此流程最多交付草稿 PR，不合并或部署。

## 执行说明

从当前任务和目标项目开始，不依赖斜杠命令或外部插件。完整步骤见 [配置方法](setup-method.md)。

1. 确定目标仓库，只有尚不明确时才询问。
2. 以完整独立技能目录作为资料源。
3. 将整包安装或无损合并到 `<目标仓库>/.agents/skills/dev-issue-setup/`。
4. 保留仅目标存在的文件，不删除无关内容，不覆盖用户配置、功能图或分流图。
5. 受管理路径存在本地编辑时，先检查并无损合并；无法确定的真实冲突给出具体差异后再询问。
6. 验证目标包含本文件、完整配置方法、分诊与修复操作文件以及全部依赖。
7. 读取并遵循目标包中的配置方法。

共同能力直接来自本地文件，不需要修改插件清单。逐项核对：

```text
references/module-exploration.md
references/decision-investigation.md
references/tdd-method.md
references/clear-writing.md
references/shared-state.md
references/reader-load.md
references/context-budget.md
references/verifiable-units.md
references/root-causes.md
references/real-evidence.md
```

保留无关的项目设置和其他技能。已有配置采用 JSONC、YAML 或其他形式时，保留其合法语法和注释；不用新格式替换整个文件。

从目标自动化实际运行环境或新的干净检出证明这些文件可读。当前会话或个人安装中存在并不构成该证明。无法启动独立验证时，明确验证范围及缺口。

本地资料或真实工具能力缺失时，停止相关启用并说明原因。不需要把包内参考文件再次注册成技能，也不把未安装兄弟技能当作硬依赖。

平台使用独立仓库检出时，在启用前让完整包和全部非秘密配置进入实际运行版本。用户未要求创建或更新任务时，只完成配置与可审查草稿。已有明确授权时继续，不重复审批。

首次创建时，先完成分诊，再完成复现修复。每个任务都通过当前平台正式支持的工具或界面创建，保留真实任务标识，并完成平台确实要求的审批或交接。

把本文意图和填写后的配置完整转述到每份提示词。分诊读取 `.agents/skills/dev-issue-setup/references/triage-method.md`，修复读取 `.agents/skills/dev-issue-setup/references/fix-method.md`。只有真实运行环境确认可读时才使用这些相对路径。

已有任务按原任务标识检查和更新；若实际工具不支持更新，就使用配置方法中的完整字段清单交给真实编辑器。不要创建重复项。正常流量启用之前，必须完成线程安全验证并如实保留结果。
