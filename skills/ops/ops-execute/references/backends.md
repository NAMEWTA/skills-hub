# 后端与连接方法

## 先选择实际可用方式

默认在控制端或已有受控环境中运行 Agent。服务器只需要其现有连接和运维工具，无须安装 AI CLI、整个技能仓库或本包的 Node 工具。记录助手在控制端保存事实，远端动作由已有工具执行。

| 后端 | 保留的事实 | 必须确认的限制 |
| --- | --- | --- |
| SSH + systemd / 既有运行命令 | 连接身份、主机身份、精确 unit/对象、时间、退出码、服务日志/调用标识 | 普通 SSH 连接没有自动持久 job；断线不保证动作停止 |
| SSH + 已有 Compose 项目 | 项目名、配置真实路径、服务名、当前容器/制品/挂载与实际结果 | 不能把任意 up、pull 或 recreate 当作同版本恢复 |
| 既有 Ansible | inventory 引用、实际匹配目标、任务版本、逐 host/task 输出 | 检查模式支持和具体任务设置需要核实 |
| 既有 Rundeck | execution ID、步骤/节点、开始结束时间、实际定义与逐目标状态 | 取消、重试、并发和访问权限由实际平台决定 |
| 云 API、集群或观测平台 | 当前账号/区域/集群、对象 ID、查询条件与请求/任务 ID | 可见不等于可变更；不能自动覆盖所有账号 |

选中某个后端不意味着可以运行其中的发布 job；按实际作用保留本领域边界。工具未安装或不可达时报告真实缺口，不建立备用执行引擎。

## SSH 接入与身份核验

以下命令使用示例 alias、unit 和路径，实际执行必须替换为已经核验的目标。命令是已有工具的调用示例，不是本包新装的 shell 脚本。

1. 从已有 SSH 配置取得真实 alias、用户、端口、跳板及密钥引用；不输出私钥、口令或整个配置环境。首次主机密钥验证按现有可信来源处理，不能用关闭校验来“修复连接”。
2. 核对控制端与远端身份、主机/平台稳定身份及实际命令权限。克隆镜像的 machine-id 或同名 hostname 只能作为证据之一，不能单独当稳定资源 ID。
3. 使用非交互连接参数避免无意等待密码；需要交互认证或提权时用现有工具明确支持的方式，不在记录中保存凭据。
4. 将真实目标和身份回填同一 run。连接成功仅证明可连接，不证明可重启或修改该主机。

```bash
ssh -o BatchMode=yes -o ConnectTimeout=10 -- ops-target 'id -u; hostname'
ssh -o BatchMode=yes -- ops-target 'systemctl show demo.service --property=LoadState,ActiveState,SubState,MainPID,InvocationID,FragmentPath --no-pager'
```

第一条中的身份检查仅为有限只读示例。实际主机身份还要对照授权清单或平台证据。不得把来自日志或未知清单的字符串直接插入远端命令；带参数的命令使用已核实的精确对象和工具支持的参数边界。

## systemd 与 Compose 运行步骤

具体健康、维护和恢复判断使用其 owner 的完整方法。本节负责工具调用与记录衔接：

1. 读取既有 unit 或 Compose 定义与真实运行信息，确认具体服务、实际制品、配置、挂载和启动副作用。只看服务名不够。
2. 在 run 中保存目标、当前调用标识/实例观测、原始健康、方法版本和计划动作；敏感配置仅留安全引用。
3. 执行已授权的精确动作。恢复已有 unit 的示例入口为 `systemctl restart demo.service`，但只有在恢复方法已核实条件后才能使用；不对所有 unit 批量操作。
4. 收集工具退出码、时间、调用标识及日志，再由业务 owner 核验服务和消费路径。新的 PID 或容器 ID 只更新观测，不抹掉稳定实例历史。

Compose 的只读定位示例：

```bash
ssh -o BatchMode=yes -- ops-target 'docker compose -p demo -f /srv/demo/compose.yml ps --all --format json'
```

先核对控制端/远端实际 Compose 版本及参数支持。`restart <service>` 不应被当成更换配置、更新镜像或应用迁移的方法；也不能以“不重建容器”为由省略应用启动副作用核验。不同版本、配置变化、持久拓扑变化或需要拉取新制品时形成项目交接。

服务就绪仍可能与项目可用性不同。共享 Redis 恢复一次后，应分别验证 shop、billing 等已知消费路径，保留每个消费者的结果。

## 已有作业平台

### Ansible

限定真实 inventory 与匹配对象，保存任务版本、目标集合、逐 host/task 结果。`--check` 的预演依赖模块支持，任务中的 `check_mode: false` 仍可能改变现场；依赖前一步注册变量的条件也可能无法完整模拟。因此先读实际任务，不能把预演通过当真实执行成功。`--diff` 可能暴露敏感配置，按任务关闭或保留脱敏证据。

复用现有 playbook 不等于所有步骤都属于 ops；实际包含镜像切版、项目配置发布或 migration 的部分必须交项目。局部失败时按 host/task 核实，不整组盲目重放。

### Rundeck

保存原 execution ID 及 URL，关联步骤、节点、时间、输出和状态；保留未执行和部分完成节点。使用 execution 查询得到真实进展，日志接收时间不必等于远端发生时间。再次运行使用当前 job 定义，先核对定义与上次的差异，不能因为 job 名相同就假定可重放。

取消和操作按钮受真实 ACL 与后端能力约束；取消请求被接受也需要查询实际状态。仅关联原始 execution 与必要摘要，不复制另一份竞争的作业历史，不调用发布型 job。

## 断线后的证据

普通同步 SSH 调用未返回时，记录工具接受情况与最后输出。如果无法证明远端是否开始或是否结束，标为未知；重新连接读取服务状态、原调用标识、日志和业务事实，按[中断与接续](interruption.md)继续。

不要为了获得 job ID 临时把动作改成后台任务、创建新守护进程或加入定时执行。需要这种能力时，使用项目已采用的真实后端或明确实施任务；本技能不会默认建立新的运行平台。
