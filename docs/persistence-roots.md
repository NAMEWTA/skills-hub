# 领域持久化目录与迁移

## 约定

每个技能在源码中的领域目录为 `skills/<domain>/`；安装后仍统一为 `.agents/skills/<domain>-xxx/`，但其长期项目记录落在目标项目的 `.agents/<domain>/`。安装器只安装技能，不自动建立、转移、清空或覆盖用户的知识、配置与部署记录。

```text
.agents/
  skills/                   # 安装的全部技能；不是项目记忆
  dev/
    changes/                 # 需求、规格、进度、验证证据
    notes/                   # 术语、ADR、背景、错误经验、学习导读
    deploy/                  # 环境与发布
    archive/                 # 历史记录
    project/                 # 项目非秘密配置
    context/                 # 模型角色与背景
  system/
    <host>/                  # 按真实设备/主机隔离诊断、清理、代理及配置记录
  <future-domain>/           # 未来新增领域同样独立
```

开发技能不把系统主机记录写到 `.agents/dev/system/`，系统技能也不把运维结果写到 `.agents/dev/`。跨领域任务只读取或引用另一领域的现有记录，不复制维护一份竞争事实；归档仍由相关领域承担。用户明确要求其他位置时遵循本次授权，并在导航中保留真实路径。

根目录的 `AGENTS.md` 保持简短导航，指向代码与各领域的现行知识。既有 `docs/`、部署手册、ADR 等仍可直接引用，避免平行复制。密码、token 与密钥不写入这些 Markdown，只保存真实安全存储的引用。

## 从早期 `.agents/wtadev/` 迁移

这是一次**用户项目资料迁移**，不是安装器升级时的自动副作用。必须先核对旧目录是否存在及是否属于本项目，再执行：

1. 只读清点旧树与目标树；记录原始文件、链接、权限和备份位置，避免泄露凭据。
2. 将旧 `.agents/wtadev/system/<host>/` 中的主机记录对应到 `.agents/system/<host>/`，将 `changes/`、`notes/`、`deploy/`、`archive/`、`project/`、`context/` 对应到 `.agents/dev/` 下的同名子目录。
3. 目标不存在的文件可复制并核对字节；完全相同的文件只保留一份；不同内容必须按语义与证据逐项合并，不允许整个目录覆盖或自动丢弃历史决定。
4. 扫描 `AGENTS.md`、主题索引、规格及文档相对链接，修复引用；按最新代码和实际环境核对现行事实。旧文档仍有历史价值时明确标记，不冒充现况。
5. 验证迁移后的读取、引用、部署信息和资料完整性，保留旧备份。只有用户明确要求且验证通过，才清理原路径。

旧路径只作为迁移输入。项目的后续所有新记录直接使用各领域根目录，避免创建两份现行记忆。

## 执行与验证

技能入口和完整参考应引用当前领域的目标路径。按需建立目录，不为每次小任务创建空模板。源码 CI 的持久化路径校验检查运行技能是否重新写入弃用的 `wtadev` 路径，并检查域内系统路径没有误挂到开发根目录。上游原始材料和历史 Git 发布版本保持原状。
