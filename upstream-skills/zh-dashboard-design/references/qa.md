# QA 检查流程

在向任何人展示设计之前、每次提交 UI 代码之前，都要执行。必须亲自打开并查看每张截图（PNG）；阅读代码不等于看过屏幕。

## 已知总数（先核对数值，再检查像素）

截图能发现布局损坏，却发现不了三个组件一致地显示同一个错误数字。截图检查之前：

1. **准备一小套固定数据**（测试夹具，或应用中使用固定随机种子的示例数据模式），并在仪表盘代码之外算出预期答案：手工计算，或使用不导入业务查询函数的独立脚本。包括周期总量、前一周期总量和涨跌、最繁忙的一天、每份排名列表的第一行及其占比。
2. **独立核对每个组件**，依据它实际渲染的内容而不是共享状态：
   - KPI 指标格：屏幕显示的数字和涨跌差。
   - 图表：在所选周期内求和的绘制系列应等于指标格总量；峰值应对应最繁忙的一天。
   - 表格或排名列表：所有行（包括“其他”）之和应等于总量；第一行及其占比应一致。
   - 所有重复出现数字的工具提示、胶囊标签或说明。
3. **做成不一致时会失败的测试**：Playwright 读取指标格文字、图表数据或 ARIA 标签及表格页脚；或者分别测试为各组件提供数据的 selector。修改查询、日期范围、时区或四舍五入规则后必须重跑。

**完成条件**：每个组件独立地与预期答案一致。随后才进行文字审查、显著性测试以及截图检查。

## 文字审查（少文字）

统计实际渲染屏幕上的完整句子数量，不包括工具提示和空状态。目标为零。

- KPI 下方用于解释数字的一句话 → 移入该指标格的工具提示。
- 一整行洞察句子 → 在数据本身标记问题，并紧邻其操作（components.md → Attention and actions）。
- 图表注释（“坐标轴从 60% 开始”“10 月尚未结束”）→ 让坐标标签和虚线样式表达，其他内容移到工具提示。
- 屏幕允许保留：名称、数字、单位、一到两个词的比较基准（“对比 9 月”“昨天”）、图例标签、按钮动词、一到两个词的状态胶囊。

**完成条件**：完整句子数量为零，或每句保留内容都有书面理由。

## 显著性测试

看完整截图一秒钟（或先把它模糊），记下视线第一、第二、第三落在何处。

- 首先看到屏幕的答案或异常；不能首先看到 Logo、装饰或健康数字。
- 构建流程第一步列出的每一个异常都无需悬停即可发现，并且是它所在卡片里最突出的标记。
- 健康数据保持克制：如果每张卡有超过少数几个醒目标记，就没有真正突出的重点。

**完成条件**：视线落点顺序与问题和异常清单一致。

## 真实数据与感知检查

- 除固定夹具外，还要用真实且杂乱的数据运行：数值为零的日子、巨大异常值、整周为空、最长的姓名、文字最长的语言环境。标记仍能阅读，没有元素溢出。
- 色觉障碍：Chrome DevTools → Rendering → Emulate vision deficiencies（deuteranopia／绿色弱视、protanopia／红色弱视、tritanopia／蓝色弱视、achromatopsia／全色盲）。每个异常仍能找到；不同数据系列还能通过形状或位置区分。
- `prefers-contrast: more` 与强制配色（Windows 高对比度）：异常标记和焦点标记保持可见。
- 使用键盘和屏幕阅读器走过主图表与热力图：焦点明确可见，语音播报每个值时先给上下文（“5-A 班，10 月 28 日，应到 26 人实到 20 人”）。

## 截图流程

- 用 Playwright 驱动真实应用（`npm i -D playwright && npx playwright install chromium`，或者复用机器上已有安装）。设置 `deviceScaleFactor: 2`，以便裁剪图清晰。
- 需要登录的页面：通过应用自身注册 API 创建临时账户、添加网站、启用示例数据或种子数据，并在结束时删除账户。如果注册有按 IP 限速且开发服务器信任 `X-Forwarded-For`，可以为每次运行提供单独的值，否则运行可能悄然落在登录页。
- 检查宽度：**3440**（超宽屏）、**1440**（笔记本）、**375**（手机，整页）。
- 需要截取：每种模式或标签页、选中某指标格、打开日期菜单、自定义日历选到一半（已设置开始日、鼠标悬停）及选完、筛选菜单、打开的手机菜单、空账户、暗色主题、打开的工具提示、执行一次操作（例如“提醒”之后的标记）。
- 使用组件裁剪（`locator.screenshot()` 或 `clip`）判断细节；用整页图判断整体平衡。
- 有疑问时实际测量布局：`getComputedStyle(el).gridTemplateColumns`；手机端检查 `document.documentElement.scrollWidth === innerWidth`。

## 一致性检查（真实可信）

- 同一个数字在任何地方一致：指标格与工具提示、热力图列与指标格、图表峰值与“最繁忙日”、渠道与来源占比、列表总数与圆环／柱状总数。
- 迷你趋势图和主图表覆盖完全相同的日期。
- 基数低于约 5 时不显示红色涨跌；对比时间窗口长度相同，且比较相同已过去时长。
- 不得出现 `NaN`、`Infinity`、`–$0.00`、`−0%`、`1m 60s`、`1 visitors`、`0.0%`。
- 快速切换网站和日期范围：旧数据变淡，没有闪成零，较老响应绝不覆盖新响应。
- 请求失败时，即使仍显示旧数据也要出现一条提示。
- 工具提示和帮助文字必须反映真实情况（刷新间隔、营收实际包含哪些内容）。

## 常见异味清单（发现问题 → 改成什么）

| 异味 | 替代方式 |
|---|---|
| 每个列表行的文字背后都有带色背景块 | 在行底部放 3 px 细条 |
| 用下划线或左边框标记选中指标格 | 柔和的带色填充 + 淡色焦点环 |
| 原生日期输入 | 有范围带及实色端点的弹出式日历 |
| 超宽屏上仍只有一条狭窄的居中内容列 | 启用宽屏模式，增加列数 |
| 标签页或导航横向滚动 | 可缩窄的分段控件；手机端采用菜单网格 |
| 1 → 0 显示红色 −100% | 灰色“之前是 1” |
| 一张卡重复指标格已有的数字 | 删除该卡 |
| 大卡片里只放一个很小的数字 | 折叠进 KPI 卡、工具提示，或直接删除 |
| Y 轴出现随机刻度（2,103） | 整齐刻度（1k、2k）、零基线 |
| 平线末端突然出现尖峰的迷你趋势图 | 裁切至与主图相同的日期范围 |
| 同一东西有两个名字（“Threads”与“Referral”） | 使用一套分类体系，明确来源 |
| 仅有 2–3 个扇区的圆环图却占据主视图 | 用带占比条的排名列表 |
| KPI 卡上有玻璃质感、霓虹渐变、3D 图标，或每张卡都有日期标签 | 克制表面、一个强调色、全局统一日期范围 |
| 每个 KPI 数字下都写一个完整句子 | 涨跌差配单词基准；解释放工具提示 |
| 一整行洞察句子 | 在数据上标记异常，操作紧邻 |
| 热力图里最糟糕的一格最淡 | 分档颜色，并设置暖色“低于目标”档 |
| 每个热力图格子都饱和：整面色墙 | 健康值用浅至中等档位，突出异常 |
| 径向仪表盘或刻度盘 | 子弹图：测量条、目标线、灰色范围 |
| 图标格彩虹配色，每卡一种颜色 | 单色图标方块，仅在有含义时用颜色 |
| 只靠红绿表达状态 | 增加形状、图标或文字，或使用蓝／橙 |
| 紧邻高卡片的一张卡被拉高却有一半空白 | 重组所在行，使卡片信息量相近 |
| 尚未结束的周期显示为红色下降 | 周期结束前用中性“昨天 94%”；不完整柱用虚线 |
| 无数据的账户显示“没有紧急事项” | 引导配置；没有数据不是好消息 |
| 手机上的姓名被截断，头像和标签却保留 | 先去掉装饰，将事实折进第二行 |
| 每张卡重复同一条错误提示 | 在页面级显示一条说明 |

## Tailwind v4 实际遇到的注意事项

- 以 px 写的任意断点（`min-[1800px]:`）与 rem 命名断点之间没有可靠的顺序，可能被 `lg:` 覆盖；应改用 rem（`min-[112.5rem]:`）。
- 类名必须以完整字面量形式出现在源码中；由片段动态拼接的字符串不会生成对应样式。
