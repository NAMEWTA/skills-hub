# 既有 PR 计划原位置（路径未提供）

## CSV 导出与导入

按 `dev-plan` 核对后，沿用 PR1 导出、PR2 导入的两个交付单元。PR1 的验收可以独立完成。PR2 原有的「测试通过」补为从实际导入入口观察到的结果，并由 PR2 验证导出与导入的组合行为。

### PR1 — 导出 CSV

**交付与边界。** 通过产品的导出入口生成 CSV。PR1 负责导出实现、供 PR2 读取的格式契约，以及导出验证。无前置 PR。

**构建。** 按项目已有约定实现导出。在 PR1 原条目记录实际表头与列映射、分隔符、引号与转义规则、编码，以及可供 PR2 复用的导出样例和对应提交。逗号属于标题内容时，解析后仍须保留在同一字段内。

**验收与证据。**

- [ ] 准备两条记录，标题分别为 `台北,車站` 和 `高雄,港口`。通过产品导出入口生成 CSV，再用独立于 PR2 的 CSV 解析器读取。解析得到恰好两条数据记录，每条记录的标题字段与其原始标题逐字一致。
- [ ] 在主干和 PR1 头提交运行同一场景。若主干没有导出入口，记录该事实，以 PR1 头提交的验收结果为准。在 PR1 验证记录中保存提交、操作入口、输入、导出样例及解析断言结果。

### PR2 — 导入 CSV

**交付与边界。** 通过产品的导入入口读取符合 PR1 契约的 CSV。PR2 负责导入实现、导入行为测试及导出到导入的整合验证。

**依赖与构建。** 取得可读取、已验证的 PR1 导出实现、格式契约和样例后，按该契约实现导入。独立 PR 以包含 PR1 的主干为基线，堆叠 PR 以已验证的 PR1 父分支为基线。

**验收与证据。**

- [ ] 将 PR1 实际导出的两条记录导入空的隔离测试环境。通过产品的记录读取入口核对，新增恰好两条记录，标题分别为 `台北,車站` 和 `高雄,港口`，与原始标题逐字一致。
- [ ] 将上述场景加入项目的行为测试。在包含 PR1 的基线和 PR2 头提交使用同一份 CSV 验证。若基线没有导入入口，记录该事实，以 PR2 头提交的验收结果为准。在 PR2 验证记录中保存两项提交、CSV 样例来源、运行入口或命令，以及新增记录数和标题断言的实际结果。
