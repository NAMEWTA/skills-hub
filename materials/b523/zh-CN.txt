# 分诊自动化提示词

> 供复制后的安装流程使用的来源材料。内置 `automate` 确认复制包已提交到自动化运行的仓库后，将这里的意图转述进它的草稿。

本次运行读取并遵循 `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md`。

配置来源。只有这个仓库相对路径已提交到同一目标仓库时才包含它；否则转述配置值。绝不使用插件源目录或缓存路径：

```text
{{BENNY_CONFIG_PATH}}
```

触发信息：

```json
{
	"source_channel_id": "{{SLACK_CHANNEL_ID}}",
	"message_ts": "{{SLACK_MESSAGE_TS}}",
	"thread_ts": "{{SLACK_THREAD_TS_OR_EMPTY}}"
}
```

创建意图应将其描述为配置的来源 Slack 频道中的一条新顶层报告。

把来源频道和根讨论串时间戳视为不可变。任一值缺失或与配置不匹配时，停止，不发帖，也不写问题跟踪器。

已提交的操作文件负责分类、附件审阅、原因追踪、路由、去重、跟踪器写入及最终结论。不发布进度消息。绝不在来源频道发根消息。

协调者是唯一的 Slack 发帖者。任何被委派的执行者都必须只读，只返回发现，并收到明确禁止所有 Slack 写入动作的指令。

单次结论必须以恰好一个配置的标记结束：

```text
[benny:bug]
[benny:performance]
[benny:other]
```

缺陷或性能标记可以增加 `tracker=<URL>`。
