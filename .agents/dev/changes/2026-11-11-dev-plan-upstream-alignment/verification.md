## 原版与修改版的自然任务

使用相同合成库存项目，分别安装 HEAD 原版（cedar）和修改版（birch）的 dev-plan。项目只含一个 JSON 序列化函数、一条 smoke 断言、规格，以及故意包含依赖环和过期完成声明的旧计划。候选只收到自然请求，不知道还有另一版本，不读取本仓库或其他项目。

首次尝试两者都在 180 秒预算内未交付最终回复；修改版还遇到 ephemeral 会话的嵌套代理初始化错误。统一禁用嵌套代理、使用相同推理设置和 300 秒预算后，两者退出 0。实际读取记录表明两者读取了入口、完整切片和现有计划资料；修改版还读取计划核对与多阶段资源。

- [同一请求](planning-request.md)
- [原版输出](cedar-plan.md)
- [修改版首轮输出](birch-plan.md)
- [匿名输出审阅](output-review.md)

两版都识别并修正依赖环、过期进度和测试后置，不能据此宣称修改版整体优于原版。匿名审阅指出：原版部分边界场景更细，修改版接口/命令与往返证据更具体；两者都对未定的导入替换/合并语义处理不足。

据此在计划核对中明确：影响产品行为或数据语义的问题不能仅标“实施假设”就交给实施。后续独立新上下文输出见 [复查](planning-followup.md)：它把该问题列为决策项，仅阻塞确认写入，导出和输入校验仍可开始。该复查支持这一场景，不代表所有产品决定都已可靠处理。

另一个独立自然请求为两个字符串修改：[请求](small-request-request.md)、[输出](small-request.md)。输出为单切片、两文件、已有命令的最小计划，未增加多阶段流程，也未越过只规划授权。
