### 性能问题

**你负责测量叙述。规划、审查、核验数字。** 每个修复关联一次测量，不用读源码替代测量。

1. 用匹配控制技能捕获基线轨迹。用 **性能测量检查** 审核基线和之后每个数字。
2. 用 `模块探索` 为假设建立背景。没有先运行就不宣称性能上限。
   按顺序尝试性能口诀，先便宜的：
   1. 不做它。停止结果无人使用的工作，不只是让它更便宜。
   2. 做，但别再做一次。
   3. 少做。
   4. 晚点做。
   5. 在用户没看时做。
   6. 并发做。
   7. 更便宜地做。

   较早口诀达到目标就停止。
3. 依据轨迹规划修复。跨函数边界先 `架构设计`。委派给配置的性能模型，默认继承当前会话模型。按本包执行支持与当前工具能力选择实际可用的模型、推理能力和速度。审差异，捕获修复后轨迹。
   按 **可验证单元**，每次尝试验证后再试下一次。
4. 解析比较产物，如 JSON 转 sqlite、差异比较。“无结论”或错误界面不是通过，必须指出。
5. PR 引用测量。
6. 交付目标包含 PR 时执行 **PR 交付流程**，否则按当前授权的提交或交付方式收束。

要围绕指标持续改进而非一次性修复，使用持续指标优化（`hillclimb.md`）。

**回复：** 基线数字、修复后数字、变化、产物路径。

相关执行条件、方案比选、记录与工具回退见 [本地执行支持](execution-support.md)；按任务选择完整方法见 [资料索引](method-index.md)。
