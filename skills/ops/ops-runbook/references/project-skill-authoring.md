# 生成项目运维技能

生成内容写给一个冷启动的新会话：它应当能找到真实对象、正确使用既有入口、核对效果并留下记录。不要让下一个 Agent 反向研究才能使用辅助工具。

## 1. 从系统与资料回答事实

先查用户指定范围内的真实资料和入口，只有无法观察且会改变产物的缺口才询问用户。

- **对象：** 项目/环境、稳定资源与实例、共享服务消费范围；目标如何从当前权威清单解析，哪些对象未覆盖。
- **运行前提：** 已有部署、当前制品/有效配置、数据条件、认证引用、窗口和健康基线。运维技能不负责从空环境构建部署。
- **操作入口：** 现有只读命令、监控查询、unit/Compose/runtime 定位和已经核验的维护/恢复方法。先检查项目已有方法，再考虑少量必要辅助。
- **观察：** 可以留存哪些日志/响应/退出码/资源状态，以及实际业务或消费者验证；原始证据保留在哪里。
- **隔离与共享：** 哪些操作只读，哪些影响共享服务/整机；并行执行是否会冲突，谁是唯一变更执行者。

当前基线异常或入口已失效时，先查清问题。调查在授权范围内可继续，应用修复、发布和配置迁移交项目；不要照着损坏基线生成看似成功的操作说明。

## 2. 写入真实项目的技能源

沿用用户指定的项目或私有运维源码仓库，新技能可命名 `ops-shop-health`、`ops-shop-diagnose-dependencies`、`ops-shop-recover-workers`，名称不与通用技能冲突。只有用户明确要求安装时才放进实际宿主发现目录；本次只编写源文件不自动安装全局技能。

采用 [项目技能模板](../assets/project-skill.md) 时替换所有占位符，写准确 `name` 与 `description`。每节基于调查结果：

- **目标与适用范围：** 明确项目、环境、任务、触发与不适用条件，保持聚焦。
- **进入现场：** 真实运维工作根、权威清单/私有资料入口、实际连接引用和项目技能发现方式；不写秘密。
- **前提诊断：** 开始操作前核验目标身份、当前制品/配置、服务状态、认证、共享影响；就绪意味着满足所选使用路径，不只是进程存在。
- **操作方法：** 真实命令/工具、条件分支、预期输出、停止条件和未知情况。检查方法可完全只读；恢复方法通过对应 ops owner 核验现有部署前提，不夹带新制品、扩容、schema 或发布配置变更。
- **执行与记录：** 定位真实可用 `ops-execute`，继承当前 run/子 run，保留实际动作和逐目标结果。缺少 owner 时只分析和报告缺口，不偷偷实现替代执行器。
- **验证：** 证明原用户路径与相关消费者的结果，记录动作和副作用，不只保留最终“绿色”截图。dry-run 的实际副作用需要核验，名字不是保证。
- **清理：** 仅清理验证确实创建的临时状态和自己拥有的连接/进程，不按名称批量杀进程，不停止共享生产服务；证据必须在清理后仍可访问。
- **维护：** 来源 runs、已验证的版本/环境/方法、维护者、失效触发条件和未覆盖分支。

新增辅助脚本用 `.mjs/.js` 并真实运行验证。现有 SSH、数据库客户端、系统运行工具照常使用；不复制别的 ops 技能脚本，也不要求远端安装 Node 或 Agent。

## 3. 建立轻量方法图

项目包含多类运维方法时，用包内短索引列出可识别的能力，先选择实际存在的 3 至 5 项；只有一项任务时无需凑数量。每份方法回答：用户要解决什么、如何定位真实对象、怎样执行/观察、什么最终结果证明完成、条件和例外是什么。

例如项目可以分别拥有健康检查、错误定位、共享依赖验证、同部署 worker 恢复；不能因为模板有四行就虚构四个生产入口。方法图与当前真实系统保持对应，缺少前提时说明不可达原因，不弱化路径以让验证通过。

## 4. 证明一条完整路径

按生成后的说明完成一次：定位目标→前提诊断→执行所选方法→验证实际结果/消费者→记录证据→清理本次临时内容→确认保留的证据仍可访问。

先选择已授权、风险可控的只读路径。已有运维执行证据可以证明其当时范围；回放可证明调查判断，不能证明恢复实际执行。危险路径没有独立授权或合适环境就保留未验证，不为验证技能在生产升级、重启或恢复数据。

隔离环境代替真实环境时，列出替代工具、身份、权限、端口、数据和运行方式，以及真实目标尚未验证的设置。完成一个路径只能证明这个路径，不能声称整个项目或全部恢复分支均已验证。

每次失败迭代都按生成的清理方法处理自己创建的临时内容，保护证据。检查失败后先重新诊断已知状态，再重试有依据的步骤；错误的原说明必须改到正确位置，不能只附上一句“谨慎执行”。

## 5. 提供维护循环

把 [维护方法](maintenance.md) 中适用步骤落实到项目自己的方法索引、重验触发和交付说明。通用包资源若为生成技能独有且运行必需，应放入其自身包；其他 ops 能力仍按名称调用原 owner，不能递归复制方法。

不因为有维护方法就创建定时任务。用户明确要求定期复核时，按现有真实调度与授权接入，说明范围；普通使用按系统变更和实际证据触发复核即可。
