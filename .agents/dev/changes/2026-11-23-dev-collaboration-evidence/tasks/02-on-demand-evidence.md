# 02 统一开发运行取证和验收报告

规格：[路径与生命周期](../plan.md#路径与生命周期)。逐包改动依据见 [dev 审查清单](../evidence-audit.md#dev直接产生取证文件或验收记录)。

交付：dev 的运行原件按 Change、task 和运行隔离在目标项目 `temp/dev/`；一张票的一切验收写同名 `evidences/` Markdown；到达交付终点后由 Change 负责人完成总报告。直接依赖：无；隔离安装联验依赖 [03](03-initialize-temp-ignore.md)。

## 实施范围

1. `dev-verify` 维护取证存储方法、最小报告模板和失败后接续的完整范例，并从入口按需指向包内参考。改功能图、验证包生成与维护，不能只改通用入口却继续生成旧路径说明。单装其他技能时，执行者仍能从其本地方法得到必要输出位置，不把兄弟包变成硬依赖。
2. `dev-plan` 提供任务到报告的同名规则和整合验收安排。删多阶段模板中固定 `evidence/` 路径，覆盖复测通道、PR 媒体及票据模板。实施、审查、Issue、交接、归档、批次、帮助与交付沿用同一任务。更新原来直接写根 `evidence.md` 或允许提交运行原件的指令。出票即创建同名 `.md` 并标「未验证」，按完整文件名核对一一对应，不只比较数量。保持实际门禁、失败判断和输出数据，不为省文件降低取证要求。
3. 对齐调试、TDD、性能、原型/UI、状态回顾和候选比选的捕获样例。说明原始表格/媒体/测试输出进 `temp/dev/`，已确认原型、可重复测试、模型、正式交付物保持原位。编辑控制适配器的输出路径约定，不改变来源、发布与清理授权。
4. `run-tlc.mjs` 要求现有第 3 个输出目录参数；`statechart.mjs`、`render.mjs` 要求现有 `--out`。旧省略形式打印清晰指引并失败，不在模型和输入旁写文件。所有技能用法均传实际目标根的运行路径：例如 `statechart.mjs MODEL.tla --out <run-dir>/chart` 与 `render.mjs <run-dir>/chart/chart.mmd --out <run-dir>/chart/chart.svg`。不按 CWD 猜项目，不加新配置。供维护回放使用的显式隔离输出保持兼容；`check-model.mjs` 和只打印终端的工具可继续不落盘，显式 `--out`/重定向示例使用相同运行目录。保留 Java/TLC 原始退出码、反例、状态图发布和中断清理、不覆盖。新暂存位置与结果同文件系统，不能借默认回落把原件写回跟踪目录。
5. 同步开发流程、Issue 来源、归档和相关帮助；只维护本次受影响的当前调用。已经生成到消费项目的 `dev-verify-<app>` 和本地适配器、旧证据都不处理。

## 验收

- [ ] 在实际安装的隔离项目先复现失败，再接手复验。两轮留下不同的运行目录，只在 `evidences/` 留一份同名报告；总报告在组合验收之后出现。无附件的轻量操作不为模板造目录。仅有 Git 文件时仍理解所证实的事实和重跑方法。
- [ ] 从项目子目录或独立 worktree 调用工具，核对目标根、空格路径、缺输出参数、目标冲突、正常运行、有效反例、工具错误与进程清理；维护状态图回放仍在原隔离边界。工具生成的 Markdown 不进报告目录，模型、正式夹具和已确认原型不误移。
- [ ] 过仓库完整检查与状态图回放，按 [03](03-initialize-temp-ignore.md) 的 Git 隔离消费者检查跟踪边界。无真实浏览器、TLC 或渲染器时明确未验范围，不用回放代替它们。
