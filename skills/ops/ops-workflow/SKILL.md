# 协调服务器与项目运维

先明确用户要处理什么、实际对象和可观察的完成条件，再持续完成已授权的工作。围绕服务器、服务实例、逻辑服务和项目环境建立同一任务的上下文；一个项目可以跨多机，一个服务可以供多个项目使用。

## 开始与选择

读取实际运维工作根的 `.agents/ops/AGENTS.md`、相关现行资料与已有 run；按需读取，不假定宿主会递归加载。不存在导航时核实实际资料位置，不为开始调查编造项目、机器或默认生产目标。

本技能拥有意图识别、任务拆分、方法选择、上下文传递和任务级汇总。完整方法由专门技能维护；调用时携带目标、证据、授权、run 和返回条件。没有专用技能调用 API 时读取真实安装的入口，不把技能名当作已运行的后台代理。

| 当前意图 | 负责技能 | 返回内容 |
| --- | --- | --- |
| 机器承载什么、项目由哪些服务组成、共享服务影响谁 | `ops-inventory` | 已核验身份、关系、来源与未知范围 |
| 指定对象的健康、容量、证书、备份或版本观察 | `ops-inspect` | 带时间、证据与覆盖范围的只读报告 |
| 异常原因、近期变化及允许范围内的处置 | `ops-diagnose` | 假设、支持/反证、影响和下一步 |
| 已明确对象的计划性维护 | `ops-maintain` | 维护前提、实际动作与逐目标验证 |
| 既有部署的运行恢复或兼容数据恢复 | `ops-recover` | 恢复证据、消费者结果与剩余问题 |
| 过去做过什么、查找旧任务或交接 | `ops-history` | 指向原始 run 的事实与未完成事项 |
| 将已验证运维方法整理成项目手册或专属技能 | `ops-runbook` | 适用范围、真实入口、验证与失效条件 |
| 执行、留记录、核实中断或接续执行者 | `ops-execute` | 主 run、步骤、后端任务引用和三维结果 |

按[意图与路由](references/routing.md)选择最小且足够的方法。只问历史不先巡检全网，只要求计划不开始维护，已有目标明确时不重新走初始化。原有专门技能可以直接调用，不需要先经过本入口。

## 推进同一任务

- 由 `ops-execute` 建立或接续主 run；所有内部调用保留对应步骤。已有独立任务才用关联子 run，不为每次技能调用另开一份主记录。
- 目标关系由 `ops-inventory` 核验；不要凭服务名、同机或一条依赖线自行扩大项目归属。协调前按[任务与共享对象](references/coordination.md)检查实际写入对象和消费者。
- 依照专门方法已验证的前提安排动作。依赖图帮助判断影响，不能直接生成万能启停顺序。
- 独立取证可并行；同一共享服务的变更只交一个执行者。传入各自可操作范围，收回逐目标结果，再由主任务负责人汇总。
- 用户补充信息、询问进展或要求继续时，沿用原目标、决定与记录。处理中回答进展后继续；只有明确暂停、取消或改变目标时调整任务。
- 遇到中断，按[接续与结果收束](references/continuation.md)回到原 run，由执行 owner 核实后端任务与现场，不根据聊天摘要重放命令。
- 同范围既有授权持续有效；缺少能力、对象歧义、范围实质扩大或底层平台要求时说明实际缺口，先完成不受影响的部分。

## 保持运维边界

运维针对已有运行定义。项目构建、部署、镜像或二进制切版、应用/中间件升级、制品或部署配置回退、持久拓扑变更与应用 migration，均交项目自己的开发/发布流程。本入口只在 ops run 中整理现场、影响和复验条件，不内部调用其他领域的发布技能，也不生成备用发布器。

恢复、维护和 repair 命令按真实效果判断；未知副作用先核实。对同一 tag、会读取新配置的 restart、夹带数据库升级的 OS 更新，使用负责技能的方法判断，不能凭入口名称放行。

其他领域独立。现有项目配置、发布记录与文档可只读引用；不改其技能、模板、记录格式，不要求安装 dev、system 或 workspace。核心服务器运维不要求存在源码仓库。

需要项目私有运维资料时，按用户选择在真实项目/运维根打开独立 CLI。核实实际 cwd、技能发现规则、可读入口、记录根与关联 run；父会话加载过技能不代表子会话可用。缺少必要 owner 时交付可完成的分析与计划并报告缺口，不临时复制另一套执行方法。

## 交付

用[任务简述](assets/task-brief.md)保留复杂任务必要上下文，用[结果模板](assets/result.md)汇总实际结果；小查询直接在现有步骤记要点。两个模板都是同一 run 的内容，不建立第二套工作流目录或日志。

对照最初目标说明实际动作、各目标结果、证据、未覆盖项和后续归属。区分临时缓解、服务恢复与根因确认；部分失败或未知如实报告。项目交接已经写好不代表项目已经发布，命令退出为零不代表所有消费者健康。

完整资料见[方法索引](references/method-index.md)。
