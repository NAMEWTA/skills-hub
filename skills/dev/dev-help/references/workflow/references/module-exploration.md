# 如何运作

探索代码库，回答“X 如何工作”。以资深工程师接手子系统所需的层次解释架构，足够建立可用心智模型，又不至于像逐行注释源码。

探索者和解释者使用本环境的子智能体能力，默认继承模型。所有调查保持只读，按任务复杂度决定是否并行。工具不可用时由当前智能体按相同分工顺序完成。主线程保留文件指针与结论，不粘贴大块源码。

## 1. 判断复杂度

范围模糊时，说明你的理解并开始探索，用户可以调整方向。

- **简单**（单个模块、小工具、例如“函数 X 怎么工作”的窄问题）：无需探索者。派一位解释者一次完成探索和解释，按 `explainer-brief.md` 构建提示，移除探索发现一节。转到第 4 步。
- **复杂**（跨多个文件或服务的子系统、横切功能、完整架构概览）：转到第 2 步。

拿不准时选简单路径。

## 2. 探索（仅复杂情况）

把问题分成 2 至 4 个角度，每个是子系统的独立切片。在一条消息中派出所有探索者，每位拿到填好角度的 `explorer-brief.md`。

## 3. 综合（仅复杂情况）

全部探索者返回后，派一位解释者，给出 `explainer-brief.md`，填入所有探索发现。

## 4. 展示

展示解释者输出。可以为清晰度或对话背景做轻微编辑，不要大幅重写。

## 输出格式

解释采用 `explainer-brief.md` 定义的章节，删除不适用部分：概览、关键概念、工作机制、代码位置、注意事项。

相关执行条件、方案比选、记录与工具回退见 [本地执行支持](execution-support.md)；按任务选择完整方法见 [资料索引](method-index.md)。
