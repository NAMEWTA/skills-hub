# 01 按文件名登记、查找和替换主机别名

规格：沿用用户确认的「给主机登记为 `01`」和「检查 `01`」两种说法。文件名就是主别名，不另建词汇表、映射表或重定向文件。当前技能区分别名和稳定资源 ID，但未定义按别名保存和读取主机登记的规则。

交付：在指定运维工作根登记主机后，下一次会话可以直接用 `01` 定位 `.agents/ops/registry/01.md`。主机定位或别名变化时直接替换现有登记，始终只保留一份现行文件。

直接依赖：无。

边界：`ops-inventory` 是登记和解析规则的唯一归属；`ops-workflow` 和 `ops-inspect` 等调用入口只负责转交线索和接收核验结果。此票使用隔离工作根，不移动真实运维记录。

当前代码指针：[inventory 入口](../../../../../skills/ops/ops-inventory/SKILL.md)、[运行关系模型](../../../../../skills/ops/ops-inventory/references/runtime-model.md)、[登记模板](../../../../../skills/ops/ops-inventory/assets/registry.md)、[路由方法](../../../../../skills/ops/ops-workflow/references/routing.md)、[inspect 入口](../../../../../skills/ops/ops-inspect/SKILL.md)、[历史查询](../../../../../skills/ops/ops-history/references/history-query.md)。

## 实施要点

- 把 `registry/<别名>.md` 作为按别名查找的唯一路径。别名在工作根内唯一，按字符串保存，保留 `01` 的前导零。接受可移植的单段文件名（小写字母、数字和连字符），排除路径成分、Windows 保留名及大小写冲突。不自动编造编号，也不因未命名就改写已有权威清单。
- 单主机登记包含稳定 `resource_id`、真实主机名、当前连接引用、环境或作用范围、身份核验依据及时间。连接引用沿用既有机制，`01` 不自动成为 SSH 入口或操作授权。已有目标路径指向另一资源、登记内容不全或身份冲突时，不覆盖、不猜、不连接。
- 已核实是同一主机时，直接替换主机名、IP 或连接引用。若本次同时把主别名从 `01` 改为 `edge-01`，直接用 `edge-01.md` 替换 `01.md`，同步仍在使用的链接，不留旧别名副本。若使用者仍称它为 `01`，则替换 `01.md` 的内容。换的是整台机器时，用新 `resource_id`；只有明确指定它承接原别名才替换原路径，历史仍按当时的 ID 查询。
- 精确按当前工作根查找。旧别名被替换后不再作为现行别名命中；明确按旧主机名、稳定 ID 或历史时间查询时仍可走原有核验或历史方法。

## 验收

- [x] 在隔离根登记「这台主机叫 `01`」，只得到 `registry/01.md`，没有按主机名另建文件。新会话仅说「检查 `01`」，workflow 和直接 inspect 两个入口都从登记得到同一稳定资源 ID 和连接引用。
- [x] 针对同一资源更改主机名或 IP，再将别名显式改为 `edge-01`。先验证 `01` 读到新连接定位，再验证仅新路径可作为现行别名命中、活动链接已更新，稳定 ID 与旧 run 快照不变。
- [x] 模拟别名未登记、`01` 被另一资源占用、非法路径及原 IP 被另一机器复用。都不覆盖已登记对象或启动现场动作。经明确指定的新机器承接别名时，新目标用新 ID，旧 run 仍指向旧 ID。

## 完成证据与进度

已完成。单主机登记和替换规则由 `ops-inventory` 维护，workflow 与 inspect 把别名转交它解析，history 按稳定 ID 查询。通过实际安装和新会话回放验证，详见[验证记录](../verification.md)。
