# Mail 离线草稿、附件恢复与投递实施计划

依据 `dev-plan`，将 Mail #8 的 M-06、M-07 和持久数据契约拆成五个可独立验收的行为切片。交付目标是让用户离线续写，在恢复后找回附件，并在发件箱查明每位收件人的投递结果。用户可对有证据表明未提交的收件人发起重试。

本轮交付这份计划，供同一会话后续开发接续。以下验证均为实施时的通过条件。

## 来源与实施起点

行为依据为本会话提供的 `mail.md` 中的「从联系人找到具体邮件」M-06、M-07 和「网络事实、发送与持久数据」。开工时核对当前检出的 `AGENTS.md`、Mail 主计划、`design.md`、`source.md` 中适用的验收项，以及已有草稿库、受管附件存储、SMTP 传输、发件箱和 #6 能力注册。沿用主计划已有切片标识，Mail 新格式子集恢复继续归 `S6b`。下文编号仅用于本计划的依赖引用。

可见交互依据是 `prototype/index.html` 与 `prototype-review.md`。实施时记录采用的版本或内容指纹、确认范围，以及写信浮层、附件待重绑、发件箱选择和投递详情各状态对应的结构、样式、交互位置。按同状态、主题和视口在桌面及 Web 产品中核对。确认资料缺失或内容漂移时，只暂缓依赖该体验决定的界面部分，继续契约和受控故障验证。

离线资料未包含上述引用文件、仓库代码或运行命令。具体代码入口、原型确认范围及命令留待实施时核实。各切片均以模拟账号、邮件、附件和投递结果开发与采证。

## 01 保存并续写离线草稿

**依赖与边界。** 无前置切片。本项负责草稿保存、版本、写信入口及发件箱中的本地草稿选择。提供后续切片消费的稳定草稿标识、版本与账号归属。

**构建。** 在可写 Vault 中保存富文本、发件账号、To/Cc/Bcc、主题和链接。非模态写信浮层支持扩大和还原。有内容时关闭前先保存，保存失败保留编辑器及内容，主动丢弃时才放弃。重开时恢复发件箱选择并可续编。修改正文或收件人产生新版本。保存不依赖邮箱连接或 Mail 密钥可用。工作台和已开放的外部入口复用同一草稿 handler，并在 Engine 边界执行 Vault 写权限检查。

**验收。**

- [ ] 断网且 Mail 密钥不可用时，在可写 Vault 编辑并关闭写信浮层。重启后选中原草稿，核对账号、收件人、主题和富文本，修改正文或收件人后确认版本变更。
- [ ] 注入持久化失败后关闭浮层，原内容仍可编辑。恢复写入后再次关闭可找回最新草稿。显式丢弃未保存修改后，重开可见此前保存的版本。
- [ ] 只读 Vault 能打开已有草稿。工作台、已开放的 CLI/MCP 和后台写入均被拒绝，原 Vault 持久数据保持一致。

## 02 管理草稿附件并恢复本地字节

**依赖与边界。** 依赖 01 的草稿标识、版本和写权限。负责受管附件、引用和待重绑状态，以及写信界面的添加、去重、移除与重绑。恢复包提交归 05。

**构建。** 在可写 Vault 通过受限句柄和流接收附件，持久化草稿引用及实际字节。引用可区分仅有名称或元数据、字节已就绪、缺字节待重绑。写入失败时保留原草稿和已提交的附件。删除引用时保留其他草稿或历史记录仍依赖的字节。为 03 提供发送快照读取能力，为 05 提供恢复和缺件登记能力。

**验收。**

- [ ] 在写信浮层重复添加同一模拟附件，保存、退出并续编，确认去重结果、持久引用和实际字节一致。移除后重开，确认引用已移除，共享同一附件的其他记录仍可读取字节。
- [ ] 用缺字节的草稿夹具打开编辑器，能看到待重绑项。注入重绑失败时原引用及待重绑状态仍可查询。提供有效字节后重启，附件可读，待重绑状态解除。
- [ ] 已开放的外部入口通过受限句柄分段提交模拟大附件。提交任意 Engine 主机路径、向只读 Vault 写入或中途传输失败时，均无可见的半成品附件引用。

## 03 提交同一草稿版本并保留可查询结果

**依赖与边界。** 依赖 01 的草稿版本和 02 的附件读取契约。本项拥有发送 handler、不可变发送快照、投递操作记录、SMTP 结果归类和发件箱基础详情。发送契约一并定义逐收件人证据，04 在其上实现部分结果的操作。

**构建。** 同一 Vault、账号和草稿版本的并发提交原子归并到同一业务操作，工作台与已开放的 CLI/MCP 均可查询。进入可能投递的网络阶段前持久化操作、发送快照和稳定 Message-ID。只有明确 SMTP 接受证据可标为已接受。无法从持久证据判定是否接受时保留「结果未知」。发送前拒绝只读、接收专用账号和缺字节附件，并给出可修复原因。关闭、超时、重启和恢复均不触发重新投递。Message-ID 用于关联核对，投递判定依据 SMTP 证据。

**验收。**

- [ ] 用模拟 SMTP 从工作台和已启用的 CLI/MCP 并发提交同一草稿版本。各入口返回同一操作，夹具只见一次投递；服务端明确接受后，重启仍可在发件箱查到已接受及对应尝试。
- [ ] 在可能接受后丢失最终响应，以及收到接受后本地结果尚未持久化时分别中断。重启查询得到「结果未知」，模拟 SMTP 的发送计数不增加。关闭和超时也验证同一不重投约束。
- [ ] 对只读、接收专用和缺附件字节的草稿显式发送，界面与已开放外部入口均给出对应原因，SMTP 夹具接收零次投递。切 Vault 或停用后，迟到响应无法更新当前工作台或其他账号代的数据。
- [ ] 干净安装时 CLI/MCP 能力默认关闭。显式开启后可独立提交和查询，关闭外部工具后工作台仍可用，停用插件后外部调用返回不可调用。

## 04 从发件箱核对部分成功与未知结果

**依赖与边界。** 依赖 03 已持久化的逐收件人证据、发送快照和操作查询。本项负责逐次投递详情、限定收件人的重试、未知结果核对入口和本地记录删除。复用 03 的结果归类和 SMTP 执行。

**构建。** 发件箱按尝试展示各收件人的已接受、可证明未提交和结果未知。常规重试须由用户发起，服务端依据原操作的逐收件人证据限制重试范围，保留旧尝试和结果。未知项提供核对所需的账号、时间、收件人和 Message-ID，私有发件记录才展示 Bcc。服务器 Drafts/Sent 与本机草稿及投递记录分别展示。删除本地记录后，仍须满足原草稿版本的重复提交约束。实施前用 `design.md` 核对账号删除与在途发送的处置，只暂缓依赖该决定的删除分支。

**验收。**

- [ ] 模拟 A 被接受、B 明确未提交。发件箱显示部分成功。重试时模拟 SMTP 信封只包含 B，A 的接受证据和首次尝试仍可查。经已开放的外部入口显式传入 A 也无法触发重投。
- [ ] 模拟 A 明确未提交，B 进入可能接受阶段后连接中断。重启后可查看两者的不同结果，核对入口显示 B 的关联信息。常规重试只允许 A，查询和打开核对入口均不发信。
- [ ] 重启后恢复发件箱选择，能续编草稿、查看每次投递，区分服务器目录和本机记录。删除本地记录后，服务商记录保持原样，同一已投递草稿版本不会因此再次提交。公开参与者视图不暴露 Bcc。

## 05 在目标 Vault 预检并恢复 Mail 子集（S6b）

**依赖与边界。** 依赖 02 的受管字节和待重绑入口，以及 03 的可恢复操作记录。04 的完整发件箱操作只依赖于最终组合验收。复用既有 Huhu 新格式包入口，核对整 Vault 恢复到新空目录的既有边界。

**构建。** Mail 子集使用带类型和版本的包，在目标 Vault 预检后显式提交。恢复草稿、已发记录、操作状态、仅本地标记、受管附件与非秘密配置。缺字节的附件登记为待重绑。新机通过重新填写密码或 OAuth 重授权建立连接。缓存、游标和连接按既有策略单独重建。恢复提交失败时保持目标已有数据一致。对于预检无法安全解析的身份冲突，停止提交并显示冲突，按现有恢复契约处理。沿用 Huhu 新格式范围。

**验收。**

- [ ] 用模拟包恢复到可写目标 Vault，重启后核对草稿正文、附件字节、已发记录、操作详情、仅本地标记和非秘密配置。缺字节项可重绑。未录入凭据时仍可访问已恢复的本地资料。
- [ ] 用错误类型或版本、无法解析的身份冲突和只读目标验证拒绝。对有效包注入提交失败，确认目标无部分可见记录，目标原数据仍可读。通过现有整 Vault 入口验证新空目录约束。
- [ ] 恢复含已接受、结果未知及无最终结果的在途快照后，依次重启、重连、清缓存、重建 FTS 并执行适用的 Git 同步回归。已接受和未知仍可查询，无法判定的在途结果按 03 的规则处理，SMTP 计数始终为零，草稿与受管附件的唯一副本仍可读。

## 执行顺序与验证证据

同一会话从 01 开始，随后完成 02、03。04 和 05 在各自依赖可用后可以独立推进。共享模型和迁移由 01、02、03 各自维护自己的记录契约，04 复用操作查询和投递能力，05 复用恢复入口。涉及同一 schema、能力注册或迁移序列的改动由接续实施者统一整合。

证据计划存放于本目录 `evidence/<切片>/<场景>/`。在实际验证版本上记录提交或工作树差异、隔离 Vault、故障位置、入口、操作步骤和观察结果。保存适用的桌面和 Web 截图、脱敏的外部调用输出、模拟 SMTP 信封与计数，以及进程重启前后的记录。实施时从仓库核实启动和验证命令，记录命令实际输出。用同一离线续编场景对照主干与交付版本，主干缺少入口时如实记录，其余适用仓库检查按当前项目规则运行。

最终组合验收归 05。在原 Vault 离线保存带附件草稿，经显式发送制造部分成功与未知结果。恢复到目标 Vault 后续编草稿、重绑缺件、核对原操作和每次尝试，通过真实入口验证常规重试只覆盖有未提交证据的收件人，并用模拟 SMTP 计数验证恢复链路没有隐式发送。Mail 主计划另有真实邮箱关闭证据时，按主计划记录实际环境与结果。
