# 并行群体执行

在 Claude Code 中，每个会话在遵循此技能前，先阅读一次 [Claude Code 适配器](../../docs/harness/claude-code.md)。它将 pstack 技能中的 Cursor 名称映射到 Claude Code。

## 开始

启动任何执行者前，建立待办清单，每个阶段一项。

1. 确定任务
2. 扇出
3. 汇总
4. 报告

## 阶段 A：确定任务

1. 陈述完成判据，以及群体必须交还的产物或报告。
2. 选择形态：拆成切片、让 N 位执行者竞赛同一份简报，或两者混用。竞赛或混合形态在派生前声明 `first pass`、`rank all` 或 `best-of`。
3. 从 `~/.cursor/rules/pstack-models.mdc` 的 `swarm workers` 行选执行模型。规则或该行缺失时使用 `grok-4.7-xhigh-fast`。值为 `auto` 或 `inherit-parent` 时省略 `model`，让执行者继承父模型。若 Task 工具拒绝标识，使用默认值并说明；若默认值也被拒绝，采用错误消息中同系列最接近的有效标识。模型竞赛时预先指出每一路的模型。按 **poteto-mode** 技能“子智能体”一节，按任务选择每位子智能体的推理级别和快速或标准速度。
4. 执行者需要写入时，为其分配独立可写输出。验证或测量提交时，每份简报写明精确 SHA。测量简报还要指出方法（样本量、一个样本是什么、顺序）。执行者在结果中记录这两者。

## 阶段 B：扇出

在一条消息中派出全部 N 位执行者，使用 `subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true` 和第 3 步的模型；`auto` 或 `inherit-parent` 时不设置模型。只有执行者需要访问用户电脑上的内容时，才用 `environment: "local"`。

执行者必须从非默认的已推送分支开始时，传入 `cloud_base_branch`。

每份简报都应独立成立，包含目标、范围、精确切片或竞赛分组、如何验证，以及报告内容。报告用 `PASS`、`ISSUES` 或 `BLOCKED` 并附证据。能够证明缺陷的执行者报告 `ISSUES`，列出所有可证明的问题，不只报第一个。

执行者退出时，继续用 N-1 位，并记录退出。

## 阶段 C：汇总

阅读终态结果。结果未记录简报要求的 SHA 和方法时，丢弃该结果并重新派该执行者一次。第二次仍遗漏，则记录覆盖缺口。缺口不算通过。覆盖任务的每个必需切片都要有结果。竞赛任务采用预先声明的选择规则：首个通过、全部排名或择优。不要粘贴原始执行者输出。

## 阶段 D：报告

在聊天中返回一份合并报告，包括结果表、每个问题的一句话摘要、缺口或退出情况，以及使用时的竞赛规则。
