# 网络变更、验收与恢复

## 变更前

记录目标应用与主机、症状、当前客户端和内核版本、有效配置来源、已知可用路径、所选代理组及其叶子。先做最小只读基线，不以出站 IP 的地理标签代替真实链路。

保存本轮将修改对象的原字节、字段、权限、所有者和“原先不存在”。完整配置可能包含凭据，备份只留在私有目录；Windows 核验 ACL，不假定 POSIX 权限命令有效。配置写入前重读，识别并发修改。

任务已经授权的具体改动直接推进。新增破坏性范围或未知数据披露先明确后果。远程网络改变之前必须有独立救援路径；不能切断唯一管理连接。

## 分阶段应用

1. 规则与策略链：只改证实的优先级或选择问题，确认实际请求到达目标叶子。
2. DNS：检查 resolver、节点引导、策略覆盖、fallback 和后缀，确认完整生成结果与内核加载。
3. TUN 与路由：保留原可用系统代理与兼容 stack/MTU，实测后才决定后续迁移。
4. 系统 DNS 与 IPv6：逐网络服务和地址族处理，先证据后改变。
5. 浏览器：只修改明确 Profile，检查安全 DNS、登录与 WebRTC 的实际需要。

每阶段先做实际内核支持的配置检查，再加载、读回、请求验证。上一阶段失败就停在该阶段并恢复，不通过增加另一层修改掩盖失败。不直接写生成文件绕过客户端，不覆盖订阅、节点密码、controller secret、端口或无关用户策略。

## 证据矩阵

| 项目 | 需要观察什么 | 不能据此声称什么 |
| --- | --- | --- |
| 文件保存 | 本轮字段与语法正确 | 内核已加载 |
| 生成配置 | 合并后完整结果正确 | 真实请求已走预期路径 |
| 内核运行 | 活动实例加载正确版本和配置 | 所有应用都遵循它 |
| 应用请求 | 原失败应用实际恢复，规则及最终叶子可定位 | 全机均无旁路 |
| DNS | 解析服务、引导例外、接口与内核路径相符 | AAAA 等于 IPv6 传输 |
| IPv6 | 本机原生与代理远端路径分别验证 | IPv4 成功保证 IPv6 |
| 浏览器 | 实际 Profile 的解析和候选行为 | CLI 与后台服务一致 |
| 节点故障/退出 | 受保护流量按设计阻断或恢复 | 未测试异常也能保证断线安全 |
| 睡眠/切网 | 实际设备切换后重新请求 | 单次在线检查覆盖全部生命周期 |
| 性能 | 相同工作负载下成功率与耗时对照 | 可用空间、国家标签或一次测速代表提升 |

每项用“已观察”“失败”“未验证”说明，附时间、具体目标与证据范围。不要把工具退出码 0 当作整机安全认证。

## 恢复

检测本轮之后的用户修改；发现冲突就停止覆盖并报告差异。只恢复本轮涉及字段、文件权限和原先不存在状态。重新通过实际客户端加载，再用原应用验证原路径恢复。写回文件不等于网络恢复。

持续失败时保留原始故障证据和本轮结果，不无限重试、不降级 TLS、不悄悄直连，也不自动更换 resolver、节点或全机模式。需要新权限或新范围时给出已完成的具体诊断与最小下一步。

## 交付

交付目标、原状态、变更、实际链路、DNS/IPv6/浏览器观察、恢复位置与未验证事项。只提供脱敏摘要，不提交订阅、认证头、Cookie、密钥或完整有效配置。
