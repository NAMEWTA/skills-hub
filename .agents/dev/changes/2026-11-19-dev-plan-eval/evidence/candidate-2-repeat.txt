# `.agents/dev/changes/2026-11-19-mail-draft-delivery/plan.md`

## Mail 离线草稿、附件恢复与投递实施计划

用户可以离线续写带附件的草稿，重启后恢复编辑，并在发件箱查到每次投递的逐收件人结果。部分成功时，只重试有证据表明未提交的收件人。投递结果未知时，用户可以核对，关闭应用、重启、重连和备份恢复均不会再次投递。

本计划采用 `dev-plan`，依据随请求提供的 `mail.md` 全文，覆盖 M-06、M-07，以及「网络事实、发送与持久数据」中的发信、只读与离线、统一能力和 S6b 恢复相关条款。本轮交付计划正文，供同一会话后续实施。离线材料未包含仓库代码、`design.md`、既有 `plan.md`、Issue 快照正文或原型确认记录，因此下文使用行为入口定位工作，文件、符号、命令和确认版本留待实施时核实。

## 顺序与责任

| 切片 | 可独立交付的行为 | 开工依赖与写入边界 |
| --- | --- | --- |
| 01 离线保存并恢复草稿 | 离线关闭写信浮层，重启后从发件箱恢复编辑 | 无前序切片。负责草稿版本、保存与读取、关闭和恢复选择 |
| 02 恢复受管附件 | 重启后恢复附件字节，发现缺失时保留草稿并可重绑 | 01 的草稿版本与保存契约。负责附件存储、引用、受限上传和编辑器附件操作 |
| 03 发送一个草稿版本并查询回执 | 同版本跨入口提交归于同一操作，明确接受后可重启查询 | 01 的提交快照与版本契约。负责发送操作、SMTP 适配与初始发件记录。无附件路径可独立验收，带附件接通依赖 02 的可读字节契约 |
| 04 查部分结果、重试未提交项、核对未知项 | 发件箱逐收件人展示每次尝试，按证据提供不同操作 | 03 的持久操作、SMTP 阶段证据与逐收件人结果。负责重试、核对与发件箱历史交互 |
| 05 恢复 Huhu 新格式邮件子集（S6b） | 预检后恢复草稿、附件和投递历史，打开即可查阅 | 02 的附件引用与重绑契约、04 的完整投递状态及历史契约。负责邮件子集包与目标 Vault 的预检、提交和恢复后验证 |

同一实施者按 **01 → 02 → 03 → 04 → 05** 推进。02 与 03 的无附件路径在 01 后均可开工。共享 schema、迁移序列与能力注册点由同一实施者接续修改，逐片核对工作台与外部调用方。05 承担最终跨切片验证，各片仍须先通过自己的行为验收。

## 01 离线保存并恢复草稿

通过写信浮层录入发件账号、To/Cc/Bcc、主题和富文本链接。有内容时关闭，保存成功后才收起。发件箱可恢复原选择并打开草稿续写。主动丢弃沿用明确的用户操作。草稿及版本归当前 Vault 与来源账号，正文或收件人变化产生新版本。工作台与已开放的 CLI/MCP 走统一 schema 和 handler。

- [ ] 在可写 Vault 断网写信，关闭浮层后终止进程，重启并打开原草稿。发件账号、收件人字段、正文和链接与保存时一致，发件箱可恢复原选择。Mail 密钥暂不可用时复验缓存读取与草稿续写。
- [ ] 注入保存失败。编辑器保持打开、输入可继续编辑、原持久版本可读取。恢复写入后再次关闭可保存。另用临时草稿验证主动丢弃行为。
- [ ] 用只读方式打开同一 Vault。工作台和已开放工具可读已有资料，持久保存、丢弃等写操作被统一拒绝。切 Vault 或停用后，在途回调无法把内容写入新上下文。

## 02 恢复受管附件

从浮层添加、去重和移除附件。重开草稿后，编辑器能区分实际可用的受管字节与仅有名称的附件。外部入口使用有范围限制的句柄和流，Engine 按当前 Vault 校验归属。源文件移动或删除后，已保存的受管副本仍可读取。

- [ ] 重复添加同一附件，再关闭、删除测试源文件并重启。打开草稿时只出现一个对应条目，读出的受管字节与原输入一致。移除后再重启，草稿中该引用消失，共享该字节的其他记录仍可读。
- [ ] 在隔离 Vault 制造附件字节缺失。重开时保留草稿及附件元数据，显示待重绑。重绑后再次重启，字节可用。发送入口在引用缺字节时提示修复并保持待发送内容完整。
- [ ] 从已开放工具经受限句柄上传大附件并重读。提交任意 Engine 主机路径或跨 Vault 句柄时，调用失败且持久附件引用不变。注入保存中断后重开，草稿仍指向可用字节或明确待重绑的条目。

## 03 发送一个草稿版本并查询回执

以 Vault、账号和草稿版本识别提交，同一版本的并发提交原子地取得同一持久操作。发送前保存操作与提交快照，固定收件人、正文、附件和用于关联的 Message-ID。SMTP 层保留逐收件人阶段与事务最终回执。收件人只有在进入提交集合且服务端明确接受邮件事务后才记作已接受。持久化的证据需能区分明确接受、可证明未提交和可能已接受；Message-ID 用于关联。发件箱可查该操作，本机发件记录与服务器 Sent/Drafts 分别展示。

- [ ] 从工作台连点并与已开放 CLI/MCP 同时提交同一版本。调用返回同一操作标识，受控 SMTP 记录一次邮件事务。明确接受后重启，发件箱仍能查到同一回执和收件人结果。改正文或收件人后产生新版本，原操作仍可查。
- [ ] 分别在断网、只读和接收专用账号条件下尝试发送，显示相应原因。恢复网络或切回正常账号后，服务器提交计数仍保持原值，直到用户明确提交。验证 Mail 停用时外部调用被拒绝，单独关闭外部工具时工作台仍可发送。
- [ ] 接入 02 后发送含受管附件的草稿。服务端收到的字节与持久快照一致，缺字节的版本在 SMTP 提交前停住。保存发送操作失败时同样停在提交前。

## 04 查部分结果、重试未提交项、核对未知项

发件箱显示原操作与每次尝试的逐收件人结果，保留私有发件记录里的 Bcc。明确未提交的收件人可由用户发起重试，服务端校验重试集合，并保留原尝试。可能已接受的项显示「结果未知」，提供该次操作的核对入口。可按账号与 Message-ID 查看关联线索，只有获得明确证据才更新相应结论。关闭、超时、重启、重连以及发现无法确认的在途记录时，保留可查状态。支持续编和删除本地记录，续编修改正文或收件人时产生新版本。

- [ ] 受控 SMTP 接受 A、拒绝 B，并明确接受 A 所在的邮件事务。发件箱显示 A 已接受、B 未提交。用户重试后，新尝试的 SMTP 信封只含 B。直接调用重试接口请求加入 A 时，服务器拒绝该请求并保持提交计数。
- [ ] 在 SMTP 接收邮件后丢弃最终回执，再分别模拟超时和进程退出。重启及重连后仍显示「结果未知」，能进入核对，常规重试不包含该收件人，服务器提交计数不增加。另注入明确发生在提交前的失败，验证该收件人仍可重试。覆盖明确回执已抵达但尚未来得及持久化的崩溃窗口。
- [ ] 从发件箱恢复原选择、查看每次尝试、续编并删除测试用本地记录。确认服务器 Sent/Drafts 与本机记录的来源可辨，删除本地记录无远端删除请求，重复查询或重复提交原版本不会因删除历史而重新发信。在途删除的具体呈现及处理按 `design.md` 核实。

## 05 恢复 Huhu 新格式邮件子集（S6b）

使用带类型与版本的 Mail 包，在目标 Vault 预检后提交。恢复草稿、受管附件、已发记录、投递操作与历史、仅本地标记和非秘密配置。缓存、游标和连接重新建立，新机重新填写密码或授权。包中缺失的附件字节指向待重绑。恢复的投递历史直接供发件箱读取，保留已接受、未提交和未知的逐收件人区别。整 Vault 包走新空目录的独立恢复入口。S6b 使用 Huhu 新格式模拟数据。

- [ ] 导出并预检含离线草稿、完整和缺失附件、部分成功与未知记录的包。提交到隔离目标 Vault 后重启，逐项比对内容、附件字节、投递历史和本地标记。补绑缺失字节后可续编。连接凭据需要重新提供，SMTP 提交计数保持为零。
- [ ] 提交不支持的版本、被只读限制的恢复请求，以及预检后目标状态发生变化的请求。核对错误与目标 Vault 状态一致。模拟恢复中断，重新打开目标 Vault 后能够判定是否已生效，重试前先核对，避免重复导入或遗留半套可见引用。
- [ ] 在恢复后的 Vault 清缓存、重建 FTS、重连，并执行项目适用的 Git 同步场景。草稿、唯一附件副本与发件记录仍可读，未知结果仍可核对，SMTP 计数保持不变。

## 实施前核对与证据

- **代码与设计。** 开始实施时定位写信浮层、发件箱、草稿持久化、附件、SMTP、Vault 权限及 #6 能力注册的真实入口，核实仓库命令及既有计划安排。读取 `design.md` 以确认在途操作、账号或记录删除及相关恢复约束。若 SMTP 适配器无法区分收件人回执及事务阶段，03 先验证可取得的证据并补齐该接缝。证据不足的结果保留为未知。
- **体验依据。** 从规格引用的 `prototype/index.html` 和 `prototype-review.md` 核实确认版本、范围和源码位置，定位写信浮层、关闭保存错误、待重绑、发件箱选择、部分成功与未知核对。当前资料缺少这些正文，仅相关可见交互的定稿与比对依赖有效确认。持久化、SMTP 和故障场景可依据书面契约先行。
- **运行证据。** 实施时在项目根核实现有验证命令，按各片场景使用隔离 Vault、模拟账号和受控 SMTP。通过工作台及已开启的真实 CLI/MCP 入口验证，记录操作标识、脱敏后的阶段回执、各收件人结果和服务端提交计数。桌面与 Web 在对应已确认状态、主题及视口记录截图或视频。证据拟存变更目录下的 `evidence/<切片>/<场景>/`，附实际提交或工作树、环境和输入。
- **整合关闭条件。** 05 用同一组数据串验离线保存、重启续写及附件读取、跨入口去重、部分重试、未知核对和恢复后查询。用全接受路径在实际主干与实施版本运行同一可用入口作为回归对照，主干缺少入口时记录差距。项目整体交付仍须核对既有 `plan.md` 要求的真实邮箱、故障、界面和来源证据。受控 SMTP 计数用于证明本计划内的故障与重试行为。

**当前进度。** 已用提供的规格文本核对切片覆盖、依赖与验收归属。当前交付为模拟写入的计划，代码、原型及运行验证均待实施。同一会话获实施授权后，从核实写信与草稿入口并执行 01 开始。
