# 按症状选择首检

本表提供调查问题和反例，不是已经在用户环境验证的根因库。实际项目规则应注明来源 run、适用版本和验证范围；缺少证据不能把“通常如此”提升为结论。

## 主机资源与运行单元

| 症状 | 首检顺序 | 可区分的事实 | 不可直接得出的结论 |
| --- | --- | --- | --- |
| 多服务同时变慢 | 确认是否共机/共依赖→CPU、内存、I/O 与时间线→读取一个代表性失败 | 压力开始时间是否早于业务失败；是否同一资源 | 同时发生不证明所有服务一个根因 |
| 进程退出或重启循环 | 单元退出原因→本次与上次日志→OOM/磁盘/权限→当前制品与配置身份 | 内核 OOM 与应用主动退出不同；PID 变化不是发布证据 | 非零退出不能单靠 restart 解决 |
| 磁盘写入失败 | 相关挂载的空间和 inode→具体路径/卷归属→增长窗口→备份/保留任务 | 空间、inode、只读挂载和配额分别确认 | “磁盘满”不授权全主机清理或删卷 |
| 个别副本异常 | 稳定实例与位置→同版本其他副本→配置/挂载/节点差异→失败日志 | 局部资源与服务整体问题不同 | 不能仅凭一个健康副本宣称完整项目正常 |

首检使用 ops-inspect 的具体只读方法，目标关系使用 ops-inventory；不在本包复制检查工具。

## 依赖与异步消费

| 症状 | 首检顺序 | 候选解释与所需反证 |
| --- | --- | --- |
| API 超时 | 原请求时间与路径→调用链→依赖接收端→连接池/队列和资源 | 上游未发出、网络未到达、接收端拒绝、依赖执行慢是不同故障 |
| worker 运行但无消费 | 队列积压/到达率→实际消费身份/逻辑范围→最近完整消费窗口→worker 日志 | “队列为空”“无新任务”“消费者断连”“处理失败”分别核实 |
| 多项目数据库异常 | 确认是否同一服务→实际逻辑库/schema 消费范围→服务状态与具体请求 | 一份共享服务故障可有关联，单个逻辑库权限异常不自动等于全实例损坏 |
| Redis PING 正常但业务失败 | 原失败命令/键空间或队列范围→权限/容量/持久化/消费链 | PING 不验证所有权限、持久化、业务读写或消费路径 |

不要用探测性生产写入验证业务路径，除非该验证本身已明确授权且对象、清理与影响可控。

## 访问、身份与证书

“甲无法访问乙”先看乙的实际接收记录，而不是只重复核对甲的声明配置。没有请求与请求被拒绝是不同分支；代理、跳板、服务账户和转发可能让接收端看到不同身份。

核对真实到达身份、具体路径、拒绝原因、SNI/证书身份、证书有效期和时间。权限配置修复如涉及项目声明配置或发布流程，交项目处理；不能以排查为由授予宽泛权限或永久放开网络规则。

## 变更与观察缺口

| 发现 | 需要复核 | 后续 |
| --- | --- | --- |
| 维护/发布被怀疑，但发生在异常之后 | 从指标固定首次异常时间，检查时区与讨论时间偏差 | 重新建立时间线，不继续以它为起因 |
| 手工缓解短暂生效后消失 | 是否有声明式控制器或项目自动化重应用配置 | 报告临时性，永久配置修复交项目 |
| 一次重试后恢复 | 同一制品/配置是否真的没变、依赖与时序是否变化 | 记录为有限缓解，不称持久修复 |
| 图表平直但业务明显变化 | 指标来源、旧实例序列、标签、采集延迟和聚合 | 先修正观察结论；监控变更另按授权处理 |
| 无数据 | 查询完整性、权限、目标匹配与采集器 | 缺失不是零错误或健康 |

## 已知原因和责任归属

只从当前项目经核验历史和手册取得“已知原因”、严重度、责任方及恢复窗口。示例频次、通用百分比和其他项目事故编号不能作为本项目经验。

确需项目部署或应用改动时，保留原症状、当前事实、影响和后续运维复验条件，交项目自己的流程；调查本身仍可完成，不要求项目安装另一领域。
