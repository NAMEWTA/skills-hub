# 页面结构与层级

## 概要

每页先给新读者一个简短入口，再展开操作或实现深度。跨包学习与工程材料放在有意设计的 `docs/` 层级下，包约定仍紧邻代码。小规则文件负责独立可搜索的要求，但不以任意碎片化为目标。最后的 Dev Note 将活动工作上下文与上方稳定解释隔开。

## 页面顺序

格式负责者允许时，人工编写、面向人的页面采用此顺序。生成产物可以生成相同入口章节；Agent Notes 和事后复盘保留仓库定义的骨架。

1. YAML 元数据。
2. H1 标题。
3. 双语页面的语言切换。
4. `## Summary`：三到五句解释性文字，陈述读者能做或观察什么、为何关心、主要运行模型及最重要限制。英文包 README 的 Summary 遵守门禁负责的 100 词上限。
5. `## Table of Contents`：链接页面 H2 章节；保持导航用途，不写成描述。
6. 稳定内容，从面向用户的使用，依次到面向开发者的设计和操作细节。
7. 可选 `## Further Exploration`，提供面向新读者的相邻主题链接。
8. 最后的 `## Dev Note`，用于非权威的活动工作上下文。

不要强行为微小的机器负责文件、生成片段，或实际解析器定义了其他头部的格式包装 Summary／Table of Contents。在格式负责处说明例外，而非生成无效输出。包 README 门禁要求 `Model Experience` 和 `Known Limitations and Deferred Work` 是最后两个 H2：`Further Exploration` 放在它们之前，并在限制 H2 内以最后的 `### Dev Note` 收尾。

## 章节递进

每个有实质内容的 H2，先用简短定位段落开头，再放表格、代码或 H3 子节。解释该节主题及与决策有关的要点，不重复完整内容。

页内按读者深度排序：

1. 基本使用：何时选择功能、必需输入、最短安全示例、可观察成功及可能的恢复。
2. 高级使用：配置选择、限制、操作及集成行为。
3. 开发者细节：值得维护的责任归属、生命周期、数据模型、失败、性能、安全及扩展点。

大量开发者细节与最终 Dev Note 折叠到 `<details>` 区块后，章节标题保持可见（机制见 [style.md](style.md)）。

折叠的开发者细节必须在概念层面：总体设计概念、主要组件架构、概略数据流，足以理解包如何工作；再加源码地图表和准确细节的代码链接。绝不变成穷尽目录：不放完整 API 清单、列清单、事件负载枚举或 JSDoc 重述。只有 Dev Note 可以放不完整想法、草稿及未定方向；其他所有内容，包括折叠区，都是打磨后的现状文字。

穷尽的生成类型、模式或目录，放在紧凑入口段落及稳定索引之后。一次查找必须扫描无关分组时，按已有领域负责者拆分。

## 文档层级

包约定使用包内 README，保持紧邻源码。跨包 Markdown 按受众及学习意图组织，不让无关页面平铺在 `docs/`。

```text
docs/
  learn/
    overview/
    cordis/
    practices/
  user/
  developer/
    discussion/
  scratch/
  subsystems/
```

这是目标地图，不是顺便大搬迁的许可。一次移动一个连贯主题，原子地修复每个入链及网站映射，保留公开路由或别名；`subsystems/` 保持平铺，因为页面逻辑平行。

`docs/scratch/` 包含受跟踪、有期限、必须在交接后保留的讨论。每页指明拥有者、创建日期、过期时间及晋升目标。本地一次性笔记继续忽略且不提交。

## 小规则文件

独立可搜索的规则、实践、示例家族或决定，如果有自己的拥有者、变更节奏、入链或验证，就给一个小文件。相关文件按描述性层级分组，例如 `docs/developer/code-quality/`。拆分会迫使读者打开多个文件才能理解同一义务时，将紧密耦合的规则留在一起。

索引页用三到五句话解释目录，按用途链接直接子项，不重述每个子项的规则。

## 进一步探索

此可选章节面向读完本页、希望了解相邻知识的新读者。链接三到七个直接相关页面，从最近的前置知识到深入探索排序，每项用短语说明补充什么。不要变成完整站点索引。

## 开发笔记归属

人工页面以 Dev Note 结尾，但明确其非权威性。活动假设、兼容性顾虑、粗略备选、进度指针及未解决问题可以放这里；稳定行为、必需限制和已接受理由归各自常规负责处。

Dev Note 可以镜像或链接任务进度，但不能成为第二个可写队列。工作结束时，晋升持久结论，把可复用理由移入 Agent Note，事故时间线留在事后复盘，删除已解决的讨论。Git 历史保留旧迭代。

## 开发笔记

必需的最后一节有意是人工页面中最不精致的部分，但仍有生命周期纪律。空 Dev Note 写 `None.`，而非积累占位文字；生成格式及解析器负责格式可通过具名例外省略。
