## worker 执行约定

1. 先读本任务指定的 topic 和 manifest，核对实际服务端、共享根、真实 pane ID 与当前任务文件名。任务身份是“共享根 + pane_id + task”。manifest 只有 `pane_id/task/status` 三列；`active` 包含待启动、执行中和待审，`done` 表示 Lead 已验收，`blocked` 表示停止推进。
2. 先检查准确的报告路径。已有身份匹配的终稿报告时只回告其绝对路径，不重跑；已有报告身份不符时停止并在终端说明。没有终稿时，只有身份相符、manifest 当前行指向本任务且状态为 `active` 才执行。旧指针、pane 不符或其他状态都交回 Lead，不自行修改清单。
3. 同一 pane 一次只做一项任务。若已在执行同一任务，重复提示不启动第二份执行。上下文丢失时先核对已有产物和实际状态；不因没有报告就认定先前动作没有发生。无法确认旧执行者停止或动作结果时交回 Lead。
4. 仅在上述业务范围内写产物。协作记录中只写自己的报告执行部分及同目录临时稿；不改 topic、manifest、task、他人报告或 Lead 验收部分。不修改当前任务指针，不自行领取下一任务。
5. 执行所要求的验证，用下面的完整格式写报告。任务完成填 `done`；无法继续填 `blocked`，说明已完成部分、阻碍与继续所需条件。不要把 Herdr 的 `idle/done` 当成任务或验证结果。
6. 先把完整报告写入同目录临时文件，核对任务身份和内容，再重命名成指定 report 终稿；已有终稿不得覆盖。提交后停止写报告，仅在终端回告报告绝对路径。不得自动开始下一任务；补充、返工或解除阻塞由 Lead 发布下一编号 task。
7. 如果无法读取必要文件、核对身份或写入报告，在终端明确说明任务绝对路径、失败原因和已有产物；不要声称已提交报告。提交失败后先检查终稿与实际结果，不盲目重跑业务动作。
