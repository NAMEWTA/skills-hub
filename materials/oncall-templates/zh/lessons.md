## 条目格式——三种

**事件条目**（默认——已解决事件或被否定的假设）：

```
## {{date}} · {{一句话标题}} · #{{failure-class-tag}} · {{INC-nnn 或讨论串链接}}
- What happened: {{新读者能理解的一句话}}
- Root cause: {{机制，附证据链接}}
- Fix: {{什么解决了它，由谁决定}}
- Gotcha / rule: {{可复用经验——本文件存在的理由}}
```

**调查条目**（冗长或无结论、但值得保留轨迹的调查——让未来会话不再
重复走同一批死路）：

```
## {{date}} · Investigation: {{调查内容}} · #{{tag}} · {{讨论串链接}}
| step | result |
|---|---|
| {{执行的检查}} | {{✅/❌ + 链接}} |
- Checked out on paper: {{所有理论上应使其正常工作的条件，每项都已核实 ✅——
  这是宣布“无法解释”前的标志性动作}}
- Could not verify: {{什么、为什么，以及负责人应执行的确切单行命令——
  交给人员一条 grep，不要交给他一个谜}}
- Rabbit holes eliminated: {{假设 → 排除它的证据}}
- Confidence: {{约 N%，并明确指出剩余百分比是什么}}
```

**GOTCHA 单行**（工具或环境意外，不是事件）：

```
- GOTCHA（{{date}}）：{{意外，以及它意味着的规则——一行}}
```

## 升格

一个标签累计了**同一机制的 3 个条目**，或者一条记录从故事变成了
*流程*（一个陌生读者也能直接照做的检查表）时，通过 PR 把它提升到
对应类别的参考文件（CLAUDE.md 规则 9），并用一行指针替换这些条目。
升格本身也记录成条目——参考文件的出处会指回这里。

## 2026-06-30 · 示例：read-mode 开关让已退役跳过规则重新出现 · #test-failures · INC-example
- What happened: 加载器的 read-mode 开关变化后，本应运行的测试被悄悄跳过；
  流水线绿色，但已执行测试数量下降。
- Root cause: 双读模式从次级存储带出了 44 条陈旧规则
  （证据：已执行集合差异、开关变更时间）。
- Fix: 回退 read-mode 开关；约 20 分钟后执行数量恢复。
  回退经人员批准，由队友执行。
- Gotcha / rule: *绿色*流水线却执行越来越少的测试，是覆盖事故，
  不是平静的一天。简报现在追踪已执行测试数量。

## 2026-06-14 · 示例：根据配置推演，而没有检查指标 · #process · thread-link
- What happened: 花了一小时研究一个看起来合理、却没有指标支持的配置假说。
- Root cause: 先审查配置，后查看数据。
- Fix: 不适用（流程经验）。
- Gotcha / rule: 先查数据，再提出理论。配置说明什么*可能*出问题；
  指标说明什么*实际*发生了。（已提升为 CLAUDE.md 规则 5。）

- GOTCHA（2026-06-08，示例）：团队代码搜索工具会悄悄把包含多字节 UTF-8 的
  文件当成二进制，不返回匹配——因此在并不存在的“代码被回退”问题上浪费一小时。
  当证据显示不可能的事情时，先怀疑测量工具。
