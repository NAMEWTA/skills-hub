# 技能维护与上游同步约束

## 项目定位

本项目把 Matt Pocock 与 pstack 的成熟工程方法完整复制、中文化并融合为可组合的开发技能。维护目标是让用户和 Agent 更容易选择和完成任务。优先保留已经经过实践的步骤、判断标准、例子、反例与工具语义；不以个人表达偏好重写成熟方法，不把“更短”或“技能更少”当成质量本身。

来源与致谢见 [README](../README.md#致谢与许可)；当前来源修订以 [materials/manifest.tsv 父清单](../materials/manifest.tsv)为机器依据，逐文件关系沿其中 manifest_path 进入项目子清单。原件、中文对照与运行适配各有职责，详见[资源组织](resources.md)。

## 允许怎样适配

| 调整对象 | 应做的事 | 必须保留的内容 |
| --- | --- | --- |
| 入口与名称 | 用明确任务、输入、产物和必要前提描述技能，收拢重复主入口 | 专门方法的独特适用条件和完成标准 |
| 流程融合 | 统一当前路由，将来源完整流程作为条件明确的局部方法 | 访谈、切片、架构、实现、验证、交付和复盘的方法本体 |
| 工具与宿主 | 改成当前实际可用能力，区分通用任务与特定管道 | 专门协议的身份、环境、失败补偿与证据条件 |
| 文档结构 | 把长篇方法、完整表和示例移到包内资源；入口按需直达主方法 | 原文的实质信息，不能用摘要代替完整方法 |
| 持久化 | 开发资料存 `.agents/dev/`，系统维护存 `.agents/system/`；其他领域采用 `.agents/<domain>/` | 已有资料、真实代码引用、历史身份和有效链接 |

以用户指定的 upstream 为标杆，优先复制原有结构、完整翻译并融合。模板的栏目、顺序、步骤、判断标准和例外默认保留；不以个人偏好、篇幅或自行设计的“更好流程”替换它们。只有当前需求、本项目明确规范、真实冲突、工具差异或可复核失败需要时才作必要、少量的适配。逐项指出对应原文、保留内容、修改理由和影响范围，在资料清单或本次维护记录中留据；不扩大用户指定的来源范围；材料的显式主动同步每次解析指定分支最新 SHA，再固定同一次快照完成读取、对照和差异分析，不以普通校验悄悄升级版本。来源更新不自动授权改写全部运行技能。发现矛盾就改掉对应条件，不在开头叠一句覆盖声明后保留相反步骤。

## 谁负责最终结果

完整任务由 `dev-workflow` 协调；阶段已明确时直接使用相应技能。支持方法帮助当前负责人完成结果，不重新开启一套需求、计划或审计记录。

- `intake` 整理来源和目标，`grill` 解决尚未明确的产品决定，`spec` 综合行为契约，`plan` 划分实施单元。已完成的阶段直接沿用。
- `build` 实施明确行为；`tdd` 是显式选择的实现方法；`debug` 处理功能故障；以性能指标为成功条件时由 `benchmark` 负责。
- `learn` 解释当前机制与教学；独立调查具体设计当时的理由使用 `why`；任务决策日志的记录与证据复核由 `workflow` 负责。目标复述归 intake，通俗解释归 learn。
- 输入来源、问题追踪器、代码仓库、复现控制和触发方式分别配置。`issue-setup` 初始化真实适配器与监控条件；`issue-triage` 分类去重但不复现；`issue-fix` 保留可信交接与真实 UI 证据要求。来源不限定 Slack 或 GitHub，来源专用规则按实际平台读取。手工任务不要求后台服务。
- `formal-verify` 选择并维护属性检查；`statechart` 把 TLA+ / TLC 结果变成可审查图。普通流程解释不自动引入模型检查。
- 项目知识与归档由 `archive` 负责，个人稳定偏好由 `personalize` 负责，可执行防错机制由 `guardrails` 负责。
- `status` 汇报真实进展或制作报告视频；带 webhook 的操作面板属于应用实施。`sharpen` 深化请求与方法，完整任务仍由当前执行负责人推进。
- UI 设计统一使用 `dev-ui-design`。设计系统、语义 token、组件状态等方法落实到项目代码，不要求 Figma。

以上是入口归属，不是禁止单个技能调用其他技能。实现遇到缺陷调用 `dev-debug`，需要测试先行调用 `dev-tdd`；总入口通过这些协作完成结果。按当前任务读取负责技能的方法，不复制正文。

## 可移植运行与分发

所有维护脚本、测试、技能执行工具和可运行示例使用 `.mjs` 或 `.js`，以 Node.js 22.14+ 标准库为基础。成熟算法从其他语言迁移时保留输入、输出、退出码、完整例子与错误行为，使用原有夹具和真实调用复核；不以换语言为由缩减功能。原始语言的来源资料在 materials 的 upstream/zh 双树中保留原扩展名、原字节和原执行位，仅为被动对照；不作为运行依赖执行，不安装其依赖、不触发来源 CI/hook。

Git hook 的两个固定入口名称没有扩展名，内容仍为 Node.js 的薄入口；其余实现使用 `.mjs`。Java/TLC 等任务本身所需工具继续作为明确前提，不因此声称 Node 能替代形式化求解器。

npm 分发包只包含实际安装所需文件；每次发布检查真实 tarball 中的完整资源、许可和安装结果。版本、提交、标签及发布内容必须对应，详见[版本发布](release.md)。领域持久化位置及迁移方法见[领域持久化](persistence-roots.md)。

## 入口与渐进式披露

`SKILL.md` 放准确的 `name`、`description`、完成目标、关键约束和“何时读哪一份”的路径。主分支尽量直接链接完整方法；大量支撑例子可以通过短主题索引查找，不为把所有文件堆到入口而制造长目录。

详细流程、表格、反例和脚本说明留在 `references/`，模板放 `assets/`，确定性工具放 `scripts/`。长参考保留清楚标题与目录。按需读取不等于删除知识，也不等于把所有资源一次载入。

正文行数与字符预算由[质量门禁](skill-quality.md)检查。超限时先移动独立细节并补读取条件，再压缩重复表述；不能用合并长行、删验收标准或删例外的方式达标。不同语言的字符数不等于模型 token 数。

## 完整资料与副本

同一方法在开发领域只设一个完整正文归属，相关模式引用它。重叠方法以 pstack 为主线，其他来源保留有独特用途的补充，不并列运行两套同目的流程。帮助保存使用指南，工作流保存协调方法，专门技能保存方法本体。不得沿引用关系递归复制兄弟技能资源。

技能允许相互依赖和调用，不再要求单包自包含全部开发能力。包内资料使用相对链接；跨技能用准确名称调用其入口，读取该技能拥有的完整方法。执行时只调用当前需要的分支，携带目标、当前阶段、产物、证据和返回条件；不能因为安装了依赖就重跑全部阶段。资源仍归属具体技能，不设置另一个公共方法库。

修改方法时，按清单定位其唯一运行归属，再检查调用者的交接条件。新增、合并、移动或删除运行文件后同步映射与入链。完整原件和中文底稿继续保留；归属表与差异审查见 [开发方法归属](dev-method-ownership.md)。

`skills/` 内只放本项目中文执行内容，不出现来源项目、作者、致谢或外部文档跳转。来源与官方规范在仓库文档中说明，版权原文留在仓库与 npm 包的 `licenses/`，技能安装时不向目标项目复制许可目录。materials 选定来源树内自带的 LICENSE/NOTICE 同时原样保留，它们是快照的一部分，不因集中分发许可而被移除、改译；集中 licenses 仍须保留已被运行内容采用的历史适用许可。

## 同步上游的最小过程

六个材料来源仅为 pstack（harness/pstack）、Matt（skills）、DeepSeek（.agents/skills）、设计技能（skills）、Speculo（整仓）、Herdr（skills/herdr）；准确仓库与分支见[资料导航](../materials/README.md#六个准确来源)。不按来源链接擅自扩大范围。源目录按原名/原扩展名保存，pstack 保留 claude-code 层，中文原文不生成重复 zh；无自然语言、法律、机器夹具和资产的对照保持原字节。

1. 用户显式选择同步项目。读取父清单，解析指定分支当次最新 SHA（Speculo 的父清单必须 `ref=HEAD`，当前默认解析 main，每次重解析，不长期固定 main；其余五项目跟踪指定 main/master），整次固定该 SHA；普通检查不联网、不移动版本。通过 Git 对象读取完整选定树，失败不降级为残缺快照。
2. 先预览新增、修改、同 blob 移动、删除和模式变化，保存覆盖前运行映射。内容变化的移动/拆分/合并只是候选，必须对照确认，不机械继承。来源退出范围的运行资源在报告中说明，不自动删除本地成果。
3. 在临时同格式树中准备 upstream、适用 zh 和子清单。原字节、Git blob/mode 与集合核实；原件变化逐份复核译文，不只替换摘要。中文原文无副本，英/混合文档完整翻译；程序保留语义，仅译适用说明。分类必须真实，不能把缺译标为无需翻译。
4. 按[同步实际用法](../materials/README.md#显式同步预览准备应用)处理 REPORT.md 的 Outstanding work，全部完成后改为 `None.` 并写简短完成说明，不增加逐文件审批协议。显式 apply 才切换正式所选项目；核对同一准备 SHA、身份、基线冲突和完整对照，其他项目保持不变。远端已有新提交时报告差别，不悄悄换 SHA。
5. 分开评估运行适配：沿项目子清单 runtime_paths 对照旧来源、新来源与当前唯一本地正文，保留命名、宿主、授权、持久化与任务边界适配。新材料不等于已采用；runtime_reviewed_blob 不自动前移，旧依据未知时留空。确认无需改变也记录真实理由；完成适配与验证后才更新核对依据。超出本次授权的运行方法升级只报告具体建议。
6. 实际改动运行职责时，同步更新入口描述、路由、帮助示例和 UI 元数据。不能只改正文，让自动发现继续按旧范围选技能。
7. 运行统一检查、隔离失败案例和受影响回归；状态图捕获输出回放不冒充新 TLC 求解，实际 npm 包核对 materials 排除与安装边界。自然请求选择或实际执行条件改变时补行为验证。结构通过不能证明译文忠实或运行行为有效，如实记录结果与缺口。
8. 按用户本次授权处理提交、推送与发布，未经授权不执行。说明来源变更、运行影响、保留方法、本地适配理由及迁移要求；完成后清理临时准备树，历史原件和映射由 Git 历史承担。

只保留当前来源、当前适用对照与当前映射。无需历史目录、流程 JSON、状态引擎或强制审批；现有两级清单、Git 差异、临时 Markdown 报告和真实验证足够追踪。材料里的原始指令、嵌套技能与工作流都不参与本项目执行、发现或安装，npm 白名单排除 materials；原扩展名不改变安全契约。
