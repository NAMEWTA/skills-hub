# 开发工作树与合并验证

## 实施范围

- `dev-worktree` 负责按需建树、接手、集成和回收。审计脚本与完整清理方法从 `dev-deploy` 迁入，原来源与固定对象保留。任务图、候选协调、PR 和发布仍由对应技能负责。
- 新工作树位于主检出的 `.agents/dev/worktree/<任务名>/`。安装任一 dev 技能补齐根忽略规则，dev 和 system 混选共用一次提交到文件的安装事务。
- `dev-merge-conflict` 按实际操作与三方差异解决并验证组合结果。逐项集成从直接父提交生成双亲提交。项目合并记录用三个 SHA 引用 Git 历史和已有验证。

## 本机验证

- Windows PowerShell、Git 2.47.1.windows.2、Node.js v24.21.0。47 项专项测试通过，覆盖 Git 工作树、安装及 TUI、审计入口和方法归属。
- 隔离仓库实测两个同父分支任务，顺序合并一项无冲突和一项有冲突的提交。验证三方索引、父树独立提交、每次合并的两个父 SHA、验证树与实际提交一致、子提交可达性及移除检出后的 Git 提交图。另验证过期候选无法推进已变化的父分支，取消只恢复集成树，父树未提交文件原样保留。
- 安装检查涵盖 dev 单选、混选、预览、重复安装、先有一条规则再补另一条、部分写入回滚。实际 `git check-ignore` 确认工作树和系统附件被忽略，change 记录和 Herdr 协作文件仍可追踪。
- 在两个隔离项目中分别安装新技能，验证只安装所选技能并补齐 dev 忽略规则。单独安装的工作树审计脚本可显示帮助。
- `npm run check` 和 `npm run check:package` 通过。实际 npm 制品包含 54 个技能、1037 个分发文件。完整回归 362 通过、11 跳过、1 失败，失败来自 Windows 在 `tests/materials-sync.test.mjs:160` 创建测试符号链接时返回 `EPERM`。

验证覆盖真实本地 Git 行为与安装制品。真实 agent 路由、宿主自动清理及远端 PR 策略以对应环境的实际结果为准。
