# 归档 DeepSeek Harness Agent Notes

缩小活动决策资料集，同时保留仍能指导工作的历史。按语义判断每篇笔记；字数和年代仅用于发现候选项，绝不作为归档标准。

## 阅读约定

分类前阅读 [Agent Note 规则](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/.agents/notes/README.md)、[归档说明](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/.agents/notes/archived/AGENTS.md)以及适用的活动生命周期说明。使用当前代码、配置、包文档、生成的目录、较新的 Agent Notes 和入站链接，判断某段理由是否仍然负责或约束任何事物。

## 新增笔记时检查替代关系

起草前应用[创建标准](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/.agents/notes/README.md#when-to-write-one)。每篇新 Agent Note 都会触发一次范围明确的活动笔记审计，覆盖同一决策、机制或被拒绝方案。撰写新笔记时，对每项完全替代或部分替代进行分类：符合条件的已实施三文件组在同一个 PR 中归档；部分替代或仍有独立价值的理由保留并交叉链接；拒绝过时提案；删除不再能阻止合理误判的已拒绝笔记。新责任记录吸收了全部独特论点时，应用 Agent Note 合并规则；不要把已知的对应关系拖到以后的全资料审计。

## 按未来价值分类

按生命周期采用以下结果：

- **已实施——删除：** 删除仅描述小型界面调整或纯机械性变更的完整三文件组，并修复或移除入站链接。局部缺陷修复、性能变更、新能力，以及实质性的行为或责任归属决策，不能仅因为已经实施就归入此类。先应用这一标准，再判断保留或归档。
- **已实施——保持活动：** 如果理由、备选方案、否定保证、持久化或传输语义、责任边界、安全规则或重新引入条件可能指导未来修改，就保留。分类对象是决策，不是实现动作：机械性重命名或类型提取，也可能记录长期有效的命名、兼容性或责任规则。篇幅无关。
- **已实施——归档：** 实质性的历史决策已经完成，不太可能指导未来工作，但其历史理由仍值得保留时归档。满足直接删除标准的记录不归档。
- **提议中——永不归档：** 有效提案保持活动；如果不再值得推进，给出真实拒绝理由，并满足已拒绝生命周期的格式。
- **已拒绝——仅作为防误用提醒保留：** 只有落选提案仍是有诱惑力、有意义的错误选择，且笔记说明其落选原因时才保留。
- **已拒绝——删除：** 被拒绝想法已过时、已被替代、不再合理，或不太可能防止重复争论时，删除整个三文件组。修复或删除入站链接。

不要为达到配额而归档。检查范围内的每篇笔记，用同一原则分类相似组，对接近边界的情况运用判断，并在交接中记录真正难以取舍的决定。

## 校准示例

下列示例确定判断尺度；字数用来说明篇幅不是判断标准。

删除以下已实施笔记：

- 折叠侧栏控制轨——533 词：已结束的轻微界面行为。
- issue-policy 模块归属——已经完成的函数搬迁与导入重接，行为没有变化。

保留以下已实施笔记：

- 事件溯源会话——248 词：基础事实来源与持久化边界。
- 单一 Harness 主目录解析器——596 词：跨产品责任归属规则。
- 项目会话目录——628 词：持久存储与身份策略。
- 并行推送前检查——400 词：接近边界，但仍指导检查调度和资源调整。
- 移除的图片内容块——334 词：在多模态支持落地前保留，因为它说明协调重新引入的条件。

对于已拒绝笔记：

- 保留合并上下文压缩包拆分的提案——426 词：合并这些包的诱惑仍然存在。
- 删除通过工具调用流式传送工作流进度的提案——972 词：其 ACP/UI 前提已过时。
- 删除丢弃 ACP 终端元数据的提案——362 词：后来仅面向自动化的 ACP 决策已解决此问题。

## 归档一个已实施三文件组

1. 将完整的 `foo.md`、`foo.zh.md` 和 `foo.i18n.yaml` 三文件组从 `implemented/<kind>/` 移到 `archived/<kind>/`；归档路径有意不包含 `implemented`。
2. 不改正文。只在两个语言文件的 `Status: implemented` 下方紧接着插入 `Archived: YYYY-MM-DD`，使用归档当天日期，两边保持一致。
3. 为这两处仅元数据变更机械地重新记录附属文件哈希。不翻译、重排格式、更新事实，也不修复笔记内部链接。已有标题标点、空行布局和语言切换文字都原样保留，不将它们视为归档前提。
4. 搜索来自活动正文的入站链接。将它们重定向到当前权威记录；只有有意引用历史快照时才改为归档路径，否则删除。绝不验证或修复归档笔记的出站链接。
5. 执行 `pnpm run verify-archived-agent-notes --write`。其只追加模式先证明全部现有封存内容仍匹配，再仅添加新三文件组的哈希。之后执行普通校验器。

三文件组封存后，绝不编辑、移动、翻译、重排格式或删除。归档笔记仍可作为入站链接目标，但它们是历史快照，不是当前行为的权威依据。

## 验证与报告

运行归档校验器的聚焦测试、`pnpm run verify-archived-agent-notes`、`pnpm run doc-sync`、`pnpm run lint` 和 `git diff --check`；通过 [dsh-pre-push-checks](../dsh-pre-push-checks/SKILL.md) 选择其他所需证据。

报告：保留的活动已实施笔记、删除或归档的已实施笔记、保留或删除的已拒绝笔记、被拒绝的提议中笔记（如有），以及每个真正难以取舍的案例及其字数和最终结果。不要声称归档笔记的出站链接有效：归档校验器有意不检查它们。
