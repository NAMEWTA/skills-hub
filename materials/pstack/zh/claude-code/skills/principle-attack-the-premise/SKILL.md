# 质疑前提

当两个或更多共享同一前提的修复都未通过同一个检查时，应怀疑前提，而不是修复本身。

- 写下前提：每个失败修复都默认成立的那一句话。
- 下次修复前先检验它。找出一种观察：如果前提为假，其结果就会不同，然后实际观察。不只看失败的大小，还要看失败如何分布。
- 如果证据与前提矛盾，寻找这些失败共有、却不在前提预期中的特征。如果某个部分总是处于不利一侧，就改变导致它处于该位置的条件，而不是增加事后清理机制。

前提未被写下并检验之前，不开始下一次修复。
