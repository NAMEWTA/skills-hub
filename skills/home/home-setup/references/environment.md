# 有关环境事实与能力核查

此方法只检查当前任务所需的能力。只保存配置时跳过；用户指定接入、切换主机或真实验证工具时使用。不要把开发环境的完整资源预算或 worktree 回收流程复制到 Home。

## 采集与分层判断

1. 明确实际执行主机、Home 根、目标项目及用户选择的工具/派遣技能。远端只检查用户指定且已有访问能力的环境；不可达或身份不明写未知，不把同名本地路径视为远端证据。
2. 读取已安装的准确技能入口，按其真实能力和当前帮助核对本次所需条件。未选用的工具缺失不算故障；不维护固定支持 CLI 清单。
3. 在授权内执行最小只读探测：入口是否存在、版本能否读取、所需能力或权限能否确认、真实目录是否可达。不要输出环境变量全集、认证 URL、token 或私钥。
4. 如果用户请求实际工作，交由选定方法执行一次必要链路验证。Home 只汇总其证据，不自建 launcher、终端探测器或会话数据库。
5. 使用 [环境记录](../assets/environment.md) 保存时间、主机、目标、版本、事实来源和未知边界；已有等价记录原地维护并引用。

已授权的宿主接入确需根 AGENTS 之外的薄入口时，仅记录非秘密的本机派生方式、真实入口和当前验证等级。薄入口本身不随 Home Git 白名单提交，不 force-add。换机按实际所选宿主重新核验，并按已有授权重建必要适配；方法记录不证明新机已经加载，也不要求为未选宿主生成文件。

| 结论 | 所需证据 | 不可推导 |
| --- | --- | --- |
| 配置已保存 | 文件回读与差异 | 工具已加载、默认已生效 |
| 入口存在 | 实际路径或技能入口 | 账号、网络和模型可用 |
| 版本可读 | 当前命令结果 | 所需权限存在 |
| 任务可投递 | 选定方法的就绪和投递证据 | 项目资料已读取或交付已完成 |
| 指定模型/模式已运行 | 实际宿主可验证信息 | 单凭输入参数无法证明 |
| 交付已验收 | task owner 对绑定产物的验收 | worker 自报、idle 或退出码不能代替 |

没有运行证据时不要用“已生效”描述参数意图。所选工具无法证明最终模型或模式，就保留未知。普通 shell 或终端已建立也不证明 Agent 已就绪。

## 资源与生效范围

Home 和项目可能共享主机、限流、磁盘或容量池。只引用现有资源 owner，不在各层各写一份可叠加额度。角色人数按项目计算，实际并行规模、调度与资源预留归用户选择的方法和当地 owner。

需要完整开发资源核算时，按准确名称调用项目当地实际采用的环境方法；项目选择 `dev-setup` 时由该技能处理。Home 不强制项目安装 dev，也不替其回收 worktree。

环境记录是观测，不是运行时限制。给出在主机、版本、权限、负载、连接或实际 checkout 变化时需要重新核查的条件。未测过的远端不计入可用范围，不承诺仅凭 Markdown 不会过载。

## 输出

报告用户意图、已观察能力、实际生效结果三列及其来源，列出阻塞项与仍可继续的工作。秘密只保存已有安全引用。只核查不变更全局配置、不登录、不安装未知工具、不启用 auto memory 或后台调度。
