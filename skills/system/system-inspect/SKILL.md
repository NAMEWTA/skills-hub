# 系统取证

先定位慢在哪里、从何时开始、受影响的工作负载和真实目标：原生 Windows/macOS/Linux、WSL、容器或远程主机。运行工具的环境不自动等于用户要处理的机器。

## 采集与判断

1. 复用已有诊断、当前配置和错误，只读取与问题有关的内容。
2. 记录系统/架构、采样窗口、工作负载、挂载或网络命名空间。缺少目标访问时说明缺口，不拿别的机器测量代替。
3. 先取小范围基线，再沿证据深入具体卷、进程或目录。磁盘空间和 inode、内存压力和可回收缓存、CPU 使用和 I/O 等待分别判断。
4. 用 [平台取证参考](references/platforms.md) 选择实际存在的命令；缺少命令就记录，不为了体检安装一套工具。
5. 将观察、推测和未验证分开，提出最小可检验的下一步。

本技能只读：不清缓存、不重启、不停服务、不改代理或配置，不自动联网测速。任务已包含具体修复授权时，完成必要诊断后直接继续范围内的修复流程；不重新索取已经给出的授权。

## 可选离线基线

有 Node.js 22.14+ 时，可运行本目录的 [只读脚本](scripts/inspect.mjs)。`SKILL_DIR` 表示本 SKILL.md 所在目录：

```bash
node "$SKILL_DIR/scripts/inspect.mjs"
node "$SKILL_DIR/scripts/inspect.mjs" --path "/path/on/target/volume"
```

原生 PowerShell 使用已确认的 `node`。脚本仅读取当前 OS、架构、CPU 数量、所选路径所在文件系统空间与可用的 load average；不联网、不扫描目录、不读取日志或配置。它不能识别所有虚拟化边界，也不是性能评分。CPU 数量不代表容器可用配额。

## 交付与记录

给出症状、目标、基线、支持结论的证据、仍待排除的原因和下一步。需要新增长期记录时，在 `.agents/system/<host>/` 写一份简短 Markdown；纯查询无需强制落盘。

报告不带密钥、完整环境变量、进程参数或私有日志。不要把单次快照、空闲磁盘或脚本成功退出说成“系统已优化”。

空间问题可继续交给 `system-cleanup`，代理问题可交给 `system-proxy`，配置变更可交给 `system-config`；这些是可选协作技能，未安装时直接交付同等明确的计划。
