支持将未归档笔记导出为用户指定的 JSON 文件

## 更新正文

### 问题与价值

用户需要将当前未归档笔记导出为可供其他工具读取的文件。此次交付一个 JSON 数组文件，保留笔记的标识、标题、正文和更新时间，并让用户选择文件名与保存位置。

本次行为以 [product-owner 的确认评论](https://example.invalid/example/memodesk/issues/42#issuecomment-11) 为准：只支持 JSON 数组，字段为 `id`、`title`、`body`、`updatedAt`；不做 CSV；文件名由用户选择；取消不写入；写入失败显示原因，重试由用户触发。此前 CSV 目标由这项决定替换。[同时支持 CSV 和 JSON 的提议](https://example.invalid/example/memodesk/issues/42#issuecomment-10) 不属于本次范围。

### 目标与范围

1. 导出当前笔记集合中的全部未归档笔记。沿用原目标的未归档范围；导出数据构造时不传入标题搜索词，不把当前搜索结果自动变成导出范围。
2. 输出是 UTF-8 编码的有效 JSON 数组。每个对象只包含 `id`、`title`、`body`、`updatedAt` 四个字段，保留当前有效笔记记录的原始值；不输出 `archived` 或其他内部字段。
3. 沿用项目的更新时间降序规则。没有未归档笔记时输出 `[]`。
4. 复用已完成的目录选择与目录记忆行为，并允许用户选择文件名。只有用户完成选择后才执行导出写入。
5. 用户取消时不发起写入、不生成导出文件，也不显示导出成功。
6. 写入失败时显示具体原因，不显示成功、不自动重试；用户处理问题并主动重试后才再次写入。
7. 导出不修改内存中的源笔记，也不把导出字段裁剪结果写回源笔记存储文件。

本次不实现 CSV、双格式选择、新数据库、前端框架或导入功能。项目继续使用 Node.js 22 标准库和现有 JSON 存储方式。

### 主流程与边界行为

| 场景 | 动作与可观察结果 |
| --- | --- |
| 正常导出 | 用户进入既有导出入口，选择文件名和位置；读取当前笔记集合，复用未归档过滤与排序，投影四个字段，再写入所选目标。写入 Promise 成功后才报告成功。 |
| 文本含中文、双引号或换行 | 使用 JSON 序列化保留文本，导出文件经 `JSON.parse` 读取后，四个字段与源记录对应值一致。 |
| 集合为空或全部归档 | 用户确认保存后生成内容为 JSON 空数组的文件。 |
| 用户取消选择 | 不调用写入函数，源数据和文件系统中的导出结果保持取消前状态。 |
| 无权限、目标路径失效等写入错误 | 捕获写入错误并显示原因；保留用户再次发起导出的入口；用户明确重试后重新执行写入。 |

### 复用与设计

- **查询和过滤：**复用 `src/notes.mjs` 的 `listNotes(notes)`。默认空查询覆盖所有标题，已有逻辑负责归档过滤和更新时间降序。不要在导出层重新实现另一套过滤规则。
- **导出数据：**在过滤结果上构造仅含四个允许字段的新对象。不要直接序列化完整存储记录，以免带出 `archived` 或今后新增的内部字段；不要删除源对象上的字段来完成裁剪。
- **JSON 写入：**`src/store.mjs` 的 `saveNotes(file, notes)` 已使用 `JSON.stringify(notes, null, 2)` 和 Node 标准库 `writeFile`，可以将其用于向用户选择的导出目标写入投影后的数组。调用者负责等待结果、处理错误和区分导出目标与源存储路径。现有实现没有展示原子写入或失败后自动清理能力，不把这些能力描述为现状。
- **选择和状态：**接回已完成的目录选择与记忆入口；取消必须在写入前返回，失败原因由调用入口展示，重试仅响应用户操作。该入口未包含在精简源码快照中，接入时从完整项目定位并复用。
- **依赖：**已有查询和 JSON 写入能力足够支持本次范围，不需要引入新依赖或引用未提供的外部实现。
