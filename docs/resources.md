# 资源组织与完整性

## 三类文件各有职责

| 位置 | 内容 | 使用时如何读取 |
| --- | --- | --- |
| `skills/<domain>/<domain>-xxx/` | 本项目的中文技能、完整方法、模板、示例和必要脚本 | 按需安装后，只沿本技能内部相对路径读取 |
| `materials/` | 648 份固定版本原件及逐份本地对照，共 1296 个配对文件 | 维护时核对，不参与技能发现，不安装、不执行 |
| `licenses/` | 原作者完整版权与许可、必要法律通知 | 安装时原样附带到 `.agents/skills-hub-licenses/` |

运行技能中的每份 Markdown 资源都必须从本技能 `SKILL.md` 沿本地链接可达。入口直接指向当前主分支需要的完整方法，大量辅助例子可以通过短主题索引查找。完整资源可被发现，不意味着每次任务都全部读入上下文；入口预算只计算 `SKILL.md` 正文，不限制完整参考的知识总量，详见[质量门禁](skill-quality.md)。

## 全文底稿

[本地资料索引](../materials/README.md) 按六组列出全部原件与中文对照。[逐文件清单](../materials/manifest.tsv) 记录原路径、固定原件摘要、中文底稿摘要、对应运行文件和适配说明。

复制原件时核对固定版本的 Git blob；保存原字节，不把提取时多出的换行当作原件。211 份文档逐段保留正文、列表、表格、例子、反例、代码和数值，技术标识按原样保留；原本已经中文的材料以原文作为中文对照。PR 材料的译文带有明确翻译说明，以保留适用许可要求。

68 份代码与配置保存程序和技术标识，翻译适用的说明与注释；362 份机器夹具保持原字节，包括必要的空文件、协议输出与预期结果。这两类使用 `localized.txt`，不冒称为逐段中文文档。文档使用 `zh-CN.txt`；7 份图片保留原扩展名与原字节，中文图意随对应指南保留，原品牌插画不进入运行技能。清单的 `kind` 只描述资料类别，不构成工作流状态。

B 组完整覆盖固定版本目录树的全部 573 个文件，包括 61 个技能入口、23 个流程、24 条原则、2 个代理定义、全部指南、自动化配置与工具。技能按用途整合，创建和维护验证的方法可以合在同一个入口，教学和通俗复述也可以合入学习入口；完整方法仍作为独立文件保留，不用几段摘要替代原文。

文本底稿保留历史来源名称和原始指令，因而使用 `.txt`，仅供对照。不能将底稿直接复制进运行包：其中可能有固定模型、旧目录或特定宿主工具约定。当前任务执行以本项目技能为准。

## 实际运行版本的适配

| 项目约定 | 运行资源的具体处理 |
| --- | --- |
| 中文与完整内容 | 保留完整方法和重要示例，将章节、说明、提示与可翻译注释转为中文 |
| 全部本地引用 | 复制所需资源，改为同一技能内相对路径；不用来源 URL 代替参考内容 |
| 独立命名 | 来源专有技能名、项目名、作者名、署名与来源段落不进入运行包 |
| 工程与验证方法 | 保留并按任务组合规格驱动、TDD、真实运行、状态图及形式化方法；不把单一范式作为所有任务的硬门槛 |
| 宿主能力 | 按实际工具完成等价工作；来源特定 CLI、模型或辅助脚本不成为未提供的硬依赖 |
| 脚本运行环境 | 维护、安装、测试及技能脚本统一使用 Node.js 22.14+ 的 `.mjs` / `.js`；归档底稿保留原字节，迁移后的行为用原有夹具和边界检查核对 |
| 轻量记录 | 项目资料统一写入 `.agents/wtadev/` 的职责子目录，使用必要的 Markdown、真实代码引用和 Git 历史；不移植复杂状态引擎、准入网关或任务 JSON 合同 |
| 持续工作 | 复用用户已经给出的授权；完成可做的准备与实现，不把每一步变成重复审批 |
| 项目现状 | 示例始终标明为示例；实际结论核对目标项目代码、版本和运行证据 |

适配改变了运行语境，不能把运行版宣称为“原件未经修改”。完整中文底稿用于核对内容是否缺失，运行版用于执行本项目约定；二者都保存在本仓库。

## 资料如何进入技能

需求、澄清、规格、切片和架构资料分别进入对应 `dev-*` 技能；执行操作规程、审查、诊断与发布资料进入工作流、实施、审查、调试、部署包。设计资料保留完整规范与组件、尺寸、颜色和变体说明。知识资料包含完整保留／替代判断和模块调查方法。系统资料提供平台检查、开发缓存清理、客户端代理与配置的完整本地操作说明。

状态图包携带实际的解析、投影、反例与报告算法；开发夹具留作本地审计和维护依据。脚本直接由 Node.js 运行，不需要 TypeScript 编译器。实际执行 TLC 求解时仍需要 Java 与 TLC，生成 SVG 时仍需相应渲染器；这些领域工具分别核对，不能把工具未安装写成已验证。形式化包另有独立的有限状态示例，明确其状态不变量范围，不冒充 TLC 或任意规模证明。

同一包内，同一方法保留一份完整正文，其他入口或模式引用它；合并时核对适用条件与链接指向，不能仅因文字相同而混淆不同语境。相同方法被多个独立技能需要时，可以在各包保存完整副本，避免单独安装后缺资源。修改公共约定时检查这些副本，但不增加运行时共享目录或隐式安装依赖。各项精确映射以逐文件清单为准。

PR 观察器中的真实服务地址用于解析仓库、构造结果链接和实际查询，不是外部文档依赖。观察器使用 Node.js 与实际已认证的 GitHub CLI；其他工具按任务核对 Java、TLC、渲染器等前提，没有自动下载或隐式联网安装。

报告自动化保留完整初始化、分诊与 UI 修复方法，来源适配则区分手工材料、聊天、工单、邮件和监控告警。各包的 `source-adapter.md` 是本地适配契约，不是来自上游的通用连接器实现；来源、追踪器、代码仓库及实际触发能力分别核对，详见[来源与监控配置](issue-sources.md)。

正式 ADR 用于同时具有难以逆转、缺少背景难以理解、存在真实取舍的决定。在 `.agents/wtadev/notes/` 中，其他仍有长期价值的背景与业务约束进入 context，复发错误与恢复经验进入 errors，术语进入 glossary。没有达到正式 ADR 条件，不等于知识可以删除；已有外部文档按真实位置引用，迁移本套技能资料时保留有效内容并修复导航。

## 维护与验证

新增或更新参考时，先固定来源修订并在 README 更新集中记录。完整取得实际使用的正文及所引用的模板、提示和操作说明，再做全文翻译与运行适配。来源范围之外、不涉及本项目的其他技能或业务代码不属于自动同步对象。

运行 `node scripts/check.mjs` 统一检查入口预算、元数据、资源可达性、单包链接边界、外链、来源残留、资料配对、摘要和运行映射；`--full` 追加隔离行为检查。内容是否忠实、适配是否合理仍需对照阅读，不能仅靠结构计数或摘要证明。后续调整按[技能维护与上游同步约束](development-constraints.md)处理。

本次实际做过的检查、覆盖范围和限制记录在 [验证记录](validation.md)。许可与贡献者归属见仓库 [README](../README.md#致谢与许可) 及 [第三方声明](../THIRD_PARTY_NOTICES.md)。
