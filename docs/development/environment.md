# 开发环境、资源与团队配置

`dev-setup` 核对项目要求与实际执行环境，并形成可用于派发的容量记录。完整方法和模板由[技能入口](../../skills/dev/dev-setup/SKILL.md)维护；调度和清理继续使用现有阶段技能。

## 初始化会得到什么

```text
使用 dev-setup 核对本项目的运行要求和当前主机资源。
我指定的远端 host-a 也用于执行构建，请通过现有连接核验。
给出 Agent、重任务和 worktree 的上限、当前可新增量及依据。
```

只指定本机时不发现其他主机。远端不可达就记录未知，不把它的假定容量加入本机。环境要求来自实际项目文件；读取资源不自动安装依赖、配置系统服务或执行远端部署。

环境记录默认在 `.agents/dev/context/environment.md`。已有等价权威记录原地维护，各工作树、Change 与执行者引用同一位置；存在原生调度器时引用其预算入口。记录包括：

- 实际执行主机、容器/虚拟机边界、版本要求与核对结果。
- CPU 有效配额、可用内存与压力、真实卷剩余空间，以及适用的 PID/inode 等限制。
- 主机、父配额与共享存储的对应关系，采样时间与未知项。
- 当前负载的峰值估计、系统保护量、已经兑现和未兑现的预留。
- 会话、重任务、保留 worktree 的上限和当前可新增量，排队原因及刷新条件。

这里的上限随负载变化。例如代码编辑、浏览器测试和依赖安装的成本不同；多个 Agent 各自启动多个测试 worker 时，不能只统计最外层 Agent 数量。物理机总内存也不能突破容器配额。

## 谁读取预算

| 阶段 | 责任 |
| --- | --- |
| `dev-setup` | 核验环境、测量负载、维护容量方法与环境记录 |
| `dev-plan`、`dev-program` | 引用预算，区分依赖就绪与资源排队；跨 Change 共用预留 |
| `dev-parallel`、`dev-build`、`dev-review` | 启动前复测并取得预留，控制嵌套 Agent、构建与测试 worker |
| `dev-worktree` | 创建和初始化前核对容量；集成树也计入；按唯一清理方法回收 |
| `dev-deploy` | 本地/CI 构建及指定部署目标按实际执行位置核验 |
| `dev-handoff` | 传递预算位置和未退出实例，恢复前重新采样 |
| `dev-archive` | 核实剩余占用，将已结束检出交回清理方法 |

同一资源池由一个负责人或已有调度器安排准入。多个协调者不能分别读取相同空闲量后同时占满；子代理继续分工时使用父任务分配的额度。资源不足时保留任务范围、分批执行，允许新增量为 `0`，不伪造 DAG 依赖。

技能使用实际可用的系统观测、CLI 并发参数和运行时能力，不新增调度服务。建议预算与已经生效的系统硬限额分别记录；Markdown 约定本身不提供 OS 级资源隔离。

## 资源如何释放

沿用 `dev-worktree` 的审计与清理入口，检查任务已经结束、写入者已交回、最新提交落在实际直接父分支，以及文件、会话和保留状态。再核实本任务残留进程的主机、会话、PID、启动时间和停止入口，有序退出后删除符合条件的检出。

删除后的卷空间与进程状态要重新读取。停止请求已发送、目录预计大小或 `git worktree prune` 成功都不等于资源已释放。部分回收成功只归还相应部分，用户固定、手工锁定或归属不明的对象保留。

## 多套团队配置

普通环境初始化不创建团队文件。用户明确要求保存时，按团队主题分别存放：

```text
.agents/dev/context/team/capture-annotations.md
.agents/dev/context/team/release-review.md
```

用户给定名称或文件时沿用；没有名称时从 topic 生成单段名称，并检查重名。每份只保存这个团队实际使用的角色、模型/推理意图、成本与协作约定，具体参数必须由当前宿主能力证实。

使用时明确引用，例如：

```text
本次按 .agents/dev/context/team/capture-annotations.md 协作，
实现当前已确认的截图批注规格。
```

团队文件不设项目默认，不因存在而自动加载，也不写入根 `AGENTS.md` 的自动读取指令。`dev-build` 等阶段不主动选择模型规则。未被点名的团队保留供以后使用，文件里的角色数量表示覆盖需求，实际并发仍使用环境预算。

本版不自动搬迁目标项目已有的角色文件。需要整理时明确指定文件和主题，由 `dev-setup` 保留内容、核对引用后迁移。历史文件中的自动加载导航若要移除，也应在该次整理范围内处理。

## 方法来源

资源保留、按负载测量、准入和工作树生命周期参考的官方资料与固定上游地址集中见[第三方声明](../../THIRD_PARTY_NOTICES.md#开发环境与资源准入)。本项目把这些机制适配为现有技能之间的协作约定，没有引入 Kubernetes、特定 CLI 或额外常驻服务作为必需依赖。
