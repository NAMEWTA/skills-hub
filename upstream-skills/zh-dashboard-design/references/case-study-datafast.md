# 案例研究：DataFast

DataFast 是以营收为重点的网页分析产品（datafa.st）。2026 年 10 月通过公开演示、试用账户、文档及更新日志进行研究。以下是我们用自己的话总结的设计经验；与该产品没有隶属关系。

## 值得学习的模式

- **顶栏**采用单行排列：网站选择器 · ‹ 日期范围 ›（前进/后退一个周期）· 对比 · 粒度 · 筛选 · 刷新。
- **日期菜单**：顶部显示当前时间，提供实时的 **Now** 选项，每个预设有单字母快捷键；“更多周期”默认折叠；“自定义”使用双月日历，并支持直接输入开始和结束日期。
- **KPI 指标条**：包含营收产品依赖的资金比率——收入、转化率、访客平均收入，以及访客数、跳出率、会话时长和实时“在线”人数。
- **主图表展示营收**：访客数用折线，收入用柱状并对应右侧货币坐标轴；发生销售的日期上方标记来源 Logo。
- **能展示自身价值的空白区**：目标、漏斗和用户旅程在柔和遮罩下展示示例数据，并只放一个行动按钮，使新用户知道后续能获得什么。
- **分组筛选菜单**：按来源、URL、位置、系统、访客及自定义分组，基于当前排名靠前的项目生成建议筛选标签。
- **洞察页面**：用句子陈述“桌面用户带来的收入最多”等事实，提供访问至购买、购买所需天数的柱形展示、购买时间中位数，以及工作日 × 小时热力图；需要足够数据才能解锁，未解锁时显示模糊预览。
- **新手引导**：角落放置配置步骤清单；“使用 AI 配置”卡片可复制一段为编码 Agent 准备好的提示词。
- **便于 Agent 使用的文档**：每页文档还提供 Markdown，另有 `llms.txt` 索引、写入前先预览并要求确认的 MCP 服务、CLI 和 API Playground。
- **实时数据的愉悦感**：显示实时访客的地球仪，配以友好的生成姓名与头像，旁边是一条实时事件流。

## 借鉴时需要权衡的取舍

- 归因依赖长期存在的第一方 Cookie；文档说明无 Cookie 模式能力较弱。隐私优先的产品在借鉴这些 UI 模式时，应结合无 Cookie 的匹配方案。
- 两种销售检测方式（重定向 URL 和支付元数据）如果不关闭其中一种，会重复计数。这提醒我们让默认路径先保证安全。
- 排名列表行使用文字背后的带色条形；相比之下，components.md 的细条模式看起来更清爽。
- 研究时告警只支持邮件；用户通常还会要求 Slack、Telegram 和 Discord 等聊天通知渠道。
