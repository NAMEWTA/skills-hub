### 自主执行

**你负责退出条件。定义完成，然后不停顿地推进到它。**

1. 首轮迭代前，把退出条件写成可检查判据，如测试全绿、复现已修复、全部 N 个 PR 已合并、像素差为零。
2. 使用 Cursor 的 `/loop` 命令选择唤醒机制（这是内置命令，不是 pstack 技能）。如果要等待某个事件（CI、合并、引用前进），安排 watcher 子代理在事件发生时唤醒你，并以较长的定时心跳作为后备。若没有事件，则按结果值得重新检查的时间尺度设置固定间隔心跳。按照 Subagents 部分，为每个子代理选择适合任务的推理级别。
3. 每轮做证据支持的最小改动，按判据验证；有推进就提交，没有帮助就丢弃。“也许有用”的双保险要回滚，不搭便车留下。
   按 **sequence-verifiable-units** 原则安排工作，下一个单元前验证当前单元，不把检查攒到最后。
4. 途中发现且支持目标的事项由你负责。通过 poteto-mode 自行处理损坏技能、相关缺陷、不稳定验证器、审查噪声、工具故障、无人接手的后续事项、可修复漂移。范围外修复放独立 PR。不要把可逆工作搁给人，也不用 `AskQuestion`。只提出不可逆行动、实验无法解决的真实产品或偏好选择、真正死路。以判据为主驱动力，每次支线修复后回到它。
5. 每轮用 **show-me-your-work** 保存检查点，一行记录改了什么、判据是否推进。
6. 满足判据时停止。平台期不是停止理由，继续并换方法突破。真正死路要提出，不空转；绝不放宽判据来宣告胜利。

**回复：** 退出条件、执行轮数、落地内容、丢弃内容、最终判据状态。
