# 02 把部署登录资料写入项目选定的本地 env.md

规格：用户指定 DBX 的 `.agents/ops/projects/dbx/env.md`，要求部署中已获授权且实际用到、生成或变更的登录资料直接以明文保存，打开文件即可查看和复制。项目部署归原有发布流程；这项改动只增加部署资料的写入和更新规则。

交付：项目的部署入口一旦明确选用本地 `env.md`，每次部署根据实际结果写入该项目、该环境的账号和可用凭据。未指定此用法的项目继续沿用现有规则，不默认保存明文。

直接依赖：无。夹具中给定明确的项目、环境及其登录资料，不依赖主机别名实现。

边界：本票负责通用部署方法与持久化说明，真实 DBX 手册的接线由本地落地票负责。凭据明文只保存在指定的本地 `env.md`；普通手册、run、release、报告、提交和安装包仍不包含值。该文件是人读的部署资料，不替代应用实际读取的 `.env` 或平台配置。

当前代码指针：[dev-deploy](../../../../../skills/dev/dev-deploy/SKILL.md) 及其[项目部署](../../../../../skills/dev/dev-deploy/references/project-deployment.md)、[凭据与恢复](../../../../../skills/dev/dev-deploy/references/secrets-recovery.md)，以及[持久化约定](../../../../../docs/reference/persistence-roots.md)、[ops 说明](../../../../../docs/operations/overview.md)和[安装器托管的 ops 导航](../../../../../scripts/persistence/ops.md)。调整其中把所有 Markdown 都视为普通文档的措辞，明确用户选定的本地凭据文件是例外。`ops` 不因此执行部署，也不依赖安装 `dev-deploy`。

## 实施要点

- 由项目部署文档明确写入目标路径及它所对应的运维工作根。按环境分节，在节内按服务及账号用途或配置键定位同一条目。记录登录入口、账号、适用库或租户、实际密码、令牌、密钥或私钥及必要口令。实际使用带认证信息的连接串时可原样保存。多行密钥用能保留换行的 Markdown 代码块存放，不转义或截断。保留已有非凭据内容和不在本次范围的条目。
- 使用本次授权范围内已掌握的真实值，不扫描整机、不收集无关账号。原来未改的值保留；需要记录却无法取得的值写明缺口，不虚构、不为补文件擅自重置。重复部署同一环境和账号时更新原条目，不追加第二份现行记录。
- 以凭据实际是否生效为准，而非只看整次发布成败。已确认的新值更新原条目；失败且新值未生效不覆盖现行值；状态未知时标明待核实，不把计划值写成可用值。回滚时核对恢复的是哪组凭据，再同步。写入失败时保留原文件，单独报告「部署结果」和「登录资料未写入」，不重放部署来补记录。
- 不要求更换保管工具或加密该文件。若实际写入位置在 Git 仓库中，先核实该文件未受跟踪并按实际路径排除，不把凭据文件放进暂存或发布。该检查只防止意外入库，不改变文件内明文直读的行为。记录外部结果时只报告路径、环境、条目名称和写入状态，不复制值。

## 验收

- [x] 在隔离根模拟已选用 `env.md` 的 DBX 部署，用假账号、密码、令牌和多行私钥比对文件中的原始值。环境和用途能区分，第二次部署更新同一条目，另一环境和原有说明内容不变。
- [x] 模拟未生效、部分生效、状态未知、回滚、不可取得的凭据和本地写入失败。现行资料只跟随已核验的事实，文件保持完整，结果能区分部署成败和资料同步状态。
- [x] 在未选用 `env.md` 的项目走同一个部署分支，不创建明文文件。用合成值核对写入时只有指定的本地文件包含该值，部署手册、run、release、可提交文件和安装产物都不包含该值。

## 完成证据与进度

已完成方法与导航更新。使用隔离工作根的部署文档、合成结果和独立会话验证实际文件更新及失败路径，详见[验证记录](../verification.md)。规则由项目部署流程执行，没有常驻钩子。
