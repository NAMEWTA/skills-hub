# 交互启动版本检查验证

现有入口仅在查到新版时显示当前版本，查询失败、超时或版本相同都没有查询结果提示。[交互入口](../../../../cli.mjs)现在先显示当前版本号，再按安装方式决定是否查询。[版本查询](../../../../scripts/update-cli.mjs)共用 3 秒预算读取并核对 npm 响应，超时后取消请求并忽略迟到结果。源码和交互预览只显示当前版本号，非交互命令不受影响。

- CLI 定向测试：25 项通过。覆盖相同版本、本地版本更高、离线、取消后仍返回的响应体、新版确认与拒绝，以及预览不查询。模拟时钟验证 2,999 毫秒仍等待、3,000 毫秒进入兜底。
- `npm run check:full` 通过：365 项通过、11 项因 Windows 环境条件跳过、0 项失败。
- `npm run check:package` 通过：实际压缩包在隔离项目中安装，54 个技能的资源和命令入口通过检查。
- 用临时安装的 npm 包启动实际交互界面，模拟终端输入和注册表响应。版本相同直接进入选择；检测到新版时按 Enter 选默认的「否，直接进入」；查询悬挂时显示「未检测到最新版本号」，从请求到选择界面用时 3,074 毫秒（含技能目录加载）。三次取消后目标项目均无文件写入。

更新确认由测试替身验证为调用现有更新函数并传入目标版本，未执行线上自更新。

`0.1.23` 发布候选在 Windows（Node.js 24.21.0、npm 12.0.2）重新安装锁定依赖后通过完整回归（365 项通过、11 项跳过）、状态图回放（33 项通过）、实际 npm 包验证和 Archify 真实浏览器检查。
