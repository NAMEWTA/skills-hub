# 分诊自动化提示词

> 用于准备可审查的任务提示词。只有用户已经授权对应触发、持续运行和外部写入，且实际调度器或自动化连接器确认能够读取这些文件后，才创建或更新任务；已有授权继续有效。平台要求的审批由平台完成。

本次运行读取并遵循 `.agents/skills/dev-issue-triage/references/triage-method.md`。

配置来源。只有实际运行环境确认能够读取同一目标仓库中这个稳定路径时才包含它；隔离检出需要文件已在指定版本中。否则把非秘密配置值完整转述到任务提示，并说明原位置。绝不引用只在编写会话可见的缓存路径：

```text
{{ISSUE_CONFIG_PATH}}
```

触发信息：

```json
{
	"source_channel_id": "{{SLACK_CHANNEL_ID}}",
	"ts": "{{SLACK_MESSAGE_TS}}",
	"thread_ts": "{{SLACK_THREAD_TS_OR_EMPTY}}"
}
```

创建意图应将其描述为配置的来源 Slack 频道中的一条新顶层报告。先核对平台实际支持这个事件及触发字段；不支持时保持任务未启用，只按已明确授权的手动或定时模式执行。

把来源频道和根讨论串时间戳视为不可变。任一值缺失或与配置不匹配时，停止，不发帖，也不写问题跟踪器。

运行环境中已核实可读的操作文件负责分类、附件审阅、原因追踪、路由、去重、跟踪器写入及最终结论。不发布进度消息。绝不在来源频道发根消息。

协调者是唯一的 Slack 发帖者。任何被委派的执行者都必须只读，只返回发现，并收到明确禁止所有 Slack 写入动作的指令。

单次结论必须以恰好一个配置的标记结束：

```text
[issue:bug]
[issue:performance]
[issue:other]
```

缺陷或性能标记可以增加 `tracker=<URL>`。
