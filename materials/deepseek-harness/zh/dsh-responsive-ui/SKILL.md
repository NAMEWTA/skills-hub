# 响应式客户端 UI

视觉审查时，先选择[影响范围](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/docs/cookbook/reviewing-ui-design.md#review-scope)，再应用这些行为要求及 [UI 审查基线](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/docs/ui-design-review-cases.md#review-baseline)。在完整页面或模态框的语境下，比较受影响的换行与布局关系，同时保留草稿、焦点和动作可达性。明确要求全界面审查时，检查所有区域。例子不定义覆盖范围；仅仅适配视口还不够。

## 1. 最小视口

主要验收下限为 390 CSS px 的视口宽度。不得出现非预期重叠、裁切、整页横向滚动，或不可访问的主要操作。低于 390px 时，可放宽布局要求。

## 2. 决策顺序

1. 先调整空间分配或让元素换行，再考虑文本截断、纯图标控件或将图标移入“更多”菜单。
2. 不得省略主要操作与主要状态。
3. 不通过全局裁切、缩小全部字号或缩小点击目标来掩盖冲突。
4. 只有产品设计明确要求时才减小字号。

## 3. 文本截断

1. 被截断内容必须能在次级页面或打开菜单后完整获取。例如输入框下方的 Session 统计信息。
2. 截断不得丢失错误或其他关键信息。
3. 标签导航、可见选择器、按钮、标签及类似组件优先使用单行截断。
4. 其他页面无法获取的重要信息必须完整显示，不得截断。

## 4. 标题

1. 优先完整显示页面标题，必要时把操作区移到下一行。例如插件页的标题换行行为。
2. 卡片标题优先自然换行。如果限制行数，仍必须能查看完整标题。

## 5. 纯图标控件

1. 把控件缩减为图标必须同时满足：
   - 图标能清楚表达含义，或操作为用户熟悉。
   - 悬停时出现提示框；必要时添加。
2. 不把“更多账户信息”缩为图标，因为它导航到独立页面。
3. 输入框内的模型选择器可以缩为图标，因为用户经常看到它，也能打开菜单切换模型。
4. 自动化任务中的关联对话也是一个例子。

## 6. 移动端悬停行为

1. 在 `@media (hover: hover)` 下启用悬停效果，与视口宽度无关。它查询的是主要指向设备，而非当前事件；混合输入设备上的 JavaScript 悬停处理器必须忽略触摸事件。
2. 手机点击后不得残留仅为悬停设计的背景、高亮或操作按钮可见状态。不支持悬停时，操作仍保持可见，或可通过明确控件访问。键盘用户能访问并显示相同操作。
3. 保留正常的选中、展开、启用和按下状态及焦点指示。让这些样式独立于悬停能力。不要为了去掉悬停效果而清除焦点；`:focus-visible` 也可能适用于触摸聚焦的文本框。
4. 宽度变化时，控件若仍可见且可交互，就保留焦点。避免仅为改变布局而重新挂载控件。如果聚焦控件隐藏或移除，把焦点移到适当的剩余控件，不要不必要地弹出移动键盘。

## 7. 移动端提示框

1. 移动端不显示仅提供操作名或快捷键等辅助信息的提示框。例如复制按钮省略“复制”提示；点击仍直接执行原操作。
2. 提供补充解释的提示框，移动端必须支持点击显示。例如插件页描述旁的信息提示框。

## 8. 移动键盘

移动端不要自动唤起输入键盘，除非这是明确意图。

## 9. 输入能力与移动端文本框

1. 表现层优先使用 CSS 媒体特性：`(pointer: coarse)` 描述主指针的精度，`(hover: none)` 描述其无法悬停，宽度查询选择布局断点。这些查询不检测物理键盘。绝不根据解析后的 user agent 分支选择布局。
2. 在 `(pointer: coarse)` 下，文本框字号下限为 16px，避免 iOS Safari 聚焦缩放。精细指针保留现有紧凑输入框尺寸。以 `packages/client/ui-plugin-manager/src/client/PluginManagerPage.module.css` 的输入框规则为参考。
