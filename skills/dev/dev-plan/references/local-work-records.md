# 事项跟踪器：本地 Markdown

新增事项和规格统一以 Markdown 文件存放在 `.agents/dev/changes/`，已有记录按真实位置查阅引用；技能自身目录只存方法，不写项目工作数据。

## 约定

- 每个功能一个目录：`.agents/dev/changes/<YYYY-MM-DD-slug>/`
- 规格为 `.agents/dev/changes/<YYYY-MM-DD-slug>/spec.md`
- 较大或需要分工的实现任务可各一个文件，位于 `.agents/dev/changes/<YYYY-MM-DD-slug>/tasks/<NN>-<slug>.md`，从 `01` 开始编号；小需求可在 plan.md 中使用一张切片表，不强制拆文件。
- 当前进展选择一个权威位置：小任务可写在任务文件顶部，多任务可集中在 progress.md。其他位置链接它，不重复维护同一状态；无需固定状态枚举或额外配置文件。
- 进展说明实际已完成与已验证的范围、证据和版本、剩余部分、当前阻塞与下一步。前置产物可用才写可实施；本机实现、整合通过和发布完成按实际证据分别说明，不预填通过。
- 评论和对话历史追加在文件底部的 `## 讨论记录` 标题下；过期结论留作历史并注明被什么替代，不与顶部当前状态并列。恢复时核对实际代码和证据，沿用仍有效结果，不重做已有工作。

## 当技能要求“发布到事项跟踪器”

在 `.agents/dev/changes/<YYYY-MM-DD-slug>/` 下创建所需文件；已有任务则更新原记录，保留标识和有效引用，不因重新规划而重建整套文件。

## 当技能要求“获取相关任务”

读取引用路径处的文件。用户通常会直接提供路径或事项编号。

## 探路操作

供大型需求的决策地图使用。**地图**是一个文件，每项任务对应一个**子文件**。

- **地图**：`.agents/dev/changes/<YYYY-MM-DD-slug>/map.md`，正文由笔记、目前决定和迷雾组成。
- **子任务**：`.agents/dev/changes/<YYYY-MM-DD-slug>/questions/NN-<slug>.md`，从 `01` 开始编号，正文写问题。用普通文字记录工作方式：研究、原型、访谈或前置操作；并记录负责人、当前进展和答案位置，不要求固定字段。
- **阻塞关系**：顶部附近的一行 `依赖：NN, NN`。当列出的所有前置问题都有可核对的答案时，解除阻塞。
- **前沿**：扫描 `.agents/dev/changes/<YYYY-MM-DD-slug>/questions/`，寻找开放、未被阻塞且未被认领的文件；编号最小者优先。
- **认领**：并行工作时由协调者分配唯一负责人，每人只写分配的问题和研究文件，地图与共享进度由协调者更新；已有跟踪器按其认领机制执行。单人工作无需额外锁或状态系统。
- **解决**：在 `## 答案` 下追加已证实答案，把进展记为已解决，再把上下文指针——要点加链接——追加到 `map.md` 的目前决定。
