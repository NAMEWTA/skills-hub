# 接入 Home 与用户配置

交付可回读的仓库登记和用户实际要求的配置。项目地图按需查看，明确要求导出时才保存。用户选定的 Home Repo、skills-hub 源码仓和目标项目分别有自己的职责；Home 不等于操作系统用户目录。保留已有权威资料和当前授权，不为相同设置新建第二份真源。

## 先选择本次分支

只收到 `$home-setup` 时，按下表的 Git、入口、登记和派遣参考只读检查现有 Home，报告 Git 根和白名单、入口、登记、默认派遣方式、默认 team 的状态，请用户选择完整初始化或具体操作。随后只收到项目清单时，完成登记，并在交付时说明已发现的其他缺项。用户已经要求完整初始化时，项目清单作为同一任务的登记输入，继续处理根入口、Git 和派遣默认值。

| 任务 | 必读方法 | 产物 |
| --- | --- | --- |
| 完整初始化 Home，含已有 `.git` 的目录 | [Git 基线与换机恢复](references/git.md)、[根导航与交付](references/registry.md#根导航与交付)、[派遣与团队初始化](references/dispatch.md)，有项目时读[登记方法](references/registry.md) | 本地 Git、跟踪校验、根短入口、默认派遣方式与 team、适用的登记 |
| 给已有 Home 补 Git、检查跟踪范围、克隆 Home 后恢复项目 | [Git 基线与换机恢复](references/git.md) | 可提交的 Home 基线或逐项目恢复结果 |
| 只补初始化派遣 | [派遣与团队初始化](references/dispatch.md) | 默认派遣方式与 Home team |
| 登记、移址、解除登记或查看、导出项目清单 | [登记与入口](references/registry.md) | repos.json、按需地图 |
| 保存用户背景、偏好、派遣方式或团队 | [用户配置](references/configuration.md)，涉及派遣时读[派遣与团队初始化](references/dispatch.md) | context 文档或现有 owner |
| 验证本次所需工具或执行位置 | [环境事实](references/environment.md) | 有来源、时间、边界的能力观察 |
| 单独要求补根导航 | [根导航与交付](references/registry.md#根导航与交付) | 根 AGENTS.md 中的 Home 入口 |

普通查询已有足够资料时直接继续，不要求完成全套初始化。只编辑配置时不探测全部账号、不启动任务；同一请求含执行工作时，完成保存后把选用配置交回 `home-workflow`。

## 执行方法

1. 确认用户指定的 Home 根，读取 `./.agents/home/AGENTS.md`，再按导航读取本次有关资料。同一上下文已有同版本可复用；新会话、压缩后缺失内容、文件变化或 Home 根改变时重读。读不到时先只读核对根、文件和安装状态；缺失交实际安装机制补齐，自定义或损坏边界先交 `home-knowledge` 保留内容并整理后重装，不循环要求先读缺失文件。先复用既有要求，只有缺项阻止当前行动时询问具体项。
2. 登记项目时按准确名称调用 `home-route`，核实既有 clone、实际 checkout 与全部 remote。新登记采用 v2，保存名称、完整 URL 列表和明确的主 remote，路径写成 Home 根相对的 `./` 或 `../` 形式。旧 v1 继续读取，改写前按现场核查结果迁移。项目内部知识仍由进入项目的 Agent 读取；不移动仓库、不重新 clone、不切分支。
3. 按本次范围维护 Git、登记或 context。完整初始化包含根短入口的合并或复用，保留用户已有规则；领域 AGENTS 的基础区由安装机制维护，区外知识导航交 `home-knowledge`。完整初始化或补派遣时保留有效旧选择，只询问仍待确定的默认派遣方式或 team。仅补 Git、登记、偏好或换机恢复沿用既有入口与配置。
4. 将用户的配置意图、现场能力观察和本次实际运行证据分开。CLI、模型、推理设置和派遣技能不设固定候选枚举；未知值不传入工具。
5. 用包内工具校验、保存，再回读所改字段、路径和作用范围。地图按需从登记生成，显式导出时才保存 `repos.md`。
6. 按 Git 分支验证真实仓库根、跟踪状态和随仓技能，或从同仓技能恢复登记项目。初始化时回读根指针与其实际目标，核对当前所选宿主的发现能力；当前运行宿主是已选环境，无须再问品牌。报告文件保存、宿主发现、暂存、提交与项目恢复各自的实际结果。保存配置只表达用户选择，执行时再核对能力。

先确定派遣方式，再选择 Home team，最后应用 repo ID 对应的执行者配置与本次覆盖。Home 默认只约束 Home 发出的直接任务，项目再派遣按当地规则，除非用户明确指定全链范围。

## 工具与模板

登记工具只读命令先行，完整参数与失败处理见登记方法：

```sh
node <本技能目录>/scripts/registry.mjs inspect --home "<Home 根>"
node <本技能目录>/scripts/registry.mjs validate --input "<候选登记.json>"
```

使用 [repos schema](assets/repos.schema.json)、[本机覆盖 schema](assets/local.schema.json) 校对输入；只有路径可以进入 `local.json`。秘密保留已有安全位置的引用，不写入登记或配置。

按真实内容选择 [profile](assets/profile.md)、[preferences](assets/preferences.md)、[派遣方式](assets/dispatch.md)、[Home team](assets/team.md) 和[环境记录](assets/environment.md)。按需要填写模板，已有等价文档原地维护并引用。

## 完成条件

完整初始化分项报告 Git 跟踪范围、根与领域入口、当前宿主的发现证据、项目登记、默认派遣方式和默认 Home team。标明已验证、待确认、有冲突或本次没有项目需要登记的项。核查已配置默认值的引用和适用范围。

登记有稳定 ID、明确用途和核实过的身份；地图可由登记重建；自定义内容和其他领域资料保留。配置变更可与用户要求逐项对回，实际能力与运行结果有独立证据。所选宿主确需接入时按根导航方法做最小适配，普通安装和局部操作不改宿主配置。不得创建项目接收器、全局默认、会话账本或自动后台服务。
