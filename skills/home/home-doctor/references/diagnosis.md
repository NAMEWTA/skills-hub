# 诊断与修复路由

## 有界只读检查

从用户实际问题选择范围，读取有关 Home 记录。工具只递归 Home 自己的 `.agents/home/` 普通 Markdown 做结构链接检查，不跟随数据目录 symlink，不读取链接指向的项目正文。超过单文件 1 MiB 的资料报告未检查。一次结构遍历最多读取 2000 个 Markdown、总计 8 MiB，深度 10、目录 1000 个；达到预算时返回 complete: false 与具体未覆盖项，不把截断后没看到问题当没有问题。

对 Home 外的 Markdown 指针只记录为外部入口，不能用文件存在或摘要替代项目证据。项目路径/身份按 `home-route` 取得，只检查登记范围，不遍历磁盘发现项目。技术事实或当前代码关系由项目当地 Agent 返回。

没有 Home 资料、也未在同仓安装 Home 技能的目录，可以保持未初始化状态。已有 `.agents/home/`，或 `.agents/skills/home-*/SKILL.md` 是实际同仓普通文件时，必读 `AGENTS.md` 必须可读。只存在相似目录名、未选用的其他 domain 或外部符号链接不作为已安装 Home 技能的证据。工具不会因此创建入口或其他资料。

主入口缺失、空白、不可读、目录/链接等异常类型以及基础区损坏都有具体 findings。基础区只接受唯一一对精确 v1 起止标记，顺序正确且各自独占一行，支持 LF、CRLF 和文件开头的 BOM；缺半边、重复、嵌套、未知版本和空基础区均不能判为健康。裸名称的普通讨论不是标记。完整方法由 `home-knowledge` 维护，doctor 只检查这些结构条件。

缺文件、已知旧官方模板和合法标记内空白可由所选安装方法补齐。空文件、未标记自定义文档和损坏标记会被安装器拒绝，先交 `home-knowledge` 按入口维护方法核对版本、保留用户内容并整理明确边界，再重复安装。未知版本先核对匹配工具或明确兼容依据，原文保留。诊断不自动降级、不改标记或全文覆盖。缺少尚未创建的 profile、SOUL、历史、登记或未选用的派遣工具，不自动构成故障；已写入正文的真实 Markdown 指针失效时再报告断链。

## 检查项与 owner

| 问题 | 核查方式 | 修复 owner |
| --- | --- | --- |
| repos JSON、未知版本、重复 ID、非法 local 覆盖 | 结构报告后由 setup 完整 validate | home-setup |
| 已导出 repos 地图的来源 revision 不同或目标由用户维护 | 结构脚本读生成标记，setup inspect 比较完整派生内容；没有导出地图是正常状态 | home-setup |
| 默认路径、真实 checkout、remote、worktree 不符 | route 的实际只读 Git 核查 | home-setup 维护登记，home-route 提供解析依据 |
| 必读入口缺失、合法标记内空白或旧官方模板 | 核对本域目录、实际已安装技能及入口结构，保留现场 | 用户所选安装方法 |
| 空文件、损坏基础区标记 | 先核对版本与已知边界，保留用户内容，安装器不会直接覆盖 | home-knowledge 处理明确迁移，再交安装方法 |
| 未知基础区版本、不可读或异常文件类型 | 核对匹配工具、文件与当前读取条件，保留现场，不降级 | 用户所选安装方法 |
| 自定义导航或 SOUL 的语义/引用、未标记自定义入口 | 按所在文件解析真实相对引用，结构结果不代替语义判断 | home-knowledge |
| profile/preferences、派遣方式或 team 的配置引用失效 | 核对配置 owner 与实际相对引用 | home-setup |
| notes、inbox、exclusions 的断链 | 只报路径与影响，不判结论真假 | home-knowledge |
| history/归档的断链或接续线索缺失 | 只报结构；时间、去重与语义回查交 owner | home-history |
| relations 证据引用不可达 | 报结构位置；当前关系由项目取得新证据 | home-map |
| coordination 主题目录引用缺失或待重建的状态视图 | 核对编号文件与原件，不用旧视图推断派遣状态 | home-tasks |
| 旧协调页引用缺失或责任入口不清 | 核对当前目标与直接负责人入口 | home-workflow |
| 本次必要技能本体/发现别名异常 | 检查 canonical、lstat/readlink/realpath 和同仓目标 | 用户所选安装方法 |
| 投递、就绪、恢复、回收不明 | 使用原派遣记录与原方法 | 实际选用的当地派遣技能 |

生成索引和地图是派生资料，不通过手写第二套权威内容“修好”。索引缺失时原正文仍可查询；重建不刷新事实核查时间，也不从 archive 自动恢复当前规则。

## 链接与同仓技能检查

`--require-skill` 只接受当前明确需要的准确技能名，检查 Home 的 `.agents/skills/<name>/SKILL.md` 与 `.claude/skills/<name>`。标准本体是同仓普通目录，Claude 别名是逐技能目录 symlink，真实目标必须等于该本体。

同名普通目录/文件、错误链接、错向断链或链接父目录都是具体冲突，保留原内容。不要用 `--replace` 绕过链接保护，不创建整目录 symlink，不把链接改到另一仓库或 npm 缓存。升级、补链或删除依所选安装方法的原有事务处理；doctor 不重复实现安装器。

用户要验证实际工具发现时，让实际选定的 CLI 执行最小读取并记录来源；单纯 realpath 相等只证明文件系统关系。Home 只检查本次实际需要的能力，不维护固定的全 CLI 测试矩阵。

## 修复与复验

先给出具体文件/ID、观察、影响和建议 owner。主入口缺失时仍能运行本包的最小诊断，不要求先加载缺失文件或安装其他 owner。默认只诊断；当前任务已授权修复时，直接把基线、原件位置和范围交 owner，保留已有决定，不重复征求相同许可。修改由 owner 先读、合并、写后回读；不批量删除历史或自动迁移知识。

对未取得新项目证据的问题保持待核实，不能把文件时间或生成时间当事实验证时间。只复验受影响项，并报告已修复、仍受阻和未检查范围。不得把诊断脚本退出 0 或没有结构错误写成项目功能、Agent 生命周期或所有知识均健康。
