# 技能编写指南

编写技能时，先确定它负责的任务和交付结果，再组织完整方法与按需读取的资源。维护范围和上游适配原则见[开发约束](development-constraints.md)。

本文的领域命名、简化 frontmatter、入口预算和资源可达性规则适用于自有 `skills/`。独立上游中文包按[独立技能约定](upstream-skills.md)保留原结构、必要 metadata 和工具，两类统一安装到 `.agents/skills/<技能名>/`。

## 一个技能解决一个可识别的任务

先核对[方法归属](dev-method-ownership.md)或对应领域的归属文档。已有技能能够负责时修改该方法；有独立触发条件、成果和调用价值时再建立新入口。

名称使用小写连字符的 `领域-动作`，与目录相同。description 说明用户什么时候需要它、要解决什么、容易与哪些任务混淆。写具体触发分支，不把“所有开发、设计和审查”当作万能范围，也不把执行步骤塞进描述。

自有技能的 frontmatter 只保留 `name`、`description`：

```yaml
---
name: dev-example
# 下方是结构示例，实际描述须改为这个技能的真实任务。
description: 描述可识别的任务、成果和必要边界。
---
```

技能正文使用中文，保留真实命令、文件名、API 和配置键。需要 UI 元数据时放在 `agents/openai.yaml`，默认提示点名本技能。名称、描述和完整方法的职责必须一致。

## 定义成果与判断方式

先说明用户会得到什么，给出可观察的完成条件。步骤应明确输入、适用前提、行为、失败分支和返回结果；模型已经熟悉的普通操作无需逐次列出点击或思考过程。

用条件表达不同规模。小修改可以只有简短规格、实施和验证；复杂任务再使用设计决定、垂直切片和多轮集成。已完成的决定和已有授权继续沿用，不能让新技能重启同一需求或重复审批。

如果技能只返回某个阶段的产物，写清谁接续。通用任务负责人仍负责集成和最终结果，被调用技能不另造平行计划或日志。

## 完整内容与按需加载

| 位置 | 内容 |
| --- | --- |
| `SKILL.md` | 任务入口、完成条件、关键边界、资源读取条件 |
| `references/` | 完整方法、参数、表格、例子、反例和工具说明 |
| `assets/` | 需要填写或复用的模板、示例产物和必要资产 |
| `scripts/` | 确定性且值得自动化的操作 |
| `agents/` | 宿主需要的 UI 元数据 |

每份自有 Markdown 资源必须从 `SKILL.md` 沿本地链接可达。主分支直接指向完整方法，大量支撑例子可用主题索引；不要求每次任务读完全部资源。移动内容后同步修改读取条件和链接。

同一方法只保留一份完整正文。跨技能按准确名称调用其入口，不用包外相对链接或复制整套依赖。调用时提供目标、已有产物和证据，完成后回到原任务。缺少宿主调用工具时读取已安装文件，不伪造执行。

自有 `SKILL.md` 正文最多 500 物理行、12000 个非空白 Unicode 字符，description 最多 1024 字符。字符不是 token；预算不限制参考资源的知识总量。精确计数和超限处理见[质量规则](skill-quality.md)。

只有确定性、重复且容易出错的步骤才增加脚本，明确依赖、输入、输出和退出行为。模板提供最小有用结构，允许按任务裁剪；没有事实支持的字段不强制填写。

## 中文整合规则

按原文逐份完整翻译，保留步骤、条件、表格、数值、例子、反例及代码语义。中文底稿用于核对完整性，实际运行包再做本项目所需适配；两者职责不同。

运行版逐处解决不兼容指令：改成本地资源路径，使用实际可用的调用能力，把项目资料写入对应领域，保留真实工具身份和失败条件。不能只加顶部声明而让下文继续要求相反行为。

自有技能采用本项目的中文执行语境，第三方来源、署名、外部参考和改造声明统一见[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。原生法律文本按声明要求保留，不能用翻译替代。独立上游包的允许适配范围见[上游独立技能](upstream-skills.md#可以怎样改)。

## 工程实践与分层验证

按行为和风险选择规格驱动、TDD、原型、回归或形式化方法。保留方法本身的机制和适用条件，不把一个成功案例或个人偏好固化为全部任务的固定路线。

结构检查验证包装和引用，行为检查验证具体工具及场景，全文对照验证内容忠实性。形式化结论需要明确模型、属性和边界；用户确认也须绑定具体产物与范围。各类证据不能互相替代。

## 项目记忆

技能保存可复用的方法，项目记录保存具体事实、意图和决定。本次任务进度、账号秘密、业务事故和产品实现细节不写回通用包。代码能直接表达的事实优先引用源码，笔记保留难以恢复的理由和边界。

## 修改后的检查

```sh
node scripts/check.mjs
node scripts/check-skill-quality.mjs --report
```

修改安装、校验或运行行为时执行完整检查和受影响专项，见[验证指南](validation.md)。修改触发描述、路由或读取条件时，另用自然请求核对实际选择和方法读取。结构通过不等于技能已经完成实际使用验收。

## 领域持久化路径

自有技能的项目记录使用对应领域根，dev 为 `.agents/dev/`，system 为 `.agents/system/<host>/`，ops 为 `.agents/ops/`。`.agents/skills/` 只存安装包。领域导航由安装器管理，业务内容按任务建立，详见[持久化规范](persistence-roots.md)。

已有规格、原型、交接和知识文件保留真实位置；移动资源时更新入链，不借技能升级搬迁业务记录。活跃 change 与归档分类按[知识与归档](knowledge.md)处理。
