# 实体关系渲染器

将 `diagram_type: "erd"` 的 JSON 文件渲染到标准 Archify HTML 模板中。

```bash
node archify/renderers/erd/render-erd.mjs input.erd.json output.html
```

渲染器使用随包独立校验器，按照 `archify/schemas/erd.schema.json` 校验输入，不需要安装依赖。

如果省略 `output.html`，渲染器使用 JSON 文件的 `meta.output`，或回退到当前工作目录中的 `erd.html`。

渲染后运行产物检查器：

```bash
node archify/scripts/check-render-output.mjs output.html
```

<a id="input"></a>

## 输入

ERD JSON 文件必须设置：

```json
{
  "schema_version": 1,
  "diagram_type": "erd",
  "meta": { "title": "Order management schema" },
  "entities": [],
  "relationships": [],
  "cards": []
}
```

实体通过 `label` 承载表名，通过 `attributes` 承载字段，并在带状网格中占据一个 `row`／`col` 单元。盒子高度随声明字段数量变化，因此布局不需要手工测量尺寸。字段的 `key` 接受 `pk`、`fk`、`uk` 或它们的列表：关联表的字段常常既是主键的一部分，又是指向同一父表的外键，只声明一个角色会隐藏另一个。每个角色各绘制一个徽标，色调来自其图例系列；同一角色出现两次只绘制一次；键列按该表最宽的徽标排列测量——不会窄于共享宽度，徽标需要时会更宽。每个 `fk` 角色，无论单独还是在列表中，还必须在 `references` 中以 `"entity.attribute"` 指定目标，并按已声明实体和字段检查该目标。

关系按 `from` -> `to` 阅读，两端都使用乌鸦脚表示法。每端连接到一张表；它位于某行旁边，并不表示指定了某个列。用属性的 `references` 指定精确目标列，用关系标签区分并行关系。乌鸦脚朝向其描述基数的实体展开：脚趾位于表边，顶点沿线向后退一个脚长，因此不会被误读成指向表的箭头。两端分别声明自己的最大基数：`fromCardinality`/`toCardinality` 接受 `one` 或 `many`，且为必填，因为作者没有声明的最大值会成为图擅自编造的事实；`fromOptional`/`toOptional` 在顶点外添加可选圆圈，把该端最小值从一降到零。`identifying: false` 绘制非标识虚线，并由它决定虚线样式：若 `variant` 同时要求把关系画成实线，schema 会拒绝，因为实线表达的事实恰好相反。对于每条标识关系，variant 仍负责选择强调色。

<a id="layout-and-routing"></a>

## 布局与路由

`layout.mode: "grid"` 按 `row`/`col` 放置各实体。每个列索引采用该列最宽实体的宽度，每个原始行索引采用该行最高实体的高度，因此同一带内的框无需手工测量就能对齐，空索引则留下路由通道。`pos` 可为有限例外覆盖所在单元格。

从 `row`/`col` 开始，省略 `layout.entityW` 和 `entities[].width`。自动网格从每表 240 单位起步，在正常字号下按各表字段名、类型和键徽标扩展宽度。表的显式 `width` 或继承的 `layout.entityW` 保持固定。固定 view box、固定表位置，或作者编写的路由、途经点、通道、标签点，也会阻止自动尺寸调整，因为尺寸变化会移动表边和通道。

关系经过其他类型化渲染器使用的正交路由器（`../architecture/routing.mjs`），因此遵循相同契约：共享实体上的自动端口分散、端点侧契约、路由节奏下限，以及通用 Clean Flow 门禁。ERD 是调用方，不是 fork：它传入 `sideFor`、`maxPortSpacing`、`preferredCandidates` 和 `compositionFloors: false`，读取不依赖规划的 `inferredSides` 与 `ports` 映射。每个选项省略时均不产生影响，因此 Architecture 和 Lifecycle 可以逐字节保留路由。本渲染器有五项特有差异：

- 与其他非 Architecture 类型一样，端点优先横向解析：表并排时，关系从左右进出；只有同列时才回退到顶部／底部端口。共享路由器默认采用 Architecture 的主轴推断，如果某目标纵向距离恰好大于横向距离，就会把一个扇入拆为两组。
- 同一侧的自动端口最多相距 24 个单位，因为基数符号高 14 个单位：如果使用共享的 14 单位间距，同一表边上的两个乌鸦脚会像一团污点。该间距是上限，不是下限——一侧只能容纳 `(extent - 32) / (ends - 1)`——因此当表的关系端点多于一侧空间所能容纳时，会报 `layout/marker-capacity`，指出表、端口侧、间距及三种解决办法。
- 本来会共享同一通道的关系获得确定性的轨道偏移，因此平行外键绝不会落在完全相同的通道线上。
- 共享一个实体侧（外键扇入或父表扇出）和一种标记样式的关系，会捆绑到该侧外部的一条主干：每条关系对应一个短分支的一条总线，替代一束平行轨道。主干桥接一个端口步长的未覆盖总线，使上述端口分散仍可读成一条线。主干仅为优先路由——若某分支违反端点契约或裁切实体，就回退到普通路由族并保持未捆绑；任何作者指定项（`route`、`via`、`labelAt`）都保留自己的线。逻辑路由仍经过主干，因此每道门禁、每个标签和布局报告都看到完整几何。
  自动补出的主干桥接还会检查无关关系及已接受的其他桥接；出现交叉、接触或
  重叠时保留分离的主干段，避免把独立关系画成同一条总线。检查按双方描边的
  半宽之和留出间隔，并计入无关关系的显式 `width`；中心线未相交但描边接触
  也会阻止桥接。这个回退不移动
  实体、显式途经点或端口，也不改变关系基数；无障碍的同簇分支仍可共享主干。
- 实体盒子是不透明障碍。当第三个实体位于两个对齐锚点之间时，共享障碍网格会绕行；仍无法避开无关实体的路由，以 `clean-flow/edge-through-node` 失败，而不是画穿盒子。

渲染器还报告 ER 特有诊断：`from`／`to` 中未知实体、未知字段名和无法解析的 `references`、重复字段名、自引用关系、实体盒子重叠，以及文字无法容纳在声明实体宽度内的行。

如果两个关系符号恰好落在同一表端口，即使其推断连接侧仍有空间，制品检查也会给出建议。Finalize 回执列出每条关系及其 `fromSide` 或 `toSide`。为其中一条关系选择清楚的替代连接侧；如果有助于保持路由清晰，也调整另一端。如果换侧使路由纠缠，就移动相邻表，腾出空间。保留现有基数，以及本来就绘制独立符号的有效共享主干，并重跑 finalize 检查新布局。

<a id="domain-bands"></a>

## 领域带

`tag` 命名表的功能域。当带该 tag 的表填满一个实心矩形网格区域——其包围盒中的每个单元格都由它们之一占据——该域绘制为一条带。单行、单列和填满的矩形块表达相同主张（L 形或对角线不算）；单表域是该主张最小的形式。带根据已摆放盒子测量，并以 tag 作标题；这让分组 schema 一眼可读：读者看到的是块，而不是六个同等权重的盒子。

某 tag 的成员没有填满一个矩形时，不会获得域带，因为包住它们的带会圈进该域不拥有的单元格，声称一种与布局矛盾的分组。域带是唯一绘制域名称的位置，因此渲染器返回 `erd/domain-not-drawn`，而不是发布表完整但域无法命名的图。将成员移入一个矩形、拆分 tag，或去掉 tag。同一诊断还覆盖其他导致名称缺失的情况：成员放在网格外，因为域带按单元格测量，绝对坐标没有单元格；两个成员位于同一格，此时改由网格摆放检查报告，让作者看到必须移动的节点对；域带内边距覆盖无关表，这会在 `layout.gapX`／`gapY` 小于内边距时发生；或标题不在画布覆盖范围内，这会在 `layout.origin` 离边缘比内边距还近时发生。

表头只显示表标题。它以表自身中心线居中，并约束在用于测量的区间内——左侧为符号预留区，右侧为内边距——因此在共享文字模型的 advance 估计有效时，不会越过任一侧。标题在可读字号下放不进表头时，报 `erd/header-text-capacity`；扩大表宽或缩短标题。除非作者修改，否则保留现有表头和实体尺寸。作者提供的 `sublabel` 不会绘制：它以 `data-node-sublabel` 保留在节点上，也保留在可访问名称中。

<a id="cardinality-ink"></a>

## 基数墨色

乌鸦脚、单竖线和可选圆圈采用主题的弱化文字墨色，而不是共享箭头 token：浅色主题的箭头色叠在表填充上时，对比度接近 2:1，看起来像污点；弱化文字墨色则在两种主题下都超过 3:1 的非文字下限。图例使用相同墨色和描边重量，标签比共享图例默认值大且重一级，因此图例展示的正是图中实际绘制的符号。

<a id="the-legend-band"></a>

## 图例带

默认图例属于生成内容，因此自动画布会调整尺寸容纳它：共享测量决定预留条带能否放下，绘图区按带逐次增长直到容得下。路由或关系标签仍与已摆放图例带碰撞时，这是实际容量失败，应报告诊断，而不是丢弃图例；作者指定的 `meta.viewBox`——固定绘图区——会指出缺少的容量（`legend/vertical-overflow`、`legend/label-too-wide` 或 `legend/content-overlap`，每项都带解决它的修复）。

图例分为两组，中间有分隔线。键条目绘制与字段行相同的徽标；关系条目绘制一条抵达表边的短路由，带标记自身符号。ERD 的 kind 是列键和关系端点，不是节点种类，因此条目不会进入查看器的计数节点 lens，否则每项都会显示错误的零。悬停或键盘聚焦条目时，直接在 SVG 中高亮匹配项：键使其他字段行变淡，并描边匹配徽标；关系端点在所有绘制位置重着色该符号，并使不包含它的路由变淡。静态导出保留普通图例。

高于一屏的画布是正常 schema，不是缺陷。自动画布声明 `data-reader-fit="intrinsic-height"` 和 `data-reader-min-text="7.5"`，允许阅读器把较高 schema 缩窄到页面可容纳的程度——绝不低于声明的最小值，因此字段行保持可读，超过该高度的内容滚动；作者指定的 `meta.viewBox` 保留作者的适配契约。字段行、类型和键符号的文字自身携带 `data-detail="context"`，因为阅读器根据声明级别的文字计算图表尺寸——如果仅在行组中把字段标为 context，高 schema 中它会被缩到可读下限以下。

缩窄是底线，不是目标。同样的表和字体，随包十一表示例在 1440x900 测量时为 1230x678 画布，阅读器以完整 1346px 渲染（比例 1.09），字段类型最终为 11.5px。同样的表若分为四个横向域，则形成 910x874 画布，阅读器缩窄到 777px（比例 0.85），同样类型最终为 9.0px。能铺满阅读器宽度而不被缩窄的横向排列，仍需用文字尺寸换取所需列数，因此这里提供的是一对测量结果，而不是断言哪个轴正确的规则。

<a id="typography"></a>

## 字体排印

表行是供读者扫读的文字，因此 ERD 节奏比通用图更宽松：表头 30 单位、行高 20 单位、表名 13 单位、字段名 11 单位、类型 10.5 单位。类型使用与字段名相同的文字颜色，因为它是数据，不是旁注：使用弱化色时，它与表填充色的实测对比度为 3.98:1，低于 4.5:1 的文本下限，所以在审查中显得淡。文字放不下的行会产生诊断，不会静默截断单元格。`erd/attribute-text-capacity` 标明字段，并给出该行所需最小宽度。应扩宽表，或在网格可自动定宽时移除固定网格宽度。保留字段名、物理类型和键角色。

字段行、类型和键符号各自在文字自身携带 `data-detail="context"`，不只放在行组上：查看器阅读器根据声明级别的文字计算图表尺寸，否则高 schema 会被缩到可读下限以下。自动画布还声明 `data-reader-fit="intrinsic-height"`，让高于一屏的 schema 能以可读大小滚动，而不是被挤压到一屏；作者指定的 `meta.viewBox` 保留作者适配契约。

关系标签使用 9 单位字号和关系自身强调色，遮罩按相同因子测量，因此带标签的 schema 能让语义文字保持在可读下限之上。它们是图表中最小的文字，并且是语义数据：发生碰撞就应修复（移动标签、加宽通道），绝不能作为删除措辞的理由。

<a id="reading-a-schema"></a>

## 阅读 Schema

ERD 也是表目录。Schema 超过 8 张表或 50 个字段时，从 `meta.quality_profile: "standard"` 开始，以完整字段可见性为优先；只有分组布局确实可读后才提升到 `showcase`。在 `entities[].attributes` 中包含每个物理列，保留 SQL 类型；schema 没有独立注释字段时，将来源注释以 `SQL_TYPE｜中文备注` 保留在类型字符串中。例如，即使应用代码限制了某 SQLite `TEXT` 列的取值，它仍应保持 `TEXT`。这些值有助于解释领域时，记录在卡片中。渲染器在默认 `read` 层级显示 ERD 属性行，因此字段不依赖悬停或聚焦。卡片仅用于补充约束、推断关系和领域规则；绝不能用它隐藏完整表。

分配网格单元前，先按功能域分组表。同一域成员使用相同而简洁的 `tag`，并保持在一段连续、不交错的排列中——相邻列构成的一行，或相邻行构成的一列；域带即按这段排列测量。需要同时看见整个 schema 时，为每个域分配独立一列：域从上到下读取，相邻域关系从左到右，画布保持足够宽，使阅读器能以完整字号显示。较宽实体对路由器而言是更难绕过的高墙，1440x900 下仍须满足投影文字最小值，因此优先采用紧凑分组网格，而不是缩小或隐藏字段。
