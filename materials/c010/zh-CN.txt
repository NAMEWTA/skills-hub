# AGENTS.md

DeepSeek Harness 是完全基于插件的 Cordis Agent 运行框架。修改 `packages/` 前阅读 [docs/architecture.md](docs/architecture.md)；文档遵循 [docs/AGENTS.md](docs/AGENTS.md)。

## 稳定版之前的 API 与已发布 Session 数据

公开 API 尚未稳定；修改时更新全部消费者。遵循[版本与状态](docs/session-format-status.md)和[类型确认](docs/cookbook/reviewing-persistence-type-changes.md)。[相邻版本迁移](.agents/notes/implemented/architecture/2026-08-31-released-session-format-migrations.md)可以增加按版本命名的后继版本，但不能移动、覆盖或删除已提交的世代；前代存在并不意味着支持回退或降级。SQLite 使用单调递增的 `SCHEMA_VERSION`。

确认[已声明的持久化类型变更](docs/cookbook/reviewing-persistence-type-changes.md)。

每项外部可感知的破坏性变更，都立即记录在[升级指南](.agents/skills/dsh-create-upgrade-guide/SKILL.md)中。

**应用启动。** 只有 `dsh` 配置档可以启动受支持的 Node 应用；禁止包可执行入口、演示以及公开 SDK argv 逃逸入口（[规则](docs/architecture.md#application-launch)）。

## 命令

```sh
pnpm install            # pnpm 工作区，node >=24.9
pnpm run clean           # 删除构建产物及已删除包的安全残留
pnpm run test           # 单元测试
pnpm run test:coverage  # CI 覆盖率检查：packages/*/*/src 每个文件 100%
pnpm run test:e2e       # 真实 API 测试；没有 DEEPSEEK_API_KEY 时自行跳过
pnpm run test:expected  # 由各负责模块就地维护的进程预期
pnpm run test:snapshot  # 通过交付配置档进行无密钥录制会话重放；过滤：-t <name>
pnpm run test:snapshot:record  # 重新记录预期输出，需要密钥
pnpm run typecheck
pnpm run lint
pnpm run duplication    # 跨文件 TypeScript 重复代码检测
pnpm run build          # 并发执行 build:artifacts 与 build:check
pnpm run build:artifacts # 产物：tsc 生成 lib/types，tsdown 打包运行时和 Web
pnpm run build:check    # 基于当前 build:artifacts 输出检查聚合测试与脚本的类型
pnpm run hygiene        # publint、工作区/包/依赖检查与 NodeNext 消费者检查
pnpm run check:windows-wine  # 仅在诊断已知 Windows 失败时运行，需要 wine；CI 负责此信号
pnpm run doc-sync       # 文档检查（scripts/run-gates.ts）
pnpm run test:docs      # 快速文档检查，无需构建，使用 doc-quick 聚合
pnpm run website:build  # VitePress 构建，同时检查死链接
pnpm dsh --profile headless "任务"  # 从源码运行单项任务，需要 DEEPSEEK_API_KEY
pnpm run demo:ptc -- "任务"  # 无界面 PTC 模式运行，需要密钥
pnpm run dev:web | dev:desktop  # 先 build:artifacts 再启动；Web 还在编辑时重建客户端包。start:web | start:desktop 跳过构建
make web|dev-web|desktop|dev-desktop|build  # 相同命令；ARGS='--no-open' 转发选项
```

### 宿主沙箱失败

必须执行的 `gh`、`pnpm`、构建、测试或生成器命令，若因沙箱阻止凭据、网络、IPC、监听或嵌套 `sandbox-exec` 而失败，保持命令不变，以最小宿主权限提升重试。必须有沙箱导致失败的证据；不绕过测试失败或产品沙箱。

### 在本地运行相关检查

推送前遵循 [dsh-pre-push-checks](.agents/skills/dsh-pre-push-checks/SKILL.md)，只报告实际运行的命令。`gh stack sync` 后立即验证；检查通过前不合并。

- 证据匹配受影响界面：聚焦行为测试、模型或用户输出快照、文档用 `doc-sync`、发布路径用构建后冒烟检查、提供方用真实 API 端到端测试。
- 不默认运行全套，也不为了提交或推送重复已通过检查。CI 负责全面覆盖与平台矩阵；只有用户明确要求、诊断 CI，或确实无法缩小的仓库级变更，才在本地全面预演。
- CI 覆盖率检查是 `test:coverage`，不是 `test`（[原因](docs/testing.md)）。
- 开发时用 `build:artifacts`；声称完成前，在最新 `build:artifacts` 后运行 `build:check`，或执行 `build`（[布局](docs/development.md#typescript-project-layout)）。
- **Web 浏览器自动化和 GIF 录制：** 用 `pnpm dsh web --patch apps/web/tests/pin-browse-picker.overlay.yml` 启动，使用[页面内目录选择器](apps/web/tests/pin-browse-picker.overlay.yml)；只有明确测试原生选择器行为时才省略覆盖。

## 密钥与 .env

Windows 打包与签名：[必读](apps/desktop/windows-signing/README.md)。

真实 API 测试与演示读取 `DEEPSEEK_API_KEY`、可选 `DEEPSEEK_BASE_URL` 及根 `.env`。cordis.yml 在插件 `config` 和条目 `disabled` 下允许 `!!js`，不能写 `!js`；其他元数据保持字面量，因此条件组合也使用覆盖文件（[入门](docs/cordis-primer.md#loader-configuration)）。不要提交凭据。CI 端到端测试没有密钥时跳过；[testing.md](docs/testing.md) 负责密钥政策。

## 约定

- 包使用 `@deepseek-ai/dsh-<name>`；内置依赖[重新指定作用域](docs/rescope.md)，并设为 `private: true`。Harness 包在 `peerDependencies`/`devDependencies` 声明 `@deepseek-ai/cordis`。工作区依赖段中，DSH 用 `workspace:*`，vendor/native 用 `workspace:~`（[规则](.agents/notes/implemented/process/2026-08-10-npm-release-sequences.md)）。
- 全部使用 ESM（`"type": "module"`）。跨包使用包名，本地相对导入用 `.ts`。配置子进程在普通 Node 下运行构建后的 `lib/`；源码回归使用其声明的启动器（[测试政策](docs/testing.md#test-subprocess-launch-modes)）。`dsh` CLI 源码启动经过 tsx 的仅 ESM 钩子（`node --import tsx/esm`）；它触达的模块必须保持 ESM，不能仅导出 CJS（[源码启动约定](.agents/notes/implemented/architecture/2026-07-29-dsh-source-launch-tsx-esm.md)）。Raw/Web `cordis.yml` 中裸插件必须出现在其解析器清单的 `dependencies` 中，`verify-cordis-config` 负责检查。
- **注册是副作用：** 每项贡献经过 `ctx.effect()` / `ctx.on()`；注册表的 `register()` 直接或通过文档规定的注册句柄返回释放函数。
- **有类型事件使用声明合并**和可合并扩展映射。事件 JSDoc 需要 `@mode` 和载荷 `@param`。公开服务方法说明参数和非 void 返回值。`SessionEventMap` 成员在读取时必须处理，除非封套含 `ignorable: true`。只有现有判别符无法阻止不安全解读时才增加 `SESSION_FORMAT_VERSION`；同版本变更要求安全读取行为（[评审](.agents/notes/implemented/process/2026-10-08-session-reader-compatibility-review.md)）。
- **按判别标签分支。** 封闭联合以 `assertNever` 结束；可声明合并扩展的联合落到有文档说明的默认分支。
- **瀑布式监听器必须调用 `next()`** 以委派；不调用而直接返回会短路调用链（[语义](docs/cordis-primer.md#cordis-waterfall-semantics)）。
- **模型可见 ⟺ 已记录：** 到达模型请求的内容都必须能从会话日志重建；新增模型可见输入需要会话事件。
- **会话投影：** 创建、扩展、评审投影，或把折叠辅助函数迁移为投影时，遵循 [dsh-session-projection](.agents/skills/dsh-session-projection/SKILL.md)。
- **使用插件，而非修改循环：** 新行为放在有文档的扩展点；修改 `agent-loop` 必须更新 docs/architecture.md。
- **一个能力分界包含 Service Definition / Service Provider / Consumer 三种角色。** 它必须完整，不是单一角色；只有角色独立演进时才拆分（[术语表](docs/glossary.md#capability-seam)）。
- **优先采用有人维护的依赖，而非自行重写，** 前提是它们确实能删除本项目负责的代码和测试（[政策](.agents/notes/implemented/process/2026-07-26-dependencies-over-hand-rolling.md)）。
- **包边界上显式优于隐式：** 默认值处理是负责实现中的显式 `resolve(request): Spec` 步骤，不能藏在 `run()` 的 `?? default` 中，`dsh-shell` 的 request/spec 拆分是模板。
- **插件不硬编码可调参数：** 随部署变化的选项是经过校验的 `Config` 字段，可从 cordis.yml 修改；`DEFAULT_*` 常量或测试钩子不算可配置。协议常量、外部规范和安全不变量保持固定。
- **错误配置明确失败：** 自包含问题在加载时失败，否则在最早可解析时点失败；不悄悄跳过缺失引用对象。
- **跨边界不透明 ID 使用品牌类型**，即 `dsh-brand` 的 `Branded<B>`，不使用裸 `string`。
- **信任同进程有类型边界上的 TypeScript。** 不仅因为静态接口要求的值而增加运行时验证、回退行为或恶意输入测试；解析器/配置、队列、模型/工具 JSON、持久化/文件、worker、进程和传输边界才做验证。
- **不新增到 `unknown` 的断言**，包括 `as unknown` 或 `<unknown>`。保留或减少精确遗留基线；替代实现使用有类型值或验证（[规则](.agents/notes/implemented/process/2026-09-19-no-unknown-casts.md)）。
- **源码层与产物层不混用。** 静态检查和测试通过 tsconfig `paths` 把工作区导入解析到 `src`，并能在干净目录上通过；消费构建 `lib/` 的检查声明此依赖（[布局](docs/development.md#typescript-project-layout)）。
- **显式保留编译器视面。** 同时包含 Host 与 Client 程序的包提供各视面的叶配置，并使用仅包含 solution 的根配置；仓库级程序引用视面配置，不引用根 solution（[布局](docs/development.md#typescript-project-layout)）。
- **错误处理：** 使用带类型、结构化失败，以及本地化、可操作的报告。定义处理责任、影响隔离和失败保证；停止依赖工作，并明显报告不可信状态或未知结果。遵循 [dsh-error-handling](.agents/skills/dsh-error-handling/SKILL.md)。
- **空 `catch` 说明错误及原因，** 且 `try` 只保留一条语句。
- **注释保持局部。** 不复述代码、不扩展无关注释，也不在局部无必要时解释远处行为（[理由](.agents/skills/dsh-prose-standard/SKILL.md)）。
- **禁用 `prove` + `nance`**（[规则](.agents/notes/implemented/process/2026-08-26-ban-ambiguous-origin-label.md)）。
- **并列值优先保持对称；** 无解释的不对称通常意味着遗漏提取。
- **测试描述行为，而非正确性。** 修改过时行为时同步修改测试，并在 PR 中解释原因。
- **只为长期决策理由创建 Agent Notes；** 机械性或局部编辑免除，包括局部界面变化（[范围](.agents/notes/README.md#when-to-write-one)）。归档笔记冻结，不编辑，也不视为当前权威依据（[归档政策](.agents/notes/README.md#archiving-and-deletion)）。
- **官方插件图形：** 官方与官方实验插件图标使用 [dsh-official-plugin-artwork](.agents/skills/dsh-official-plugin-artwork/SKILL.md)；新图形合入前获得设计师批准。
- **客户端界面文案归语言资源负责。** 产品文字经过有类型字典和 `t`，或本地化基础组件属性传递；`verify-client-ui-i18n` 拒绝硬编码文案（[决策](.agents/notes/implemented/architecture/2026-08-23-locale-owned-client-ui-copy.md)）。包括插件标题在内的英文文案使用句首大写（[规则](.agents/skills/dsh-prose-standard/SKILL.md#required-coverage-by-prose-location)）。
- **界面变化：** 使用 [dsh-client-ui-ux](.agents/skills/dsh-client-ui-ux/SKILL.md) 作为设计与评审入口，按需加载其参考资料。
- **测试政策：** 见 [docs/testing.md](docs/testing.md)。每项非平凡、对模型或产品用户可见的变化都更新无密钥录制会话快照；[快照归属](snapshots/AGENTS.md)将顶层目录树保留给会话驱动场景，其他预期输出由所属模块就地维护。样例在 macOS/Linux 重放；修复样例，不修改规范化器。
- **提前设计每个工具的界面呈现。** Host 呈现器保持纯函数；Web 卡片由原始事件和已持久化的结果元数据派生（[操作指南](docs/cookbook/adding-a-tool.md)）。
- **规划单元、端到端和快照覆盖，** 覆盖能力分界、生命周期路径和交互记录输出；缺少的快照框架支持纳入同一次变更。
- **两个 SDK 都投影循环。** Agent-loop、会话生命周期和 `SessionEventMap` 的变化，在同一个 PR 中更新 TypeScript 与 Python SDK 预期输出；`pnpm run test` 不覆盖这两者（[界面](docs/testing.md#when-a-snapshot-test-is-required)）。
- **有意识地选择 PR 历史。** 拆分独立变更，并在传播前修复引入问题的 PR。独立分支或堆叠分支可选择向前合并或变基。改写使用 `--force-with-lease`，远端移动时中止，绝不用裸 `--force`；采用更新基准前，保留进行中向前合并的检查点（[理由](.agents/notes/implemented/process/2026-08-02-native-github-stacks-and-optional-rebases.md)）。
- **标签：** PR 使用一个 `kind/*`、全部实质相关的 `area/*`，以及原生 Issue Type（[分类](.agents/notes/implemented/process/2026-08-08-unified-github-label-taxonomy.md)）。
- **PR 描述：** 每个 PR 的描述都按 [dsh-pr-description](.agents/skills/dsh-pr-description/SKILL.md) 撰写并更新。
- TODO 标记按紧急程度使用 `FIXME`/`TODO`/`XXX`（[语义](docs/development.md)）。
- 文件末尾恰好一个换行；提交前由 `git diff --cached --check` 检查。

## 防御性模式

修改包接口、远程服务、客户端组件或状态、对话或 Session 行为，以及生命周期、并发、子进程、清理代码前，阅读 [docs/defensive-patterns/README.md](docs/defensive-patterns/README.md)。其[评审原则](docs/defensive-patterns/README.md#why-these-rules)逐产物适用。

## 类型安全与文档

全部代码在 `strict: true` 和 `noImplicitAny` 下编译；每个剩余 `any` 都解释为什么无法收窄。每个模块和导出都有简明 JSDoc，说明不明显的约定；函数类导出包含 `@param`/`@returns`，由 `verify-export-jsdoc` 检查。继承声明成员、插件协议槽位和构造函数的文档，保留在声明它们的 Service Definition、协议或类上。

注释与文档说明完整约定和背景，不记录推理过程。用直接、具体的词，不用比喻。在写 `contract`、`boundary` 或 `shape` 前，先判断更精确的词是否能命名对象，例如写 `response fields`、`JSON validation` 或 `ESM exports`，不写 `response shape`、`validation boundary` 或 `module shape`。`contract` 留给前置条件、后置条件、不变量、兼容承诺，以及调用者、被调用者、实现者、提供方、生产者或消费者依赖的其他义务。真正的进程、传输、安全、事务或生命周期边界可以保留。不旁白控制流或测试，不保存评审历史，也不复述代码。保留行为、失败、时机、责任归属和安全使用事实；理由用链接引用。文字决策使用 [dsh-prose-standard](.agents/skills/dsh-prose-standard/SKILL.md)。把可机械检查的不变量接入实际执行的顶层检查，并证明每条修改后的接纳路径能拒绝一个无效案例。使用范围窄、有依据的例外，不全局关闭规则。

每次代码变化都伴随文档：一并更新受影响 README 与 JSDoc 约定。日常双语工作遵循 [docs/AGENTS.md](docs/AGENTS.md)；只有用户明确调用时才可运行 `dsh-translate-docs`。当前状态文字、每段一个物理行、每个事实一个归属处，以及字数预算都在该文件规定。

## 编辑这些指令

根目录和 `packages/` 下的 `CLAUDE.md` 是指向 `AGENTS.md` 的符号链接；编辑真实文件。每条规则保持自包含，同时链接高层文档。清楚程度不下降时可压缩；必需内容确实需要更多空间时，提高 `verify-doc-budgets` 上限。

## 内置依赖政策

`vendor/` 包是固定版本的源码副本，清单与来源 SHA 位于 [vendor/README.md](vendor/README.md)。通过其中的同步流程更新；重新应用或移除已记录的本地修改；重新运行 `pnpm run test && pnpm run build`。
