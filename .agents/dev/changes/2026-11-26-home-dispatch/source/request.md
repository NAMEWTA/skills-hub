# 需求与确认决定

用户要求先设计再升级 `D:\Document\code\skills-hub` 的 Home 技能。初始化时可保存多个派遣方式，选择一个默认。没有明确选择时采用当前 Agent CLI 的原生派遣。原生默认随当前宿主重新解析；已有 Home 通过显式再次调用 `home-setup` 补初始化。

初始化同时建立独立 Home team。预设最小 team，CLI、模型和推理等级沿实际默认。用户可以长期保存「使用某种派遣方式时默认使用某 team」，也可以在相应 team 中为 A、B 指定不同的项目负责人运行配置。项目规则仅在指定 team 生效，未指定时改 Home 默认 team。负责人进入项目路径后按项目当地规则自行执行或继续派遣。

用户要求主题目录使用 `YYYY-MM-DD-topic/`，持久化 `task_序号.md`、`report_序号.md` 和 `status.tsv`，全局 `all.status.tsv` 汇总主题与项目。任务以业务主题为主体，A、B、C 可同时属于同一条派发消息。追问、进度和结论分别追加独立编号 report，用户答复后的追加派发是新 task。状态表按每次派发消息一行。参考 system-herdr-core 的记录方法，派遣方式和 Home 持久化方式独立。

独立任务即使发给同一项目也各自建主题。主题可先接收，实际派发按 Home 已有直接任务与明确的外部占用决定。多项目任务的空闲部分可以先做。用户确认可增设管理任务状态的 Home 技能，随后授权实施计划。
