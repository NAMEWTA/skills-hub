# 先造工具

工作并非微不足道时，先构建完成它的工具（codemod、脚本、生成器或可重跑的检查），而不是手工操作。判断标准是工作是否简单，而不是是否重复。只有几个一眼能看清的修改，才跳过工具。

- 先手工完成一个单元，再构建工具，并在该单元上重跑以证明它有效。让工具可安全重跑。
- 确定性工具优于分派多人手工处理。确实需要分派时，把做法、验证约定和不可触碰的边界写成一份技能，让受派代理读取且不能修改。
- 应用本原则会产出文件。差异中没有脚本、codemod、生成器或受派代理技能，就没有应用它。工作需要在本次会话后继续存在时，将它提交。
- 构建能完成或证明任务的最小脚本，不构建框架。
