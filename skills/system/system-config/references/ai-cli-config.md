# AI 编码客户端配置

覆盖 Codex CLI 与 Claude Code 的初始化、只读检查、配置修复、隐私控制、状态栏、上下文与常见请求失败。采用本机事实驱动的流程：发现 → 检查 → 具体方案 → 范围内最小写入 → 实际加载验证与恢复。

## 1. 确认环境和范围

区分初始化、故障修复、隐私收敛和只设置状态栏。明确客户端、版本、用户级或项目级，以及实际目标主机。容器、WSL 和远程机器不等于用户电脑。

路径按照显式参数、客户端支持的专用环境变量、用户默认目录解析。`CODEX_HOME` 与 `CLAUDE_CONFIG_DIR` 只读取其实际含义，不改作临时脚本变量。项目根与工作树位置明确后再找配置，不猜旧版客户端或管理器的路径。

目录不存在可以是正常初始化。读取祖先和目标身份，遇符号链接、junction、非普通文件、权限拒绝或未知并发写入时先澄清实际拥有者，不换工具绕过访问控制。配置读取只涉及本次必要字段，不输出完整密钥、提供方地址、认证内容或命令秘密参数。

**完成条件：** 主机、路径、版本、作用域、缺失或损坏文件、加载来源、继承环境冲突与未知能力有明确结论。

## 2. 确定真正生效的来源

分别检查命令参数、进程环境、项目配置、用户配置、组织策略、配置管理器和运行时覆盖。文件写入成功与客户端实际加载是两个结果。项目配置不能覆盖的机器级字段，不通过扩大作用域悄悄修改。

本地帮助、已有版本信息和实际配置解析结果是能力证据。只有检查已存在的命令且确认不会启动登录、MCP、hook、插件或外部请求时，才把帮助或版本查询作为离线诊断。不要为了查看状态自动启动全部集成，也不读取账户凭据查询额度。

记录每个候选键的作用、当前版本是否接受、用户或项目作用域、更高优先级来源、预期行为和核验方式。未知键不猜写。没有整个配置的可验证语法时，继续完成已知部分并报告缺口。

## 3. 选择最小方案

阅读[优化方法](ai-cli-optimization.md)。用户提供的模型、供应商、审批、沙箱、MCP、hook、历史和未知字段默认保留。最高推理、最大上下文、最多并发或关闭沙箱都不是默认优化。

| 目标 | 具体范围 | 完成边界 |
| --- | --- | --- |
| 隐私控制与状态栏 | 用户选择的非必要外部流量和原生状态项目 | 分别核验每个开关与显示来源 |
| 仅隐私控制 | 遥测、反馈、外部域名预检、目录刷新或更新中明确点名的项目 | 不换用户现有状态栏，不把普通模型请求或云端数据政策混为本机遥测 |
| 仅状态栏 | 宿主已经提供的上下文、五小时或周额度信息 | 不宣称其他隐私项已关闭 |
| 故障修复 | 与错误证据直接相关的字段 | 不顺带换模型、路由、账户或权限 |

Codex 原生状态栏使用当前版本支持的 `tui.status_line` 项目；Claude 的自定义渲染器必须只处理宿主提供的标准输入，只有确认脚本存在且审核其行为后才配置。缺失额度显示未知，不能显示成 0% 或伪造余额。分别确认“已用”和“剩余”语义，不抓 Cookie、OAuth 或非公开接口，不设后台额度轮询。

Claude 的个人项目设置常由 `.claude/settings.local.json` 承载，但仍须核实版本与宿主加载位置；本地配置和运行资源应避免误提交。状态栏已有回调时先比较功能和替换后果，不为方便覆盖未知脚本。

## 4. 形成可审查的差异

使用普通 Markdown 或直接展示逐字段脱敏差异即可，包含当前值与来源、目标值、理由、质量或成本代价、版本与作用域依据、保留项、验证及恢复方法。任务已明确授权时，完成准备后继续执行，不重新要求一次同内容确认。

备份放在用户私有目录，保存本轮原字节、权限、所有者及“原先不存在”。不要保存一份可提交的完整秘密配置。多文件替换不是瞬时事务，也不能承诺断电自动恢复。

**完成条件：** 所有目标具体，未知项明确；静态方案可执行不等于已写入、已加载或账户额度已验证。

## 5. 最小写入与恢复

使用适合 TOML、JSON 或客户端支持格式的解析编辑方式，保留未知键、注释和无关配置。写前重读，检测本轮之后的并发修改。优先客户端支持界面或明确配置文件；配置管理器可能覆盖文件时，修改实际拥有者。

相关程序若持续写配置，使用其正常暂停或退出机制，不能自动杀用户进程、关闭安全 hook 或伪造静止状态。平台不支持所需安全写入或权限不足时，只交付具体修改步骤和已核实部分，不从 WSL 绕写宿主配置。

按当前平台支持的方式暂存后替换。异常时只恢复本轮字段；检测到后续用户编辑则停止覆盖，保留现场。无强制覆盖、无全局 shell 环境改写、无认证内容操作。

## 6. 验证实际加载

先检查保存后的完整语法及本轮字段，再核对宿主加载来源、真实状态栏和保留功能。需要新会话或用户正常重开时明确说明，不擅自关闭会话。离线语法验证不代表账户额度可用、云端政策生效或所有集成都零外联。

为了验收额度，不额外发起模型或账户请求。只有任务确有相关网络授权，才执行与故障直接有关的最少请求，分别记录请求、响应与尚未覆盖部分。

## 7. 错误诊断

| 信号 | 应拆开的证据 | 避免的误修复 |
| --- | --- | --- |
| 401 / 403 | 本机加载、认证状态、权限、供应商响应、代理路径 | 公开密钥，或用换地区设置假装解决权限 |
| 404 | 基础地址、API 路径、模型与供应商兼容 | 猜测 endpoint 或切换账户 |
| 413 | 实际 HTTP 请求大小、代理与服务器限制、上下文组装 | 盲目提高上下文窗口，或把压缩阈值当 body 上限 |
| 429 | 限流、订阅额度、并发与服务端返回 | 无限重试或提高并发 |
| SSE / 超时 | 代理缓冲、流式连接、服务端时延、客户端超时 | 关闭 TLS 校验或把所有超时设无限 |
| 上下文压缩失败 | 当前版本、实际上下文、压缩入口与已有日志 | 删除历史、放宽权限或反复触发同一失败 |

不接管配置切换器数据库、反向代理或远端 API，除非用户任务明确包括这些对象。外部问题给出具体证据与交接位置。

## 交付

报告已改变、已保留、已验证、未验证、受阻和恢复结果。真实设备行为、账户请求、跨平台检查、离线样例与模型质量评估分别说明；没有执行的项目不能标成通过。
