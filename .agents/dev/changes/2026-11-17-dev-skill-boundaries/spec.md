# dev 技能职责与交接边界

## 目标与基线

用户认可既有 32 个 dev 技能的审查建议，要求实施职责优化并推送 `main`。来源基线为 `94a2318b3dbe6c8e6d8d30d95736cc9267d279c1`。本变更保留 32 个入口及其 ID、成熟方法、完整示例和专门工具，调整实际触发、方法归属与调用条件。

本文件是本次维护的行为契约；总体使用方法维护于 `docs/` 和技能包，具体来源适配见 [source-adaptations.md](source-adaptations.md)，验证记录见 [verification.md](verification.md)。不创建新领域、流程状态机或依赖注册表，不改变独立上游中文包或 npm 版本。

## 必须成立的行为

| 任务或冲突 | 调整后的行为 |
| --- | --- |
| 散落聊天、Issue、截图、日志 | `dev-intake` 整理来源、事实、目标、范围、已有决定与缺口 |
| 尚未确定的产品取舍 | `dev-grill` 按依赖访谈，写回调用方指定的决定位置，完成后返回 |
| 已定规则缺少实施或验收约定 | `dev-spec` 补足现有权威行为契约；充分的 brief 可直接复用 |
| 仅改写请求 | `dev-sharpen` 交付改写后的表达，不启动开发 |
| 报告分类、查重、分流 | `dev-issue-triage` 接受手工或已配置来源；复现和修复另交对应方法 |
| 没有 spec 文件但有明确用户要求 | `dev-review` 仍审需求符合性；依据不足与审查通过分开报告 |
| 一个强证据支持的故障解释 | `dev-debug` 可立即验证，不要求先凑够 3–5 个假设 |
| 注释审查与重复纠正 | 调用者保留 `dev-guardrails` 的适用条件、收益、误报和维护成本判断 |
| 创建 PR、跟进 CI、合并或直接推送 | `dev-deploy` 进入代码交付分支，核对远端事实；环境部署有独立前提与结果 |
| 编写项目技能 | `dev-personalize` 直接处理技能编写；提炼个人方式才读取授权历史 |
| JavaScript 有限状态模型 | 使用兼容检查器的报告和反例；仅 TLA+/TLC 模型进入 `dev-statechart` |
| 状态不变量与时序属性 | 分别使用适合的 `INVARIANT`、`PROPERTY`；时序反例保留循环或停顿，不承诺最短 |
| 两类项目验证技能同名领域 | 应用验证用 `dev-verify-<app>`，形式验证用 `dev-formal-verify-<area>`；创建前核对现有职责与目录 |
| 跨技能协作 | 一个当前负责人，传入已有契约、决定位置、证据与返回条件，完成局部方法后回到原任务 |

一个变更只有一份权威行为契约，一个决定只有一个权威记录位置。原型仍独立提供其覆盖范围内的可见效果依据；架构、计划和验证资料按真实职责引用契约，不将所有资料机械合成一个文件。

已有验证证据在代码、环境、输入和覆盖范围仍适用时直接复用。条件改变或存在具体证明缺口时才补足受影响检查。已确认决定和已授权工作继续沿用，不因技能交接重新审批或重走访谈。

## 资源归属决定

将完整实施简报从 `skills/dev/dev-intake/references/implementation-brief.md` 移到 `skills/dev/dev-spec/references/implementation-brief.md`。完整模板、缺陷示例、增强示例、已有 PR 示例和反例保留；intake 使用来源简报，按需调用 spec。来源清单和资源迁移夹具同步更新。

同时修正拆分后的含糊指代：模块探索归 `dev-learn`，历史理由归 `dev-why`，架构归 `dev-architecture`，PR 跟进归 `dev-deploy`。`dev-setup` 核对形式验证的工具接入；属性、模型、故障注入和反例方法归 `dev-formal-verify`，原有专门能力继续保留。

## 验收范围

- 元数据、中文展示、完整参考、模板、帮助及工作流表达同一职责。
- 包内引用可达，跨技能调用使用准确名称，不复制完整方法。
- 材料映射指向唯一运行归属，原件、中文对照、许可及固定来源版本保持原样。
- 仓库既有结构检查及资源迁移检查通过；使用独立上下文处理代表性请求，核对实际选择与结果。
- 提交包含实际修改与验证记录，远端 `main` 指向已核对的提交；完整 CI 状态以对应提交的真实工作流结果为准。
