# 少样本泄漏示例

提炼自 2026-08 全仓清理及其评审轮次。用来识别支配原则，不作为文字模板。本文件有意引用泄漏措辞用于校准；[召回探针组](recall-batteries.md)排除技能目录，这些措辞不构成其他地方的许可。

## 失效引用

### 有已提交负责者的决定序号

**泄漏：**“斜杠输入针对可见目录解析（decision 21）。”

**修正：**“斜杠输入针对可见目录解析——纯文本引用决定，由 [Web 输入状态机笔记](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/.agents/notes/archived/architecture/2026-07-25-web-input-machine-and-slash-pipeline.md)负责。”

序号在 HEAD 无处解析；决定名称及负责笔记路径可以。每文件至少一次命名负责笔记路径，支持链接的表面应链接，后续可只用可搜索名称。

### 无负责者的决定序号

**泄漏：**“注册表拒绝重名（decision 7：名称扁平，无命名空间）。”

**修正：**“注册表拒绝重名；名称扁平，无命名空间。”

没有已提交产物负责“decision 7”，所以删引用，但事实子句（扁平名称）独立重述，不随它删除。

### 审计项编码

**泄漏：**“渲染是纯的：相同快照，相同字符串（audit R3）。”

**修正：**“渲染是纯的：相同快照，相同字符串。”

仓库无审计文档；编码是纯会话简写，没有命题。

### 未提交草稿章节编号

**泄漏：**“分层遵循设计（v2 §3.2）：`src/core/` 是纯核心。”

**修正：**“分层：`src/core/` 是纯核心。”

无人提交的草稿 `§N` 无法解析。对比：“按 RFC 9110 §10.1.5 转义”保留——外部标准有意在仓库外解析，自行负责 § 编号的已提交文档也可按节引用。

### 计划阶段标签

**泄漏：**“`src/client/` 是外壳（T4）；P-I 迁移负责适配器。”

**修正：**“`src/client/` 是外壳；适配器位于 `src/client/adapters/`。”

标签索引从未落地的计划。用阶段产出替换标签。

## 堆叠及 PR 视角

### 长期文字中的堆叠位置

**泄漏：**“未来远程后端实现此接口（沙箱后端在此堆叠后续 PR）。”

**修正：**“远程后端无需改变渲染层即可实现此接口。”

长期文字看不见堆叠。保留扩展点约定；待办归 PR 自身、`TODO` 或 Issue。

### README 中的“本 PR”

**泄漏：**“本 PR 给会话列表新增游标分页。”

**修正：**“会话列表按游标分页。”

README 比任何 PR 长寿；机制写成当前事实。

## 变更叙述及版本印记

### 带 PR 编号的往事

**泄漏：**“颜色过去来自从未定义的 `--widget-*` token，所以总渲染回退；别名 token 修复了它（PR #88）。”

**修正：**“颜色来自别名 token；未定义 token 会渲染回退。”

两个现存事实都保留：当前机制及持续失败行为，改写为现在时。缺陷生平属于 PR 及 Agent Note。

### 删除叙述

**泄漏：**“`probe` 字段随删除轮次消失；徽章现在搭载泛用投影对。”

**修正：**“徽章使用泛用投影对。”

没见过 `probe` 的读者从它不存在学不到东西。与已删过去对比的“现在”是版本印记。

### 已修回归 → 现在时反事实

**泄漏：**“这以前会双重编码多字节标签。”

**修正：**“没有字节长度守卫，多字节标签会双重编码。”

回归固定说明以点名守卫的现在时反事实保留；“以前”把它绑在仓库考古上。

### 指示性版本印记

**泄漏：**“本轮批量渲染同步；异步路径是路线图工作。”

**修正：**“批量渲染是同步的。”（延期放调用点 `TODO(widget-batch):`。）

“本轮”／“v1”／“今天”一合并就过时。Agent Note 变更故事节内历史阶段名（“首版交付 X”）不违背当前状态要求；指示性形式永远不行。

## 评审编排

### 把评审结论写成文字

**泄漏：**“评审中拒绝：缓存解析后的 spec。我们保持逐次调用解析。”

**修正（在 Agent Note 的 Alternatives considered）：**“**缓存解析后的 spec。** 拒绝：spec 依赖逐调用 cwd，所以按请求键缓存会返回过时根。”

已考虑替代方案的文体是获准位置；评审者及轮次不是理由。

### 草稿序号

**泄漏：**“截至本笔记 v5，加载器还验证清单。”

**修正：**“加载器验证清单。”

已实施笔记陈述交付现实；自身修订历史在 Git。

## 向评审者辩护

### 为强转争辩

**泄漏：**“此强转安全——SDK 构造对象，只是可选字段声明不够严格。”

**修正：**“SDK 构造此对象时填充每个可选字段；声明类型比运行保证更宽松。”

陈述维护者不可破坏的不变量。“只是……”是在回应 HEAD 无人提出的异议。代码已可见不变量时，改为删注释。

### 诉诸评审权威

**泄漏：**“这是正确的，因为评审者确认了包装顺序。”

**修正：**（删除；包装顺序在函数 `@returns` 中。）

正确性主张引用不变量或测试，不引用人。

## 重述及推导

### 控制流叙述

**泄漏：**“先规范标签，再截断，再包装。”

**修正：**（删除。）

注释下面三行代码说了相同内容。

### 测试走读

**泄漏：**“本测试建会话、发两条消息、等第二个回复，再断言日志四项。”

**修正：**“两次往返必须恰好产生四条日志——投影会去重共享前缀。”

只保留非显然断言理由；走读重述测试体。

## 含糊及规划残留

### 无标记延期

**泄漏：**“暂时立即渲染大概没事。”

**修正：**（删除；延期已有 `TODO(widget-batch):` 标记。）

没有负责者的含糊话是规划残留。无标记时写标记（`TODO(name): coalesce per animation frame`），不保留含糊话。

### 模糊容量

**泄漏：**“64 KiB 缓冲区对多数情况应该够。”

**修正：**“64 KiB 能容纳观察到的最大帧（48 KiB）并留余量；更大帧在 `decode` 显式失败。”

用实际边界及超界失败行为替换含糊话。

## 写作语言混入

**泄漏：**“The renderer runs on the client 端; see the 设计稿 for spacing. ---- 私有 ----”

**修正：**“The renderer runs on the client side; spacing follows the Figma frame `widget-badges`.”

工作语言碎片及会话分隔符是转录残留。Figma 画框名保留：它是有意在仓库外解析的外部来源。

### 配对围栏中的写作语言混入

**两文件均泄漏：** 逐字代码块内 `// 更新这里 before returning`。

**两文件均修正：** `// Update this before returning.`

修正一次，将字节完全相同的围栏复制到双语文件。中文对应页把代码注释译成另一种措辞，即使各自流畅，也破坏配对约定。

## 行为可见候选

**可疑：** 导出 JSDoc 句子说“暂时可用”，生成器将其复制到模型可见目录。

**错误：** 纯文字清理只改源句，或只手改生成目录。

**正确：** 追踪源的生成扇出，更新负责者，重生成每个派生物，更新负责的可运行快照。GUI 字符串包含仓库必需行为证据。授权范围无负责场景则保留措辞，报告延后。

## 保留项

### Issue 引用在每种表面都持久

**保留：**“上限适用于完整渲染值，含包装（issue #1470 负责后续）。”

一次无辅助清理以 Issue 引用属于 Agent Notes 为由删了它。方向错了：Issue 在任何表面均可从 HEAD 解析，“#N 负责后续”是 README 延后工作的获准位置。Agent Notes 及复盘额外允许的是引用*已合并 PR*为证据。

### 失效点名不是“命名负责者”

**删除：**“位于 widget 接缝上的徽章渲染器（见 widget-rendering RFC）。”

一次无辅助清理以“按主题命名负责文档”为由保留。检验是可解析性，不是形式：没有已提交文件对应 “widget-rendering RFC”，所以指针失效。有已提交负责者则重定向，否则删。

### 抑制理由

**保留（修正后）：** `// oxlint-disable-next-line no-non-null-assertion -- the one-element literal guarantees index 0.`

理由子句必需。所述理由错误时（原文说“上面循环守卫证明有帧”，却根本无循环），修理由，绝不删。

### 测得边界

**保留：**“深度上限（实测：512 层嵌套 ≈ 0.15s 同步；4096 层阻塞循环）。”

测量保护常量免于无知调节，“实测”表明数据而非猜测。

### 运行新旧不是变更历史

**保留：**“旧连接排空后新连接才接收。”

此处“旧”“新”是交接时两个活运行对象，不是仓库状态。变更叙述禁令针对仓库历史，不是生命周期词汇。

### 运行自然时间不是版本印记

**保留：**“今天几号？”

提示询问运行时钟，“今天”不对比仓库状态。文字会到模型，任何改写仍需其负责行为证据。

## 过度纠正陷阱

以下每个陷阱都曾在最初清理中交付，并在评审发现。清理前列举段落命题。

### 将义务翻转成背书

**原文：**“这些直接注册是待迁移到槽位的例外。”

**过度纠正：**“这些直接注册是获准例外。”

**正确：**“这些直接注册是待迁移到槽位的例外。”

“待迁移”是义务；“获准”为现状背书。清理在缩短句子时翻转了情态。

### 将假设提升为已交付功能

**原文：**“未来基于 IPC 的 shell 子类化执行器并覆盖 `spawn`。”

**过度纠正：**“基于 IPC 的 shell 子类化执行器并覆盖 `spawn`。”

**正确：**“假设的基于 IPC 的 shell——尚无这种 shell——会子类化执行器并覆盖 `spawn`。”

只删未来标记，会把设计示例变成类已交付的主张。显式标假设，不只是取消未来标记。

### 把真实事实连同周围记录删除

**原文：**“门禁提示叙述检查顺序；提示文字也是 `verify-doc-typecheck` 编译所针对的内容。”

**过度纠正：**“……”（整句按叙述删除。）

**正确：**“提示文字是 `verify-doc-typecheck` 编译所针对的内容。”

半句是叙述，另半是承重耦合。命题同占一行时删子句，不删整句。

### 保留数字却丢测量来源

**原文：**“4 MiB 上限来自实测：最大生成 `py-types` 模块是 3.1 MiB。”

**过度纠正：**“上限 4 MiB；最大生成 `py-types` 模块是 3.1 MiB。”

**正确：**保留“实测”。

没有“实测”，3.1 MiB 像定义而非观察，提高上限前便无人重新测量。
