# 技能机制

这是 [智能体文档写作](agent-writing.md) 中专门针对技能的分支：当文档是一项技能时会发生什么变化，包括 frontmatter、调用方式选择和路由技能。关于如何编写文档的其他内容都在 [智能体文档写作](agent-writing.md)中。

## 调用方式

有两种选择，分别在两类负担之间取舍：

- **模型调用型**技能保留 `description`，因此智能体能自主触发，其他技能也能调用。人仍然可以输入技能名称：模型调用始终包含用户可访问性；描述只增加智能体发现能力，绝不会移除人的访问能力。描述是技能的顶层上下文指针，被强制永久加载：用持续上下文负担换取可发现性。内容全是参考资料的模型调用型技能也可以承载共享参考：另一项技能可以调用它，因此支持该机制的环境可共享参考；本项目独立安装包仍须自含所需内容。机制：默认使用标准 `name` 和 `description`，可选调用控制字段只在当前宿主明确支持时使用；省略 `disable-model-invocation`，编写面向模型、包含触发分支的描述；智能体文档写作中的指针写作规则全部适用。
- **用户调用型**技能把描述移出智能体可访问范围：只有人输入名称才能调用，其他技能也不能调用。上下文负担为零，但需要认知负担：人必须充当记得它存在的索引。机制：仅在宿主明确支持该语义时设置 `disable-model-invocation: true`；否则用描述说明触发范围，不能假定字段存在就能禁止模型调用；`description` 改为面向人的一行摘要，移除触发条件列表。

只有当智能体或其他技能必须自主触达它时，才选择模型调用。如果永远只会手动触发，就使用用户调用，不承担上下文负担。

两个用户调用型技能都需要的共享参考不能寄存在其中一个技能里：没有描述，双方都不能触发对方。独立分发时把必要参考复制到每个技能包内部，并让本包相对指针指向它。共享唯一来源可在仓库维护阶段管理，但安装后不得依赖仓库外部文件或未安装兄弟技能。

## 按调用方式拆分

这是拆分中的调用切口；按执行顺序拆分见 [智能体文档写作](agent-writing.md)。当存在一个应独立触发技能的不同引导词——而且确实会在提示词中使用——或其他技能必须触达它时，拆出一项模型调用型技能。新增的常驻描述会增加上下文负担，因此独立可达性必须值得这个成本。

## 路由技能

当用户调用型技能多到难以记住时，累积的认知负担可以用**路由技能**解决：一个用户调用型技能列出其他技能，以及何时应使用各项技能，这样人只需要记住一个入口。它只能提示，不能触发：用户调用型技能没有可供模型发现的描述，因此只有人能触达它们。

按任务选择本包完整方法见 [资料索引](method-index.md)，能力与授权边界见 [本地执行支持](execution-support.md)。
