# 浏览器解析与 WebRTC

浏览器登录、CLI API、插件、MCP、更新器和系统请求可能走不同路径。先确认用户实际使用的浏览器、版本与 Profile，不把默认 Profile 当作当前 Profile，也不把浏览器成功当作 CLI 已修复。

## 安全 DNS

浏览器自己的 DoH 可绕过系统普通 DNS，但若该 DoH 本身按用户选择的代理路径运行，不必机械关闭。用户选择集中解析时，先证明系统 DNS 已接管，再调整指定 Profile 的安全 DNS 设置。关闭 DoH 后可能退回未接管的 DHCP 解析，不能把开关本身当防泄漏结果。

使用版本支持的界面或管理策略。运行中的浏览器会覆盖偏好文件；未经用户明确任务，不关闭浏览器、不修改全部 Profile、不清 Cookie 或登录态。保存必要字段与原先不存在状态，恢复时不覆盖后续用户编辑。

## WebRTC

区分本地私有地址、mDNS 名称、服务器反射候选和中继候选。私有地址并不直接证明公网出口泄露。实际行为取决于 ICE、STUN/TURN、UDP 能力、浏览器策略、代理与 TUN。

需要测试时，用明确的测试页面或用户已有应用，在允许的范围读取本次候选与连接证据。不能未经要求把用户配置或完整连接记录上传给第三方检测站，也不能用一个国家标签认证整机路径。

## 请求与恢复

对登录、API、资源请求分别关联时间、目标、命中规则与最终节点。OAuth 回调的 localhost 应保持本地可达，不用宽泛代理规则破坏它。没有现场访问时交付确切步骤和未验证项。

不要为了通过地区验证修改账号国家、时区、语言、TLS 校验或防火墙。正确网络路径仍被服务拒绝时，保存脱敏服务响应，继续按服务资格与出口识别区分原因。
