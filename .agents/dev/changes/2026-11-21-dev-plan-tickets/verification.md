# 实施票据与 DAG 验证

## 实施范围

- `dev-plan` 先保存独立 Markdown 票据，再把每票的直接依赖和所需产物汇总为 `plan.md`。显式单票规划也保存这两个文件。
- `dev-build` 读取原票与实际前置产物，以计划中的共享契约、环境和整合验收接续实施。明确的单项实施走现有直达入口。
- 按 Matt Pocock 的固定版本核对垂直切片、真实阻塞与重构例外，按 Speculo 的固定版本核对设计引用、覆盖、协作及原条目状态。运行采用范围见[第三方声明](../../../../THIRD_PARTY_NOTICES.md)。

## 隔离样例

在 Windows PowerShell 与 Node.js v24.21.0 上通过真实安装入口，将 `dev-plan`、`dev-build` 和 `dev-workflow` 装进临时项目。依据安装后的模板构造 Markdown 文件，并用临时 Node.js 脚本执行文档里的依赖与链接核对。

| 场景 | 实际结果 |
| --- | --- |
| 显式规划一个文案切片 | 保存一张 Markdown 票和一行 DAG，按相对链接打开票据及规格。核对已安装规则中明确单项直达 `dev-build` 的分支。 |
| 回执写出与读取 | 拓扑分层为 `01 → {02, 03} → 04`。只有契约、缺少夹具时，02 和 03 仍等待。产物齐备后两项均可开工。写出端单独检查回执，读取端独立重放夹具。仅写出完成时联验仍等待。两个入口可用后，实际传递回执并确认重复输入得到一次结果。 |
| 多阶段与依赖错误 | 两个交付组链接到同一组票据。缺失文件、漏列节点、自依赖、重复节点、重复边及循环均被核对过程发现。 |
| 接续旧计划 | 从旧表格提取 07 号票，保留原计划路径，原 `progress.md` 内容保持一致。索引链接回进度出处。 |
| 外部事项导航 | 使用只含标题和两个链接的草稿检查结构。 |

隔离检查覆盖实际安装、Markdown 链接、图检查过程及样例命令。宿主模型的自动路由和第三方事项发送属于本次未实测的部分。
