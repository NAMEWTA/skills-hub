# 可靠的 DSH CI 测试

构建在仓库真实 CI 拓扑下仍正确的测试，而不只是安静工作站上单独运行时正确。本技能负责隔离与可靠性判断，不替代仓库测试层级政策，也不选择推送的所有命令。

## 阅读负责规则

- 用[测试政策](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/docs/testing.md)选择单元、覆盖率、预期输出、快照、浏览器或真实 API 证据。
- 生命周期、子进程、取消和拆除行为遵循[防御模式](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/docs/defensive-patterns/general.md)。
- worker 或任务拓扑影响测试时，阅读实际 Vitest 配置与 GitHub 工作流。
- 录制会话场景还遵循[快照说明](https://github.com/deepseek-ai/deepseek-harness/blob/e8f7b93a344964de3dca1ace9e72b6e4d6de87cb/snapshots/AGENTS.md)。
- 测试设计正确后，用 [dsh-pre-push-checks](../dsh-pre-push-checks/SKILL.md)选择待推送验证。

## 建模执行拓扑

除非实际配置证明不会，否则假定这些层可重叠：

1. 同一 Vitest 文件内的测试。
2. 不同 Vitest 文件或 worker 进程。
3. 同一任务中独立的 Vitest 或仓库门禁进程。
4. runner 共享同一主机的不同 Actions 任务。

进程隔离不隔离主机端口、可预测文件系统路径、外部服务、数据库、套接字或继承的子进程。每个获取的资源都要识别拥有者、原子分配机制、可观察就绪信号、已注册清理及静止完成信号。

不要仅因一个夹具缺少隔离就串行化整套测试。先缩小独占范围或改变资源分配。顺序 Vitest 区块不能保护主机资源免受另一个文件、进程、任务或 runner 的影响。

## 原子分配资源

使用资源拥有者的分配器，不先检查可用再稍后认领。

- 网络夹具用 `listen(0)` 绑定回环地址，服务器报告正在监听后才读取分配地址。绝不先扫描空闲端口再稍后绑定。
- 用 `mkdtemp` 为每项测试创建私有临时根；不获取可预测的共享路径。
- 共享数据库、套接字、会话和输出位置使用每测试唯一命名空间。
- 路径不得已存在时，使用独占创建。
- 稳定的录制标识符与临时传输地址分开。在夹具内部转换，不强迫活跃资源使用录制值。

仅作解析输入或预期值的字面路径与 URL 不是被获取的资源。不要仅因看起来固定就改写。

## 隔离进程全局状态

把 `process.env`、`cwd`、假计时器、语言区域和时区、模块模拟、注册表、console 钩子、`globalThis` 和全局 `fetch` 拦截视为独占可变资源。

优先注入依赖或实例局部适配器。必须修改时：

- 捕获原值是缺失还是存在；
- 恢复准确原状态；
- 立即注册恢复；
- 在最小修改范围周围使用 `try/finally`；
- 局部 `finally` 前可能失败时，保留 `afterEach` 后备；
- 只拦截夹具拥有的最窄、精确请求或调用。

## 尊重平台负责的语义

CI 在 Windows 和 POSIX 主机上运行同一套测试，操作系统负责的值不一定按测试写入的方式返回。

- 只有断言容忍写回失败时，写回值才安全。恢复文件 `mtime` 以证明指纹无论如何都会失效，在各处成立；恢复它以证明记录仍有效，则假定无损往返，而 NTFS 的 100 纳秒刻度不能保证小数毫秒无损。断言依赖恢复时，从新读取获取预期值，不用记忆值。
- Windows 不区分环境变量名大小写，因此同时设置 `http_proxy` 和 `HTTP_PROXY` 的夹具，在那里只有一个条目。
- Windows 异步释放文件句柄，因此 POSIX 上立即完成的重命名或删除，需要按观察到的争用设置有限重试。
- Windows 没有 POSIX 权限或信号语义。依赖它们的案例应显式按平台跳过并指明理由，而非削弱所有平台的断言。

优先各平台均成立的观察。案例确实无法跨平台时，明确在该平台排除。

## 按 CI 通道预算超时

`describe` 或单案例超时会覆盖 runner 的 `--testTimeout`，而不是让步，因此低于通道预算的值会缩减 CI 已授予的时间；同一字面值在默认值更小的主机上却会表现为放宽。受进程创建限制的测试套件采用通道预算；更紧的值应带缩紧理由。

测试预算提高时，也提高钩子预算。准备和拆除承受相同争用，只提高案例预算会把争用失败转移到 `afterEach`。

超时本身是测试对象时，外层等待应远大于被测超时。证明 20 ms 截止会触发的案例，不得与执行框架自身等待竞速，否则负载决定哪个截止先报告。

## 按状态同步

固定 sleep 不能证明准备完成或清理结束。

- 等待显式就绪事件、握手、状态转换、有拥有者的 Promise 或外部可观察条件。
- 用 deferred Promise 或屏障把竞态放到确定性时点，证明相关操作重叠。
- 超时仅用于限制等待，绝不作为断言正确的条件。
- 除非顺序就是被测产品行为，否则不对依赖调度器的顺序断言。
- 时间本身是测试对象时，注入或模拟时钟，并始终恢复真实计时器。

## 释放到静止状态

获取资源后立即注册清理，确保断言失败也释放资源。清理停止新回调或请求，移除监听器，恢复全局钩子，终止所拥有的工作，并等待子进程退出、服务器关闭、worker 终止或等效完成信号。

只调用 `abort()`、`close()` 或 `kill()` 而不等待所拥有的完成信号，是不完整拆除。可能晚完成时，证明释放会阻止它修改另一项测试。

## 证明目标回归

- 实际可行时，观察普通回归在修复前失败。
- 新静态或语料防护检查，临时引入被拒绝案例，观察目标失败。
- 竞态用屏障证明重叠；只重复执行不是竞态测试。
- 端口、套接字、共享路径、子进程或其他主机资源，如果跨进程隔离是修复一部分，就并发运行独立测试进程。
- 夹具按自身截止启动子进程时，在断言退出状态前，先断言子进程未被信号或超时终止，让被杀子进程报告为超时，而非状态不匹配。
- 验证外部状态、事件、文件、日志、退出或释放，而非相信组件自述。

压力运行补充确定性回归，不替代它。

## 拒绝掩盖不稳定失败的修复

对于确定性本地测试，不把以下手段当根因修复：

- 未识别等待状态就增加超时；
- 增加重试；
- 让所有文件串行；
- 吞掉错误或未处理拒绝；
- 削弱断言；
- 把不稳定行为规范化掉；
- 清理或断言前增加 sleep。

真实 API 政策下，对文档说明的外部提供者瞬态失败测试，重试仍有效。此例外留在外部边界。

恢复预算不是掩盖。把套件提高到通道本来已有的预算，或按 runner 实测争用确定有限重试，明确了所等待工作，并归还通道授予的时间；二者都不是围绕未经检查的等待凭空增加余量。

## 诊断已有不稳定失败

已有概率性 CI 失败，阅读 [CI 不稳定失败诊断流程](references/ci-flake-diagnosis.md)。仅诊断请求仍只读：除非用户也要求修复，否则报告原因与证据。

## 验证与报告

运行受影响行为的最小聚焦回归。只有变更负责该风险时，才补拓扑专用证据：

- 全局修改需要恢复证据；
- 生命周期或子进程工作需要静止拆除证据；
- 端口、套接字或共享路径需要并发独立进程证据；
- 新防护检查需要负对照。

推送前使用 [dsh-pre-push-checks](../dsh-pre-push-checks/SKILL.md)。报告准确命令及观察结果；不把重试、跳过测试或等待中的 CI 描述为通过。
