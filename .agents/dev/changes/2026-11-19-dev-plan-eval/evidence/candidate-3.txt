## `.agents/dev/changes/2026-11-19-execution-receipts/plan.md`

# #4 / #5 执行回执实施计划

通过真实 Agent CLI 启动一次任务轮次。发起方可以用原身份查到进程、现场和输入受理情况。Tasks 可以在重启、回执响应丢失或 Markdown 写入失败后，继续把已保存的问题、进度和结果投递到原任务，并保留用户对任务完成状态的控制。

本计划采用 `dev-plan` 的垂直切片方法，依据本次提供的 `agent.md`「启动、断线与持久化」及工作区操作表，以及 `automation.md`「用户可以做什么」「何时自动派遣」「并发与失败的外部语义」「界面、权限与数据范围」。范围为回执生产、持久消费及两模块的联合验收。调度、工作区布局、历史和工具授权仅纳入直接影响这条链路的行为。

本轮交付计划正文。仓库入口、测试命令、完整 Issue 矩阵和原型版本未核实。以下模块名是责任边界，验证场景是待执行项。实施时沿现有调用链核实入口和命令，并用两份规格各自引用的 `prototype-review.md` 核对确认版本、范围及对应页面和状态。缺少有效确认时，受影响的可见交互等待核实，回执和持久化工作可继续。

## 共享执行合同

| 边界 | 实施约定 |
| --- | --- |
| 发起身份 | 手动派遣、规则发生和同一意图重试保留稳定来源身份，竞争同一任务时关联到同一次有效接受。执行前固定 Vault/Engine、机器、操作/派遣身份、taskId、runId 及目标快照。目标快照包括 Space 配置 revision、目标策略、适用的 Tab/leaf、方向、cwd、provider、模型和参数。session 创建后持久绑定。工作区导航代次只用于保护视图更新。 |
| 回执事实 | Agent CLI 分别提供可查询的本地登记、进程创建、attach 可见、Agent 对本轮输入的受理，以及问题、进度、明确的业务结果和运行退出。使用稳定事实身份、作用域、绑定及必要的请求版本和因果引用。可见性和退出是独立事实。退出码、最后一行输出和静默都不能判定业务成功。 |
| 权威与对账 | Agent CLI 持久保存可重查的执行事实，Core 提供受管进程和现场的权威观察。发送方在副作用前登记身份。响应丢失时按原身份查询，权威未明时显示 pending/unknown，保留相关任务、实例和资源占用。只有权威证明未执行且原意图仍有效时，才可按原身份继续。其他机器的遗留执行须经对账。 |
| 消费与确认 | Tasks 按稳定回执身份持久接收，核对 Vault、任务、轮次、会话及相关请求绑定。接收保存后方可确认消费，时间线送达另记事实。每条待投递记录保留稳定 messageId、目标及内容。Markdown 条件写冲突时重新读取，依据稳定标识核对已写事实后再补送。 |
| 文件与权限 | 沿用单 Vault、单 Engine 的 Markdown/JSON 文件事实，SQLite 作可重建索引。任务状态和时间线由 Tasks 写入，进程事实由 Agent CLI 写入，运行与布局事实各自恢复。回执仅按受权内部 task/run 绑定传递。持久记录和诊断仅保存可披露字段，启动秘密经 Agent CLI 或规则所属模块的受权路径注入。 |

这里的字段分组、确认顺序和责任划分是拟实施设计。落地前由 Agent CLI 和 Tasks 负责人核对现有恢复接口，记录具体的序列化、读取及确认入口。共享合同由 Agent CLI 负责人统一维护，变更须同步协调 Tasks 和工作区调用方。必须保证上述恢复窗口，具体文件和原子写方式沿用经核实的项目约定。

## 01 真实启动并回查原回执

把工作区现有启动入口接到共用 resolver 和同一个执行合同。先登记冻结后的操作身份，再执行进程创建。Agent CLI 提供可重查的阶段事实与错误，工作区按冻结目标和导航代次应用结果。Tasks 接入所需的受理和结果事件使用相同回执合同，并通过拟新增的合同夹具独立校验。

- [ ] 在 B 的 pane 右分栏启动真实 Codex，临时丢弃 run 响应，切到 A，并以同身份再次查询。进程枚举只出现一个新受管进程，B 可定位该进程，A 的布局保持原样。再做两次独立新建，分别观察到各自的进程和操作身份。
- [ ] 请求返回前关闭目标 leaf，界面显示目标过期，已启动的进程仍可在 B 找回。断开传输并重连，观测原进程仍在。模拟 Core keep 恢复成新 shell，原 Agent 显示丢失，启动与输入记录显示旧 argv 和旧轮次均未重放。
- [ ] 用同一 resolver 对照真实 Codex、Claude Code、Pi 和 shell 可用时的启动观察，另以受控夹具覆盖显式 cwd 错误、有效 cwd 与参数边界、创建后响应丢失，以及只有退出或屏幕输出的情况。阶段事实各自可查，屏幕输出与退出单独留证。provider 和平台缺口随证据登记。

证据保存到 `evidence/01/`，包括脱敏请求与回执序列、真实进程计数、现场截图和故障注入点。用工作区正常入口证明启动行为，用合同夹具覆盖难以稳定触发的窗口。

## 02 把受理与结果补送到原任务

从任务详情「立即派遣」走通目标冻结、任务占用、Agent CLI 回执接收、条件写和重启读取。任务处于待派、进程已创建或输入受理未知时，初次派遣仍显示未开始。确认实例受理本轮输入后投影为进行中，并追加一次系统评论。用户手动控制完成。结果先持久保存，再按原 messageId 送达原任务。消费接收、文件投递和送达确认分别可追查。

- [ ] 保存任务时进程数不增加。Automations 停用时从详情立即派遣，逐步观察待资源、已启动和已受理。只有受理后才进入进行中且系统评论恰好一条。重复派遣可查到原接受或明确排除原因。显式提前派遣记录本次覆盖。
- [ ] 在 Tasks 持久接收前和接收后分别中断，恢复后重取原回执，回执、业务结果和运行数保持各一份。再分别让 Markdown 写入失败，以及让写入成功后的送达记录丢失。恢复后同一 messageId 恰好出现一次，进程和输入次数不增加。并发修改任务文本时，条件写保留区段外字节和既有编辑。
- [ ] 关闭任务后补送已产生的历史结果，任务仍为已完成。删除任务后可查目标已消失的送达诊断。只读 Vault 或临时状态目录在外部执行前拒绝持久派遣。损坏记录显式报告并冻结受影响领取。切 Vault 后旧回执只能在原作用域核对。

证据保存到 `evidence/02/`，包括注入点前后的持久文件、Markdown 差异、运行与输入计数及任务详情。对一条结果同时核对回执身份、messageId 和任务路径。

## 03 持久回复并关联原问题

默认选最后一个仍有效的问题。Tasks 校验 task/run/session、request/version 和 replyId，先持久保存，再尝试发送。补充消息同样先保存，可合并的消息以原 ID 和顺序进入下一轮。普通问题的回答启动同任务、同会话的新轮并保留 parentRunId。支持原生 deferred 的 provider 恢复原 run/request。仅有 blocked 信号时提供原现场定位。等待用户释放工作槽，任务和实例绑定继续保留。

- [ ] 在同一任务分别发普通评论、问题回答和补充消息。评论只进讨论。回答和补充在重启后仍可追查已保存、待发送、拒绝、待核实或已处理。普通问题的下一轮显示正确 parentRunId 和原 session；捕获的输入只包含本轮选择的内容。
- [ ] 同键同内容重试返回原结果，换键争抢同一请求版本只有一个被接受。人工输入、评审发送与回答竞争同一 session 时只出现一个输入所有者。让受理确认丢失，重启后按原身份核对，实例输入计数保持一次。关闭任务后的新输入需显式重开。
- [ ] 在确认支持的真实 provider 上验证原生 deferred 恢复同一 run/request。对仅有 blocked 信号的实例，任务详情定位原现场，实例已失效时显示原因。实现前核实 provider 能力及权威确认信号，未验证的能力保留受限状态。

证据保存到 `evidence/03/`，包括请求版本、回复身份、父子 run 关系、仲裁记录、真实 provider 观察及任务详情截图。

## 04 联合验收与切换

整合负责人在当前主干与待交付版本运行相同的关键任务场景，记录实际提交、系统、CLI 版本、Core、Vault、时区及夹具。主干缺少完整链路时，记录可运行的基线路径和实际差异。待交付版本须通过以下场景。故障夹具负责精确控制中断时间，真实任务详情、工作区和 CLI 负责证明用户能走完整流程。

| 场景 | 操作与通过判据 |
| --- | --- |
| 到点派遣和竞争 | 使用固定 `Asia/Taipei` 时钟，在同一任务上竞争两条规则和手动派遣，构造到点与未到点的 `availableAt`。同一 `now` 和规则版本的预览与扫描分类一致，未到点任务保持未派，符合条件的任务只接受一个有效执行。发生重复、规则停用和恢复后核对已入队项、跳过原因、接受 ID 和实际进程数。后台启动归属正确 Space 且保留前台焦点。 |
| 从原任务到原现场再返回 | 由真实 CLI 提问，重开应用，从原任务前往绑定现场并回答。观察等待时释放工作槽。正常业务提问和受支持的 deferred 各验证相应 run 关系。返回原任务可查看问答、摘要和最终结果，各 messageId 唯一。任务完成由用户触发。 |
| 双方独立暂停及进程失联 | Tasks 暂停时产生问题或结果，Agent CLI 恢复可查询的原回执。Agent CLI 暂停时提交回答，Tasks 恢复保有原输入。分别丢弃启动响应和输入确认，重启后对原身份对账。无权威时保留 unknown 及占用，Core keep 替代 shell 时显示 Agent 丢失。按阶段检查进程数、输入次数和评论条数。 |
| 写入失败、作用域与备份恢复 | 让结果已保存时评论写失败，恢复后补送原结果。期间执行任务删除、切 Vault、受控记录损坏和异机遗留检查，各自观察目标消失、作用域隔离、显式冻结和保留占用。用空白测试 Vault 验证新格式备份与恢复，按模块导出范围核对任务、待投递记录和绑定，并验证损坏报告。布局备份覆盖按 #4 设计末节核实后执行。 |
| 权限与直接切换 | 在干净安装验证 MCP/CLI 工具默认关闭，内部受权任务回执仍可消费，外部创建只有获得派遣授权后才可执行。注入可检索的假秘密，核对它只到达受权执行路径，扫描回执、布局、评论、日志、诊断、导出和重启记录。核对所有涉及的调用方已切到新合同，并保护真实旧数据、外部历史和存活进程。 |

实施时复核调用方清单，至少追踪手动启动、历史恢复或 fork、任务立即派遣、规则触发、回复和补充、人工输入及 `review.send`。共享合同如需一次性替换，在同一整合边界迁移全部受影响调用方并清理旧路径。允许整合中的临时不完整提交，待交付版本须通过正常入口和旧调用表面检查。
