# dev-handoff 实施计划

## 目标与本轮范围

在 `skills/dev/` 增加独立 `dev-handoff`，将现有开发交接、会话接续和安全暂停方法迁到唯一归属，支持保存当前开发现场、交给下一会话，以及从已有交接继续同一任务。用户要求优先复制、完整翻译和复刻成熟方法，只作项目约定所需的融合；本轮实施并提交 PR，不发布 npm、不合并 PR。

基线：`NAMEWTA/skills-hub` 的 `main`，提交 `e058268749db6dcfcf3dca89b0134529be195442`，文件树 `c722ab71f9e07d2b1194d351f0596929f0615941`。本地工作树逐文件匹配该树的 Git blob 与执行位后开始修改。

本计划取代上一轮以会话日志定位为中心的设计：本轮不实现 JSONL 查找、解析、宿主适配器、会话导入、后台启动或自动调度。开发域独立，`dev-handoff` 与 `system-herdr` 无依赖、调用或共享记录协议；系统域不在修改范围内。原始记录若已由用户提供，可作为普通资料引用，不成为生成或恢复交接的前提。

## 预期结构与使用流程

新技能仅包含 `SKILL.md`、`agents/openai.yaml`、`assets/handoff.md` 及三个 references：`handoff-method.md`、`session-resume.md`、`safe-pause.md`。不增加脚本或运行依赖。

1. 保存/交接：沿用当前任务目录，在 `.agents/dev/changes/<日期-主题>/handoff.md` 保存。已有规格、计划、决定、提交和日志按实际位置引用，不复制全文。文档包含下次重点、建议 dev 技能和首个具体动作。
2. 恢复：先读交接与必要引用，核对真实工作区、未提交修改和现有证据，说明停点，再按原目标继续。只有真实缺失或矛盾阻塞接续时才问用户。
3. 明确暂停：停在安全边界，保存本任务现场与恢复记录。仅保存检查点或即将压缩上下文不意味着暂停；“保存后继续”应回到原任务。
4. 单独安装：一个 `dev-handoff` 包即可保存和读取交接。建议技能为按需选择，未安装的可选技能不阻塞接续。
5. 输出：给出实际交接路径与可直接复制的接续提示。没有实际投递或运行证据时，不宣称另一 Agent 已接收或已启动。

## 实施顺序

### 1. 方法迁移与入口

将 `dev-workflow` 的四个原资源迁到 `dev-handoff`；保留完整方法及原模板有用栏目，补齐上游明文要求的“建议使用的技能”“下一会话重点”。新增简短入口和 UI 元数据。移除旧文件，不保留重复正文或兼容占位。

### 2. 开发域路由

更新 `dev-workflow`、`dev-plan`、`dev-learn`、`dev-help` 的说明、路由和帮助。直接修复“只允许四类交接”的穷尽列表，以及“压缩触发暂停”的冲突。`dev-workflow` 继续负责完整任务协调；`dev-status` 继续负责向用户报告进展；任务拆分仍归 `dev-plan`。

### 3. 文档、映射与许可

更新 README、开发流程、方法归属、维护约束和交接使用说明。将 15 条历史迁移记录的最终目的地改为新归属，再追加四条本次迁移。更新 Matt/pstack 三条 `runtime_paths`、适配理由，并在实际对照完成后填写相应 `runtime_reviewed_blob`。保留原件、中文底稿和来源修订；许可原文沿用已分发 MIT，第三方声明补充实际采用范围。

### 4. 验证与 PR

运行仓库完整门禁，覆盖预算、链接、安装、单一方法归属、材料哈希和迁移记录；验证真实 npm 打包结果。对独立安装、保存后继续、带 WIP 的明确暂停、旧摘要与当前证据不一致等场景做不提供预期答案的行为检查。只针对发现的真实问题修改，再复核受影响场景。记录实际通过项和环境限制，提交含来源、改造、验证和迁移说明的 PR。

## 验收条件

- 新入口能在保存、恢复、明确暂停之间正确选择；普通报告不被交接流程替代。
- Matt 五项、pstack 接续五步和暂停四步仍完整；上游/本地差异可逐条解释。
- 接收者只看交接文件及必要引用即可知道目标、停点、真实证据、剩余工作和第一步。
- 不因摘要或旧记录自报成功而误报完成，不因接续从零重做，不因保存自动停止。
- 全部运行方法与模板唯一归属，旧引用和材料映射同步修正；不引入跨域依赖。
- 完整检查和可执行行为检查结果如实写入 [验证记录](verification.md)，PR 可直接审查。
