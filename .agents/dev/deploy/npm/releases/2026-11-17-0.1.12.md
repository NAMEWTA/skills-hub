# 0.1.12 发布准备与验证

## 用户要求与源码

用户在已有上游技能实施完成后，要求基于最新技能更新继续推送并发布。最新功能基线为 `c9b492fcb71a440dfd89f3b9623785d13c15731a`（PR #7），完整内容树为 `ba32156dfd8f382758f53a50a62f3903c8a8a318`；本次从已公开的 `0.1.11` 递增到 `0.1.12`。

本次包含 `dev-prototype` 与其规格、设计、计划、实施、审查、验证、交接和归档衔接。既有三个 `zh-*` 上游运行包、来源映射、双根发现和 TUI 分组保留；发布器修复 npm 公开延迟的等待窗口，Windows 捕获回放增加有限等待余量与用例耗时记录。

## 已知问题与处理依据

- `0.1.11` 上传成功后，公开包约数分钟后才可读。原发布器只检查两次、间隔 1.5 秒，造成提前失败；新版本使用 20 分钟只读窗口，公开完整性与 stage 审查条件保持。
- 最新功能基线的 Windows 回放在 CounterAction 单例触发 45 秒超时。同一内容树此前两次 Windows 验证成功，未发现结果断言或路径错误。仅将 Windows 单例上限调为 120 秒并记录耗时；其他平台保持 45 秒，全部 33 例与断言保留。这不证明更深层延迟原因。
- 原型文档的源码限定说明改为 `0.1.12` npm 安装；已有 dev 用户更新整个领域，或至少同时更新 `dev-build` 与 `dev-prototype` 及已安装调用者。
