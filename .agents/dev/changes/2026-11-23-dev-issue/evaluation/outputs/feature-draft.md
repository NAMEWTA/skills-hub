## 问题与价值

用户需要将重要笔记固定在列表前面，并能取消置顶。当前列表仅按更新时间倒序，较早更新的重要笔记会被排到后面。完成后，用户选择的置顶状态会写入现有笔记 JSON 文件，重新读取文件后仍然有效；搜索和归档行为保持原样。

本快照只有可调用的笔记与存储模块，没有 UI、命令行入口或前端组件。本文将切换入口明确为供调用者使用的公开模块函数，不假设已有按钮、设计系统或界面原型。

## 目标与范围

1. 在笔记记录上新增可选布尔字段 `pinned`，由调用者显式设置置顶或取消置顶。
2. `listNotes` 返回的符合原有过滤条件的笔记中，所有置顶笔记排在所有未置顶笔记之前；每组复用原有 `updatedAt` 降序比较方式。
3. 沿用原 JSON 文件与存储接口，保存成功并重新读取后保留置顶选择。
4. 旧文件缺少 `pinned` 时正常工作，不要求启动时批量改写旧文件。

本项不新增数据库、前端框架、正文搜索、归档列表、手动拖拽排序或笔记内容编辑能力。原有 `listNotes`、`loadNotes`、`saveNotes` 的调用形式保持兼容；导出及导入非法字段的错误处理不并入本项。

## 行为契约与场景

### F1. 数据与切换入口

- 仅 `pinned === true` 视为置顶；缺失字段或 `false` 视为未置顶。新操作只写入布尔值，不引入旁路配置文件。
- 拟新增公开函数 `setNotePinned(notes, id, pinned)`：`id` 定位目标笔记，`pinned` 为调用者期望的布尔状态，成功返回包含该状态的新数组。采用显式目标状态，使同一请求重复调用时结果一致。
- 函数不修改传入数组或原笔记对象；只对目标笔记创建包含新状态的记录，保留其余字段。找不到 `id` 时明确报错，非布尔状态参数以 `TypeError` 拒绝；失败不得产生可保存的新状态。
- 切换时只改变 `pinned`，保留 `updatedAt`，避免置顶操作改变原来的组内时间顺序；取消置顶后按原时间回到未置顶组。
- 上述函数形式、错误方式及“切换不更新时间”是本草稿明确采用的新增实现约定，并非现有接口或已有讨论中确认的历史决定。

### F2. 列表排序

沿用现有归档与标题过滤后，按照以下顺序比较结果：

1. 置顶状态：`true` 在前。
2. 同一置顶组：复用 `b.updatedAt.localeCompare(a.updatedAt)`。
3. 同组且更新时间相同：保留输入中的相对次序，不增添新的 ID 或标题排序规则。

例如，四条未归档且匹配查询的记录分别为：A（置顶，11 月 20 日）、B（未置顶，11 月 23 日）、C（置顶，11 月 21 日）、D（未置顶，11 月 22 日）。结果应为 **C、A、B、D**。取消 A 的置顶后应为 **C、B、D、A**。日期示例使用当前比较方式可处理的相同格式，不新增日期转换规则。

### F3. 搜索和归档保持

- 置顶不能绕过标题搜索条件：未匹配查询的置顶笔记不出现。
- 标题搜索仍采用大小写不敏感的包含匹配；正文命中而标题未命中时不出现；查询不自动去掉空格。
- `archived` 为真值的笔记即使已置顶也不出现。
- 归档状态与置顶状态独立保存。本项不删除归档笔记的 `pinned`；若调用方将该笔记恢复为未归档，查询应再次按保留的置顶状态排序。恢复归档的操作本身不在本项实现范围内。
- 空输入数组或无匹配结果仍返回空数组；`listNotes` 不改变输入数组的次序或记录内容。

### F4. 保存、重读与失败

调用者读取当前数组，调用 `setNotePinned` 得到候选数组，再等待 `saveNotes(file, candidate)` 成功；成功后可以用 `listNotes(candidate, query)` 展示结果。对已有 `pinned` 的文件执行 `loadNotes(file)` 后，字段与列表顺序应保持一致。

保存失败时，`saveNotes` 的 Promise 必须继续拒绝并保留错误原因，调用者不得把候选状态当作已持久化结果。纯修改函数不会改写原始数组，调用者可保留该数组并在处理错误后显式重试。当前存储实现直接调用 `writeFile`；本功能不假定它已经具有原子替换或断电恢复保证。

旧记录示例保持兼容：

```json
{"id":"a","title":"Alpha","body":"one","updatedAt":"2026-11-20","archived":false}
```

该记录完成置顶并保存后，除新增 `"pinned": true` 外，其现有字段值应保持不变。
