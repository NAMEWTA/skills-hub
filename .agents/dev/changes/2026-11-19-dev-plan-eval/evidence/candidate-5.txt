# 邮件提交投递与发件箱核对实施计划

用户可以从工作台或已启用的 Mail 外部工具提交同一草稿版本，查询同一笔投递操作，并在重启后从发件箱查看每次尝试和逐收件人结果。「结果未知」可进入核对，常规重试只处理有证据表明未提交的收件人。规格见 [Mail #8 的 M-06、M-07](../../../mail.md#workspace)和[发信与持久数据契约](../../../mail.md#durability)。

| 任务 | 独立交付 | 开工依赖 |
| --- | --- | --- |
| [01 提交草稿并查询投递结果](tasks/01-submit-delivery.md) | 同版本提交归并为同一笔操作，SMTP 结果逐收件人持久化，工作台和已开放的 CLI/MCP 可查询 | 无本计划内任务依赖。接入需要 Mail 草稿版本、可发送账号和 SMTP 入口 |
| [02 从发件箱核对投递并安全重试](tasks/02-reconcile-outbox.md) | 重开发件箱后可定位原记录、检查未知结果，并对已证实未提交的收件人发起重试 | 依赖 01 提供已验证的持久操作与尝试记录、逐收件人结果查询，以及复用同一投递入口的防重约束 |

01 负责共享发送契约、记录结构及 SMTP 副作用。02 负责发件箱查询与操作、证据核对和重试入口，复用 01 的记录与提交机制。02 负责最终整合验收，使用真实提交生成记录，再走发件箱核对及重试，结合 SMTP 服务端记录检查实际投递次数。

本次仅依据提供的 `mail.md` 和规划方法拟定本地文件路径与正文。实施前从仓库复核草稿、SMTP、发件箱及统一能力入口，并查阅规格引用的 [设计](../../../design.md)、[上游快照](../../../source.md)和[上层计划](../../../plan.md)。原型版本、实际确认范围、代码符号和验证命令均待核实。相关体验确认只约束对应的界面实现；远端核对证据能支持怎样的状态变更，由 02 按设计和协议能力查明。进度和证据入口分别维护在任务正文，本次交付止于规划。

# 01 提交草稿并查询投递结果

## 交付

用户从编辑器提交已保存的草稿，立即取得可查询的操作身份。重复点击、并发请求，或从工作台和已启用的 CLI/MCP 提交同一草稿版本，都返回同一笔操作。重启后仍可查询每次尝试及其逐收件人结果。来源为 [M-06、M-07](../../../../mail.md#workspace)及[发信、只读与统一能力条款](../../../../mail.md#durability)。

## 被谁阻塞

无本计划内任务依赖。实施时核实已有草稿及其版本标识、账号与 Vault 代隔离、SMTP 发送能力、受管附件和统一能力入口。若其中某项尚未交付，将对应生产入口的接入和验收挂到该产物。已有代码、命令及上层切片编号待核实。

## 行为与边界

- 在可能发生 SMTP 提交之前持久化操作身份及尝试记录，使同版本的并发调用共用一笔操作。保留 Vault、账号、草稿版本、稳定 Message-ID、尝试历史和逐收件人结果，供发件箱及重启查询使用。修改正文或收件人产生新版本，原操作历史仍可查询。
- 只有 SMTP 明确接受才记录「已接受」。部分接受逐收件人记录，并区分「已接受」「可证明未提交」「结果未知」。SMTP 最终应答缺失，或进程中断后无法证明未提交，保留未知及可供核对的记录。稳定 Message-ID 用于关联。
- 关闭、超时、重启、恢复备份及重连本身均不启动新投递。只读 Vault 从工作台、外部工具及后台入口统一拦截持久写和发送。离线及接收专用账号显示当前不可发送原因，已保存草稿可继续使用。停用或切换 Vault 后，旧响应不能污染当前范围。账号删除与在途尝试的处理沿用 [设计](../../../../design.md)，其具体约定待实施前核实。
- 本任务拥有提交、查询和 SMTP 结果落盘的共享契约。已启用的 CLI/MCP 与工作台使用同一 schema 和 handler，按 #6 的能力开关接入。查询向 02 提供核对所需的身份及尝试历史，发送入口支持复用同一套逐收件人防重约束。发件箱核对和常规重试入口由 02 交付。

## 验收

- [ ] 在可写测试 Vault 从工作台提交，再从已启用的 CLI/MCP 并发提交相同版本。各入口返回同一操作身份，SMTP 服务端只观察到一次该提交，重启后仍能按原身份查到结果。编辑正文或收件人并保存后，显式提交新版本得到新的操作身份。
- [ ] 用受控 SMTP 服务分别制造明确接受、部分接受、确定未提交，以及服务端接收后最终应答丢失。查询逐收件人结果与协议事实一致。混合结果保留同一操作下的完整尝试明细。
- [ ] 在可能提交后、结果持久化前中断进程。重启、重连、关闭后重开及读取恢复状态时，原操作可查，无法确认的结果保持未知，SMTP 提交计数不增长。恢复路径用本地状态夹具验证，实际备份导入接入由 S6b 承担。
- [ ] 在只读 Vault、离线、接收专用账号及外部能力关闭场景分别操作相关入口，观察对应的禁用或拒绝结果与 SMTP 零提交。外部能力关闭时，工作台仍可在可写、在线、可发送的账号中提交。切换 Vault 或停用后释放迟到响应，当前范围的操作与记录不受污染。

## 当前进展与完成证据

已拟定任务，代码及运行结果待核实。实施前定位编辑器提交、统一 handler、SMTP 结果和生命周期入口。可见的提交反馈及查询状态按 [原型](../../../../prototype/index.html)和[确认记录](../../../../prototype-review.md)定位对应页面、状态、源码和确认版本，按适用的桌面及 Web 主题与视口验证。完成时在本任务记录实际提交或工作树、测试环境、命令或操作步骤，以及 `../evidence/01/` 下的脱敏查询结果、SMTP 日志及界面证据。受控 SMTP 用于复现故障，真实测试邮箱用于采证正常发送路径。

# 02 从发件箱核对投递并安全重试

## 交付

用户重开发件箱后可恢复选择，查看原投递操作、每次尝试和逐收件人结果。对「结果未知」可进入核对并查看已有证据及仍然不确定的原因。常规重试只发送给有证据表明未提交的收件人，新的尝试追加到原操作。来源为 [M-06、M-07](../../../../mail.md#workspace)及[发信、只读和恢复条款](../../../../mail.md#durability)。

## 被谁阻塞

[01 提交草稿并查询投递结果](01-submit-delivery.md)交付可跨重启读取的操作及尝试记录、逐收件人结果、Vault 和账号作用域，以及可复用的投递入口与防重约束后解除阻塞。核对依赖可信证据的具体逻辑及界面入口还需核实[设计](../../../../design.md)和已确认原型的适用范围。

## 行为与边界

- 发件箱区分本机发件记录、服务器 Sent 和服务器 Drafts，展示记录所属账号、历史尝试、逐收件人结果和核对入口。重开后恢复仍存在的选择。已有本地草稿可回到编辑器续编，删除本机记录只影响本地。删除后须继续防止同一草稿版本的重复提交。
- 核对使用同 Vault、同账号下可用的投递证据。稳定 Message-ID 可关联本地记录和远端候选。仅存在同 ID 的 Sent 副本或搜索无结果时，保留逐收件人的未知结果。状态变更应有对应收件人的可验证证据，并保留证据来源。查询失败、离线或权限不足时说明原因，已有结果和历史继续可读。基线缺少已验证的远端 Sent APPEND，本项范围限核对和本地记录操作。
- 显式重试时按当前证据重新检查收件人资格，防止并发或过期界面引起重复投递。已接受和结果未知的收件人留在原记录。正文或收件人经编辑后按新版本提交。只读 Vault 可查看原有记录，拒绝重试、删除和核对结果的持久写入。
- 本任务负责发件箱查询、选择恢复、核对展示、本机记录操作及常规重试调用。工作台与已开放的 CLI/MCP 共享支持这些操作的 schema 和 handler。01 持有共享投递记录和 SMTP 提交语义。CLI/MCP 的选择状态以各入口的使用方式为准。

## 验收

- [ ] 通过 01 的真实提交入口生成一笔投递记录。关闭并重开发件箱，核对恢复选择、账号和逐次尝试详情。服务器 Sent/Drafts 与本机记录分别显示。续编本地草稿可回到编辑器。删除可删除的本机记录后，服务器、其他账号及 Vault 的记录不受影响，重复提交原草稿版本也不产生额外 SMTP 投递。
- [ ] 让 SMTP 在可能接收后丢失最终应答。重启后从未知结果打开核对入口，分别模拟远端缺项、仅有同 Message-ID 的候选、查询失败和离线。各场景保留「结果未知」，显示可用线索或失败原因，常规重试不可用于该收件人，SMTP 提交计数不增长。若设计支持通过权威证据更正结果，另验对应账号、操作及收件人匹配后才发生状态变更。
- [ ] 制造 A 已接受、B 明确未提交、C 结果未知的同一笔投递。通过工作台和已开放外部工具对同一批次并发重试，受控 SMTP 仅收到一次面向 B 的重试。随后重启，原尝试与新增尝试均可查，A、C 的原有结果仍保留。用陈旧页面再次发起请求，服务器按最新结果判断资格。
- [ ] 在恢复的可写 Vault 与只读 Vault 分别打开发件箱。恢复后可查询原操作及未知结果，打开、核对和重启均无自动投递。只读入口同时拒绝重试、删除和持久更新。先用恢复状态夹具验证消费契约，实际 Huhu 新格式包恢复后的联合证据归 S6b。

## 当前进展与完成证据

已拟定任务，等待核实 01 产物及现有发件箱入口。实施前从[原型](../../../../prototype/index.html)和[确认记录](../../../../prototype-review.md)定位发件箱、未知结果、核对和重试状态的源码及确认版本，在相同状态下核对适用桌面与 Web 的主题、视口和焦点。若设计和实际协议行为仍无法确定某类远端证据是否允许更新逐收件人状态，记录证据缺口，仅暂停该类状态更新的实现。

完成时在本任务登记实际提交或工作树、验证环境、操作步骤及 `../evidence/02/` 下的界面、脱敏查询和 SMTP 计数证据。整合验收使用 01 实际生成的记录贯通「提交、重启、核对、显式重试」，以服务端实际收到的收件人及次数核对结果。
