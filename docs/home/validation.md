# Home 验证

验证结果需要说明它证明了什么。静态 Markdown 检查、文件系统链接、模拟派遣、实际 Agent 执行和服务联合验收不能相互替代。每次交付在所属 Change 中记录实际版本、命令、输出摘要、来源和未覆盖项。

## 自动化工具与安装检查

从源码根运行：

```sh
node scripts/check.mjs
node scripts/check.mjs --full
node scripts/check-skill-quality.mjs --report
npm run check:package
npm run check:statechart
npm run check:upstream
```

Linux CI 另外在独立临时目录安装官方 `@anthropic-ai/claude-agent-sdk@0.3.332`，运行 `npm run check:claude`。本地复验先设置 `CLAUDE_AGENT_SDK_PREFIX` 指向该独立安装目录。维护脚本启动 SDK 自带的真实 Claude Code，用 `supportedCommands`、`reloadSkills` 检查全部安装技能，再由 Claude 的 `readFile` 逐个读取 `.claude/skills/<name>/SKILL.md` 和参考资源，核对单一本体内容及有效路径。它记录实际 SDK/Claude 版本，不发送用户回合；此项证明宿主发现与读取，不证明模型执行了技能。接口依据为 [Claude 官方 SDK 文档](https://code.claude.com/docs/en/agent-sdk/typescript)，SDK 不进入 npm 运行依赖。

依赖、浏览器与平台前提沿用[仓库验证说明](../maintenance/validation.md)。针对 Home 的隔离 Node 测试验证危险路径、身份、写前修订、事件去重与派生索引等实际风险；纯文本内容仍需逐段核对。

| 对象 | 需要验证的边界 |
| --- | --- |
| registry/route | 多 remote 和多 URL 无损回读、指定主 remote 首 fetch 身份、fork 与镜像误匹配、附加 remote 漂移、无 remote 本地仓、v1 只读兼容、显式相对路径与本机覆盖、中文/空格/括号链接、worktree、只读不改 Git |
| 项目登记地图 | 保存不写地图、缺地图正常、默认 stdout 零写入、显式导出、源与目标 revision 冲突、手写地图保护与旧地图过期诊断 |
| Home 直接任务 | 一条消息覆盖多个项目、多回执编号、同项目不同主题争用、待核实占用、验收与释放、只读查询、TSV 重建与旧记录保护 |
| knowledge/history | 来源与作用范围、候选和已核实事实区分、写前修订冲突、事件 ID 冲突、同源重导、不同后续事件、索引回退与重建、排除依据、防路径逃逸 |
| 安装事务 | 新装、混选、unchanged 补链、正确断链、错向与父目录链接冲突、旧资源删除与备份、锁后重算、注入失败与回滚 |
| 安装入口 | dry-run/list/help/version/取消零写入；真实 tarball 安装；链接包含所有资源，realpath 回到同仓本体；项目整体搬迁 |
| Windows | 有权限时真实 dir symlink；权限不足时明确失败并恢复，不改用 junction 或复制 |
| 单包使用 | 实际安装目录运行工具；资源闭包；缺少兄弟方法准确报告，不能借用源码外部文件 |
| Home Git 与换机恢复 | 提交并克隆一份带技能本体的 Home；无旧机资料时可直接查正式历史、知识、任务；按真实登记恢复项目并核验身份、默认分支、完整远端和重复执行；子仓与本机资料保留在 Home 跟踪边界之外 |

Home Git 回归还覆盖已有仓库补白名单、子仓忽略规则、写前修订过期和用户规则覆盖。检查子仓在 Home 中的可见性、登记可跟踪性和双方索引。技能指令走查覆盖只发技能名、只登记、完整初始化缺默认设置和完整初始化已提供默认设置四种输入。逐项核对写入范围、需要确认的选择和交付状态。

## 真实组合验收

在隔离的 Home、项目 A、项目 B 和可选 worktree 中，用实际选择的 Agent 与派遣方法验证。普通自动化 fixture 可以准备目录和断言文件，不能伪造 Agent 身份、回执或已执行的业务任务。

1. 从 Home 交付分别属于 A、B 的任务，项目执行者实际进入目标根并读取当地 `AGENTS.md`、技能与有关知识。
2. 至少一个项目依自己的规则继续派出子 Agent。记录实际关系、工作目录、协调根、所用方法和直接交付；检查派遣记录未跨仓混写。
3. 查询一条只有项目内部资料能回答的知识，核对回报的来源、版本、范围和真实性。Home 不在派遣前替项目扫描答案。
4. 让两个项目完成一条真实接口或产物链，并由明确执行者联合验证。记录参与版本、产物、服务身份，以及 dirty、mock、缺环境和未覆盖路径。
5. 结束原上下文后，让新会话从 Home Markdown 读取管理知识与历史，正确区分现行结论和当时理由。恢复已有任务需现场查原 owner；不得从摘要重复启动修改。
6. 在实际所选 Claude Code 版本验证 `.claude/skills` 目录链接的发现和资源读取，记录版本与有效来源。单独 `realpath` 或读到 `SKILL.md` 只证明文件系统，不证明宿主调用。
7. 完成更正、部分替代、退役和忘记的跨 owner 场景。再次查询及重建索引后确认旧内容没有无声复活，并说明外部原件的未覆盖范围。

## 配置与运营审查

使用实际用户请求检查显式初始化、旧 Home 补初始化、原生默认随宿主解析、命名方式和 team 的选择顺序、项目级覆盖、条件不兼容和临时覆盖。分别保留原生入口、实际 checkout、当地规则和回执证据。保存配置只证明选择，实际执行再核对能力。主机/账号共享额度只引用同一 owner，角色数不当并发数。

历史记录准确表达取消、失败、部分完成、已验证、已交付和已部署；事件发生时间、整理时间和事实核验时间各有含义。重复摘要不构成独立证据，来源过期或丢失需限定检索和结论范围。

日周回顾按实际授权运行；安装、普通查询和编辑偏好不会启动服务或新建计划任务。配置和知识忘记必须检查有关 owner，而不只是删掉一个索引。

## 结果归档

把自动化、实际运行与未覆盖项分别写入对应 task 的同名 Markdown 验收报告。源码基线、环境版本与完整交付点必须可复核；原始日志和截图留在项目既有运行原件位置。未取得实际宿主或多项目证据时保留未验证状态，不把模拟标为完成。
