# 关系核实与影响分析

## 分清对象

`repos.json` 负责仓库身份、位置与一句话用途；`relations.md` 负责跨仓结构事实；notes 负责当前长期理由；history 记录当时发生过程；coordination 负责这次目标与依赖安排。其他 owner 只引用关系 ID 或段落，不双写另一张权威关系表。

| 关系 | 应核对的证据 | 不可推导 |
| --- | --- | --- |
| 源码/模块依赖 | 实际 import/build 配置与有关代码版本 | 同组织或同语言不代表依赖 |
| 运行调用 | 调用方配置、接口 owner、真实环境/报告 | 文档示意不等于当前服务连通 |
| 发布包依赖 | 声明、锁文件、解析来源和版本/产物身份 | 包名相同不证明正在使用新产物 |
| 数据/事件契约 | 生产者/消费者、schema owner 与各自证据 | 双方口头一致不代替实际结构 |
| 共同交付 | 已确认的交付条件及负责项目 | 同一计划不自动形成代码依赖 |
| 仅作参考 | 明确用途及来源 | 不自动阻塞消费者构建或运行 |

每条关系写出方向语义。例如“生产者 A → 消费者 B”表示能力/数据流向；代码 import 可能写成“B 依赖 A”。不要只画无标签箭头导致影响方向被反转。

## 获取项目证据

1. 明确要回答的问题和观察范围，例如“A 的包接口变化是否会影响 B 的登录流程”，避免要求每个项目上传全量架构。
2. 读取既有关系证据与核查时间，先判断本次是否仍适用；新 HEAD 本身不证明所有边过期。重要输入、契约或环境变化才触发有关核查。
3. 按准确名称调用 `home-route` 定位项目，把只读调查作为普通项目任务交 `home-workflow`。项目无需新接收器或固定回报 schema，只需返回这次结论所需的事实。
4. 生产者确认提供的契约及 owner，消费者确认实际消费方式和版本，必要执行者确认部署/运行条件。返回 repo ID、实际 checkout、原件相对路径/符号、revision、观察时间、验证方式与未覆盖项。
5. 不把用户假设、模型推断、旧摘要或同源转述视为独立确认。证据只有一方时说明范围；双方矛盾保留各自版本/环境，向有关项目核实差异。

Home 只保留足以支持关系的摘要与指针。源码、配置全文、内部永久知识和日志留原项目；确需重新读正文时由项目 Agent 完成。项目路径不可达不自动取消依赖，标待复核。

## 最小关系记录

参考[关系模板](../assets/relations.md)。只为实际存在的边建记录，稳定关系 ID 供引用。

| 信息 | 内容 |
| --- | --- |
| 身份与方向 | 准确 repo ID、生产者/消费者、方向解释 |
| 类型与用途 | 上表具体类型及为何存在 |
| 契约 owner | 哪个项目/权威文档维护约定，真实位置 |
| 来源 | 各项目报告及原件引用、相关 revision/时间 |
| 状态 | 已核实、候选、争议、退役，保留核实范围 |
| 核查时间 | 实际取得新证据的时间，不因重排文档刷新 |
| 限制与下一 owner | 版本、环境、未知项、应由谁继续调查 |

不要将“已核实”写成永不过期的全局事实。固定 commit 来源说明当时版本；当前事实需与本次组合对齐。

## 形成影响集合

1. 给出变化起点、变化种类和契约边界；起点可以是接口、包、事件、数据或交付日期，不只是某仓整体。
2. 先列实际直接消费者，再沿相关生产者→消费者方向追踪间接消费者。每一步标出所依赖的边和传播条件，不能把所有连通节点都判成必受影响。
3. 区分必须修改/复验、可能受影响待调查、仅需通知/参考、已有证据表明不受影响。候选或争议边可加入调查集合，但不得报告为已确认运行依赖。
4. 记录环或共同契约。它们说明可能需要协调验证顺序，不证明可原子发布；无需引入图数据库或统一 DAG 调度器。
5. 把影响集合与证据缺口交原任务负责人。需要跨项目功能共同验证时交 `home-integrate`；单项目实现和测试由当地规则处理。

例如 A 产生版本化包，B 的锁文件仍指向旧包，C 仅参考 A 的文档：A 的变更对 B 是否生效要先确认包解析和组合，C 不应被自动列为运行联调阻塞。若 B 又向 D 提供事件，只有变化可能改变事件约定时才沿该边扩大验证。

## 更新、退役与交付

修改前读取当前关系正文并记录基线，形成最小差异；写前重读，出现其他写者更改就合并，不整页覆盖。修改当前状态时保留原证据的历史边界，必要变更过程由 `home-history` 记录；当前理由由 `home-knowledge` 保存并引用。

路径移址或 repo 解除登记时，检查受影响关系和入链；不要按同名新仓替代旧身份。退役关系标明范围与依据，旧历史仍可引用，不擅自清除项目资料。
