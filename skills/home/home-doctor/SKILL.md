# Home 结构诊断

交付具体问题、证据、影响和应由谁修复；默认零写入。已有授权包含修复时交唯一 owner 继续完成，不因切换技能重复请求权限。

## 执行

先尝试读取下述 Home 主入口，再按[诊断与修复路由](references/diagnosis.md)检查；入口读取失败时直接使用其中的最小诊断分支。

1. 从实际 Home 根读取 `./.agents/home/AGENTS.md`，明确异常和本次所需能力。同一上下文已读同版本可复用；新会话、压缩后缺失、入口变化或 Home 根改变时重读。读取失败直接进入下面的最小只读检查，不把先读到缺失入口作为诊断前提。单装 Home 技能也应有本域入口；可选业务资料和未选择的其他 domain 可缺省。
2. 使用包内工具检查 Home 自身结构、相对引用、地图来源标记及显式要求的技能入口：

   ```sh
   node <本技能目录>/scripts/doctor.mjs --home "<Home 根>"
   node <本技能目录>/scripts/doctor.mjs --home "<Home 根>" --require-skill "<本次确实需要的技能名>"
   ```

3. 按需调用 `home-setup` 的只读完整 schema/地图核查，以及 `home-route` 对有关 ID 的实际 Git 身份、路径和 worktree 核查。结构脚本不读取项目知识，不复制这些 owner 的完整方法。
4. 报告实际检查范围、问题与未知。入口缺失、旧官方模板或合法标记内空白交实际安装方法；空文件、损坏标记和自定义导航先交 `home-knowledge` 核对边界、保留内容，再由安装方法填入模板。未知版本保留并核对匹配工具，文件类型/读取异常先交安装方法核对现场。SOUL 或知识矛盾交知识方法，配置交 `home-setup`，历史交 `home-history`，派遣状态交原技能。缺少 owner 只限制相应修复，不妨碍诊断。
5. 已授权修复时提供原件、基线和具体问题给 owner；保留当前授权和任务。修复后只复查受影响范围，不自动升级、重装所有工具或改项目配置。

## 输出

Node.js 22.14+ 脚本输出结构化 findings、owner 和范围。可定位的入口缺失、不可读或结构错误返回 findings 并退出 1；输入、Home 根或无法继续的读取错误退出 2，其他退出 0。warning 或未检查项仍需如实报告，0 不等于全系统健康。

同仓技能软链接的文件系统核查不证明实际 Claude 已发现并调用；资料路径存在不证明 Agent 已读取；终端存在不证明 Agent 就绪。将这些未覆盖能力交相应实际方法，不能推断成功。
