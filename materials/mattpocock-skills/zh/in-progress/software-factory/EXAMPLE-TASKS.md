# 示例任务

按所解决的问题分组。每个任务都说明启动运行的触发器、一次运行做什么，以及下一步触发什么。大多数工厂从其中一种起步，再通过串接后续任务成长。

## 未分诊工单不断堆积

**探索任务**
- 触发器：创建工单，或人类为其添加标签。
- 工作：对照代码库检查工单，将其归类（容易判断、需要人类、不是缺陷）。
- 后续触发：容易判断的工单触发实现运行。其他情况以工单被标为等待人类结束。

## 就绪工单等待有人实现

**实现任务**
- 触发器：人类或探索运行将工单标记为就绪。
- 工作：实现工单，直到自动检查通过，再打开草稿 PR。
- 后续触发：自动审查运行。

## PR 等待审查

**自动审查任务**
- 触发器：PR 已打开且尚无自动审查，或人类为其添加标签。
- 工作：依据代码库标准及其来源工单审查差异。
- 后续触发：失败时触发返工运行。通过时结束，PR 等待人类审查，再由人类合并。

## 自动审查失败后无人修复

**返工任务**
- 触发器：自动审查运行判定 PR 失败。
- 工作：只修复自动审查指出的内容，然后推送。
- 后续触发：自动审查运行。达到设定失败次数后，结束并将 PR 标记为等待人类。

## 规格过大，单次运行装不下

**拆解任务**
- 触发器：规格工单被添加标签。
- 工作：将规格拆成工单，每张记录依赖哪些其他工单。
- 后续触发：实现运行。

此处的实现运行选择下一个所有依赖都已关闭的工单，并再次触发自己，直到没有工单剩下。

## 迁移到更严格的自动检查

启用新的 lint 规则（或更严格的类型设置），但只有部分文件能通过。规则对通过的文件强制执行，失败文件放入例外清单。

**棘轮任务**
- 触发器：每日时钟。
- 工作：从例外清单取出一个文件，修复到通过更严格检查，然后打开 PR。
- 后续触发：自动审查运行。例外清单为空时，棘轮运行已无文件可取，迁移完成。

每天一个小 PR，使人类审查成本低廉，检查只会越来越严格。

## 用户报告的缺陷无人阅读

应用中的反馈按钮是工单来源：将每份报告提交为工单，并预先附探索标签。探索运行负责其余工作。

## 生产问题发现太晚

监控器（慢查询、错误率）是工单来源。每个问题提交一张工单，再次看到同一问题时则在未关闭工单中评论。修复合并后，如果问题持续存在，则重新打开工单。

## 工厂自己的运行失败

**修复任务**
- 触发器：编排器报告运行失败。
- 工作：把失败日志提交为工单；若失败可修复，尝试以 PR 提交修复。
- 后续触发：自动审查运行。修复运行自身的工作失败时，不触发任何事，因此修复永不形成链条。由于修复改变工厂自身，始终需要人类审查。

## 代码库逐渐漂移

**架构任务**
- 触发器：每夜时钟。
- 工作：扫描近期变更，找出重构候选项，并合并提交成一张工单。
- 后续触发：无。人类选择候选项并加标签，启动通常的处理链。

## 同样的错误反复出现

**回顾任务**
- 触发器：PR 合并，节流为每十个已合并 PR 触发一次。
- 工作：读取 PR、其工单、自动审查及运行日志，以 PR 形式提议修改工厂自己的指令。
- 后续触发：自动审查运行。
