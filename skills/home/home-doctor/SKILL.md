# Home 结构诊断

交付具体问题、证据、影响和应由谁修复；默认零写入。已有授权包含修复时交唯一 owner 继续完成，不因切换技能重复请求权限。

## 执行

先读[诊断与修复路由](references/diagnosis.md)。

1. 明确 Home 根、实际异常和当前任务所需能力。只检查相关项目与用户已选择的工具；单选包、未初始化业务资料或未使用 dev 不一律算故障。
2. 使用包内工具检查 Home 自身结构、相对引用、地图来源标记及显式要求的技能入口：

   ```sh
   node <本技能目录>/scripts/doctor.mjs --home "<Home 根>"
   node <本技能目录>/scripts/doctor.mjs --home "<Home 根>" --require-skill "<本次确实需要的技能名>"
   ```

3. 按需调用 `home-setup` 的只读完整 schema/地图核查，以及 `home-route` 对有关 ID 的实际 Git 身份、路径和 worktree 核查。结构脚本不读取项目知识，不复制这些 owner 的完整方法。
4. 报告实际检查范围、问题与未知；知识矛盾/过期交 `home-knowledge`，历史去重/时间/接续问题交 `home-history`，派遣状态交原技能。不要自行解释或重写这些语义。
5. 已授权修复时提供原件、基线和具体问题给 owner；保留当前授权和任务。修复后只复查受影响范围，不自动升级、重装所有工具或改项目配置。

## 输出

Node.js 22.14+ 脚本输出结构化 findings、owner 和范围；存在错误退出 1，输入/读取失败退出 2，其他退出 0。warning 或未检查项仍需如实报告，0 不等于全系统健康。

同仓技能软链接的文件系统核查不证明实际 Claude 已发现并调用；资料路径存在不证明 Agent 已读取；终端存在不证明 Agent 就绪。将这些未覆盖能力交相应实际方法，不能推断成功。
