# 分层取证与最小修改

## 从一次真实失败开始

保存发生时间、应用/版本、真实主机或网络命名空间、脱敏错误、目标域名和请求类型。CLI API、浏览器登录、MCP 子进程、插件和更新器可能来自不同进程，逐条检查相关路径。

401/403、TLS 错误、连接超时、DNS 失败和限流不是同一个问题。不要看到“地区”就重写 DNS，或看到 HTTPS 错误就禁用证书验证。

| 层 | 最少证据 | 对应下一步 |
|---|---|---|
| 应用 | 实际代理支持、继承环境、NO_PROXY、配置优先级 | 只对目标会话/进程修正，先不改全局环境 |
| 监听 | 正确主机、真实端口、监听进程、协议 | 不猜 7890；确认 HTTP/mixed/SOCKS 与应用相容 |
| 规则 | 一次请求的首命中规则、策略组、最终叶子 | 修正有证据的优先级或组选择 |
| TUN | 实际路由、接口和相关请求 | 开关 true 只是配置，不能当接管证明 |
| DNS | 应用/系统 resolver、代理内解析、节点 bootstrap | 分离谁解析与如何到达 resolver |
| IPv6 | 本机原生路由、应用连接、代理远端能力 | 选择已支持的隧道/策略；不把 dns.ipv6=false 当系统禁用 |
| TLS | 主机名、信任链、系统时间、实际响应 | 修证书/配置来源，不使用 -k 或 skip-cert-verify |
| 服务 | 正确路径上的脱敏响应与错误 | 核对账号/服务资格与出口信誉，不保证换 DNS 即解决 |

一个阶段失败就集中修该阶段；不要同时更改节点、DNS、MTU、TUN stack 和浏览器设置，否则无法解释效果。

## 有限的真实请求

先核对实际代理 URL 与用户已允许的目标。使用中性/任务相关端点，不把账号密钥放进命令行。下面变量是需要填入的真实值，不是默认地址：

```bash
curl -q --proxy "$wta_proxy_url" --noproxy "" \
  --connect-timeout 10 --max-time 20 \
  --output /dev/null --silent --show-error \
  --write-out 'http=%{http_code} connect=%{time_connect} tls=%{time_appconnect} total=%{time_total}\n' \
  "$wta_probe_url"
```

原生 PowerShell 使用 `curl.exe`，输出文件可用 `NUL`，变量换成该会话的实际变量。先确认命令存在。避免自动跟随重定向或失败后改用直连；错误本身是证据。

`socks5h://` 与 `socks5://` 的解析位置不同，按应用支持选择；一次 curl 只证明该请求，不证明其他应用和原生系统 DNS。显式进入 HTTP 代理也仍可能由其 rule 判定 DIRECT，核对内核连接链。

通过代理的本地 `time_namelookup` 不一定包含远端目标解析耗时，不能把它直接标成“目标 DNS 延迟”。对同一主机、节点、目标重复少量可比样本，报告样本和失败率，不编造性能提升。

## 修改与回滚

优先受支持的界面/导入/覆写。保存本轮要修改的原字段或原文件字节、权限、内容指纹以及原先不存在状态；完整配置备份保存在私有位置，不提交 Git。

改动前再次确认当前值未被用户或配置管理器改变。只写本轮范围，随后读回实际加载结果。发现新冲突就保留现场，不能整文件覆盖。

回滚只恢复本轮改变；存在后续用户编辑时合并或停止，不能覆盖。重新加载后验证原代理与业务访问恢复。会影响远程管理的改动，必须先落实独立控制台、第二路径或平台支持的恢复机制；没有它就停在具体计划。

## 验收范围

分别标记配置来源、运行时加载、目标应用、规则链、DNS、IPv4/IPv6、切网/冷启动与回滚。未做的故障断开测试留作未验证。

严格防直连需要额外的系统级隔离设计与真实故障验证，TUN 本身不等于 kill switch。只能对已验证的应用、目标和网络条件报告结论。
