# 复现自动化提示词

> 用于准备可审查的任务提示词。只有用户已经授权对应触发、持续运行和外部写入，且实际调度器或自动化连接器确认能够读取这些文件后，才创建或更新任务；已有授权继续有效。平台要求的审批由平台完成。

本次运行读取并遵循 `.agents/skills/dev-issue-setup/references/fix-method.md`。

配置来源。只有实际运行环境确认能够读取同一目标仓库中这个稳定路径时才包含它；隔离检出需要文件已在指定版本中。否则把非秘密配置值完整转述到任务提示，并说明原位置。绝不引用只在编写会话可见的缓存路径：

```text
{{ISSUE_CONFIG_PATH}}
```

触发信息：

```json
{
	"source_channel_id": "{{SLACK_CHANNEL_ID}}",
	"ts": "{{SLACK_MESSAGE_TS}}",
	"thread_ts": "{{SLACK_THREAD_TS_OR_EMPTY}}"
}
```

创建意图应将其描述为配置的来源 Slack 频道中的一条新顶层报告。先核对平台实际支持这个事件及触发字段；不支持时保持任务未启用，只按已明确授权的手动或定时模式执行。它应包含已配置的仓库、默认分支、问题跟踪器、控制适配器、功能图及草稿拉取请求能力。

把来源频道和根讨论串时间戳视为不可变。任一值缺失或与配置不匹配时，停止，不发帖。

在这个准确的讨论串中，等待配置的分诊身份发出配置的分诊标记。只有 `[issue:bug]` 或 `[issue:performance]` 才继续。

尝试复现前必须具有配置的控制适配技能。通过真实 UI 两次复现能够区分该问题的准确症状。验证已有拉取请求或提交，不在其上编写改动。只有确认复现、通过操作文件的修复门槛且用户已有代码修改授权时，才尝试有边界的修复。打开草稿拉取请求和发送结果分别需要相应已有授权；无人反对不等于新增许可。

协调者是唯一的 Slack 发帖者。每份子任务提示都必须禁止 `SendSlackMessage`、`PostToSlack`、`chat.postMessage` 及其他所有 Slack 写入。子任务只返回发现。

绝不在来源频道发布根消息。
