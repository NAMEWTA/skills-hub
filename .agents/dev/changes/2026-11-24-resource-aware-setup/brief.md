# 资源感知的开发初始化与按需团队配置

## 目标与授权

用户要求优化 `skills/dev/dev-setup` 及相关 dev 技能，研究并采用成熟官方与开源方法，推送 `main` 并发布补丁版本。基线为 `62aa895600d18891219af9e97046e393b8f66647`，版本 `0.1.26`；计划发布 `0.1.27`，发布前复核远端避免覆盖并行维护。

## 行为契约

1. 环境接入检查当前执行宿主及用户指定且可访问的远端，对照项目运行要求与有效 CPU、内存、磁盘及适用限制，记录实际来源和未知项。
2. 分开报告 Agent、重任务和 worktree 上限及可新增量，按主机/共享池统一预留。计入嵌套执行、完整进程树、依赖缓存与峰值增长，容量可以为零，单会话上限不代表全机容量。
3. 规划区分 DAG 就绪和资源准入；派发、安装、构建、验证、恢复及回收后复测。未知成本先有界校准，资源不足排队，子任务不重复取得整机预算。
4. 清理复用 `dev-worktree`，补进程身份、有序退出与释放复测，不增加第二套删除脚本。保护未保存内容、活动或固定会话、手工锁与未知归属。
5. 团队配置仅按明确请求创建/修改，按 topic 保存 `.agents/dev/context/team/<team_name>.md`；使用由用户显式引用，不选默认组，不向根指令注入自动加载。阶段技能不主动选择模型规则。目标项目历史配置不因技能升级自动搬迁。
6. 自有技能遵守中文、两字段 frontmatter、包内资源可达和单一方法归属。同步模板、帮助、文档、运行映射与历史迁移目标。

## 范围与依据

完整容量方法归 `dev-setup`，完整创建/合并/清理归 `dev-worktree`，其余阶段只消费权威环境记录。复用本仓既有模板、只读审计、验证器与发布工作流；不新增调度服务、资源管理依赖或主机探测脚本。

研究证据见 [research.md](research.md)，实施与验收见 [plan.md](plan.md)。真实远端主机和用户电脑资源不属于本次代码维护的实测对象；自然语言场景使用明确的合成现场，真实跨平台包装与运行回归由仓库 CI 验证。
