# MISSION.md 格式

`MISSION.md` 位于工作区根部。它记录用户学习此主题的_原因_。每个教学决策（接下来教什么、推荐什么资源、设计什么练习）都应能追溯到本文档。

## 模板

```md
# 使命：{主题}

## 为什么
{1–3 句话。用户追求的具体现实目标。掌握该技能后，其生活或工作会改变什么？避免“理解 X”这类抽象表述；追问背后的结果。}

## 成功的样子
- {用户将能做的一件具体、可观察的事}
- {另一件具体的事}
- {……}

## 约束
- {时间、预算、既有承诺、学习偏好，任何限制方法的条件}

## 范围外
- {用户明确暂时不想追求的相邻主题，以保护最近发展区}
```

## 规则

- **每个工作区一个使命。** 用户想学两件无关的事，就应有两个工作区。
- **具体胜过抽象。** “十月前跑完半程马拉松”优于“变得更健康”；“向团队交付一个 Rust CLI”优于“学习 Rust”。
- **反对含糊。** 用户说不清为什么时，先访谈再写。糟糕的使命比没有使命更糟。
- **现实变化时修订。** 使命会变。用户目标改变时，更新此文件：不要让过时使命引导未来会话。
- **保持简短。** `MISSION.md` 超过一屏时，它已不再是指南针，而成了计划。
