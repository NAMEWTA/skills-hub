# 代理与网络路径

先明确应用、真实运行主机、故障时间、预期出口和受保护范围。当前 Agent、容器、WSL 或 SSH 会话里的 localhost 不自动等于用户电脑。

## 工作方法

1. 复用错误、当前客户端/内核版本、有效配置和已有授权。只读任务只诊断；用户已经指定的改动范围直接推进，不重复确认。
2. 用 [分层诊断](references/diagnosis.md) 区分应用、代理监听、规则、TUN、DNS、IPv6、TLS 与服务响应。一个出口查询不能证明整机路径。
3. 用 [平台取证](references/platforms.md) 查真实运行环境；Clash Verge Rev、FlClash 或 Mihomo 再读 [客户端与 DNS](references/mihomo.md)。
4. 先形成字段级差异与回滚办法，然后改动实际配置来源。保留订阅、节点凭据、用户策略与未涉及字段；不要修改客户端会覆盖的生成文件。
5. 分阶段应用、读回运行时结果，再用原失败应用复验。写入成功、配置加载、实际请求成功分别记录。

修复需要的最少、与任务相关的网络请求可在任务授权内执行；只读离线要求则不联网。不要默认上传配置、访问第三方“泄漏检测”站或进行中断网络的 crash 测试。远程改路由、TUN 或防火墙前必须有独立救援路径，不能切断当前唯一管理连接。

## 判断边界

- DoH 是加密解析，不自动表示经过代理；fake-ip 不表示所有系统/浏览器 DNS 已接管。
- Rule 模式可命中 DIRECT；看到代理端口请求仍需确认最终策略链。
- AAAA 回答和 IPv6 传输是两件事；代理出口 IPv6 与本机原生 IPv6 分别检查。
- 清缓存不改变路由；改时区/语言不修网络；服务地区拒绝本身不是 DNS 泄漏证据。
- 不用关闭 TLS 校验、放宽防火墙、清空系统代理或失败后直连来“通过”验证。

## 记录与完成

记录目标应用/主机、原状态、必要变更、真实命中链、DNS/IPv6 观察、回滚位置和未验证项。可用 [网络记录模板](assets/network.md)，保存在用户现有运维目录或 `.agents/system/<host>/`。

订阅 URL、controller secret、认证头、Cookie、节点密码及完整有效配置只留在适当的私有配置位置；公共记录保存脱敏证据和凭据引用，不保存秘密值。

原任务已恢复才报告修复。没有现场访问或某层证据不足，就交付具体下一步并标明未验证，不作“绝不泄漏”“全机都生效”或服务资格保证。
