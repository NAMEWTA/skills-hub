# 向导

**向导**是一个 bash 脚本，逐步引导人类完成手工流程：手动做很繁琐，每次重新向 AI 解释也很繁琐。它打开每个 URL，准确说明点击和复制什么，捕获值并写到正确位置（`.env`、GitHub secrets），每阶段确认，并显示还剩多少阶段。它可以配置第三方服务、执行一次性迁移，或将项目从一种状态切换到另一种状态。

[template.sh](template.sh) 已解决友好的用户体验：分阶段进度、确认关卡、跨平台打开 URL（包括 WSL）、隐藏密钥输入、幂等 `.env` 更新插入、`gh secret`/`gh variable` 写入和结束摘要。**你的工作只是明确流程范围并编写各阶段。** `STAGES` 标记上方的库在每个向导中都相同；一致性就是目的：绝不手动编辑它。

向导默认是临时产物：为一次运行而构建，保存到临时工作路径或 `scripts/`，任务结束即删除。只有用户希望仓库保留可重复的设置路径时才提交它。

## 过程

### 1. 明确流程范围

弄清人类必须执行的每一步，以及沿途捕获的每个值。先读仓库，不要毫无准备地提问：

- 配置时：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置和 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是向导必须产出的值）。
- 迁移或转换时：当前状态、目标状态、两者之间不可逆的操作。

然后向用户展示按顺序排列的阶段，以及每阶段产出的值并确认：用户可以增加、删除或调整顺序。

**完成条件：** 每个阶段均按顺序命名；对每个捕获值，你都知道 (a) 人类从哪里获取它，(b) 写到哪里（`.env`、GitHub secret、两者都有，或哪里都不写；某些阶段纯粹是操作），(c) 它是密钥（隐藏输入）还是公开值。

### 2. 映射各阶段路径

为每阶段写出人类应遵循的精确路径：打开哪个 URL、在那里做什么、值显示在哪里、填入哪个变量。例如“Dashboard → Developers → API keys → Reveal test key → copy”。如果你实际上不知道当前 UI 或准确命令，就说明情况并询问用户或查阅文档：绝不编造可能不存在的步骤。

**完成条件：** 每阶段都有陌生人也能遵循的具体指令。

### 3. 编写向导

把 `template.sh` 复制到目标路径。用每一步一个 `stage` 替换示例阶段，按依赖顺序排列。使用库辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设为所写阶段数量。

保持模板设定的标准：先打开 URL 再询问其中的值；所有密钥使用 `ask_secret`；每个需要持久化的值都用 `write_env`；只有 CI 真正需要的值才用 `set_secret`；任何不可逆操作之前先 `confirm`。每个 `stage` 清屏，只显示当前步骤：每阶段只聚焦一个任务，避免人类所需的信息滚出屏幕。不要改动标记上方的库。

### 4. 验证并交接

- `bash -n <script>`；若有 `shellcheck`，运行它。
- `chmod +x <script>`。
- 不要自己端到端运行：它会打开浏览器并阻塞等待人类输入。改为静态追踪：步骤 1 中每个值都被捕获，且落在步骤 1 规定的位置；每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用准确匹配。
- 告知用户如何运行。如果它是可重复使用的设置路径，就提交并从 README 链接它，让下一个人直接运行脚本，而不是再询问 AI。
