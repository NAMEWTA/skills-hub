### 调查

**你负责答案。规划、路由、写作。**

调查请求只读，产出有引用的解释或建议，不改代码。

1. 追踪问题涉及的代码。对于动机类问题，也路由到 **why** 技能。
2. 吞吐检查点保持一行：`throughput checkpoint: n/a, read-only investigation`。
3. 输出结果（概览 / 关键概念 / 工作原理 / 位置索引 / 注意事项）；若请求是在备选方案间作决定，则给出建议并附上取舍表。
4. 回复应用 **unslop**。

不开 PR、不跟进、不运行 `architect`，除非调查是代码改动前置。若是，则交还用户，再路由缺陷修复或功能开发。

**回复：** 调查结果。“我们确定吗”类回答包含有理由的真实判断。前提错误就提出异议，见自主性。
