# 任务示例与反例

需要判断小任务是否过度规划、独立任务是否足以接手，或如何表达覆盖与共享边界时读取。以下均为假想项目的写作示例，不是当前仓库事实，也不是已经运行的检查。路径、符号和命令在实际项目必须重新核实；示例约定不成为其他项目的默认产品决定。

## 小改动保持小

**请求：** 把两个既有提示中的“暂存”改为“保存”，行为不变，只需要实施前的简短计划。

**反例：** 新建数据库、接口、页面、测试四张票，补齐多阶段 PR、回滚和审查流程。

**合适的最小计划：** 一个切片修改两处提示，范围仅限文案；核对差异及原有文案检查，确认交互和数据逻辑未改。用户只要求计划就在此交付，不创建独立任务文件或实施代码。

## 独立任务写成交接契约

**示例前提：** 假想项目已确认“从 CLI 创建任务，重启后仍可读；空标题不得写入”。已有 `cli.mjs`、`src/tasks.mjs` 的 `createTask` 与 `listTasks`，以及 `test/smoke.test.mjs`；计划新增的行为测试尚不存在。此例沿用[单个切片](plan-template.md#单个切片)，不是第三套模板。

**反例：** “完成创建功能；更新 tasks 模块；测试通过。”接手者仍不知道入口、持久化要求、失败行为和如何证明。

```markdown
# 01 从命令行创建并持久保存任务

规格：spec.md 的“创建与持久化”及“空标题”两节；目标是让用户重启 CLI 后仍能读取刚创建的任务。
交付：通过现有 CLI 创建任务，再启动一个进程列出它；空标题不产生记录。
依赖：无；本项包含自身验收所需的 CLI、业务和存储改动。
边界：只负责创建与读取结果；沿用现有存储格式，不增加编辑、删除或新存储后端。
当前代码指针：cli.mjs 为入口，src/tasks.mjs 的 createTask/listTasks 连接现有存储；实施前复核观察版本。拟新增 test/task-create.test.mjs，不是已有测试。

## 实施要点（需要时）
沿用现有错误与存储约定，先核对相邻实现；新增行为测试包括独立进程与临时数据隔离。局部函数组织由实施者决定。

## 验收
- [ ] 在隔离数据目录通过现有 CLI 创建任务，结束进程后重新列出，标题与记录保持一致；由拟新增行为测试及真实 CLI 操作验证。
- [ ] 空标题被拒绝，进程返回现有约定的失败结果，存储字节不变；由拟新增测试验证。
- [ ] 既有读取场景继续成立；由现有 smoke 验证。

## 完成证据
实施时在项目根创建并运行 node --test test/task-create.test.mjs，核对上述行为断言实际被执行；另运行已有 node --test test/smoke.test.mjs。
记录 CLI 操作、隔离数据位置、真实退出与观察、工作树或提交及证据路径。测试未创建前不宣称命令已可运行，也不预填通过。
```

任务交接给无法读取同一文件系统的实施者时，应提供相关规格和必要源码材料，而不只发送文件名。公开接口、产品决定和完成标准清楚即可，不需要预写每个函数。

## 覆盖与依赖不能互相冒充

**请求：** 用户需要创建、编辑、删除三个行为。

**反例一：** 三个任务都写成“完成任务管理”，各自只验证创建；所有复选框勾完后声称三个行为都完成。

**修正：** 按行为明确责任，逐项从原规格反查。编辑与删除若需要已有记录，可以各用自己的夹具；只有确实消费前项实现或契约时才连阻塞边，不把准备测试数据的便利当作强制依赖。

**反例二：** 早期切片承诺“创建后可编辑”，却把编辑留给后续任务；早期切片无法完成自己的验收。

**修正：** 创建切片只承担创建及读取；编辑另有独立验收。跨场景组合由明确的整合责任验证，放在现有合适任务中即可，不强制新增“检查票”。覆盖表只链接这些责任，不复制验收正文或进度。

用户要求的是三个行为，不意味着必须恰好三张票；用户明确指定票数时也不能静默改成别的数量，确有冲突应说明。

## 共享语义与风险边界

### 不同文件也可能冲突

**反例：** A 修改 API，B 修改 CLI，因为路径不同而直接并行；两者却对同一个金额字段分别采用“元”和“分”。

**修正：** 沿用规格已经确认的金额单位，由明确负责人稳定共享契约，再安排消费者适配和各自验证；核对接口两端及真实调用方。若单位尚未决定，只阻塞依赖该决定的工作，不能让两个实施者各自猜测。独立工作区不能解决语义冲突。

### 高风险才固定必要顺序

**反例：** 把数据迁移写成“执行脚本，失败就再试一次”，没有说明部分写入或旧调用者。

**修正：** 根据既定迁移约束说明备份或安全恢复、如何确认已发生的写入、何时能重试、遇到何种不一致停止，以及旧调用者退出的判据。需要持续兼容时保留扩展、迁移、收缩；已允许整体替换时使用真实整合边界，不凭空保留两套接口。这里需要的是本项真实风险的处理，不是每张票复制同一段回滚清单。

### 设计引用要能定位

**反例：** “按最新原型实现详情页”，只给原型首页；实施者重新决定错误状态与窄屏布局。

**修正：** 引用已采用版本的详情页、对应状态、结构/样式/交互定位及必要视口；未确认的状态记录为缺口。原型截图只证明原型，最终仍需验证实际产品页面；缺少浏览器时如实保留未验证范围，不虚构视觉通过或额外设计审批。
