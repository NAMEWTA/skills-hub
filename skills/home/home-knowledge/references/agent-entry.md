# Home 入口与合作约定

本方法维护 Home AGENTS 的组织、读取条件和知识指针，以及确有需要的长期合作风格。入口使实际任务能找到必要正文；具体知识与配置在各自权威位置维护。

## 入口层级与读取时机

| 位置 | 职责 | 维护方式 |
| --- | --- | --- |
| Home 根 AGENTS 或已选宿主的有效等价入口 | 用短指针让 Home 工作进入 `.agents/home/AGENTS.md`，保留原有根规则 | `home-setup` 在完整初始化时合并或复用 |
| `.agents/home/AGENTS.md` | Home 的约定、作用范围及实际资料入口 | 缺失时安装器创建，此后按本方法和用户授权维护 |
| context、notes、history、coordination、relations 等 | 本次任务需要的配置、现行结论、历史或当前任务 | 原 owner 保持唯一正文 |
| 实际项目 checkout | 项目有效指令、内部知识、代码和技能 | 项目 Agent 在当地读取与执行 |

现有 `.agents/AGENTS.md` 可继续作为中间指针；无需新增第二份必读规则。区分 Home 根、OS 用户目录、技能源码根与目标项目根。指针相对包含它的文件解析，不能一律相对当前 cwd。

激活任何 Home 技能时，执行者显式读取实际 Home 主入口。同一上下文已读同一根、同一版本时可复用；新会话、压缩后缺失、入口变更或 Home 根变化时重读。父 Agent 读过不证明子 Agent 已读。按入口读取已有且影响本次行为的 preferences；职责背景、可选合作风格和主题正文按条件展开。

主入口不可读时先只读核对实际根、入口路径、文件类型和安装状态。可用时调用 `home-doctor`；未安装 doctor 仍可做这些最小检查。安装缺项交实际安装入口重装已选 Home 技能，语义或冲突由本方法处理。诊断不以先读到缺失文件为前提，也不借机初始化其他 domain。

## 写清渐进式披露的指针

每条指针说明“何时读取、读取哪里、用于什么”。只保存能影响本次选择的信息；短入口保持步骤和分支清晰，完整方法留技能参考，正式知识留现行 owner。

例如，已有 `notes/delivery.md` 时可在入口写：

```md
## 当前资料入口

- 协调版本交付前读取 [发布约定](./notes/delivery.md)，核对项目交付边界与验收责任。
```

只有实际建立且需要使用的文档才写 Markdown 链接。说明潜在路径时使用行内路径及“存在时”“明确启用后”等条件。新增链接后核对目标真实存在、大小写及相对基准；缺少尚未创建的可选资料不是初始化失败。

单次查询先沿主题、repo ID 或时间找到有关正文，命中后读足够完整的结论及条件。索引缺失或截断时检索正文并报告覆盖范围。大量候选、归档和全部项目知识不随启动全量加载。项目内部细节交当地 Agent，只回传管理需要的证据。

当前工作方法和路由以已安装技能的 `SKILL.md` 和包内参考为依据。入口保留本 Home 的约定及实际资料位置。未装某项技能只限制需要该方法的工作，其他已安装技能可独立使用。

## 同一文件的维护边界

| 内容 | 写入责任 |
| --- | --- |
| 首次 Home 主入口 | 文件缺失时由实际安装器创建 |
| 已有 Home 主入口的约定、说明和资料指针 | 用户和经授权的 home-knowledge；技能安装保留整个文件 |
| profile、preferences、dispatch、team、environment | home-setup；本方法仅维护必要引用和理由 |
| 主题、历史、当前任务 | 各原 owner；主入口只指路 |

长期规则沿用原权威文档。旧入口的历史安装标记可以作为普通注释保留。技能更新通过安装包替换本体，入口内容按实际需要和授权编辑。

## 首装、迁移与修复

安装器只在入口缺失时补齐。已有普通文件在重装后保留原字节。空白正文、失效指针或过期说明按实际需求处理。

已有授权包含入口迁移/修复时，按以下顺序完成具体恢复；无需再为 owner 交接询问权限：

1. 阅读全文、当前用户约定及相关技能方法，核实仍有效的规则、需要修复的指针和实际冲突。
2. 按下方写前复核步骤直接编辑授权范围内的入口，沿用有效正文及资料位置。历史标记按原件及请求处理。
3. 回读改动和受影响的链接，确认现有入口能够引导实际任务。无法读取或修复时指出具体缺项。

主入口完全缺失且没有待迁移内容时，直接交原安装机制补齐；不先写一个同名空白文件制造额外冲突。普通安装不修改根指令，完整 Home 初始化的根短指针由 setup 合并。

## 最小编辑与复核

AGENTS/SOUL 不属于现有知识 CLI 主题白名单，也不受其 `--expect`、主题索引或 `.home-content-write.lock` 保护。使用当前环境真实的文件编辑能力：

1. 读取真实目标完整内容与基线摘要，核对文件身份和已有链接；新建时确认路径仍不存在。链接或类型异常先核对目标，不跟随不明路径写入。
2. 在内存或过程临时文件准备最小修改。入口与 SOUL 只改已明确授权部分。保留其他用户内容、有效范围和实际来源日期。
3. 写入前重新读取目标，比较原内容或摘要。基线变化就重新合并双方内容；不能更新 hash 后直接重放旧稿。新建目标已被他人创建时改为读取合并。
4. 使用当前工具支持的最小编辑或原子替换，写后回读正文和受影响链接。发现并发变化后保留双方有效内容并报告范围。
5. 多文件维护中断时记录实际已完成与待修项。正文保存成功而入口更新失败时，保留正文并说明入口待修；继续时读现状，避免重复写入。

知识/历史工具支持的主题继续使用其已有版本检查和写锁。不要放宽通用 `put` 路径，也不要为入口维护建立第二套知识数据库。

## 可选 SOUL 和唯一归属

先找到现有 owner：Home 职责与用户提供的工作背景在 profile，语言、时区、派遣/team、保留和复核偏好在 preferences，现行主题在 notes，历史在 history，当前直接任务在 coordination。已有等价风格文档可原地使用，不强制改名。

只有用户明确要求长期保存、且现成 owner 尚未承担的合作原则和表达方式，才按[SOUL 模板](../assets/soul.md)建立 `.agents/home/SOUL.md`。缺省合法，不建立空人格档案，不新增同义 USER/MEMORY/policies 文件。角色背景或语言已在 profile/preferences 时只引用原件；同项更正交 setup 继续完成。

保存后在 AGENTS 增加有条件的真实链接，例如“制定协作计划与汇报结果前读取合作约定”。已有等价启用指针直接复用。任何宿主是否原生加载另行验证。

一次临时风格要求只作用于本次。明确长期更正按授权更新原 owner，来源文章、历史转述和模型推断不能自行改变用户默认或权限。停用时更新读取条件；忘记按[维护方法](maintenance.md)处理实际正文及已知派生引用，保留无关有效约定，报告未触达的原生会话、远端、Git 历史及备份。

## 完成条件

Home 主入口能按本次任务找到已维护的正文。请求包含完整初始化或根接入时，再核对根入口能指向 Home 主入口。直接激活任一已安装 Home 技能可完成其独立分支。入口编辑已回读，现行规则和合作风格有各自可核实的来源，安装与宿主执行按实际证据报告。
