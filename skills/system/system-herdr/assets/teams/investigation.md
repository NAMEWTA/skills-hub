# 调查与方案

适用于调研、故障诊断、根因判断和方案比较。按不同假设、证据来源或问题边界分工，让每个任务能够形成独立、可核验的结论。

## 使用方式

1. 在 [topic 模板](../topic.md) 写明需要作出的决定、已知事实、尚未回答的问题和停止条件。按问题价值选择投入，不预设人数或固定轮数。
2. 用 [task 模板](../task.md) 给出必要背景、调查边界、证据范围与输出要求。任务之间应有实质区别；需要独立判断时不把 Lead 偏好的答案写成前提。
3. 让各 worker 分别检验自己的假设，寻找支持与反例，记录信息来源、复现条件和搜索范围。没有找到证据时说明查过哪里，不直接断言对象不存在。
4. 按 [文件协议](../../references/file-protocol.md) 先投递所有独立任务，再观察和等待。默认不修改业务产物；确需实验或修改时，在任务中明确允许范围。
5. Lead 对照原始证据合并结果，区分一致结论、冲突证据和缺失信息。只有缺口会改变决策或验收时才继续派发；冲突通过有针对性的核验解决，不用报告数量表决。
6. 更新 topic 中的必要结论，交付建议、适用条件和剩余不确定性。若下一步需要实现，另行写明任务边界与验证要求。

## 报告应回答

- 检验了什么假设，取得了什么证据，哪些结果能够复现。
- 事实、推断和不确定性分别是什么；是否存在反例或证据冲突。
- 可行方案的关键取舍、建议和适用条件。
- 哪项额外验证最可能改变当前结论；没有必要继续时直接说明。
