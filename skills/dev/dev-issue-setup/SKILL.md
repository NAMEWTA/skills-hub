# 问题自动化配置

为两个协作任务准备完整可用的项目配置：问题报告分诊，以及真实 UI 复现与范围受限的修复。本包包含两个完整运行方法和共同资料，单独安装即可配置和运行；不要求另装其他技能。

先阅读 [目标与运行契约](references/automation-intent.md)，再完整执行 [配置方法](references/setup-method.md) 的八个阶段。快速导航见 [包内概览](references/package-overview.md)。

## 完成配置

1. 确定目标仓库和现有任务身份，把完整包无损安装到 `.agents/skills/dev-issue-setup/`。保护用户本地编辑、仅目标存在的文件和包外配置。
2. 从 [配置模板](assets/configuration.yaml)、[功能图](assets/feature-map.md) 和 [分流图](assets/routing.md) 创建项目副本。新增配置统一使用 `.agents/wtadev/project/issue-automation/`；已有配置按真实位置查阅引用。
3. 填写频道、身份、追踪器、仓库、控制能力、预算和实际可用的角色模型。先从项目与工具读取，只问关键缺失决定。
4. 核对真实读取、线程回复、附件、追踪器去重与补偿、仓库及草稿 PR 能力。秘密只存密钥管理器或环境，不进入配置正文。
5. 按 [控制契约](references/control-adapter.md) 执行九步无害检查，证明功能图可以真实驱动应用、捕获证据并清理。
6. 创建时依次准备 [分诊提示词](assets/triage-prompt.md) 和 [修复提示词](assets/fix-prompt.md)；已有任务按原标识更新，先核实实际工具是否支持更新，不创建替代重复项。
7. 核对运行环境能读取完整本地操作文件与非秘密配置。独立仓库检出需要它们位于实际使用的分支或版本，不能只在当前会话存在。
8. 执行完整方法的七项线程安全检查。全部通过且启用已经获准后，才接入正常流量。

## 保持授权和工具真实

配置文件与技能安装不会自动授予后台调度、消息发送、追踪器写入或代码修复权限。用户只要求配置时，先完成可审查配置、完整提示词和已执行检查；已有明确创建、更新或启用授权时继续完成，不重复审批。平台真正要求的审批按平台流程执行。

来源频道新顶层消息触发必须是当前平台真实支持的能力。缺失时写清限制，保留完整配置；不编造事件监听，也不自行替换成未获授权的轮询。用户明确选择手动或定时模式时，按实际工具能力配置并说明变化。

一次性的配置或测试不等于启用了后台任务。回读实际任务标识、触发器、提示词和启用状态，再报告完成结果。

## 运行方法

- [完整分诊方法](references/triage-method.md)：冻结坐标、完整附件、原因追踪、分类、分流、追踪器、去重、新单条件、一次结论和后续窗口。
- [完整复现修复方法](references/fix-method.md)：可信分诊、归属、真实 UI 双次复现、媒体证据、已有修复验证、根因修复、前后证明、草稿 PR 和清理。
- [验证已有修复](references/verify-existing-fix.md)：隔离基线和修补版本，明确已确认、修复不足与无法下结论。
- [全部本地支持资料](references/method-index.md)：代码理解、历史、测试、写作和执行原则。

## 交付和维护

交付配置路径、完整提示词、实际创建或更新结果、适配器验证、线程安全证据和仍受阻的能力。没有真实工具返回或回读证明时，不宣称任务已经运行。

项目配置和功能图独立于技能包，更新包时保留。运行记录默认用 `.agents/wtadev/changes/<日期-任务>/evidence.md`，长期理由与术语沿用 `.agents/wtadev/notes/`。只记录恢复所需事实、证据和决定，不引入复杂 Schema、固定状态迁移或逐次工具调用台账。通用约定见 [本地执行支持](references/execution-support.md)。
