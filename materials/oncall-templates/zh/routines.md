例行任务刻意保持薄：它们决定*何时、何地*；技能与 ONCALL.md 决定
*怎样做*。如果想把阈值或格式塞进例行任务，先停下——那属于策略，
应通过 PR 放进仓库。

每个计划都写时区（“9am {{TZ}}”），否则默认使用 UTC。

## 成本是什么（读一次）

常驻工作是 Agent 花费 token 的主要地方；本套件旨在让成本保持低位。
交接每周一次。告警观察任务由事件驱动——没有触发就没有花费，
告警风暴会合并成一次分诊。**没有快速轮询项**。修复后的验证是
三次有界检查，不是轮询循环。你能控制且最影响成本的一点是：
观察任务覆盖哪些频道（不要监视高流量却很少有可行动告警的频道——
先修好这些告警）。

这里刻意没有*轮询式*状态服务。下方可选的天气任务在事件门控的
编写步骤之前，放了一个确定性的频率保护：计划会频繁触发，但
大部分触发在两次读取后提前退出，不发布内容，只消耗几百 token。
频道只收到*事件*；报告页面承接其他内容。

可用于预算的粗略 token 量级（依赖模型和技术栈——只当数量级，
并且**试点期间实际测量**，支出限制正是为此设置）：单次分诊约
30–100k tokens（达到呼叫级别且并行展开时可能是其数倍）；每周交接
约 50–150k；安静的一周约等于一次交接；天气完整周期约 2–5k，
提前退出约 0.3k——安静的一天只有少数完整周期。
按你的模型当前价格换算。

## 检测怎样接线（粘贴前阅读）

现有确定性告警仍是真相来源：PagerDuty（或同等工具）把告警发送到
告警频道，值得呼叫的告警像以前一样直接呼叫人员。**Claude 绝不在
检测路径上**——它的常驻角色是观察告警频道并对触发的事件分诊
（例行任务 2）。它在检测本身中的角色仅为建议与调优：新服务的
初始规则（见下文）、覆盖缺口和事件后循环产生的调优——始终由人员
安装进真正的告警工具，让它们不会悄悄失效。

## 1 · 每周交接（只读）

```
@Claude 每逢 {{Monday at 8am {{TZ}}}}，运行仓库中的 handoff 技能，
覆盖过去一周，并把结果发到这里。
```

## 2 · 观察告警频道 → 分诊（发布诊断）

<!-- 旁路观察期间，把“发布到它的讨论串”改为“发布到
     {{#review-channel}}”，并按 eval/replay.md 每日评分。 -->

```
@Claude 观察 {{#alerts-channel-1}} 和 {{#alerts-channel-2}}。新告警到达时，
运行仓库中的 triage 技能，把诊断发到它的讨论串——先按技能要求进行
跨频道关联。如果多条告警同时到达或关联一个未结束事件，按技能把它们
作为一批分诊：一份诊断列出它解释的每条告警，绝不每条告警发一份。
只建议修复——绝不执行任何操作。
```

## 3 · 新服务？先设初始告警，不设临时桥梁

新服务没有常驻例行任务——检测始终是确定性的。上线前（或上线时）
在频道里请求：

```
@Claude {{service}} 即将上线但还没有告警。请提出保守的初始规则——
借用与它最接近的现有服务中挖掘到的阈值，加上标准默认值——
给出可直接粘贴到 {{alerting tool}} 的内容，让人员在上线前安装。
```

由人员安装；从第一次真实事件开始，事件后循环（triage 的“有没有规则
本能更早发现？”以及告警覆盖报告）持续调优。

## 4 · 例行任务登记（Claude 维护；粘贴一次）

```
@Claude 维护“本频道的常驻工作”画布（或置顶说明）：每当这里的例行任务
被创建、编辑、从旁路观察转正或停用时，更新登记——每项的名称、计划、
一句话用途、正式/旁路状态和最后变更日期。末尾写：
“要改变何时/何地，编辑这里的例行任务；要改变方法/策略，向 {{repo}} 提 PR。”
```

## 5 · 早间简报（工作日，只读）

```
@Claude 每个工作日 {{8:30am {{TZ}}}}：读取 paging-log.md，以及上次简报
之后的 lessons.md 条目和未结束事件记录，最多发布 6 行：每个未结束
事件（状态 + 新读者能理解的一句话经过）、昨天值得人员关注的日志级
观测，以及所有僵尸事件（未结束、沉默 >{{24h}}——按 ONCALL.md 生命周期
规则，附三项证据一句话）。如果确实无事——没有未结束事件，也没有日志级
条目——就完全不发布内容。
```

## 6 · 天气报告（选择启用——先读成本段）

```
@Claude 每隔 {{10 min}} 运行仓库中的 weather 技能。它的阶段 0 是频率保护——
有呼叫级别未结束事件时目标间隔 {{10 min}}，平静时 {{60 min}}——
所以多数触发在两次读取后退出。只有技能的某个门控触发时才发到本频道；
每个完整周期无论如何都更新 {{report canvas / repo file}}。
```

计划间隔是你想要的*最紧密*频率；技能内部的保护决定一次触发是否做事。
绝不把计划设得比最快目标间隔更慢，否则呼叫级别事件无法获得紧密频率。

## 管理这些任务

在频道内：“这里设置了哪些例行任务？”· 描述修改 ·“停用 {{Friday rollup}}”。
频道中的任何人都可以做这三件事——这是设计如此。登记画布提供相同答案的
一眼概览；每周交接中的漂移检查验证它仍与实际安装内容一致。
想知道当前状态，任何人都可以直接在频道里问（“@Claude 当前情况怎样——
可以安全合并吗？”）——按需回答不需要常驻例行任务。
