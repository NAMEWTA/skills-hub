# 更正、整理与忘记

## 目录

- 更正和部分替代

- 写入冲突和中断

## 更正和部分替代

先读用户所指主题、源证据和实际生效位置。配置中的偏好或默认由 `home-setup` 修改；项目内部真源由项目 owner 处理。knowledge 更新自己的现行结论和指针，history 处理有价值的当时事件。复用用户已授权范围，交给相应方法完成，不把跨 owner 当成停在建议阶段的理由。

按结论逐项比较新旧内容：

| 情形 | 更新方式 |
| --- | --- |
| 原来记错 | 更正原主题，明确旧错误不再生效，修复引用与派生摘要 |
| 真正改变决定 | 新结论写明生效范围和后继关系，保留必要的当时理由 |
| 只替代一部分 | 修改被替代部分，保留其余有效条件、反例和约束 |
| 只是补来源或整理措辞 | 保留事实核验日期，不把整理日期当重新验证 |
| 用户临时覆盖默认 | 应用于本次，只有明确改默认时才交 setup 保存 |

不要整页覆盖新证据，也不因为 Git 留有历史就删除仍有决策价值的动机。需要保留历史理由时链接 history 或原记录，不形成另一份可编辑默认。

## 合并与退役

合并前阅读两边完整相关内容，保留有价值的来源、理由、替代方案、代价、反例、风险和重新适用条件。合并主题不改变结论原本的 owner 与观察时间。二次摘要注明派生关系，旧页有入链时逐个修复。

知识已不适用但仍有解释价值时，标明被何项取代或适用截止，按用户范围退役至 `.agents/home/archive/notes/`。归档默认不参与现行规则选择，历史查询可以显式读取。仍受阻、尚待决定的工作继续放在当前协调 owner，不能以清理资料为由记成完成。

工具没有自动判定事实真假或整批归档命令。对自己维护的原件采用读、写、回读、删旧的明确步骤；先保存目标并核实，再移除旧文件和修复入链。若用户已经有可恢复编辑方法，按其实际能力使用。

## 处理忘记请求

先分清用户是在纠错、停止使用、退役，还是删除内容。明确的“删除/忘记这项内容”沿用当前授权完成，无需重复询问；范围不明时先处理确定部分，仅澄清会造成错误删除的具体分歧。

1. 识别内容的实际来源身份、当前权威位置和已知派生引用。只调查本次范围，不扫私人宿主历史。
2. 列出受影响的 owner：setup 的 profile、preferences、team 和 AGENTS 中有效规则；knowledge 的主题、候选和归档；history 的事件与归档；map 或 coordination 中仍生效的引用。若没有某类副本，无需为流程建立空文件。
3. 各 owner 处理其真源及已授权派生内容。文档混有其他仍需保留内容时定点删除，不删整份无关资料。知识工具的 `remove` 只删指定文件，不代表整项忘记已完成。
4. 若用户允许保留防止再次摄取的最小身份，维护 `exclusions.md` 中的来源标识、范围和依据引用。排除条目不写被忘记正文，不以审计名义保存另一份内容。
5. 若连最小排除身份也不应保留，删除该条目并报告影响：将来重新导入未处理原件时，无法靠已删除标记判断它曾被排除。无需为未来假设增加一次审批。
6. 修复索引、常用入口、当前结论和历史指针。在已授权范围再次按关键词与来源标识检查，重建有关索引后复查，不让旧摘要重新成为规则。
7. 返回实际处理位置、结果和未触达范围。原生 CLI 记忆、原始对话、项目原件、Git 历史、远端与备份各有独立 owner；本地删除不证明它们全部消失。

只有纠错或退役时才按价值保留变更过程。用户明确要求忘记时，历史摘要不能重新复述完整旧内容。已经授权的外部原件处理交其真实方法继续；能力缺失时说明具体位置和未完成项。

## 排除与再次摄取

使用[排除模板](../assets/exclusions.md)或工具创建最小条目。排除由本技能维护，history 只读取。表头和格式不明时先读取用户原约定并整理，不能将无法解析当成空名单。

工具只对 `sources` 或 `derived_from` 中准确相同的来源标识、准确 scope 或显式 `*` 范围生效。它不爬取引用链，也不推断同义来源。范围扩大需要真实授权；不因为一个项目忘记某段内容，就删除别的项目独立合法资料。

混合主题中的一条来源被排除时，先由 owner 删除相关部分并保留其他有用结论，随后更新真实来源列表。不能只删 `sources` 字段来绕过正文处理。再次摄取时恢复原始来源与派生关系，先执行排除判断；换文件名、生成新的摘要 ID 和重建索引都不能成为重新使用旧内容的理由。

排除依据不是生成索引，index 命令不会清空它。解除排除也是对持久约定的定点更新，先读原文、核对用户明确决定并保留其他条目；本包没有一键清空名单命令。

## 写入冲突和中断

同一主题按单写入者组织，owner 是方法归属，不是进程锁。使用本包工具时，先 `read` 获取正文与 SHA-256，再按 `--expect` 写入。knowledge 与 history 的配合写入共用 Home 中 `.home-content-write.lock`，在锁内校验版本、判断排除和替换正文；不同事件使用不同文件。

`STALE` 表示原件已变化。重新读取并合并实际差异，不把 `--expect` 改成新 hash 后重放同一旧稿。`BUSY` 表示存在写入者或残留锁；核对所属操作和真实状态后处理，不能仅按锁的年龄或 PID 猜测删除。手动编辑和其他程序不受此锁约束，普通原子替换也不是 OS 隔离或跨主机锁。

工具只保证其明确单文件操作及读回，不提供跨 owner 全局事务。多文件更正或删除中断时，记录已经完成和待处理的文件；继续时重读现状，跳过已完成项，验证每一项结果。不会把半次操作标成全局完成。

## 重建与复核

正文是真源，索引仅含路径、用途和检索提示。正文保存后索引更新失败时，返回“正文已保存，索引待修复”，保留正文；修好阻碍再执行 index。不以删正文修索引，也不把 partial 当全部成功。

索引缺失或截断仍可检索正文。重建保持排序和内容稳定，不刷新 `observed_at`、`verified_at` 或历史事件时间。`review_after` 到期只产生复核提示，当前 HEAD 变化只触发相关内容的调查，实际核验完成前不能改日期或宣称结论已失效。

文件工具的 lint 只检查元数据、显式引用与复核提示。知识语义、来源原件真实性和项目当前状态仍由相应 owner 判断，doctor 只负责结构和导航诊断。
