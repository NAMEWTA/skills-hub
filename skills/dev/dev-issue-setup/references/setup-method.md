# 配置问题自动化

本包提供尚未启用的分诊与复现修复方法。安装目录固定为目标项目的 `.agents/skills/dev-issue-setup/`；本包已经包含两个操作方法、全部共同资料和模板，可以独立安装。读取本包 [自动化目标与运行契约](automation-intent.md) 理解完整意图，再执行本流程。

实际运行还需要包外项目配置，以及当前宿主真正支持的两个自动化或相应手动执行入口。文件存在不代表任务已经创建或启用。

用户未明确要求时，不创建或更新后台任务。已有创建、更新或持续运行授权继续有效，不重复询问。秘密值不写入技能包、提示词或已提交配置。

## 1. 安装并核对完整本地资料

在询问尚缺配置或调用实际自动化工具之前，先完成这一步。

从当前任务确定运行自动化的目标仓库；只有仍不明确时才询问。已安装时以本包为资料源；还未安装时，按项目安装器把整个独立包复制到 `<目标仓库>/.agents/skills/dev-issue-setup/`，不增加领域中间层。

将整个包合并到目标：

1. 目标不存在时创建。
2. 将包内每个文件复制到相同相对路径，包括全部参考资料和资产。
3. 保留只存在于目标的文件。安装或刷新期间不删除无关文件。
4. 用户拥有的配置、功能图和分流图保存在技能安装包之外，绝不覆盖它们。
5. 已有受管理文件存在差异时，检查差异并保留本地修改。归属不明确且无法无损合并时，先形成具体差异和候选合并，再只询问冲突决定。
6. 验证目标包含本文件、[自动化目标与运行契约](automation-intent.md)、[分诊方法](triage-method.md)、[复现修复方法](fix-method.md)、它们的参考资料及全部模板。

已从安装目标读取此文件时，复制视为完成，但继续之前仍做相同验证。

本包通过本地文件提供共同能力，无需插件开关或额外配置 JSON。逐项验证这些完整方法在目标包内可读：

- [模块运行追踪](module-exploration.md)，以及探索者与解释者任务书
- [历史依据调查](decision-investigation.md)，以及来源索引、调查任务书与综合方法
- [测试驱动方法](tdd-method.md)，以及行为测试和模拟指南
- [清理机械写作](clear-writing.md)
- [先拆分共享状态](shared-state.md)
- [降低阅读负担](reader-load.md)
- [上下文预算](context-budget.md)
- [可验证单元](verifiable-units.md)
- [修复根因](root-causes.md)
- [真实对象证据](real-evidence.md)

从实际自动化运行环境或一个以目标仓库为根的干净检出验证文件。不能把只在当前会话、个人安装目录或临时缓存中存在的资源算作可用。无独立执行环境时，检查目标文件与相对引用，并明确“自动化运行环境尚未验证”，不伪造新智能体验证。

任一必要本地文件不可读时修复安装；无法修复就说明具体缺失并保持相关任务未启用。不要依靠另一个未安装技能补足。

本包 `SKILL.md` 是标准技能入口，自动化可以直接读取稳定的 `references/triage-method.md` 或 `references/fix-method.md`。不要求宿主支持斜杠命令发现。

如果平台在独立仓库检出中运行任务，启用前必须让完整包和被引用的非秘密配置存在于实际使用的分支或版本中。用户已经授权提交或推送时完成它；否则准备可审查差异并说明启用所缺条件。不要无故要求本地读取型调度器提交文件。

通过此检查之后，任务提示词才可以通过稳定的仓库相对路径读取操作文件。不要引用会话缓存路径，也不要用不完整摘录替代方法全文。

## 2. 适配配置

打开本包示例：

- [配置模板](../assets/configuration.yaml)
- [功能映射模板](../assets/feature-map.md)

在技能安装包之外创建用户拥有的副本。它们是项目配置，不是包文件。新增配置统一放在 `.agents/wtadev/project/issue-automation/`；已有配置按真实位置查阅引用，不擅自移动或覆盖。具体文件如下：

- 项目配置：`.agents/wtadev/project/issue-automation/configuration.yaml`
- 项目功能图：`.agents/wtadev/project/issue-automation/feature-map.md`
- 项目分流图：`.agents/wtadev/project/issue-automation/routing.md`
- 仅在实际运行环境能读取时使用的个人配置：`~/.config/issue-automation/configuration.yaml`
- 同样条件下的个人功能图：`~/.config/issue-automation/feature-map.md`

为自动化可能复现的每个面向用户功能填写一个功能图章节。保持用户视角，不把实现细节或当前代码路径固定到图中。

不要编辑包内示例。刷新包可以在审阅冲突后更新受管理文件，但不触碰用户副本。

新的隔离自动化检出需要读取文件时，优先使用目标仓库中已提交的非秘密文件；否则将所需非秘密配置值完整转述进实际提示词。引用仓库文件前，由实际工具或运行环境确认它属于任务运行的同一仓库和正确版本。

配置使用简单 YAML，功能图、分流理由、运行证据和恢复点使用轻量 Markdown。`schema_version` 仅标明配置格式版本，不用它创建工作流状态机、状态迁移表或复杂校验体系。

使用稳定的项目相对路径。实际自动化不引用技能源码检出、会话缓存或仅作者机器存在的位置。

## 3. 填写必需选择

从已有项目资料、工具能力和用户决定中取得或确认以下信息，只问无法推断的缺失项：

- 来源 Slack 频道 ID
- 可选运维或状态频道 ID
- 仓库标识及默认分支
- 分诊身份或 Slack 用户 ID
- 问题追踪器类型、团队、项目、标签和接收状态
- 追踪器适配技能、连接器或实际动作
- 可选分流图路径
- 必需的控制技能或适配器名称
- 必需的用户视角功能图路径
- 状态表情字符串
- 拉取请求规范链接形式
- 轮询和工作量预算
- 分诊、复现、代码工作和媒体审阅的模型选择

默认继承当前模型。只有用户需要区分角色、且宿主确实支持时才配置不同模型；标识必须来自实际模型列表，不猜测名称，也不保留私有默认值。没有分角色模型能力不妨碍顺序执行。

来源频道、分诊身份、仓库、追踪器适配器、控制能力和功能图必须明确。任一必需值仍含糊时，完成其余准备，记录缺失项，保持受影响的自动化未启用。

同时在项目配置说明中写清已有授权覆盖什么：单次或持续运行、哪些频道的线程回复、追踪器创建与失败补偿、代码修复、提交与草稿 PR。配置值不是新的授权；用户已有明确授权无需再确认。

保存前，用 [清理机械写作](clear-writing.md) 检查最终任务名称、描述和提示词。

## 4. 检查集成能力

分诊自动化需要：

- 配置来源 Slack 频道及线程的读取能力
- 该频道中的线程回复能力
- 报告含媒体时所需的附件元数据和下载能力
- 通过已配置追踪器搜索、读取、创建和更新的能力
- 新工单交接失败时，能取消、关闭或删除本次新建工单的补偿能力

复现自动化需要：

- 来源线程读取能力
- 来源频道中的线程回复能力
- 配置运维频道中可选的发布和编辑能力
- 仓库读取和历史访问
- 当前目标包含交付草稿 PR 时，实际可用的创建草稿 PR 能力
- 已配置的控制适配器

能力契约不表示某个固定 API 必然存在。优先使用当前宿主已配置并核实可用的专用连接器、API 或 CLI。可选 `ISSUE_SLACK_BOT_TOKEN` 只用于用户配置的狭窄缺口，例如编辑一条运维状态消息或下载附件。令牌值保存在密钥管理器或环境中，不放 YAML，不传给子执行者。

不要使用未记录的集成端点。只读分析不需要写权限；缺失写能力时，不伪造完成结果，也不通过另一个频道补发。

## 5. 准备分流映射

用户希望转交或提醒负责人时：

1. 将 [分流映射示例](../assets/routing.md) 复制到技能包之外。
2. 把每个占位值替换为当前项目或组织的真实值。
3. 默认关闭负责人提醒。
4. 只有映射已列出且配置允许的功能负责人，或证据充分的可能回归作者，才可以被提醒；涉及向他人发消息时还需对应授权。

没有配置分流图时，分诊可以分类报告，但不能猜测目的地或负责人。

## 6. 验证控制适配器

阅读 [控制适配器契约](control-adapter.md) 和用户填好的功能图。

确认指定控制能力能够：

- 启动目标应用
- 通过真实 UI 导航到每个映射功能
- 通过声明的适配器动作操作映射状态
- 检查状态但不强制制造结果
- 捕获截图
- 开始和停止录像
- 清理自己创建的进程与临时数据

在已经授权的测试环境中执行契约末尾的九步检查。缺少任一必要能力时，保持复现自动化未启用，指出具体限制；不能把源码阅读、状态注入或单元测试称作真实 UI 复现。分诊能力已独立验证且用户授权时，可以单独启用分诊。

## 7. 准备实际自动化

先检查这是首次创建还是修改已有任务，复用用户明确给出的任务标识与授权。使用实际可用的自动化连接器或调度能力；需要界面时遵循当前宿主的真实界面操作。读写工具必须来自工具说明，不能编造动作、事件类型、隐藏端点或深链接。

两种路径都完整阅读 [自动化目标与运行契约](automation-intent.md)，理解两个触发器、工具、指令、结果和共同规则。文档描述的是可配置目标，不是本次自动获准执行的外发命令。

### 首次创建

一次创建一个任务。用户未请求创建或启用时，完成配置、提示词及检查结果，交付可审查草稿。

对每个已获创建授权的任务：

1. 阅读对应的 [分诊提示词](../assets/triage-prompt.md) 或 [复现修复提示词](../assets/fix-prompt.md)。
2. 将完整意图、填好的项目配置和模板转换为完整自然语言请求。
3. 让实际提示词读取本包在运行环境中稳定可访问的 `references/triage-method.md` 或 `references/fix-method.md`。
4. 使用经过核实的仓库相对路径，不用会话缓存路径。不用不完整副本替代完整操作文件。
5. 阅读实际自动化工具的能力、触发方式、更新语义和平台审批要求。
6. 通过实际连接器解析目标 Slack 频道、仓库及已连接集成，不重复询问已有明确值。
7. 确认完整包和引用配置在任务运行环境中可读；独立检出还需核对分支和提交。
8. 完成可审查的任务名称、触发器、提示词、授权范围和工具列表，再执行已经授权的创建或更新。平台确有强制审批时通过该流程；不人为增加重复批准。
9. 回读任务标识、提示词和启用状态，完成当前任务的配置后再处理下一个。没有可调用创建能力时，提供包含全部值的具体编辑器清单，不声称已经创建。

分诊任务的完整意图为：

- 名称 `issue-triage`。
- 每次运行读取并遵循 `.agents/skills/dev-issue-setup/references/triage-method.md`，或安装时已核实的同包稳定路径。
- 由已配置来源 Slack 频道中的新顶层报告触发。
- 读取触发线程，只在该线程内回复。
- 使用已配置的问题追踪器集成。
- 分类、检查证据、追踪原因、去重，只为明确新缺陷创建工单。
- 在仅限线程的单次结论末尾，附一个已配置的 `[issue:bug]`、`[issue:performance]` 或 `[issue:other]` 标记，以及可选问题链接。
- 绝不在来源频道发布根消息。

分诊任务配置完成后，处理完整的复现修复意图：

- 名称 `issue-reproduce`。
- 每次运行读取并遵循 `.agents/skills/dev-issue-setup/references/fix-method.md`，或安装时已核实的同包稳定路径。
- 由同一来源频道中相同的新顶层报告触发。
- 使用已配置的仓库和默认分支。
- 读取来源线程，只在该线程内回复。
- 包含实际可用且已获授权的草稿 PR、追踪器、控制适配器和功能图要求。无法读取文件时，完整转述必要用户路径、状态及非秘密配置，并说明限制。
- 行动前等待可信分诊标记。
- 通过映射的真实 UI 两次复现精确症状并捕获证据。
- 验证已有修复，不另写竞争改动。
- 只有确认复现后才在已有代码修改授权内尝试可选、范围受限的修复；证据与检查通过且 PR 创建已获授权时，打开草稿 PR。
- 绝不在来源频道发布根消息。

核实平台能否实现新顶层消息触发、所需消息坐标和可信分诊身份。若不支持，不创建虚假事件订阅，不自行改成高频轮询。可以准备手动执行或平台真实支持的定时模式；只有用户已经明确授权相应持续范围时才启用该模式，并写清差异。

不要重复连接器已经完成的解析、认证或强制审批；但必须回读实际创建结果，不把草稿当作已启用任务。

### 已有自动化

先核对实际工具是否支持读取和更新。支持时使用已有任务标识更新，不新建重复项；工具只支持创建或界面更新时，不假装存在更新 API。

完成配置、分流、控制适配器和功能图验证，然后更新或提供以下完整字段清单。

已有分诊任务：

- 名称和描述
- 直接读取本包稳定 `references/triage-method.md` 的指令
- 新顶层 Slack 报告触发器及来源频道
- Slack 线程读取和回复能力
- 问题追踪器集成及失败补偿
- 完整分诊指令、仅限线程规则和结论标记

已有复现任务：

- 名称和描述
- 直接读取本包稳定 `references/fix-method.md` 的指令
- 匹配的 Slack 触发器和来源频道
- 仓库和默认分支
- Slack 线程读取和回复能力
- 草稿 PR 动作与已有授权范围
- 追踪器、控制适配器和功能图要求
- 完整标记等待、证据、已有修复验证和范围受限修复指令

只有人工编辑器可用时，向用户交付已填好的精确改动，说明具体限制。不要创建替代或重复任务。实际更新后回读任务身份、内容与状态。

### 创建和启用边界

只通过正式支持的工具或界面创建和更新任务。没有事件监听或后台执行能力时，如实报告，保留可运行配置，不伪造后台循环。文件准备、任务创建和启用是三个不同结果。

平台强制审批不能由智能体代签。用户已经明确授权的创建、更新和启用无需再走自设审批。线程安全测试通过前，保持新任务未启用或只运行平台支持的测试模式；现有生产任务的变更使用真实可用的暂停、草稿或受控测试策略，并保护用户已有服务。

## 8. 测试线程安全

使用已有测试频道中的无害报告、平台测试事件或用户提供的报告。只有发送测试消息已获授权时，才自行发送；否则先完成其余准备并让用户提供该一项输入。

测试前确认运行环境能读取整个包与每个非秘密配置。平台使用独立仓库检出时，核对它们已存在于实际检出分支和版本。确认两个提示词指向准确的完整操作文件。任一检查失败，保持未启用并说明具体原因。

验证：

1. 分诊保存根 `thread_ts`，恰好发送一条作为回复的结论。
2. 结论包含一个已配置标记。
3. 复现只接受已配置分诊身份发出的标记。
4. 复现保持同一组不可变来源坐标。
5. 没有出现来源频道根消息。
6. 被委派执行者不能使用任何 Slack 写入动作；无法隔离时不委派，由协调者完成。
7. 坐标缺失、父消息已删除或预检失败时，不发帖，也不创建追踪器问题。

全部七项检查通过且启用已获授权后，才接入正常流量。保存实际任务标识、触发方式、配置路径、测试证据和未覆盖限制到项目 Markdown；不写凭据、不建立重型状态台账。不能执行的检查标记为未验证，不算通过。
