# 设计灵感：X 上资深仪表盘设计师反复采用的做法

一项对 X 仪表盘设计帖的研究（2026 年 11 月 24 日）进行了八次搜索，包括“dashboard design”“analytics dashboard”“saas dashboard”“finance dashboard design”等，每次设置 150–500 个赞的下限并限定含图片，得到来自 127 位作者的 197 条帖子。逐一查看了设计师发布的 64 条最高赞帖子，其中 43 条是仪表盘，其余为聊天应用、落地页和课程封面。下面的计数表示“采用该做法的帖子数 / 45”。

当设计需要规则之外的审美判断时使用本文件：例如用户说“做得像 Dribbble 作品”、页面真实却平淡，或者需要第二种视觉方向。学习制作技巧，不照搬设计师的具体布局、品牌或插画；用户询问创意来源时说明作者。

## 43 份作品中的共同模式

| 模式 | 数量 | 示例作者 |
| --- | --- | --- |
| 浅色页面 | 27/43 | Marcel Kargul、Sujon、Sajibur、Barly |
| 深色页面 | 16/43 | ln_dev7、Toby Belhome、Marcel Kargul（FlowSync） |
| 用问候语作页面标题（“Welcome back, Marcel”“Good morning, Sajibur”） | 16/43 | ln_dev7、Sajibur、Sujon、Salung Prastyo |
| 浅色条形图中高亮一根条，并在其上显示深色工具提示 | 9/43 | Sujon、Barly、heysatya、Yasir |
| 总数位于圆心的圆环图或环形图 | 7/43 | Toby Belhome、ln_dev7、TailAdmin |
| 将支付卡或钱包卡绘制为物体 | 6/43 | Sajibur、Sujon、Mide Ajibade |
| 将 3D 渲染、照片或无人机航拍作为主视觉 | 6/43 | srotimi_ui、UiRahMan92、Sujon（医疗心脏） |
| AI 面板：建议问题，或将“本周总结”作为操作 | 5/43 | Marcel Kargul、Yasir、heysatya、Augustas |

这些数字说明：

- **风格不决定点赞数。** 深色帖的点赞中位数为 709，浅色为 628；上面每种模式大约都落在 620–750 之间。作者对点赞量影响更大：仅 Marcel Kargul 就发布了 64 条中的 13 条。应为读者选择外观，而非迎合信息流。
- **高亮单条是被借鉴最多的图表创意。** 九位设计师将整个系列设为浅色，只给重要的条（本月、选中点）着色，并在深色工具提示里显示数值。这是本技能“没有重要事项就保持克制”的视觉形式。
- **问候语随处可见，却要占一行。** 简短问候可作页面标题；下方的解释句（“以下是你店铺今天的情况”）应首先删除，遵循少文字原则。
- **概念图不等于仪表盘。** 无人机画面、3D 心脏、等距建筑作为艺术作品能获得点赞，但在产品中会将数字挤到首屏以下。学习制作技巧，舍弃抢占空间的背景。

<a id="rules-designers-wrote-down"></a>

## 设计师写下的规则

以下是设计师公开分享的简短规则；它们是个人实践，不是标准。与 tokens.md 或 layout.md 不一致时，以本技能的 Token 为准：

- **@_heyrico** 的仪表盘速查表：14 px 基础字号、16 px 基础图标、1 / 1.2 / 1.5 的图标描边，常规与中等字重，很少使用半粗体。
- **@Tanjim38** 的 SaaS 仪表盘速查表：正文使用 14 px Inter、−0.2 px 字距，240 px 侧栏，表格行高至少 48 px，主要操作放右上角；空状态应有图片和操作，不能只写“无数据”。
- **Marcel Kargul** 的移动设计：一致的间距、轻微投影、430 × 932 画框、一款出色字体（Inter、Geist、SF Pro 或 SF Pro Rounded），将一切尽量简化。

<a id="steal-these"></a>

## 可以借鉴的做法

1. **克制的系列与一根高亮条。** 所有条使用强调色的浅色调，当前或选中条使用实色；深色工具提示中放一个大数字，下方放对比。（Sujon、Barly、heysatya）
2. **带实色端帽的浅色条。** 每根条使用浅色填充，顶部加 3–4 px 实色段，让堆叠或分组条形图保持平静。（Marcel Kargul）
3. **带纹理的 KPI 卡片。** 卡片内的小条形图或点阵展示它自己的周数据，无需再添第二张图。（Salung Prastyo）
4. **包含数量和操作的提醒横幅。** 例如“12 个待处理请假请求和 5 个加班审批需要处理”，旁边直接放按钮：将监测模式压缩为一行。（ln_dev7）
5. **一张强调卡片。** 白色卡片网格中，用品牌色突出唯一一张卡片（余额、目标），承载最重要的数字。只能一张。（Sajibur、Sujon）
6. **将资金表现为物体。** 绘制的卡片，或带旗帜与币种的钱包行，比表格更快传达“我的钱”。仅适用于金融场景。（Sajibur、Mide Ajibade）
7. **能够行动的 AI 面板。** 将建议问题（“剩余资金还能支撑多久？”）或“总结本周”做成按钮，不要在页面中放 AI 生成的整段洞察。（Marcel Kargul、heysatya、Augustas）
8. **洞察卡片中的 cohort 网格。** 在指标旁用小型分级网格展示留存，解释这个指标。（Bagus Fikri）

<a id="skip-these"></a>

## 避免这些做法

- 彩虹堆叠条（每根条有五种色相），以及黑底霓虹多折线图：视线找不到答案。
- 十几个扇区的大饼图；一个数字就够却使用圆环图。
- 用照片、3D 渲染或等距场景作为数据背景，甚至替代数据。
- 问候语下方的一整段文字。
- 超过一张强调卡片，或把所有卡片都涂上颜色。

<a id="also-live-products"></a>

## 也要看实际产品

第一项研究（sources.md）查看了已交付产品。同一周再次访问后，以下产品仍展示了上述设计师作品没有体现的模式：

- **Simple Analytics**：图表注释（“HN 招聘帖”）；两项研究中唯一解释“为什么”的图表。
- **Baremetrics**：主数字旁的“原为 $183,045”，以及 MRR 变化来源的分解。
- **OpenStatus、Claude Status**：逐日可用性条带，未结束事件排在最前。
- **OpenRouter**：标题下的“使用数据截至 11 月 23 日”，以及双列排行榜。
- **Cloudflare Radar**：只有因为问题本身关心地点，地图才成为主视觉。
- **Apple Stocks**：同一行中的名称、迷你趋势图、数值与涨跌胶囊，是列表的参考模型。
