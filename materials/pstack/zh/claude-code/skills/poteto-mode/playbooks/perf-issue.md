### 性能问题

**你负责测量叙述。规划、审查、核验数字。** 每个修复关联一次测量，不用读源码替代测量。

1. 用匹配控制技能捕获基线轨迹。用 **benchmark-checklist** 审核基线和之后每个数字。
2. 用 `how` 为假设建立背景。没有先运行就不宣称性能上限。
   按顺序尝试性能口诀，先便宜的：
   1. 不做它。停止结果无人使用的工作，不只是让它更便宜。
   2. 做，但别再做一次。
   3. 少做。
   4. 晚点做。
   5. 在用户没看时做。
   6. 并发做。
   7. 更便宜地做。

   较早口诀达到目标就停止。
3. 依据轨迹规划修复。跨函数边界先 `architect`。委派给配置的性能模型，默认 `grok-4.7-xhigh-fast`。按“子智能体”一节选推理级别及快速或标准速度。审差异，捕获修复后轨迹。
   按 **sequence-verifiable-units**，每次尝试验证后再试下一次。
4. 解析比较产物，如 JSON 转 sqlite、差异比较。“无结论”或错误界面不是通过，必须指出。
5. PR 引用测量。
6. 执行 **Opening a PR**。

要围绕指标持续改进而非一次性修复，使用持续指标优化（`playbooks/hillclimb.md`）。

**回复：** 基线数字、修复后数字、变化、产物路径。
