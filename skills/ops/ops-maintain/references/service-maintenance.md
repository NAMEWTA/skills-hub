# 证书、日志、容量与备份维护

## 证书续期

适用于同一身份、既有信任与发布配置契约内的证书续期。先核对域名/SNI、证书所在位置、实际提供服务的实例、到期时间、签发机制和既有续期入口。

检查真实 job 的 challenge、文件替换、权限及后置 hook。名为 renew 的任务若顺便重新部署服务、改变域名/路由/监听配置，应分离并交项目处理。dry-run 可能访问签发测试服务或运行 challenge，不能当成绝对无副作用读取。

按既有授权执行目标证书的续期，按现行运行手册 reload/restart 前核对其实际效果。验证从用户实际访问入口完成：身份、链、有效期及相关消费者。磁盘上的新证书不证明正在服务的进程已经加载；reload 返回成功也不充分。

记录证书标识、有效期、验证结果和入口引用，不保存私钥或签发账户秘密。

## 日志保留与容量处置

先区分日志、缓存、业务数据、容器可写层、持久卷、备份及临时文件，核对实际路径、归属、使用状态和保留规则。未知归属对象只报告，不清理。

1. 用已有指标或有限范围的只读检查定位占用、增长和 inode。
2. 确认删除/轮转对象的具体集合、保留边界和恢复需求。
3. 检查文件是否仍被进程持有、轮转方式是否会导致空间未释放，以及实际工具作用范围。
4. 通过 ops-execute 执行明确对象的已有保留机制。
5. 验证空间/inode、日志继续写入、消费者和保留结果，不只看删除命令退出。

systemd journal 的 vacuum 作用范围可能覆盖共享 journal，不能把带 unit 的查询选项误当成按 unit 删除。容器全局 prune、volume prune、compose down --volumes 或递归清空未知目录都不是“磁盘满”的默认处理。

减少保留期、删除仍需恢复的数据、改变日志路由/服务配置都需要核对真实目标与影响。项目发布配置变化交项目处理；现有运维规则范围内的明确容量清理才在本技能执行。

## 备份运行与核验

使用项目/数据责任方已有的备份方法，先确定数据对象、逻辑库/卷范围、时间点要求、并发写入语义、存储位置、加密与保留条件。共享实例备份应区分整实例与某项目逻辑数据，不假定用户对一个项目的请求覆盖所有租户。

检查 backup job 真实内容：不能夹带 schema 迁移、服务升级、持久拓扑变更或重新发布。可能产生锁、暂停写入或大量 I/O 的备份不属于普通只读操作，要在本次维护影响中说明。

执行后核对：

| 项目 | 所需事实 |
| --- | --- |
| 任务 | 真实 job/execution ID、目标、开始结束、结果 |
| 备份对象 | 实际对象身份、位置引用、大小及工具支持的完整性校验 |
| 一致性 | 使用的方法、快照/事务条件、跨服务边界与未覆盖内容 |
| 恢复点 | 可恢复到的实际时间与已知损失窗口 |
| 可恢复性 | 已有演练证据、适用版本/环境；没有则明确未验证 |
| 保存 | 权限、保留与加密状态的必要引用，避免暴露密钥 |

备份命令成功或文件存在不等于可恢复。不得为了证明本次备份有效自动在生产恢复。需要演练时使用已有证据、隔离环境或明确授权范围；实际数据恢复交 ops-recover。

## 容量与调度边界

清理已确认废弃日志/缓存、执行既有保留任务可属于运维。新增持久卷、改变服务副本数、调整项目持久拓扑或扩容发布定义交项目流程；不借“容量优化”改变部署。

只有用户要求或既有计划授权时才配置 cron、平台调度或持续巡检。既有任务的停用/改时也会改变运行约定，需要明确对象、影响和验证，不能因发现磁盘压力就自动禁用全部备份。
