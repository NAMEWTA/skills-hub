## `.agents/dev/changes/2026-11-19-execution-receipts/plan.md`

# 执行回执生产、持久消费与联合验收计划

目标是让 #4 Agent CLI 产生可对账的执行事实，让 #5 Tasks 在原任务中持久接收这些事实，并在响应丢失、模块暂停、写入失败和重启后恢复到可解释的状态。首条路径从一个已配齐目标的 Agent 任务手动派遣开始，最终用同一真实 CLI 完成派遣、提问、答复及结果回投，并用定时入口重走闭环。

本计划采用所附 `dev-plan` 垂直切片方法。行为依据为本次提供的 `agent.md` 和 `automation.md`，范围集中于执行回执及其生产调用方和消费入口。计划为模拟写入的交付物，代码位置、验证命令、原型版本和运行结果均待实施时核实。回执相关界面沿用两份规格各自的 `prototype-review.md`，实施时定位已确认版本及对应状态、主题、视口和源码。确认缺口只影响依赖该体验的改动和验收。

## 共享契约

下列是实施应守住的语义。首个切片负责将其落实到现有接口和可恢复存储，具体字段名、文件组织及确认接口在核对代码后确定。

| 事项 | 约束 |
| --- | --- |
| 身份与权限 | 按 Vault 和机器作用域隔离。派遣或操作身份贯穿记录、创建和对账，任务回执绑定 `taskId`、`runId` 和对应 `sessionId`。同一意图重试复用原身份，独立意图有独立身份。回答额外核验 request/version、`replyId` 及原运行和会话绑定。内部投递按绑定授权，可在全局 MCP/CLI 外露关闭时工作。 |
| 事实来源 | Tasks 负责持久保存派遣和用户输入意图，以及任务业务状态。Agent CLI 记录执行事实，分别表达本地记录建立、进程创建、attach 可见、Agent 受理、本轮业务事件和退出。Tasks 在实例确认接受本轮输入后才推进看板并追加一次系统评论。退出码、屏幕内容和静默均不能推导业务成功。 |
| 生产与恢复 | 受理身份须在进程副作用前耐久可查。进程创建或输入确认有歧义时，按原身份查询权威 Core/provider 状态，无法证实时保留 pending/unknown。unknown 保留对应任务、实例及资源占用，跨机遗留执行也不按超时自动接管。Core keep 恢复为替代 shell 时记录原 Agent 丢失。 |
| 保留与消费 | Agent CLI 保留待投递事实，直到 Tasks 已持久接管。Tasks 用稳定事件身份去重并保存原始待投递内容，再对 Markdown 时间线做条件写。评论具有可在重启后检出的稳定标识，重复投递可核验已写事实。生产端交接确认和任务评论写入完成分别记录，任何一方崩溃后均能从自身持久事实继续。 |
| 存储与安全 | 沿用单 Vault、单 Engine 的 Markdown/JSON 文件事实，SQLite 可重建。保留 task/comments 区段语义和区段外字节。只读 Vault 或临时状态目录拒绝持久派遣及回复。发现损坏记录时报告并冻结相关领取。持久记录、普通查询、日志、诊断和导出均只允许安全字段，经授权的模块执行路径负责注入秘密。 |

## 实施切片

### 01 从原任务派遣并查到同一次启动

**依赖与边界。** 无前置切片。Agent CLI 负责共享回执契约、启动对账和执行记录，Tasks 派遣入口由 Tasks 负责人维护。本片先贯通手动派遣，稳定的真实生产入口和可重放回执夹具作为后续交付。

- [ ] 在详情对有效 Agent 任务点“立即派遣”，或对未来任务点“提前派遣”。记录稳定派遣身份、冻结目标和本次覆盖。经共用 resolver 和输入仲裁，在任务所属 Space 建立会话，任务详情可前往现场，后台创建保持当前焦点。保存任务、普通评论、无授权入口及不可持久写环境均不触发启动。
- [ ] 在实际启动后、run 响应返回前断开连接，按原身份重试。对账找到原进程时返回同一绑定，权威状态不可得时显示 pending/unknown 并保留占用。用 Core 进程数证明同意图只启动一次，用两次独立的合法操作对照。分别取证本地记录、进程创建、attach 与输入受理。明确拒绝按实际失败阶段显示。
- [ ] 从手动分栏启动执行同样的对账。B 的启动等待期间切到 A，或关闭 B 的目标，检查冻结的 Space revision、Tab、leaf、方向、cwd、操作身份和导航代次。进程只能更新有效原目标，过期进程仍可在 B 找回。切换 Vault 后旧回调不得写入当前视图。

证据为任务及现场截图、脱敏的操作身份与阶段记录、真实进程和绑定计数。首片以启动及对账成立为完成条件，任务评论落盘由 02 验证。

### 02 重启后把原回执补送到任务时间线

**依赖与边界。** 依赖 01 的回执身份、重放和交接语义。Tasks 唯一负责消费、持久交接和 Markdown 投影。用 01 的契约夹具可先独立验证恢复窗口，真实生产链在 05 联验。

- [ ] 投递受理、进度、问题和最终结果，原任务只增加有意义的条目，每个 `messageId` 唯一，详细日志仍可从现场查看。只有输入受理使未开始任务进入进行中并产生一次系统评论。运行退出、pane 关闭、原生进程丢失及业务结果均由运行事实表达，完成任务由用户操作。已关闭任务可补历史结果，删除后留下目标消失诊断并阻止重新执行。
- [ ] 分别在 Agent 已保存回执、Tasks 已耐久接收但尚未确认、评论写入失败、评论落盘但送达状态未更新四个窗口重启。恢复同一事件、内容和 `messageId`，最终只有一条评论，进程和输入计数不增加。用并发人工编辑制造条件写冲突，确认原区段外字节及人工编辑保全。
- [ ] 暂停 Tasks，恢复后消费 Agent 保留的回执。切 Vault 后投递旧回调，确认新视图及新 Vault 文件无变化。注入损坏记录，验证故障可见且相关领取冻结。删除并重建 SQLite 索引后，原文件事实仍能恢复投递状态。

证据为各崩溃点前后的脱敏回执、交接状态、Markdown 差异、时间线截图及按 ID 的投递和启动计数。

### 03 持久保存回答并恢复同一任务的执行

**依赖与边界。** 依赖 01 的仲裁、执行身份和对账接口，以及 02 的持久问题投影。Tasks 负责共享 `Question[]`、有效问题选择和输入意图，Agent CLI 负责 provider 输入、续轮或恢复及输入受理回执。

- [ ] 在原任务回答最后一个有效问题，服务端校验具体 request/version、task/run/session 和 `replyId`，持久保存后随即尝试发送。用重复请求及两个客户端抢答验证同键同内容返回原结果、同键改正文被拒、换键不能抢答同版本。普通讨论只写评论，可合并补充按原 ID 和顺序进入下一轮，新正文选择须有新版意图。
- [ ] 使实例分别被人工、评审或另一轮占用，验证共享单输入所有者，持久回答显示待发送。模拟明确拒绝、接收确认丢失和 Agent CLI 暂停，分别显示失败、待核实及保留输入，重启后按原身份核对。取消未发送只撤待发意图；关闭任务后须明确重开才能再输入。
- [ ] 普通问题结束本轮并释放工作槽，回答在同一任务和会话开新轮并记录 `parentRunId`。有能力的 provider 才恢复原 deferred run/request。仅有 blocked 信号时提供前往现场，由有权人员现场处理。检查实际送入 CLI 的本轮上下文仅含选中的未消费消息、原问答、任务正文、必要摘要和资料引用。

证据为问题版本与运行绑定、输入仲裁轨迹、实际投递次数和脱敏上下文。能力矩阵由 provider 真实验证；无法证明的原生恢复保持能力缺口。

### 04 让计划派遣进入同一持久执行链

**依赖与边界。** 依赖 01 的稳定接受入口、任务去重及资源占用契约。规则时钟、扫描和入口由 Automations 负责，Tasks 统一接受派遣。规则筛选可用固定时钟独立开发，与 02 并行时使用各自的测试 Vault。

- [ ] 用相同 `now` 和规则版本运行预览、扫描和“运行一次”。分类一致，预览无写入，运行一次不修改下次日程。覆盖 Asia/Taipei 11 月 15 日 10:00 的规格例、跨月、周一零点、DST 和设备时区不同。未来 `availableAt` 不派，逾期和未排期独立，`due` 保留业务语义。
- [ ] 手动派遣和两条命中规则同时竞争同一任务。定时发生按 `ruleId + scheduledForUTC` 去重并保留当时规则快照，手动运行有独立 `invocationId`。只接受一次并产生一个实际工作轮次，后到来源查得已有接受或排除原因。同 Space 的独立会话可并行，共享资源键串行，忙或 unknown 遵循原占用。模板生成真实任务和独立 `taskId`，保留来源与配置快照。
- [ ] 验证默认规则幂等安装、每 15 分钟、工作台时区、含漏处理及未排期、默认一个活跃工作轮次，等待回答不占槽。修改、停用和删除在重启后保留，只有显式恢复才重建。停用期间不追补，已经入队的输入、运行和回执仍可查。Engine 恢复最多补一次当前扫描，固定模板只补最近一次，记录跳过或合并原因。一次性跟进可改期或取消，只投向仍开放且获授权的原任务。

证据为时钟和规则版本、候选原因、发生和接受身份、队列轨迹与进程数。

### 05 用同一真实运行联合验收两份规格

**依赖与边界。** 依赖 01–04 的可验证产物。整合负责人维护联合场景、调用者清单和证据索引。各模块沿自己的边界修复发现的问题。

| 联验场景 | 动作与通过判据 |
| --- | --- |
| 闭环与故障组合 | 用真实 CLI 在隔离 Vault 从定时规则派遣可执行任务，手动入口并发竞争。丢失 run 响应后重启并对账，确认原 Space 内只有一次有效启动。Agent 提问后从原任务回答，在实际输入受理后丢弃确认，再让最终结果的评论写入失败。恢复后关联同一任务和会话，输入只消费一次，最终结果只显示一次，用户可从任务去现场并手动完成。 |
| 连接与生命周期 | 交替暂停 Tasks 和 Agent CLI，重启或切 Vault 后恢复。检查两端各自保留的事实，以及旧事件隔离。离开视图只 detach。关闭 pane 时分别观察 kill 回执与真实退出。Core keep 换为新 shell 时显示原 Agent 丢失，原 argv 和旧任务输入均无重放。仅有退出码 0 的轮次无业务成功结果。 |
| 真机与回归 | 以真实包验证 shell、Claude Code、Codex、Pi 的启动和能力差异，至少一个真实 provider 完成问答与结果闭环，原生 deferred 按已证实能力逐项运行。检查 GUI/登录 shell PATH、解释器或 shim、Windows 脚本、空格和 Unicode、参数边界与错误 cwd。对主干和整合版本执行同一手动启动、detach、回到原会话场景，记录行为差异和主干尚未提供的入口。 |
| 数据与权限 | 在空白测试 Vault 验证新格式备份、恢复和损坏报告，检查任务、回执和执行绑定可按模块导出范围恢复，恢复过程不重启旧执行。布局是否随包按 #4 设计末节核实。用假秘密实际运行，扫描布局、回执、评论、诊断、导出、快照、日志和重启记录。干净安装外露默认全关时内部绑定回执可送达，外部未授权创建无法派遣。 |
| 一次切换 | 枚举并核对共用 resolver、输入仲裁、回执及秘密注入相关生产调用方，覆盖手动、历史恢复、任务派遣和答复、评审及规则终端命令所涉及的契约。替换旧消费者并清理旧入口和 shell `envRefs`/`secretUse` 供应链，保全真实旧数据、外部历史与进程。若调用方必须原子切换，在整合工作树完成，允许中间提交暂不可运行，以统一验证通过作为交付边界。 |

## 执行顺序与证据

`01 → 02 → 03`，`01 → 04`，`01–04 → 05`。共享 API 和持久格式在 01 由契约负责人统一维护，02 和 04 分别拥有 Tasks 消费及 Automations 规则写入边界，03 在 Tasks 端基于 02 已接受的问题与投递语义改动。契约更新由同一负责人串行合入。02–04 各自持有独立的 Vault、Core 和测试实例，05 使用专用联合环境。

开始实施时核对现有 Engine/Core run 与状态查询、Agent CLI resolver 和输入仲裁、Tasks 条件写和任务详情、Automations Croner 入口及其真实调用者。优先复用仓库已有的恢复与故障注入入口，只有缺失的崩溃窗口才补夹具。实施者在仓库根记录实际启动、构建及验证命令，附提交、包和 provider 版本、作用域、时间输入、故障边界、持久记录摘要、文件差异、进程和投递计数及界面证据。拟保存到本计划目录的 `evidence/<切片>/<场景>/`，实际进度和剩余缺口集中记录于 `progress.md`。夹具证明重放不变量，真实 CLI 和任务界面证明联合行为。

实施前需查清 Core/provider 可提供的权威对账键及查询结果、持久文件的条件写和崩溃恢复能力、各 provider 的业务事件与 deferred 能力，以及 #4 布局备份决定。对账能力不足的路径按规格保留 unknown，原生恢复及布局随包仅在证据支持的范围内验收。对应的实际原型及源码位置、仓库基线、`source.md` 完整验收矩阵均未包含在本次离线材料中，因此引用粒度限于所附规格中的节号和行为。
