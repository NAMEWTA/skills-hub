# 开发环境与宿主配置

交付一份与当前环境一致的配置，并证明最小工作链路可用。只记录实际观察到的能力、模型和限制。用户已经指定范围或预算时直接沿用。

## 配置顺序

1. 阅读项目指令和当前工具说明，按 [宿主适配方法](references/host-adapter.md) 区分可用、不可用与尚未确认的能力。
2. 按 [完整角色配置方法](references/configure-models.md) 读取现有设置，确定预算，建立角色映射并验证每个真实值。使用 [角色配置模板](assets/model-roles.md)，不把示例值传给工具。
3. 按 [接入与首个任务指南](references/getting-started.md) 核对技能是否可读取、配置如何加载，以及第一个真实小任务如何验收。
4. 项目缺少行为验证时，提供一次按 [创建验证技能](references/verification-authoring.md) 补齐的建议；已有授权就执行。形式化检查仅在有明确属性与范围时选择 [形式化验证适配](references/formal-options.md)。
5. 用户要离线持续运行时，再读 [无人值守完整指南](references/unattended-work.md)，确认完成条件、权限、隔离、证据与实际调度机制。

## 输出与持久化

配置优先存放在项目已有约定位置；无约定时，使用 `.agents/context/model-roles.md` 保存简短角色表，在现有项目指令中加入必要导航。仅修改本次管理的设置，不覆盖用户其他规则。不因项目配置请求写入全局偏好。

配置文件不会凭空改变宿主。说明当前会话能否读取它、子智能体是否接受覆盖参数，以及新会话是否经过实际验证。未检查自动加载时，只说文件已保存。

使用 [环境记录模板](assets/environment.md) 记录事实来源、验证命令或观察、未覆盖范围；不复制秘密、完整会话或工具全量输出。交付包括已配置项、保持继承的角色、实际验证结果、以及真正缺少的条件。
