# 任务与共享对象

## 任务拆分

只在一个目标不能一次可靠完成、或有真实独立取证范围时拆分。每个单元要有实际对象、允许操作、证据输入、完成条件和返回结果。不要按技能名称机械拆成九个阶段。

例如两个项目同时超时，可并行检查各自应用日志与共享数据库指标；数据库运行恢复由一个明确执行者负责。项目成员关系和共享数据库消费范围由 inventory 的已核验资料给出；一条连接不证明完整归属，也不自动扩大操作权限。

## 传给下一位执行者的上下文

| 内容 | 要求 |
| --- | --- |
| 目标与完成条件 | 用户要看到的结果，当前已经完成的部分 |
| 身份与范围 | 项目/环境、稳定服务/实例/资源 ID，实际连接定位与核验时间 |
| 现有决定 | 已确认前提、用户授权、排除方案与不得改变的边界 |
| 证据 | 原始来源或准确查询条件、时间范围、支持与反证、仍未知项 |
| 记录 | 运维根、主 run、需要时的子 run、写入者与既有后端任务 ID |
| 返回条件 | 实际动作、逐目标状态、验证结果、需主任务决策的事项 |

小任务可以在同一 run 的步骤中传递这些要点，不必生成独立任务文件。大日志留在既有受控来源，传引用与脱敏摘录。

## 并行与冲突

按真实变更对象协调：维护一个 unit 的范围是该实例及其已核验影响；重启主机的范围是主机全部已知对象；维护共享代理要考虑同一有效配置；共享数据库恢复要考虑所有已知消费者与数据使用边界。

仅在不争写共享对象时并行。共用对象设置唯一执行者，其他任务取证或等待其结果。已有作业平台能提供锁或并发限制时复用；本地文件写锁只协调记录，不代表已锁住远端资源，更不代表跨控制端互斥。

执行顺序来自服务的已验证运行先决条件和就绪规则。关系图中 A 依赖 B 不自动意味着可以停止 A、重建 B、再次启动 A；先读取专门方法和当前项目已验证配方。

## 可选项目 CLI

服务器和运行关系任务可以在独立 ops 工作根完成，不以源码仓库为前提。确需私有项目资料或项目专属技能时，按用户已经选定的 CLI/方式进入真实目录：

1. 核对目录身份、可读资料、实际 CLI 和启动参数，保留用户选择，不假设固定模型或终端工具。
2. 核对该 CLI 实际读取的项目规则与技能发现位置；仅在父会话中 cd 不等于重新加载。
3. 明确运维记录根、主/子 run 和唯一汇总写入者。独立项目 CLI 必须能够读取所需 ops 方法；无法读取时报告缺口。
4. 传入上表最少上下文，要求返回真实结果和证据。父会话收到“命令已发送”不能写为“服务已恢复”。
5. 回到主任务按目标汇总，不自动迁移其他领域记录，不建立常驻 Agent 调度器。

项目自己的发布由用户或上层在其独立流程继续。ops 仅交接普通 Markdown，不要求外部接收器、hook 或新格式。
