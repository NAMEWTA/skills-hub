# 维护项目运维方法

系统、工具和运行关系变化会让项目技能过时。检查单位是一个完整运维方法及其前提，不是每句话；每个声明可用的方法都需要与当前证据对应。

## 结果与编辑范围

- **clean：** 声明范围的各方法都有当前资料和相应运行证据，没有需交付修改。
- **changed：** 修正并验证了手册、操作入口、辅助或方法图，按既有授权交付。
- **blocked：** 无法完成所需覆盖，或修复超出范围，准确列出阻塞和仍有效部分。

只编辑 ops 自有文档及本次用户指定的项目运维技能源码。产品、部署配置或其他领域技能不在编辑范围；发现系统回归要报告，不能把预期改成错误现状掩盖问题。

## 维护步骤

0. **定位。** 按项目、名称、描述和方法索引找到真实目标；多个候选不能区分才询问。没有现成方法时按已有授权进入生成，不凭空创建“已有技能”。
1. **整理索引。** 枚举技能拥有的运维方法，修复缺失、重复、过期或不可达引用。只有一条方法不强制建立大目录。
2. **读取真实依据。** 按方法独立核对现有配置、运行入口、运维记录、工具版本和权威资产来源。可分派独立只读调查，但它们不能同时操作共享实例。每个返回方法用途、证据入口、疑似漂移、可执行核验配方。
3. **协调。** 覆盖所有声明方法，合并重复核验和共享状态，抽查疑似漂移；检查近期系统变化是否引入方法图遗漏。不能只因名字相近认定新能力已被覆盖。
4. **验证当前声明。** 优先只读路径、已有有效运行证据、回放和适当测试环境。每次操作前核验目标与前提；失败后重新诊断当前状态再继续。恢复/数据操作若缺独立授权，保持未验证，不为了完成维护强行生产操作。证据清理后仍须可访问，本次自己创建的临时内容不得无限留存；共享生产实例不属于清理对象。
5. **分类修正。** 描述或入口错误是方法漂移，修正文档；已有能力无法被辅助工具正确驱动是辅助缺口，在范围内修复并再验证；系统本身异常是运行或项目问题，交相应 owner。改变制品、部署配置或 schema 的修复交项目，不能写进 ops 维护步骤。
6. **交付。** changed 时重读全部修改并交付已证明部分；clean 说明证据覆盖；blocked 列具体权限/环境/工具/数据前提与已尝试路径。不得仅因为某方法“看起来没变”就宣称它已重验。

所有引用保留真实路径和来源时间。原运行记录只追加更正，不用新的手册覆盖历史；生成技能的源码和安装副本有明确 owner，不在两边分别修改成竞争版本。
