# 问题自动化概览

两个相互配合的任务处理 Slack 问题报告：一个分诊每份报告，另一个复现已经确认的缺陷，并可在授权范围内准备小型草稿修复。

包内文件是完整的方法、配置与任务模板。安装技能不会自动创建或启用任务，也不依赖宿主具备斜杠命令。

## 配置顺序

1. 阅读 [自动化目标与运行契约](automation-intent.md)，确定目标仓库与已有授权。
2. 将整个独立包安装到目标项目 `.agents/skills/dev-issue-setup/`；保留仅目标存在的文件，审阅冲突，不覆盖本地编辑。
3. 按 [配置方法](setup-method.md) 核实完整共同能力在实际运行环境中可读：

```text
模块运行追踪与历史依据调查
测试驱动与清晰写作
共享状态、阅读负担、上下文和可验证单元
根因修复与真实对象证据
```

4. 用户拥有的配置保存在安装包之外，例如 `.agents/project/issue-automation/`。适配 [配置模板](../assets/configuration.yaml) 和 [功能映射](../assets/feature-map.md)。
5. 实际平台使用独立仓库检出时，启用前确保完整包与所有非秘密配置已经存在于其检出版本；本地读取型任务则验证实际路径可读。
6. 完成新任务的可审查配置，或按原身份更新已有任务。使用已获授权的无害报告或平台测试事件验证线程安全，确认来源频道中每条自动化消息都留在原始线程内，然后按已有启用授权接入正常流量。
