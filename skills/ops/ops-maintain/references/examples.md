# 维护边界示例

## 主机上有无关项目

host-b 同时运行 shop-api、billing-worker 和共享 redis-main。用户要求维护 shop-api 的日志保留：

- 只定位该服务日志与现有保留规则。
- 不重启主机、billing-worker 或 Redis。
- 若实际日志位于共享 journal 且清理会影响其他项目，说明真实影响，改用允许的精确方法或报告范围缺口。
- 已有授权覆盖的动作继续完成，不因每个文件重复确认。

## “系统更新”带入数据库版本

OS 维护预览列出了内核、基础库与 PostgreSQL 的版本变化。基础包也可能触发服务重启，需审查依赖与影响。数据库切版交项目/共享服务部署责任方，不自动执行全量升级。

## 磁盘占满与业务卷

已核验日志目录持续增长可以按保留规则处理；不认识的容器卷保持未知。docker system prune --all --volumes 可能删除恢复依赖与业务数据，不属于本请求的自动补救。

## 定时任务不是默认产物

用户说“这次备份一下”，只执行本次已授权备份与核验，记录结果。用户明确说“以后每晚按这个范围备份”时，才按真实调度平台、窗口、错误处理和记录能力配置计划。
