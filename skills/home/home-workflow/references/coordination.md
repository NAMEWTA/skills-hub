# 协调、接续与收尾

## 接收主题与准备派发

先复用用户已有 Issue、计划、任务主题或项目管理入口。需要实际向项目派发时，用 `home-tasks` 按[协调模板](../assets/coordination.md)记录主题和各轮往返。单项目与跨项目都可以先接受、记录后再派发。普通位置查询和 Home 概况回答无需创建主题。旧协调页可作为已有权威入口被引用。

协调记录保存目标、直接负责人、验收条件、依赖、未决事项、往返消息及状态依据。原方法提供会话身份、投递、接续和回收证据。项目内部 task、知识和原始测试记录由项目维护。

## 同时关注本次交付与下一次工作

长期目标由一个直接负责人贯穿，既判断本次怎样完成，也保留能改善后续工作的有根据经验。先找用户或其他 Agent 已维护的共享资料，沿其约定更新。把理解目标、决定、结果和接续条件需要的事实写进 Home 正式正文。研究笔记、报告、规格和提交用于进一步追溯，原报告、Issue、转录和来源文档仍由其 owner 保存。

重复失败若暴露环境缺口，可提出与当前目标有关的具体改进：更明确的接口约束、有效检查、代码约定、必要日志、测试数据或浏览器观察能力。项目内部改进交当地负责人，遵守用户已授权范围与项目方法；不以战略回顾为由先重构所有项目、添加后台服务或绕过既有约定。紧急任务中的例外要说明依据与后续 owner，不能把一次临时绕行变成无来源的长期规则。

当前有效结论由 `home-knowledge` 维护，发生过的决定由 `home-history` 保存。涉及实现的旧结论附准确仓库、revision 和时间；新证据替代旧结论时由各 owner 更新受影响主题、入链与索引，而非只添新页。若用户请求阶段回顾，优先查看失败、返工、重复询问和交接丢失的实例；回顾频率、是否派遣及自动触发均由实际任务与用户要求决定。

## 按缺口推进

1. 从当前请求和有关记录提炼一个实际目标，继承已经确认的范围与授权。任务内容变化时更新同一权威目标，不重新生成平行计划。
2. 项目背景不清用 `home-knowledge`；要知道过去怎样决定用 `home-history`；关系不清用 `home-map`；配置缺项用 `home-setup`。只传所需上下文和原件指针，不复制方法全文。
3. 明确各项目直接负责人的交付条件、依赖和验收人。先通过 `home-tasks` 按 repo ID 查询并在实际发送前占用目标；项目或用户已明确报告外部占用时留待派发。同项目另一个未结案主题占用时先排队，同主题追加接续原负责人。空闲项目可先接收不依赖忙碌项目的部分。项目独立与派遣工具的并行限制都适用。
4. 各项目反馈事实冲突时保留双方说法、版本和时间，向有关 owner 求证。不得让旧地图、旧历史或更流畅的自报覆盖真实证据。
5. Home 核对直接交付并更新目标状态，项目最终交付验收或确认停下后释放占用。需要跨项目验证时调用 `home-integrate`，指定执行者和组合，满足主题验收后结案。多个项目分别通过不等于组合通过。

## 接续简报

用户说“继续”时先用 `home-tasks` 查询主题或 repo ID，读最新 task/report，再向原派遣方法核查未确认动作。软超时、会话不可见或原 App 已退出都不能单独证明可安全重派。确认原结果后按需追加消息；缺少发送证据时保留占用和未核实状态。历史只说明当时发生什么，不直接当成当前运行事实。

新的 task 编号表示新的业务消息，不要求新建 session。同一主题、同一项目的追加任务优先交原直接负责人和仍可使用的会话；上下文接近上限时按实际宿主支持的压缩或恢复处理，并重新读取缺失的 Home/项目入口。只有原方法核实原会话不能接续或已有选择要求新的执行上下文时，才建立明确关联的新会话。消息送出后连接中断且结果不明时保留 unknown 和占用，先查原结果，不能当作未发送重放。

用户只询问进展时，报告各项目最近实查时间、已确认结果及仍未知部分，然后继续原先已授权任务。明确暂停或取消才改变执行目标；A 已交付而 B 受阻时，保留 A 的成果及 B 的缺口，组合验收不写成全部完成。

简报包含当前目标、已接受的决定、实际产物/版本、已验收范围、未完成条件和下一 owner，链接原任务、报告、规格、提交与差异。不得仅凭摘要判断正在运行的实例、可接管性或可删除性。原记录不可达时说明具体缺口，保留已有证据，避免重复修改任务。

## 收尾与知识形成

先按实际完成条件验收，报告完成、部分完成、受阻、取消或中断。记录未验收状态也是合法历史，不能为了“收尾”把它改成完成。

- 值得回顾的事件和会话摘要交 `home-history`，带事件时间、记录时间、来源 owner 与实际状态；不要求每次聊天保存。
- 仍适用的项目基本背景、跨项目决定或管理经验交 `home-knowledge`；保留来源、适用条件、候选状态和核查需求。项目实现细节只引用当地 owner。
- 用户纠正运行默认交 `home-setup`；旧历史或知识推断不会自动改配置。
- 当前结构关系交 `home-map`；现行理由由 knowledge、发生过程由 history、本次目标由 coordination 各自维护，互相引用而不重复编辑。
- 用户要求日常回顾时由 history 组织相应范围，再按缺口调用 owner。只有明确请求自动触发且存在已验证机制时，才交实际自动化方法；配置文档本身不创建守护进程。

没有有价值新事实时允许不写。完成报告给出产物、证据、决定和未覆盖范围，不把保存在 Home 的摘要当成项目知识迁移成功。
